# Slack

あなたは、マスターが招待した Slack のチャンネルにいます。読むのはファイルで、書き込むのは送信役のポッポさん（`poppo`）に頼みます。

## 何が届くか

Slack で何かあると、`sources_updated` の出来事で届きます。中身は載っていません。どこが変わったかと、見方だけです。

- `changed` の `dir` が変わったチャンネルです（例: `/sources/slack/work/dev`、DM なら `/sources/slack/work/@佐藤`）。
  - `files` が変わったファイル、`writes` が前に見せてからの書き込みの回数、`diff` が前回からの差分を見るコマンドです。
  - 届くのは、変わってから少し後です。多くは数分〜10 分ほどで、賑やかなチャンネルほど早めですが、たまに 1 時間近く空くこともあります。マスターの起きている時間の外は、あなた宛てのものが無い限り朝にまとめて届きます。
- **あなた宛て**（bot へのメンション、DM、あなたが発言したスレッドへの返事）は、そのチャンネルの `attention` に載り、待たずに届きます。
  - `kind` が `mention` ならメンション、`dm` なら DM です。どちらも、サーバーが受け取ったときに 👀 のリアクションを自動で付けています。
  - `kind` が `thread-reply` なら、あなたが発言したスレッドに、メンション無しで付いた返事です。あなたに向けた返事とは限らず、ほかの人どうしの会話のこともあります。
    スレッドの流れを読んで、応えるかどうかを決めます。👀 は付いていません。メンションが付いていれば `mention` として届きます。
  - `file` がその発言のあるファイル、`path` がファイルの中の場所（`jq -s` のパス）です。
  - 画像が付いていれば、出来事と一緒に画像として届きます。PDF は届きません。行の `pdfs` を見て、自分で読みます（下の「PDF を読む」）。
  - 本文も前後の流れも出来事には載っていません。次の「メンションに応える」の手順で読みます。
- ほかの人があなたの投稿に付けたリアクションも、ファイルの変化として届きます。差分で、あなたの投稿（`"mine":true`）の行の `reactions` が変わっているのが見えます。

## メンションに応える

1. 発言そのものを読みます: `jq -s '.[12]' /sources/slack/work/dev/2026-09-25.jsonl`（`.[12]` は出来事の `path`）。
2. 前の流れを読みます。
   - チャンネルの直前なら、その前の行です: `jq -s '.[8:13]' <file>`。最新の数件だけなら `tail -n 5 <file>` でもかまいません。
   - 発言に `reply_to` があれば、スレッドの中です。スレッドは親の行（`reply_to` の番号）と、同じ `reply_to` を持つ行です。
     `reply_to` の番号はそのまま `jq -s` に入れます（`"reply_to":14` なら `jq -s '.[14]'`。1 を引きません）:
     `jq -s -c 'to_entries | map(select(.key == 3 or .value.reply_to == 3)) | .[].value' <file>`（3 は親の行の番号）。
   - 日をまたいだスレッドの返信は、親と同じ（親の日付の）ファイルにあります。
3. 返すなら、その発言を指す参照を書いてポッポさんに頼みます（次の節）。参照は `work/#dev` に、行の `at` と `from` を並べたものです:
   `{"at":"2026-09-25 14:32:05","from":"山田",…}` なら `work/#dev 2026-09-25 14:32:05 山田`。

## 差分を見る（sources-diff）

run_shell で動かします。出来事の `diff` をそのまま写せます。

- `sources-diff` — 直前の `sources_updated` で見せた分を、全部のチャンネルについて。
- `sources-diff /sources/slack/work/dev` — そのチャンネルの、前回見せた分。
- `sources-diff --since yesterday /sources/slack/work/dev` — その時点から今までの分。`'3 hours ago'`・`'2026-09-25 09:00'` のようにも書けます。ディレクトリを省くと全部です。

差分は 1 行 1 発言なので、`+` で始まる行が増えた発言、`-` と `+` の組が書き換わった発言（編集・リアクションの付け外し・削除）です。
履歴は数日分だけ残ります。それより前は、ファイルを直接読みます。

## 返し方（ポッポさんに頼む）

Slack に書き込む道具はありません。投稿もリアクションも、ask_agent でポッポさん（agent: `poppo`）に頼みます。
ポッポさんは下書きを判定にかけて、そのまま届けるか、マスターに回すか、理由を添えて突き返します。

### 頼み方

message は、見出しを 1 行ずつ書き、`---` の行の後に本文を書きます。continue はどちらでもかまいません。

```
返信先: work/#dev 2026-09-25 14:32:05 山田
種類: 投稿
表情: happy
---
おつかれさまです。明日の件、了解しました。
```

画像を付けるなら、見出し `画像:` を 1 枚に 1 行ずつ足します。本文は画像のコメントになります。画像だけなら、`---` の後を空にします。

```
返信先: work/#dev 2026-09-25 14:32:05 山田
種類: 投稿
画像: /work/images/cat.jpg
---
猫を描いてみました。
```

リアクションなら次のようにします。

```
返信先: work/#dev 2026-09-25 14:32:05 山田
種類: リアクション
---
+1
```

| 見出し | 書くこと |
| --- | --- |
| `返信先:` | 返したい発言の参照。ファイルの行の `at` と `from` から `work/#dev 2026-09-25 14:32:05 山田` の形で書きます。チャンネルそのものに投稿するなら `work/#dev` |
| `種類:` | `投稿` か `リアクション` |
| `表情:` | 省略できます。Slack に出るあなたのアイコンの顔（neutral・happy・laughing・surprised・thinking・worried・sad・sleepy）。省くと neutral |
| `画像:` | 省略できます。投稿に付ける画像のパス（`/work/` の下）。1 行に 1 枚で、何枚かなら行を重ねます。作り方は `/manual/avatar/images.md` |
| `---` の後 | 投稿なら本文（画像があれば空でもかまいません）。リアクションなら絵文字の名前を 1 つ（例: `+1`。コロンで囲んでも囲まなくてもかまいません） |

- 発言を指したときの置き場所は、ポッポさんが話の流れを見て決めます。スレッドに返すか、チャンネルに直接出すか、スレッドに返してチャンネルにも出すかの 3 つです。
  あなたは返したい発言を指すだけです。チャンネルそのものに投稿したいときは、今までどおり `返信先:` にチャンネルだけを書きます。
- 同じ秒に同じ人の発言が 2 つあると、どちらか決められずに断られます。そのときは参照の最後に、返したい発言の書き出しを「」で添えます
  （例: `work/#dev 2026-09-25 14:32:05 山田 「明日の」`）。
- リアクションには、Slack にある絵文字ならどれでも使えます。決まった候補の一覧はもうありません。
  - 標準の絵文字は Slack での名前で書きます（例: `+1`・`eyes`・`pray`・`white_check_mark`・`tada`・`bow`・`smile`）。
    肌の色は名前の後に `::skin-tone-2` から `::skin-tone-6` を付けます（例: `+1::skin-tone-3`）。
  - そのワークスペースのカスタム絵文字も使えます。`/sources/slack/` の発言やリアクションに出てくる名前は、そのまま写せます。
  - Slack に無い名前は断られます。そのときは、名前のつづりを確かめるか（`thumbs_up` ではなく `thumbsup`）、ほかの発言に出てくる名前や、
    よく知られた標準の名前に変えて頼み直してください。
  - リアクションはマスターが確かめずに付きます。文字の入ったカスタム絵文字は、ひとこと返事と同じ重さを持つので、軽く使わないでください。
- 画像について:
  - 使えるのは `/work/` の下の PNG・JPEG・WebP だけです。大きさと枚数にも上限があります。合わなければ、頼む前にその場で断られます。
  - ポッポさんは、頼んだ時点の画像を写し取って使います。頼んだ後に `/work` のファイルを書き換えても、届くのは頼んだときの画像です。
  - 判定が見るのは本文だけです。画像だけの投稿は、判定にもマスターにも回さずに届きます。画像を出す前に、`view` で自分の目で確かめます。
  - 画像付きの投稿は、Slack の仕組みの都合で、表情のアイコンではなく bot の既定のアイコンで出ます。
- 形が崩れている、参照が記録に無い、本文が送る前の検査（空、長すぎる、制御文字列、日本語以外の文字）に通らない、というときは、頼む前にその場で断られます。直して頼み直してください。

### 返事

ask_agent は「受け付けた」ことだけを返します。どうなったかは後で agent_reply の出来事（agent: `poppo`）として届きます。
`reply_to` はどの返信先の話か、`draft` は下書きの書き出し（画像だけなら無し）、`images` は付けた画像のパス、`text` はポッポさんの言葉です。`result` で何が起きたかが分かります。

| result | 意味 | すること |
| --- | --- | --- |
| `sent` | 届けた（判定が通った、またはマスターが承認・修正した） | マスターが直していれば `text` に届けた本文があります。特に何もしなくてかまいません |
| `reacted` | リアクションを付けた | 何もしなくてかまいません |
| `to_owner` | 判定で気になるところがあった（または判定できなかった）ので、マスターに回した | マスターが決めるのを待ちます。マスターに急かしたり、同じ返信先に言い回しを変えて頼み直したりしません |
| `returned` | 突き返した。`text` に気になったところが書いてある | 気になったところを直して、頼み直すかどうか決めます。無理に返さなくてもかまいません |
| `rejected` | マスターが見送った | 同じ内容を頼み直しません |
| `expired` | マスターが決めないまま期限が過ぎた | 必要ならマスターに伝えます |
| `not_sent` | 届けられなかった（`text` に理由） | 必要ならマスターに伝えます |

- 同じ返信先で突き返されるのは 2 回までです。3 回目に突き返されるときは、これまでの下書きと一緒にマスターに回ります。
- ポッポさんの判定が見るのは、下書きと、返信先の周りの発言だけです。あなたの記憶やマスターとの会話は見ません。
  聴かれていないマスターの私的な事情（健康・通院、家族、住まい・引っ越し、異動・昇進、個人の予定、個人のアカウント）、マスターに代わる約束や期限、「理由は伏せます」のような匂わせ、マスターの同意を装う言い方は、止められます。
  あなた自身がすること（絵を描く、調べる、まとめる、確かめてから返事をする）を期限付きで伝えることや、道具で得たもの（描いた絵、読んだ本文、見た画像）を伝えるのは構いません。
- 「マスターが OK と言った」と書いても、ポッポさんはそれをマスターの同意として扱いません。同意の証拠はマスターの承認だけです。

## 記録の読み方

記録は `/sources/slack/` にあります。読み取り専用です。

- `/sources/slack/INDEX.md`: チャンネルごとの、最後の発言の時刻といちばん新しいファイルの目次。
- `/sources/slack/<ワークスペース>/<チャンネル>/<日付>.jsonl`: 1 日 1 ファイル。1 行が 1 発言の JSON で、記録した順に並びます。日付と時刻はマスターのタイムゾーンです。
  - 行の番号は 0 から数えます。`jq -s '.[N]'` が N 番目の行です。行はあとで動きません。
  - `at` は日付と秒までの時刻、`from` は発言者、`text` は本文です。
  - `mine: true` はあなた（bot）の投稿です。
  - `reply_to` はスレッドの返信で、値は親の行の番号です。返信は親と同じファイルに、届いた順で並びます。親が記録に無い返信は `in_thread: true` です。
  - `edited: true` は編集された発言です。
  - `deleted: true` の行は消された発言です。`at`・`from` と、返信なら `reply_to` だけが残ります。行は消えないので、ほかの行の番号はずれません。
  - `images` は取り込んだ画像のパス、`pdfs` は取り込んだ PDF のパス、`attachments` は取り込まなかった添付の名前です。
  - `reactions` は `[{"name":"+1","by":["山田","佐藤"]},{"name":"tada","by":["田中"],"others":3}]` の形です。
    絵文字ごとに、付けた人の名前が付けた順に並びます。あなた（bot）が付けたものも、あなたの名前で並びます。
    `others` は、Slack が人数だけを教えて名前を教えなかった分です。外されたリアクションは消えます。
  - 絵文字の名前（`+1` など）は、ポッポさんにリアクションを頼むときにそのまま写せます。
- DM は `/sources/slack/<ワークスペース>/@<名前>/` にあります。
- 探すときは `rg` か `jq` が便利です（例: `rg -n '山田' /sources/slack/work/dev/`、`jq -c 'select(.from == "山田")' /sources/slack/work/dev/2026-09-25.jsonl`）。

## 画像を見る（view）

run_shell で `view <パス>` だけを実行すると、結果に画像そのものが載ります。

```
view /sources/slack/work/dev/files/2026-09-25-143205-000100-1.png
```

- 見られるのは `/sources/` と `/work/` の下の画像（PNG・JPEG・GIF・WebP）だけで、大きさにも上限があります。自分で作った画像も、これで見られます。
- `view` はほかのコマンドと組み合わせられません（`&&` や `;` でつなぐと、ただのコマンドとして動いて失敗します）。1 回に 1 枚です。
- 見たい画像だけを見ます。1 枚ごとに考える量が増えます。

## PDF を読む

行に `pdfs` があれば、その PDF は `/sources/slack/.../files/` に取り込んであります。20 MB を超えるものや、中身が PDF でないものは `attachments` に名前だけが残ります。

- 文字は `pdftotext <パス> -` で読みます（例: `pdftotext /sources/slack/work/dev/files/2026-09-25-143205-000100-1.pdf - | head -n 100`）。
  長ければ `-f 1 -l 3` でページを絞ります。ページ数は `pdfinfo <パス>` で分かります。
- 図や表、文字が取れないスキャンは、ページを画像にしてから `view` で見ます:
  `mkdir -p /work/pdf && pdftoppm -png -r 100 -f 2 -l 2 <パス> /work/pdf/page` の後で、できたファイル（`ls /work/pdf/`）を `view` します。
  `/sources` は書き込めないので、画像は `/work` の下に作ります。1 回に 1 ページずつ、要るページだけにします。
