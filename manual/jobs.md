# 裏で動かしたコマンド

`run_shell` は、`wait_seconds` で選んだ秒数（省くと応答の上限）だけコマンドを待ちます。
その間に終わらなければ、そこまでの出力を返して、コマンドを止めずに裏で動かし続けます。`0` なら待たずにすぐ裏に回します。
裏に回ったコマンドが終わると、サーバーがその結果をファイルにして、`sources_updated` で知らせます。

## 裏に回ったとき

結果の文に、次のことが書いてあります。

- 終わりを置くディレクトリ（`/sources/jobs/<日時>-<短い印>/`。日時は UTC。例: `20261106T033456Z-8f3a`）
- プロセスグループの番号。`kill -- -<番号>` で、そのコマンドが始めたものごとグループで止められます。

そのあとは、`ps` や `sleep` で様子を見に行かなくてかまいません。ほかにすることがあれば続け、急がないならターンを終えてかまいません。
終われば知らせが届きます。

ディレクトリは裏に回ったときにでき、`README.md` に「動いています」と書かれています。これはあなたが始めたことなので、
できたこと自体は知らせません。

## 終わったときの知らせ

| 終わり方 | 知らせ方 |
| --- | --- |
| 終了コードで終わった | `attention` に載り、待たずに、夜でも届きます。`kind` は `shell_finished`、`file` はそのディレクトリの `README.md`、`exit_code` が終了コードです。出力は載りません |
| シグナルで終わった（`kill` で止めた、メモリの上限に当たった OOM など） | 印の無い、ふつうの変化として少し後に届きます。`README.md` にシグナルの名前があります |
| 裏に回ってから 24 時間たっても終わらない | ふつうの変化として届きます。サーバーはもう待ちません。プロセスは止めていないので、要らなければ `kill -- -<番号>` で止めます |
| 待っている途中で、サーバーが再起動した・作業環境の実行役との接続が切れた | ふつうの変化として届きます。終わりはもう分かりません。作業環境ごと作り直されていれば、コマンドも止まっています |

## ディレクトリの形

| ファイル | 中身 |
| --- | --- |
| `README.md` | 状態（終わり方）、裏に回った時刻、終わった時刻、プロセスグループの番号、コマンド |
| `stdout.txt` | 標準出力 |
| `stderr.txt` | 標準エラー出力 |

- `sources-diff` で見える差分は `README.md` だけです。出力はファイルで読みます。
- 出力が長いときは、先頭と末尾だけが残り、間に「ここで N バイトを省きました」の行が入ります。`README.md` にも省いた量が書いてあります。
  全部が要るコマンドは、はじめから `/work` のファイルへリダイレクトしてください。
- ディレクトリは消えません。

## 待てる数の上限

終わりを待てるコマンドの数には上限があります（設定で決まります）。上限まで待っているときに裏に回ったコマンドは、
止めずに動かしますが、終わっても知らせず、ディレクトリも作りません。その後の出力も読み捨てます。結果の文にそう書いてあります。
そのコマンドが終わったかは `ps` で確かめ、要らなければ `kill -- -<番号>` で止めます。

結果の末尾の「まだ動いているコマンドが N 個」は、知らせを待っていないものだけを数えています。
