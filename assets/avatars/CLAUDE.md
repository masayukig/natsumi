# アバターを新しく作るとき

最初にこの手順を読み、ファイル形式と検査の仕様は [アバターの作り方](../../docs/avatar.md) を参照する。

1. 本人に基本の LoRA とトリガー語、キャラクターの基本プロンプト、特別な Positive / Negative、モデル、ID と表示名を聞く。既に決まったことは再確認しない。猫耳だけのミャオでは Negative に `(human ears, extra ears, normal ears, realistic ears:1.7),` を加えている。
2. 表情のアイコンは sdctl で生成する。伊織・ミャオの直下の PNG にある `parameters` メタデータを読んで、品質・外見・衣装・構図・表情・LoRA の行を組み立てる。モデルに必要な VAE / text encoder を明示する。各表情を数枚ずつ生成して並べ、外見がそろい表情が自然な候補を選ぶ。共有 GPU のため候補数は少なめにし、seed と選んだ理由を README に記録する。生成した元の PNG も保存する。
3. sdctl の画像を、顔がいい感じにクローズアップされるように正方形で切り出す。表情間で目の高さと顔の大きさをそろえる。同じ切り出しから 512×512 の WebP と 256×256 の RGB PNG を作り、元画像上の左・上・一辺の座標を README に残す。
4. アニメーションの `spritesheet.webp` は Codex の `$hatch-pet` スキルで作る。Claude が作業している場合は Codex に頼む。正面に近い表情、必要なら sdctl で生成した全身像を参照にし、共通の全身像から各動作を生成する。コマの確認用画像と動作のプレビューで、外見の一貫性・透過・切れ・動作を目視確認する。確認用画像はコミットしない。
5. `appearance.yaml` の身体の特徴と `keep` は実際に描いた絵から決め、候補を PR で本人に確認してもらう。衣装と描画例、`sdctl-params.yaml`、`avatar.json`、`pet.json` を用意する。README に画像の出どころ、モデル・LoRA・生成設定、選定理由、切り出し座標、ライセンスと帰属表示を記録する。
6. `natsumi avatar check` で誤りと不足の補完がともに 0 であることを確認する。組み込みに足す場合は README・`docs/avatar.md`・一覧のテストにも追加し、リポジトリの検証コマンドを実行する。本番 config は依頼がある場合だけ変更する。

公開前には差分と画像のメタデータを確認し、内部ホスト名・個人の絶対パス・秘密が含まれていないことを確かめる。
