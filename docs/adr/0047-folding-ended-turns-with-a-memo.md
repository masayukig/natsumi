# 0047. 終わったターンを畳んで一行メモを残し、read で読んだものは残す

- Date: 2026-09-26
- Status: Accepted

## Context

なつみは一本の session に、本人との会話・Slack・予定・同僚への依頼など、文脈の違う出来事を順に積んでいる（[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md)）。
過去のターンのツールの出力や思考のような途中経過が残るほど、なつみは迷いやすくなるのではないか、と本人は考えた。

本番の直近 3 日の session を、本文を見ずに集計した結果は次のとおりである。

- 日中のターンの約 87% は、ターンの途中経過（思考とツールの呼び出し・結果）だった。届いた出来事・本人の発言・返事は 1 割あまり。
- 過去のターンの思考は、毎回モデルに送り直されていた。思考は積まれている量の 3〜5 割を占める最大の塊で、次が `run_shell` の結果だった。
- 1 日の文脈は 7〜8 万 tokens に達し、上限（6 万）での compaction が 1 日に 0〜2 回走っていた。compaction は走るたびに prefix cache を全部外す。

手元の事情は次のとおりである。

- 本人のエンドポイントのモデルは prefill が遅い。system prompt とツールの定義は session の間は動かさず、変わるものはターンの末尾に置く（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
- ターンの終わりを知らせる専用のツールは無い。なつみがツールを呼ばずに止まると、ターンが終わる（[ADR 0024](0024-no-event-ids-for-the-model.md)）。サーバーは Pi の run が戻ったことでそれを知る。
- Pi 0.87.1 には、モデルに送る直前にメッセージの列を差し替える `context` の拡張点がある。session の記録には手を触れない。拡張はコードから渡したものだけを読み込ませられ、ディスク上の拡張の探索は止めたままにできる。
- Pi の組み込みの `read` は、ファイルを読む手段（存在の確認・読み出し・画像の判定）を差し替えられる。
- マニュアル（[ADR 0036](0036-a-manual-to-read-and-a-limit-on-waiting.md)）や記憶は、一度読めば同じターンの外でも役に立つ。本人は、そうして読んだものは残したいと考えた。

設計は grill-me（Q1〜Q5）で詰めた。効果は評価の仕組みではなく、本番で畳み込みを入り切りしながら統計で比べる。

## Decision

### 終わったターンを、モデルに送る直前に畳む

- 畳むのは**終わったターン**だけである。今のターンは畳まない。変わるのは文脈の末尾だけなので、prefix cache は直前に終わったターンの始まりまで保たれる。数ターン前をさかのぼって畳むような、文脈の途中を書き換える形は採らない。
- 畳み方は機械的な置き換えであり、LLM に要約させない。同じメッセージの列には、いつも同じ結果を返す。
- 畳んだ結果は、モデルに送る直前にだけ作る。session の記録（Pi の session のファイル）は書き換えない。だから畳み込みを切れば、次のターンから元の文脈に戻る。
- 畳んだターンに残すものは次のとおりである。
  - 届いた出来事（ターンを始めた出来事と、途中で差し込まれた出来事）。本人の発言はこの中にある。
  - 本人や外へ出たもの: `reply_to_mac`・`notify_owner`・`ask_agent`（ポッポさんへの Slack の依頼を含む）の呼び出し。返事と知らせの結果は「送りました」の一言に縮める。セリフそのものは呼び出しに残っている。
  - `read` の呼び出しと結果。ただし、同じパスを前に畳んだターンで読み、結果が一字一句同じなら、「既に読みました（パス）」に置き換える。書き換えられて中身が変わったファイルは、新しい中身を残す。
  - ターンの終わりに書かせた一行メモ（下の節）。「（このターンの振り返り）」を頭に付け、なつみ自身の行として置く。
- それ以外は畳む。思考、地の文、上の以外のツール（`run_shell`・表情・予約など）の呼び出しと結果、失敗した呼び出し（送れなかった返事や、見つからなかった `read` を含む）、振り返りの頼みそのもの。
- 思考を外したツールの呼び出しは、思考と組になっていたことを示す識別子を外し、呼び出し自身の識別子だけを残す。Responses API の経路（Plus）が、組の片方だけを送ると断るためである。
- ターンの区切りは、振り返りの頼みで見分ける。頼みに答えが付き、その後に次の出来事が届いていれば、そこまでが終わったターンである。エラーで振り返りを頼まなかったターンは、次に振り返りを頼んだターンと一緒に畳む。
- compaction の要約と、ほかの種類のメッセージは、そのまま通す。

### ターンが終わったら、同じ session に一行の振り返りを頼む

- 普通に終わったターンと、呼び出しの回数・時間の上限で打ち切ったターンの後に、サーバーが同じ session に一行の振り返りを頼む。モデルのエラー、サーバーの停止で終わったターンと、夜の振り返りのターン（その後 session が替わる）には頼まない。
- 頼みの文は固定である。調べて分かった事実（予定・数字・名前・ファイルの場所）と、試してうまくいかなかったこと（何を試して、なぜだめだったか）を一行で書かせ、本人に言ったことの繰り返しは求めない。夜の振り返りでも読み返すことを伝える。
- 頼みは、終わったターンに続けて送る。ターンの最後の呼び出しの文脈の後ろに頼みが付くだけなので、prefix cache はそのまま効く。ターンごとにモデルの呼び出しが 1 回増える（相談の段階の「呼び出しを増やさない」は、本人の判断で覆した）。
- 振り返りの呼び出しだけ、thinking を切る。一行のメモに思考は要らない。終われば設定どおりの thinking に戻す。
  - 本人のエンドポイント（Qwen 系の chat template）では、thinking の切り替えは `enable_thinking` の切り替えとして送られる。前の会話の描き方が変わって prefix cache が崩れるかどうかは、本物で確かめる（下の「確かめたこと」）。崩れるなら、thinking を付けたまま短く書かせる形に戻す。
  - Plus の経路（`openai-codex` の gpt-5.5）では、切った thinking は推論の強さ `none` として送られる。入力の項目は変わらないので、キャッシュには響かない見込みである。
- 振り返りではツールを使わせない。ツールの定義は外さない（外すと prefix が動く）。代わりに、その間のツールの呼び出しは Pi の拡張で断り、振り返りは 1 回の呼び出しで終える。本人にも外にも何も出ない。
- 振り返りの間に届いた本人のメッセージは、差し込まずに待たせ、次のターンで扱う。
- 振り返りの時間の上限は 2 分とする。答えられなかった振り返りはメモ無しで終わり、ログに一行残す。
- **畳み込みが off の間も、振り返りは頼む。** on と off の違いを、畳むかどうかだけにするためである。off の間は、頼みと答えがそのまま文脈に残る。

### 組み込みの read を、作業環境の /manual と /memory に向けて有効にする

- Pi の組み込みの `read` を有効にする。読む手段は作業環境の runner に差し替え、`run_shell` と同じ道で読む。だから `read` で読めるものは、安全の面では `run_shell` と変わらない。サーバーのコンテナのファイル（ログインのファイルや secret）は、この道からは見えない。
- 読めるのは `/manual/` と `/memory/` の下のファイルだけである。範囲の制限は、安全のためではなく意味のためである。`read` で読んだものは畳んでも残るので、残す価値のある 2 か所に絞る。ほかの場所は `run_shell` で読む。
- 相対パスは、作業環境の作業ディレクトリ（`/work`）からのパスとして読む。サーバーの作業ディレクトリからではない。
- 画像とバイナリは読まない。拡張子で見分けたものは読む前に、中身に NUL を含むものは読んだ後に断り、画像は `run_shell` の `view` で見るよう伝える。画像を結果に載せることはない。
- 上限: 1 回に返すのは 400 行まで（Pi の 50KB の上限はそのまま）。続きは offset と limit で読む。1 つのファイルは 256KB まで読む。それより大きいものは断り、`run_shell` で一部を読むよう伝える。runner の 1 回の答えは 64KB までなので、ファイルは 45KB ずつ base64 で運び、文字の途中で切れても壊れないようにする。
- ツールの説明は日本語の固定の文にし、`read` をツールの並びの最後に置く。前にあるツールの定義は prefix の上で動かない。パラメーターの説明は Pi の英語のままである。
- Pi の `read` には、Pi の既定の system prompt に「cat や sed ではなく read を使え」と入れる案内が付いている。natsumi は自前の system prompt を渡しているので、この案内は入らない。これはテストで押さえる。
- system prompt の「記憶と作業場」の節と、マニュアルの `INDEX.md` で、マニュアルと記憶は `read` で読むことを伝える。`cat` で読んでも壊れはせず、ふつうに畳まれるだけである。
- 組み込みの `bash`・`edit`・`write`・`grep`・`find`・`ls` は、これまでどおり有効にしない。`bash` は `run_shell` の作り込み（まだ動いている扱い、記憶の変化の一行、タイムゾーン、日本語の案内、8000 字の上限）を失い、組み込みの上限（50KB）は文脈を軽くする方向に逆行する。`grep` は rg そのものがサーバーの手元で走り、サーバーのファイルを検索できてしまう。

### 入り切りは、設定と、経路と同じ形のコマンドで行う

- 設定の `loop.turnFold`（`on` か `off`、既定は `off`）で既定を決める。本番へは `off` のまま入れ、本人が `on` にする。
- 動いているサーバーは、コマンドの `fold on`・`fold off`・`fold status` で切り替える。モデルの経路（[ADR 0046](0046-named-model-routes-switched-by-hand.md)）と同じく、選んだ値をデータディレクトリのファイル（`.natsumi/turn-fold.json`）に書き、サーバーはターンの前に毎回読む。再起動しても続く。サーバーは、使っている値・設定の既定・選んだ値を別のファイル（`.natsumi/turn-fold-status.json`）に書き、`fold status` はそれを読む。
- 切り替えはターンの間でだけ効く。切り替えた直後のターンでは、prefix cache が 1 回外れる。

### ターンごとの統計を SQLite に残し、コマンドで集計する

- 普通のターンごとに、数だけを 1 行、SQLite の `turn_stats` に書く。本文は書かない。
  - 畳み込みの on/off、経路の名前、出来事の種類。
  - 最初の出来事が届いてから、最初の `reply_to_mac` か、ポッポさんへの依頼（受け付けられた `ask_agent`）までの時間。どちらも無ければ空。途中で差し込まれた出来事は、起点にしない。
  - ターンの長さ、モデルの呼び出しの回数、ターンの呼び出しの tokens の合計（キャッシュに乗らなかった入力・キャッシュに乗った入力・出力）、最初の呼び出しに送った文脈の大きさ。どれも Pi が provider から受け取った usage である。
  - 振り返りの時間と、その呼び出しの tokens。頼まなかったターンは空。
  - ターンの後に compaction が走ったか。ターンの終わり方（普通、上限の打ち切り、エラーなど）。
- **迷いの指標**（本人の追加）も、同じ行にサーバーが機械的に数える。
  - 読み直し: そのターンの `run_shell` のコマンド（空白を詰めた文字列）と `read` のパスのうち、session の文脈で前に使ったもの（同じターンの前の呼び出しを含む）の数。`run_shell` の中の `cat` などは解析しない。compaction の後は、要約に入ったものとは比べない。
  - ツールのエラー: エラーで返ったツールの結果の数。
  - ポッポさんの突き返し: ポッポさんが受け付けなかった依頼（見出しの誤り、一意に決まらない参照など）の数。これはツールのエラーにも数えられる。
  - 打ち切り: 呼び出しの上限か時間の上限で止まったか。終わり方の列から数える。
  - 答えなかったメッセージ: そのターンでなつみに見えていた本人のメッセージのうち、答えずにターンが終わったものの数。
    返事の宛先（`replyTo`）はなつみが選ぶのではなく、サーバーがその時点で答えていない一番新しいメッセージに付ける（ADR 0024・[ADR 0032](0032-talking-to-the-owner-as-often-as-she-likes.md)）。だから「違うメッセージに答えた」は記録の上では起こらず、数えるのは「届いたメッセージに答えずに終えた」だけである。差し込まれてまだ見えていなかったメッセージは、次のターンに回るので数えない。
- コマンドの `stats` は、期間（`--since`・`--until`、日付か時刻）の中のターンを on と off に分け、各指標の中央値と p90、compaction の回数、迷いの指標の 1 ターンあたりの平均、打ち切りの割合を並べる。
- `stats --memos <件数>` は、直近の一行メモを並べる。本人が目で質を見るためである。メモは SQLite には写さず、そのたびに設定の `pi.sessionDirectory` の session のファイルから読む。

### 夜の振り返りも、畳んだ文脈で行う

- 畳み込みが on のとき、夜の振り返り（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md)）は畳んだ文脈を見る。会話の原文と一行メモと読んだものだけが見える。夜の指示は変えない。細かいことが要れば、記憶やチャンネルのファイルを読み直せる。
- 一行メモの頼みの文を、夜の材料になる書き方に寄せておく。

## Alternatives

- **畳まずに今のまま（compaction だけ）**: 一日の途中で compaction が走り、そのたびにキャッシュを全部失う。雑多な途中経過も残り続ける。
- **数ターン前をさかのぼって畳む**: 毎回文脈の途中を書き換えるので、毎ターン prefix cache を壊す。
- **LLM に畳んだ中身を要約させる**: 毎ターン要約の呼び出しが要り、結果が毎回同じになる保証が無い。
- **session の記録そのものを書き換える（Pi の `context_edit` の記録）**: off に戻せず、畳む前の記録も失う。本人は非破壊で入り切りしたかった。
- **一行メモを、ターンを終える呼び出しのついでに書かせる**: 相談の段階の案だった。ターンを終える専用のツールが無く、なつみがツールを呼ばずに終える形（ADR 0024）を崩すことになる。本人は、呼び出しが 1 回増えても、ターンの後にサーバーが頼む形を選んだ。
- **振り返りの間はツールの定義を外す**: 定義が prefix に入っているので、外すと振り返りのたびに prefix が動く。
- **組み込みの bash・grep も使う**: 上の節のとおり、`run_shell` の作り込みを失い、grep はサーバーのファイルを検索できてしまう。
- **効果を評価の仕組み（loop-eval のような）で測る**: 本物の一日の出来事の混ざり方は再現しにくい。本番で期間を分けて入り切りし、同じ指標で比べる。
- **統計に一行メモの本文も入れる**: 本文を SQLite に写すと、同じ記録を二重に持つことになる。本文は session のファイルに一つだけある。

## Consequences

- 畳み込みが on なら、1 日の文脈は届いた出来事・返事・読んだもの・一行メモと system prompt に収まる見込みで、上限での compaction はほとんど起きなくなる。
- 畳むのはターンが終わってからなので、1 ターンで何度も呼ぶ重いターンの途中経過は、そのターンの間は積まれる。
- ターンが終わるたびに、畳んだ分だけ prefix cache は直前のターンの始まりまで戻る。1 ターンの伸びはそのターンの残す部分だけになる。
- ターンごとに振り返りの呼び出しが 1 回増える。統計の振り返りの時間とキャッシュの割合で、この費用が見える。
- 夜の振り返りは、1 日の途中経過を見なくなる。記憶に書くべきだったことに気づく手がかりは、一行メモと読み直しになる。
- 畳み込みの入り切りを変えた直後のターンは、prefix cache が 1 回外れる。
- `read` で読んだマニュアルと記憶は、その session の間ずっと文脈に残る。大きなファイルを何度も読むと、そのぶん文脈が伸びる（同じ中身の 2 回目以降は短い一文になる）。
- system prompt の「記憶と作業場」の節とツールの並びが変わったので、この版を入れた直後の session は、次の夜の切り替えまで prefix cache が一度外れる。

### 確かめたこと

- 畳み込み・振り返り・`read`・入り切り・統計は、合成したモデルでテストした。
- 本人のエンドポイントで、振り返りの thinking を切ったときに prefix cache が効くか、畳んだ文脈でなつみが普通に答えるかは、この ADR を書いた時点では確かめていない（接続の情報を読む許可が要る）。確かめたら、この節に書き足す。
