# 0077. 本人が睡眠薬を飲ませると、なつみは欠けた夜を取り戻すか、昼寝をする

- Date: 2026-10-11
- Status: Accepted（2026-10-12: 今の session が空のときの判定を直した。空の session で意味が無いのは、なつみのターンを要する `deep`・`nap` だけで、そのときも整理係が済んでいなければ `resleep` にする。表の「今の session が空」の行と、その説明を書き換え、Consequences に 1 項を加えた）

## Context

なつみは毎晩、決まった時刻に session を切り替える（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md)）。
夜の処理は 3 つの部分からなる。

1. **振り返り**: 今の session で振り返りのターン（`nightly_review`）を行い、引き継ぎ（`handoff.md`）を書いてコミットする（[ADR 0020](0020-limits-at-write-time-and-a-nightly-menu.md)）。
   引き継ぎが書かれなければ、切り替え全体が失敗になり、整理係も新しい session も無い。
2. **整理係**: 記憶の整理係が 4 つの工程（知識・archive・構成・索引）を順に行う（[ADR 0055](0055-a-memory-curator-at-night.md)・[ADR 0068](0068-a-curator-that-remembers-like-a-person.md)）。
   工程ごとにコミットし、失敗した工程の変更だけを捨てる。トピックを書き直す工程がすべて成功したときだけ、SQLite の `memory_curator.base_commit` が進む。
   進まなければ、次の夜に同じ会話と日記をもう一度渡す。
3. **新しい session**: 引き継ぎを system prompt に入れた新しい session を作り、会話をそちらに向ける。
   作れなければ切り替えは `session-create-failed` で失敗し、今の session を使い続ける。整理係はもう走った後である。

夜の切り替えはスケジューラーが起こし、1 回の夜に 1 回しか試さない。振り返りが失敗すると（`no-handoff`・`handoff-not-committed` など）、次の夜まで切り替えが起きない。
実際に、振り返りが失敗して夜の処理がまるごと走らない日があった。その日のなつみは前の日からの session のまま、遅く重くなった context で話し続ける。
切り替えを起こす口は、サーバーの中の `rotateSession` として在るが、本人が呼べる経路（ダッシュボードやアプリ）は無い。
失敗した切り替えは `session_rotations` に `failed` と理由が残り、ダッシュボードの「失敗と待ち」に出る。

本人は、好きなときになつみを寝かせて、欠けた夜を取り戻したい。
たとえとしては、夜に眠れなかったなら昼に「ガッツリ寝る」、夜にちゃんと寝ていれば「昼寝」である。
なつみは自分からは寝ない。寝かせるのは本人で、本人が**睡眠薬を飲ませる**操作が引き金になる。

昼寝は compaction（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md)）とは違う。

- compaction は同じ session を使い続ける。system prompt は変わらず、context は Pi の要約と直近の 2 万 tokens になる。要約はコーディング向けの英語の定型に指示を足したもので、なつみ自身の言葉ではない。
- 昼寝は新しい session に移る。system prompt を作り直すので、`always.md`・`personality.md`・`handoff.md` のその時点の中身が入る。
  前の session から残るのは、なつみが自分で書いた引き継ぎだけである。session の中で固まった悪い振る舞いの型（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md) の Context）も、そこで切れる。

設計は grill-me（Q1〜Q5）で決めた。本人に尋ねずに既定とした事項は、この ADR の各節に書き、本人が覆せる。

## Decision

### 引き金は本人の操作だけにする

- なつみを寝かせる操作は、本人が「睡眠薬を飲ませる」ことだけである。ダッシュボードとクライアントの契約から行う（後述）。
- なつみには寝るためのツールを持たせない。自分から寝ることはしない。ツールの一覧も、system prompt も変えない。
- 睡眠薬は 1 種類である。本人は、昼寝かガッツリ寝るかを選ばない。何をするかはサーバーが判定する。

### 何をするかは、直近の夜の欠けで決める

睡眠薬は、直近の夜の処理のうち欠けている部分だけを取り戻す。全部済んでいれば昼寝になる。

| 直近の夜の状態 | 睡眠薬ですること | 種類の名前 |
| --- | --- | --- |
| ① 振り返り（引き継ぎ）が欠けている | 夜と同じ全部をする（① → ② → ③）。「ガッツリ寝る」 | `deep` |
| ① は済み、③ 新しい session が欠けている | 残った引き継ぎから ③ をする。② が済んでいなければ、先に ② もする | `resume` |
| ① と ③ は済み、② 整理係が済んでいない | session はそのままで、整理係だけを走らせる。「寝直し」 | `resleep` |
| 全部済んでいる | 昼寝（後述） | `nap` |
| 今の session が空で、上の判定が `deep` か `nap` | ② が済んでいなければ整理係だけを走らせる（「寝直し」）。済んでいれば何もしない | `resleep` または `none` |

- **「直近の夜の時刻」**（以下 N）は、`loop.nightlyRotationAt` があれば、今から見て直前のその時刻（`previousOccurrence`）である。スケジューラーが夜の切り替えに使う時刻と同じである。
- 判定に使うのは SQLite の記録だけである。
  - ① が済んでいる: `session_rotations` に、N 以降に作られ、引き継ぎのコミット（`handoff_commit`）を持つ行がある。
  - ③ が済んでいる: 今の session が N 以降に始まっている。今の session の始まりは、その session に切り替えた行（`state = 'switched'`）の時刻、無ければ会話を作った時刻である。スケジューラーが「切り替えるか」を決めるのと同じ数え方である。
  - ② が済んでいる: `memory_curator.base_commit` のコミット時刻が N 以降である。整理係が設定で動かない（`curator.enabled` が false、または作業環境の runner が無い）なら、② は済んでいるものとして数える。
- ① が欠けていて ③ だけが済んでいることは無い。切り替えは引き継ぎのコミットが無ければ完了できないからである（ADR 0020 の不変条件）。
- `resume` の「残った引き継ぎ」は、N 以降の行のうち最も新しく `handoff_commit` を持つ行の引き継ぎである。夜に ③ で失敗した行は、`failed` のまま `handoff_commit` を持っている。
  新しい session の system prompt は、これまでどおり作業ツリーの `handoff.md` から組む（ADR 0020）。`write_handoff_note` は振り返りと昼寝の中でしか書けないので、日中のうちに書き換わってはいない。
- 今の session が空（session にメッセージが 1 つも無い）なら、なつみのターンを要する `deep`（振り返り）と `nap` はしない。夜と同じく、空の session は振り返りも切り替えもしない（ADR 0009）。
  そのときも、② が済んでいなければ `resleep` にし、済んでいれば何もしない（`none`）。`resume`・`resleep` はなつみのターンを使わないので、空でもそのままする。
  切り替えの直後は session が空でも、前の夜の整理係が締め切りなどで済んでいないことがある。整理係が読むのは前回の成功から今までの会話で、session をまたぐので、空の session でも渡す会話はある。（2026-10-12 に直した。当初は「空なら何もしない」としていた）
- 判定はサーバーの 1 か所に置く。ダッシュボードとクライアントは、その判定を見せるだけで、自分では判定しない。

#### `nightlyRotationAt` が false のとき（既定とした事項）

夜の切り替えをしない設定では、「直近の夜の時刻」が無い。この設定でも、常にガッツリ寝るのではなく、直近の寝た記録の成否で判定する。

- N を、`session_rotations` の行のうち、振り返りから始まった最も新しい行（種類が `night` か `deep`。後述）が作られた時刻とする。
- そこからの判定は上の表と同じである。振り返りから始まった行が 1 つも無ければ、① が欠けているものとして `deep` にする。
- この設定では、全部済んだ後の睡眠薬は毎回 `nap` になり、整理係は走らない。整理係が走るのは、`deep`・`resume`・`resleep` のときだけである。

### ガッツリ寝る・残りを済ませる・寝直すのは、昨夜の分として扱う

- `deep` は、夜の切り替えとまったく同じことをする。なつみには夜と同じ `nightly_review` の出来事と、同じ指示（`REVIEW_INSTRUCTIONS`）が届く。
  なつみから見て、夜の振り返りと区別は無い。モデル呼び出しと時間の上限も、夜の振り返りの設定（`reviewModelCalls`・`reviewTimeoutMinutes`）を使う。
- `resume` は、なつみのターンを行わない。必要なら整理係を走らせ、残った引き継ぎから新しい session を作って会話をそちらに向ける。
- `resleep` は、なつみのターンを行わず、session も替えない。整理係だけを走らせる。
- 「昨夜の分」と扱うのは判定の上だけである。**その後に来る夜は飛ばさない。** 昼に作った session も次の夜の時刻より前に始まっているので、次の夜はいつもどおり切り替える（既定とした事項）。
- 整理係が読む会話は「最後に整理係が成功した時刻から今まで」で、session ファイルをまたいで読む（ADR 0068）。昼に ② を取り戻すときは、取り逃した夜とその後の日中の会話も拾う。
  昼寝で session が替わっても、その夜の整理係は昼寝の前の会話も読む。

### 昼寝: 引き継ぎだけを書いて、新しい session に移る

- `nap` は、振り返り → 新しい session の 2 つだけである。**整理係は走らせない。**
- 昼寝の振り返りは、夜の `nightly_review` とは別の出来事 `nap` として届ける。指示も別の固定の文（`NAP_INSTRUCTIONS`）にする（既定とした事項）。
  - 中身は「昼寝です。起きたら思考の記録が新しくなり、今の細かいやりとりは見えなくなる。`write_handoff_note` で引き継ぎだけを書く。マスターへの返事や知らせは送らない」の趣旨である。
  - 常時記憶（`always.md`）・性格（`personality.md`）の見直し、プロセスや `/work` の片づけは、夜に任せる。昼寝の指示には候補として挙げない。
  - 引き継ぎの書き方（主語と時刻）は、夜の指示と同じ文を使う。
- 昼寝のターンは、ツールの上では振り返りと同じ扱いにする。`write_handoff_note` と `write_change_note` が使え、本人への返事と知らせは拒否する。
  上限は夜の振り返りの設定を使う。`write_handoff_note` を振り返りの外で呼んだときの拒否の文は、「夜の振り返りか昼寝の中でだけ使えます」の趣旨に改める。
- 引き継ぎが書かれなければ、昼寝は失敗し、今の session を使い続ける（夜と同じ）。
- 固定の文が 1 つ増えるのはリリースのときの 1 回だけである。走っている session の instructions は差し替えず、ツールの説明も動的に組み立てない。
  昼寝で新しい session になると prefix cache は作り直しになるが、それは本人が選んで起こす出来事であり、日常の prefix を壊すことにはならない。

### 寝ている間: 本人のメッセージは待たせ、整理係は飲ませた時刻から 90 分で打ち切る

- 寝ている間（`deep`・`resume`・`resleep`・`nap` のすべて）は、夜の切り替えと同じにする。
  - 届いた本人のメッセージは、記録して受け付け、キューで待たせる。振り返りのターンには差し込まない。起きた後に処理する。session が替わる種類では、新しい session が扱う。
  - アバターは `sleepy` にし、終わったら待っているメッセージがあれば `thinking`、無ければ `neutral` に戻す。
- **整理係の締め切りは、睡眠薬では飲ませた時刻から数える。** 飲ませた時刻から設定 `curator.pillStopStartingAfterMinutes`（分、既定 90、false で打ち切らない）を過ぎたら、次の工程を始めない。
  - 締め切りの扱いは夜と同じである（ADR 0068）。締め切りは工程を始める前にだけ見て、進行中の工程は打ち切らない。始めなかった工程は `skipped-deadline` として記録する。
  - 始めなかった工程は、次の夜に取り戻される。トピックを書き直す工程を 1 つでも始めなかったら base は進まず、次の夜の整理係が同じ会話と日記をもう一度読む。
  - 今の締め切りの数え方（`curatorDeadline`）は夜を前提にしている。直前の `nightlyRotationAt` の後で最初に来る `curator.stopStartingAt` を締め切りにするので、昼に呼ぶと最初から締め切りを過ぎていて、工程が 1 つも始まらない。
    ADR 0068 は、朝の起動の後の切り替えで係を走らせないために、この数え方を選んでいた（日中に係が数時間動き、その間なつみが寝ていることを避ける）。
    睡眠薬は本人が寝かせると決めたときだけなので、上限を 90 分にして日中にも走らせる。睡眠薬のときは、夜の数え方を使わず、飲ませた時刻から数える。
- この設定は設定ファイルだけに置き、`/settings` には出さない。`curator.stopStartingAt` と同じ扱いである。

### 走っている切り替えには合流する

- 夜の切り替えや前の睡眠薬が、待っているか走っている最中に睡眠薬を飲ませたら、それに合流する。二重には走らない（既定とした事項）。今の `rotate()` が待っている夜の切り替えに合流するのと同じである。
- 睡眠薬は思考ループの出来事（種類 `sleeping-pill`）として積み、ほかの出来事と同じ順番で処理する。session を触るのは思考ループだけ、という形（ADR 0009）は変えない。
- **何をするかは、思考ループがその出来事を処理し始めるときに判定する。** 飲ませた時点の判定は、見せるためと受け付けの答えのためのものである。
  ターンの最中に飲ませれば、そのターンの後に判定する。その間に状態が変わっていれば、判定も変わる。何をしたかは結果の記録に残る。
- 夜の時刻が来たとき、まだ始まっていない睡眠薬が待っていれば、夜の切り替えはそれに合流する。処理を始めるときの判定では新しい夜の処理が全部欠けているので、`deep` として夜と同じことをする。

### 結果は切り替えの記録に残し、本人へは送らない

- 睡眠薬の結果（何をしたか・成否・理由）は、夜の切り替えと同じ `session_rotations` に残す。昼寝と寝直しも 1 行を残す（既定とした事項）。
  - 行に種類の列 `kind` を足す。値は `night`（スケジューラーとサーバーの `rotateSession` が起こした切り替え）・`deep`・`resume`・`resleep`・`nap` である。既存の行は `night` にする。
  - `resleep` は session を替えないので、`switched` にはならない。整理係が終わったら、終わりの状態 `curated` にする。トピックを書き直す工程が 1 つでも成功しなければ、`failed`（理由 `curator-incomplete`）にする。
  - `resume` の行は、`handoff_commit` に新しい session の system prompt を組んだときの記憶のコミット（HEAD）を記録する。ADR 0020 のとおり、どの引き継ぎで始まったかを辿るためである。
  - `deep`・`resume` の整理係の結果は、夜と同じく切り替えの成否に影響しない。工程ごとの結果は、これまでどおり整理係のターンとして記録する。
  - 列と状態の足し方（表の作り直しを含む migration）は実装で決める。
- 睡眠薬を飲ませても、なつみから本人へは何も送らない（既定とした事項）。夜と同じである。結果は、ダッシュボードとクライアントの契約の判定の答えで見る。
- なつみには、睡眠薬を飲まされたことを出来事として別に伝えない。`deep` では夜の振り返り、`nap` では昼寝の出来事が届くので、それで分かる。

### 置き場所: ダッシュボードに置き、判定と実行はサーバーの 1 か所にする

本人が飲ませるのは、まずダッシュボードからである。ただし、Mac と iPhone のアプリに後から UI だけを足せばよいように、クライアントの契約にも同じ口を足す。

#### サーバー

- 判定（いま飲ませると何が起きるか）と実行（飲ませる）は、思考ループの側に置く。ダッシュボードの POST も、WebSocket のコマンドも、同じ判定と同じ実行を呼ぶ。
- 判定の答えは次を含む。
  - `kind`: いま飲ませたら何をするか（`deep`・`resume`・`resleep`・`nap`・`none`）
  - `night`: 判定に使った直近の夜の時刻 N。`nightlyRotationAt` が false で振り返りの記録も無ければ null
  - `done`: ①②③ のそれぞれが済んでいるか（`review`・`curator`・`session`）
  - `lastFailure`: N 以降の、最も新しい失敗の記録（切り替えの行の種類・状態・理由と時刻、または整理係の ok でない工程と outcome）。無ければ null
  - `inProgress`: 夜の切り替えか睡眠薬が待っている・走っているなら、その種類と状態。無ければ null
- 飲ませる要求の答えは、受け付けた出来事の ID と、受け付けた時点の判定の `kind` と、待っているものに合流したかどうか（`joined`）である。
  寝た結果は待たずに返す。結果は、判定の答えの `inProgress` と `lastFailure`、ダッシュボードの切り替えの一覧で見る。
- なつみが話せない間（`pi-unavailable`・`conversation-restore-failed`・`stopping`）は、飲ませる要求を断る。今の `rotate()` が失敗を返すのと同じ条件である。

#### ダッシュボード

- 「睡眠薬」のページ（`/dashboard/sleep`）を足し、ナビゲーションの「予約」の次に置く。
- ページには次を出す。
  - いま飲ませると何が起きるか。種類ごとに、するとなつみが寝る時間の目安（`deep`・`resleep` などは整理係で最長 90 分と工程 1 つ分）と、その間メッセージを待たせることを書く。
  - 直近の夜の時刻と、①②③ のどれが済んでいるか。
  - 昨夜の失敗の理由（`lastFailure`）。
  - 走っている・待っている切り替えがあれば、それ。
- 飲ませるのは、そのページのフォームの `POST /dashboard/sleep` である。ページそのものが確認を兼ね、開いただけでは何も変わらない。
  受け付けたら 303 で同じページに戻り、受け付けたこと（合流したなら、そのこと）を出す。
- 書き込みの守りは [ADR 0064](0064-cancelling-a-self-check-from-the-dashboard.md) の予約の取り消しと同じにする。`natsumi_session` の生きているセッションを必須とし、Origin が `publicOrigin` と一致することを照合する。GET には 405 を返す。
- 自動更新はしない（ADR 0064 と同じく、押そうとしている内容が変わらないようにする）。
- 「失敗と待ち」の切り替えの一覧に、種類（`kind`）の列を足す。
- 画面の文言・並べ方の細部は実装で決める。

#### クライアントの契約

ADR 0064 は、ダッシュボードで状態を変える口をこれ以上増やすときは、[ADR 0058](0058-settings-and-chat-in-the-browser.md) の WebSocket のコマンドに寄せるか、改めて決めるとしていた。
睡眠薬は後で Mac と iPhone からも飲ませたいので、ダッシュボードの POST と並べて、WebSocket のコマンドを足す。コマンドの流儀は `model.list`・`model.use` にそろえる。

- `sleep.status`（引数なし）: `command.accepted` で、上の判定の答えを `sleep` の欄に入れて返す。
- `sleep.take`（引数なし）: 睡眠薬を飲ませる。`command.accepted` で、`eventId`・`kind`・`joined` を返す。
  なつみが話せない間は `service.unavailable` を返す。同期の前には受け付けない（`sync-required`）。ほかのコマンドと同じである。
- 二重に送っても、待っているものに合流するので二重には寝ない。`requestId` は取らない。
- 寝ている間と起きたことは、今の `avatar.expression`（`sleepy` とその後の表情）で端末に届く。睡眠薬のための新しいサーバーのイベントは足さない。
- 契約の文書（`docs/client-contract.md`）には、この機能の実装で書き足す。欄の細部（`lastFailure` の形など）はそのときに決める。Mac と iPhone の UI は今回は作らない。

### 実装で決めること

この ADR では決めず、実装で決める。

- 思考ループの出来事の種類 `sleeping-pill` の持ち方（SQLite の出来事の種類の足し方）と、夜の切り替えの出来事との合流の仕組み。
- `session_rotations` の `kind` の列と `curated` の状態の migration（表の作り直しの要否）。
- 判定の答えの `lastFailure` に、切り替えの行と整理係の工程のどちらを優先して出すか。
- `NAP_INSTRUCTIONS` の文面。上の趣旨を外れない範囲で実装で書く。
- `resume` と `resleep` を、ダッシュボードのターンの一覧でどう見せるか（なつみのターンが無いので、整理係の工程の行だけが並ぶ）。
- ダッシュボードの「睡眠薬」のページの文言と並べ方。

## ADR との関係

- ADR 0009
  - 追加: 夜の切り替えを、本人の操作（睡眠薬）からも起こす。何をするかは直近の夜の欠けで決まり、欠けた部分だけを取り戻す。全部済んでいれば昼寝として、引き継ぎだけを書いて新しい session に移る。
  - 追加: 振り返りのターンに、昼寝の出来事 `nap` を加える。`write_handoff_note` は昼寝の中でも書ける。
  - 保つ: 引き金は本人の操作だけで、なつみに寝るツールは無い。寝ている間のメッセージの待たせ方・アバター・失敗の扱いは夜の切り替えと同じ。夜の切り替えは 1 回の夜に 1 回で、睡眠薬があっても飛ばさない。
- ADR 0055
  - 追加: 整理係は夜の切り替えの中だけでなく、睡眠薬の `deep`・`resume`・`resleep` でも動く。`resleep` では session を切り替えずに動く。
  - 保つ: 係の間なつみは寝ている。昼寝では動かない。
- ADR 0068
  - 追加: 睡眠薬のときの締め切りは、飲ませた時刻から `curator.pillStopStartingAfterMinutes`（既定 90 分）とする。夜の締め切りの数え方（直前の `nightlyRotationAt` の後で最初の `stopStartingAt`）は夜にだけ使う。
  - 保つ: 締め切りは工程を始める前にだけ見る。始めなかった工程は次の夜に取り戻される。
- ADR 0049・ADR 0058・ADR 0064
  - 改める: ダッシュボードで状態を変える口に、睡眠薬の POST を加える。守りは予約の取り消しと同じ。
  - 追加: 画面に「睡眠薬」のページを加える。クライアントの契約に `sleep.status`・`sleep.take` を加える。
  - 保つ: 画面はサーバーで HTML を組み、CSP は変えない。設定と承認は `/`・`/settings` から WebSocket で変える。

## Consequences

- 夜の振り返りが失敗しても、本人が気づいた時点で睡眠薬を飲ませれば、その夜の処理を取り戻せる。次の夜を待たなくてよい。
- 夜が済んでいる日は、睡眠薬は昼寝になる。重くなった session を、なつみ自身の引き継ぎだけを持って新しくできる。compaction と違い、system prompt が作り直され、session の中で固まった癖も切れる。
  その代わり、引き継ぎに書かれなかった日中の細かいやりとりは、思考の context から消える。記憶に書かれたことと、その夜の整理係が読む会話は残る。
- `resume` では、夜に書いた引き継ぎから新しい session を始める。夜の後の日中のやりとりは、引き継ぎには入っていない。日中の会話は、その日の整理係（または次の夜の整理係）が読む。
- 日中に整理係が最長 90 分と工程 1 つ分走り、その間なつみは寝ていて、本人のメッセージは待たされる。寝かせると決めるのは本人なので、これを受け入れる。
  90 分では 4 工程が終わらないことがある。始めなかった工程は次の夜に回る。
- 夜の時刻の直前に始まった昼寝は、その後に来る夜の時刻をまたいで走ると、夜の切り替えに当たらない。昼寝の後の session は夜の時刻より後に始まるので、スケジューラーはその夜を済んだものとみなす。
  その夜の整理係は走らず、次の睡眠薬（`resleep`）か、次の夜に回る。整理係は前回の成功からの会話を読むので、取りこぼしは無い。
- 夜の切り替えが整理係の締め切りを過ぎてから起きた（止まっている間に過ぎた夜を、朝に起こした）ときも、切り替えの直後の空の session のまま睡眠薬で寝直せる。日中のメッセージを待たずに、前の夜の会話を整理係に読ませられる。
- `nightlyRotationAt` が false の運用では、全部済んだ後の睡眠薬は毎回昼寝になり、整理係は振り返りが欠けたときと寝直しのときにしか走らない。
  夜の振り返りを本人が起こす経路は無い（サーバーの `rotateSession` は運用の確認のための口である）。この設定で整理係を定期的に走らせたくなったら、改めて決める。
- ダッシュボードで状態を変える口は、ログアウト・予約の取り消し・睡眠薬の 3 つになる。睡眠薬はクライアントの契約にも同じ口がある。
  [権限と秘密の一覧](../permissions.md)に、この機能の実装で口を足す。
- 睡眠薬のたびに `session_rotations` の行と、なつみの振り返り・整理係のターンが増える。session ファイルも、session が替わる種類のたびに 1 つ増える。
