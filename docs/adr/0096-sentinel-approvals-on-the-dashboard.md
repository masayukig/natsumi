# 0096. 関所が本人に聞くものの窓口をダッシュボードに置き、答えは /sources で知らせる

- Date: 2026-11-09
- Status: Accepted

## Context

[ADR 0095](0095-letting-her-act-and-noticing-quickly.md) で、ペネロペ（クラスタの運用を受け持つインスタンス）の出口に関所を置くことにした。
関所は同じ Pod の別のコンテナで動く別のプログラムで、宛先と操作ごとに、通す・本人に聞く（ask）・断るを決め、本人が許したことの台帳と監査の記録を持つ（用語は ADR 0095 の Context）。

関所が ask にした要求には、本人の答えが要る。

- ask の要求は、関所がすぐ 403 で断り、本文に承認待ちの id と「許されたら同じ要求をやり直して」を書く。ペネロペは答えを知ってからやり直す。
  やり直しは台帳の許しに当たって通る（natsumi-sentinel の ADR）。
- 本人が許すときは、範囲を選ぶ。1 回（その要求の中身だけ）・期限付き（1 時間・1 日・30 日）・ずっと、の 3 つである。
  期限付きとずっとは、操作と対象（名前空間・リポジトリ・node など）の組に効く。範囲の意味は関所が持つ。
- 効いている許し（期限付きとずっと）は、本人が一覧で見て取り消せなければならない。
- PR のマージと tag の作成も、関所の ask に移す。会話の中の本人の「ok」は、許しとして数えない（natsumi-sentinel の ADR）。
  そのため、本人の答えは会話の外の、本人だけが使える画面から出す必要がある。

なつみの側には、次のものが既にある。

- ブラウザのダッシュボード（`/dashboard`）。GitHub のログインと許可した本人 1 人の照合の後ろにあり、cookie は `HttpOnly`・`SameSite=Strict` である（[ADR 0049](0049-a-read-only-dashboard-in-the-browser.md)、[ADR 0058](0058-settings-and-chat-in-the-browser.md)）。
  ダッシュボードは読み取り専用で、状態を変える口は、Origin を照合するフォームの POST に限って例外を足してきた（ログアウト、予約した確認の取り消し、睡眠薬。[ADR 0064](0064-cancelling-a-self-check-from-the-dashboard.md)、[ADR 0077](0077-a-sleeping-pill-to-make-up-for-a-missed-night.md)）。
- ブラウザへの Web Push（[ADR 0070](0070-web-push-to-the-browser.md)）。返事・知らせ・Slack の投稿の承認待ちを送る。
- 外から届くものを `/sources` の下のファイルに置き、`sources_updated` で知らせる方針と、なつみ宛ての印（`attention`）。印はすぐ、夜でも知らせ、走っているターンにも差し込む
  （[ADR 0050](0050-telling-of-source-updates-with-one-event.md)、[ADR 0069](0069-agent-replies-as-files-in-sources.md)、[ADR 0094](0094-background-commands-and-waiting-for-news-within-a-turn.md)）。

なつみには、Slack の投稿の承認（[ADR 0041](0041-approving-slack-posts-on-the-iphone.md)）という別の「承認待ち」もある。この ADR の承認待ちは関所のもので、別に扱う。
以下、関所のものを「関所の承認待ち」と書く。

## Decision

### 窓口はダッシュボードの `/dashboard/approvals`、サーバーは関所への薄い窓口

- 関所の承認待ちを見て答える画面を、ダッシュボードの `/dashboard/approvals` に置く。本人のログイン（ADR 0049）の後ろである。
- サーバーは、関所の制御の口（Unix socket）とブラウザの間の薄い窓口とする。
  - 承認待ち・効いている許し・監査の記録の正本は関所の台帳である。サーバーは写しを持たず、画面を出すたびに socket で関所に聞く。
  - サーバーが自分で持つのは、知らせを二重に出さないための、知らせ済みの承認待ちの id だけである（下の「知らせ」の節）。
- socket は、サーバーと関所のコンテナだけが mount する場所に置く。関所は相手のプロセスの UID でサーバーだけを受け付ける（natsumi-sentinel の ADR）。
  作業環境には mount しない。
- **モデルには、この窓口を呼ぶツールを渡さない。** Pi のツールにも、宣言したツール（[ADR 0075](0075-tools-declared-in-the-config.md)）にも、Codemode にも置かない。
  ペネロペが関所に頼めるのは、承認待ちを作ること（関所の作業環境向けの口）と、自分の承認待ち・許しを読むことまでで、答えることはできない。

### 画面に並べるもの

1 つの画面の中に、次の 3 つを置く。

- **承認待ちの一覧と 1 件の中身。** 一覧は古い順。1 件のページで、操作・対象・差分・head SHA など、関所が示す事実を見せ、答えのフォームを置く。
- **効いている許しの一覧と取り消し。** 範囲と期限を見せ、1 件ずつ取り消せる。
- **監査の記録を読む画面。** 関所が残したもの（通した・聞いた・断った要求、出ていく書き込みの本文など）を読む。読むだけで、消したり直したりはしない。期間は関所が持つ。

画面の文は次のように扱う。

- **画面に出す文は、関所が事実から組んだものだけにする。** ペネロペが書いた説明（承認を頼む理由など）は使わない。ペネロペが読まされた文に従って、本人に誤った説明を見せられないようにするためである。
- 関所が示す事実にも、外の人が書ける文（PR の題、コメントの本文など）が入る。どれも平文として出し、HTML・Markdown・リンクとしては解釈しない。

### 答えと取り消しは、Origin を照合するフォームの POST

- 本人が答えるのは、1 件のページのフォームの POST である。答えは「許す」と「断る」で、許すときは範囲（1 回・期限付きの 1 時間/1 日/30 日・ずっと）を選ぶ。
  断るのは、その承認待ちだけに効く。「いつも断る」は画面からは作らない（断る既定は関所の表で決める。natsumi-sentinel の ADR）。
- 効いている許しの取り消しも、同じ形の POST とする。
- 守りは、ADR 0064 の Decision「取り消しは、確認のページを通した POST にする」と同じにする。
  - 生きている本人のセッションを必須とする。無いか切れていれば 403 で断り、ログインは始めない。
  - Origin ヘッダーが `publicOrigin` と一致することを照合する。無いか一致しなければ 403 で断る。cookie の `SameSite=Strict` と合わせて CSRF を防ぐ。
  - GET には 405 を返す。
- 答えは承認待ちの id に結び付けて関所に渡す。同じ承認待ちに答えられるのは 1 度だけで、2 度目以降を断るのは関所である（台帳が正本のため）。
  サーバーは、関所が断った答えを本人にそのまま伝える。
- 答えを出せるのは、この画面だけである。会話、WebSocket のコマンド、iPhone と Mac のアプリ、Slack からは答えられない。

### 知らせ: 承認待ちが出たら Web Push

- 関所は、承認待ちが出たことと答えが出たことを、socket でサーバーに流す。
- 承認待ちが出たら、サーバーはブラウザに Web Push を送る（ADR 0070）。
  - 中身は「関所の承認待ちがあります」と、関所が示す操作と対象の短い文で、承認待ちの id を tag にする。ADR 0070 と同じく 1 回だけ送り、送り直さない。
  - 送り先は、Web Push の購読があり、その端末のセッションが生きているすべてのブラウザとする。
    ADR 0070 の Decision「送るものと時は、iPhone の alert と同じにする」の、いまつながっていない端末にだけ送る規則は当てはめない。会話の画面がつながっていても、関所の承認待ちは会話の出来事には流れないからである。
  - iPhone（APNs）には送らない。iPhone のアプリには関所の承認待ちの画面が無い。
- サーバーが socket につながっていなかった間に出た承認待ちは、つながり直したときに関所に一覧を聞き、知らせ済みでないものを知らせる。
  知らせ済みの id はサーバーの SQLite に残し、二重に知らせない。

### 答えが出たら `/sources/sentinel/approvals/<id>.json` と `sources_updated`

- 関所が承認待ちを閉じたら（本人が許した・断った、または関所が別の理由で閉じた）、サーバーは `/sources/sentinel/approvals/<id>.json` を置く。
  中身は、承認待ちの id、操作と対象、結果（許した・断った・閉じた理由）、許したときの範囲と期限である。どれも関所が示す事実である。
- 置いたら、更新元 `sentinel` として `attention` を出す（ADR 0050）。印はすぐ、夜でも知らせ、走っているターンにも差し込まれる（ADR 0094）。
  ペネロペはこれを見て、許されていれば同じ要求をやり直す。ターンの中で待つなら `wait_for_events`（ADR 0094）で待てる。
- これは ADR 0069 の Decision「方針: 外から届くものは、可能な限り `sources_updated` に寄せる」の適用である。新しい出来事の種類は作らない。
- 許しの取り消しでは、ファイルを置かず、知らせもしない。取り消された許しは、ペネロペが次に同じ要求を出したときに、関所の 403 で分かる。
- ファイルは消さない（ADR 0069 の Decision「返事は消さない」と同じ）。
- 更新元 `sentinel` の読み方は、更新元のマニュアルに書く（ADR 0050 の Decision「なつみ宛ての印（`attention`）」の、種類の意味は更新元ごとのマニュアルに書く決まり）。

### config に関所の socket を書いたときだけ有効にする

- config に関所の制御の socket の場所を書いたときだけ、この ADR のすべて（画面、POST、Web Push、更新元 `sentinel`）が有効になる。既定は off である。
  書かないインスタンスでは、`/dashboard/approvals` は 404 で、更新元 `sentinel` も無い。
- 書いたのに socket につながらないときは、サーバーは止まらずに起動し、つながり直しを続ける。
  そのあいだ画面は「関所につながらない」と出し、答えも取り消しも受け付けない。承認待ちは関所の側で ask のまま残り、勝手に許されることはない。

### 守る対象・許す範囲・失敗したときの倒し方

- 守る対象: 関所の許しを出す権限。これを持つのは本人だけである。
- 許す範囲: 本人のセッションを持つブラウザからの、Origin の一致する POST だけが、関所に答えと取り消しを渡せる。ペネロペ（モデルと作業環境）は、承認待ちを作り、自分の分を読むことしかできない。
- 失敗したとき: socket が無い・つながらない・関所が答えを断ったときは、許さない側に倒す。サーバーは許しを推測で作らず、関所に答えを渡せなかったことを画面に出す。

### 本 ADR で決定しないこと

- 関所の socket の上で交わす要求・答え・出来事の形（委譲先: natsumi-sentinel の ADR と、この ADR の実装の PR）。
- 承認待ちの作り方、範囲の意味（1 回の要求の指紋、期限付きの操作と対象の組）、台帳と監査の記録の持ち方と期間、承認待ちに期限を付けるか（委譲先: natsumi-sentinel の ADR）。
- config の節と欄の名前、画面のパス（`/dashboard/approvals` の下）とフォームの欄、`/sources/sentinel/approvals/<id>.json` の欄の名前、印の種類の名前、Web Push の文面（委譲先: この ADR の実装の PR と、更新元 `sentinel` のマニュアル）。
- iPhone・Mac のアプリと Slack のボタンから答えること（委譲先: アプリの画面を見直すときの ADR）。
- 関所の承認待ちを毎朝まとめて知らせること（委譲先: 必要になったときの ADR）。

### 置き換える既存の決定

- ADR 0049
  - 改める: Decision「ブラウザのログインは既存の GitHub ログインで、cookie に載せる」の「ダッシュボードは読み取り専用とする」の例外に、関所の承認待ちへの答えと、効いている許しの取り消しの POST を加える。守りは ADR 0064 の取り消しと同じである。
  - 追加: Decision「画面に並べるもの」に、関所の承認待ち・効いている許し・監査の記録（関所を選んだインスタンスだけ）を加える。
- ADR 0058
  - 改める: 「ADR との関係」の ADR 0049 の「保つ: ダッシュボードの中は読み取り専用のまま」から、関所の承認待ちへの答えと許しの取り消しの POST を除く（ADR 0064・0077 と同じ形）。
  - 保つ: 設定と Slack の投稿の承認は `/`・`/settings` から WebSocket で変える。
- ADR 0070
  - 追加: Decision「送るものと時は、iPhone の alert と同じにする」の送るものに、関所の承認待ちを加える。送り先は、つながっているかを問わず、購読があってセッションが生きているブラウザすべてとする。
  - 保つ: 1 回だけ送ること、返事・知らせ・Slack の投稿の承認待ちの送り先の規則。
- ADR 0050
  - 追加: 更新元 `sentinel`（関所を選んだインスタンスだけ）と、関所の承認待ちが閉じたことを表す `attention` の種類。
- ADR 0069
  - 適用: Decision「方針: 外から届くものは、可能な限り `sources_updated` に寄せる」を、関所の承認待ちの答えに適用する。

## Consequences

- ペネロペは、ask で断られた要求を、本人の答えの後にやり直せる。期限付きとずっとの許しで、同じ種類の操作のたびに聞かれずに済む。
- 本人の許しは、本人だけが使える画面からしか出ない。ペネロペが読まされた文に従っても、自分の要求を自分で許すことはできない。
- 画面の文は関所の事実だけなので、ペネロペの説明（なぜ要るか）は画面に出ない。本人が理由を知りたいときは、会話で聞くことになる。
- 会話の「ok」で済んでいたマージと tag の作成が、ダッシュボードを開いて押す手間に変わる。
- Web Push は、会話の画面を開いていても届く。会話で用件を話している最中にも、承認待ちの通知が出る。
- iPhone には知らせないので、Web Push を購読したブラウザが無ければ、本人は承認待ちに気づけない。ペネロペは待ったままになる。
- 監査の記録の本文（出ていく書き込みの本文、`ask_agent` の頼みの文など）が、ダッシュボードで読めるようになる。本人のログインの守りが、この記録の守りにもなる。
- 関所が止まるか socket が切れると、本人は答えられず、承認待ちのある作業は止まる。許さない側に倒すので、これを受け入れる。
- 許しの取り消しは知らされないので、ペネロペは取り消された許しを次の 403 まで当てにする。
- `/sources/sentinel/approvals` は消さないので、少しずつ増える。

## Alternatives Considered

- **関所が自分で承認の画面を持つ**: 本人のログインの仕組みと Web Push を、関所にもう一度作ることになる。なつみには GitHub のログインと Web Push が既にある。
- **Slack のボタンで答える**: Slack の投稿の判定（ポッポさん）と同じ道に、関所の許しが乗る。最初の版では、本人のログインの後ろだけで答えられる形にした。後の候補に残す。
- **答えを会話の「ok」で受ける**: ペネロペが読まされた文や、本人の発言の読み違えで、許しが作られうる。会話の外の画面にした。
- **答えを待つ間、関所が接続を開けたままにする / ペネロペが poll する**: 開けたままでは、本人が答えるまで道具が止まり、時間切れも道具ごとに違う。poll は、ターンを延ばすか忘れるかになる。すぐ 403 で返し、答えを `sources_updated` で届ける形にした。
- **サーバーが承認待ちと許しの写しを SQLite に持つ**: 関所の台帳と写しの 2 つの正本ができ、食い違ったときにどちらを信じるかを決めることになる。
