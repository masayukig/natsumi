# 0094. コマンドは選んだ秒数だけ待って裏に回し、ターンの中で知らせを待てるようにする

- Date: 2026-11-06
- Status: Accepted

## Context

なつみは作業環境のコマンドを `run_shell` で動かす（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
長い処理（集計、変換、画像の生成、VM を立ててのテストなど）を回すと、次のことが起きている。

**待っている間、なつみは考えられない。**

- Pi は、ツールの結果が返るまで次のモデルの呼び出しに進まない。`run_shell` を待っている間は、本人が話し掛けても返事ができない。
- 待つのは、作業環境の実行役（runner）の応答の上限までである。上限は runner の `-response-limit`（既定 60 秒、`runner/main.go` の `serve`）で、
  サーバーは `loop.shellWaitSeconds`（既定 75 秒、`src/server/workspace-shell.ts` の `DEFAULT_SHELL_WAIT_SECONDS`）まで runner の答えを待つ。
  なつみは、コマンドが数秒で終わるか何分も掛かるかを先に読めないので、長い処理を回すたびに最大 60 秒止まる。

**上限を過ぎたコマンドは、終わっても知らされない。**

- 上限を過ぎたコマンドは止めずに動かし続ける。ADR 0019 の Decision「1 コマンドの寿命と、残ったプロセス」で、上限を「コマンドを止める線」から「答えを返す線」に変えた。
- その後の出力は、パイプを詰まらせないために読み続けるが、読み捨てる（`runner/runner.go` の `capped` と `drain`）。終了コードもどこにも残らない。
- 結果の文は「終わったかどうかは ps で確かめ、要らなくなったら kill してください」と伝える（`src/server/workspace-shell.ts` の `describe`）。
  終わりを知るには、なつみが後で `ps` を打ちに行くしかない。そのためにターンを延ばすか、忘れるかになる。

**1 つのターンの中で、裏の仕事の終わりを待てない。**

本人は、ペネロペ（natsumi のインスタンスの 1 つ）が 1 つのターンの中で複数の仕事を裏に投げ、その結果を見ながら同じターンで作業を続けられるようにしたい。
ペネロペのターンは長くなってもよいと考えている。今の仕組みでは次の理由でできない。

- ターンの途中に差し込まれるのは、本人のメッセージだけである。Pi の steering で、次のモデルの呼び出しの境目に入る（[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md) の Decision「思考ループ」、`src/server/thinking-loop.ts` の `ThinkingLoop.send`）。
- `sources_updated`（[ADR 0050](0050-telling-of-source-updates-with-one-event.md)）は待ち行列に 1 つまで積まれ、走っているターンが終わってから次のターンになる（`ThinkingLoop.raiseSourcesUpdated`）。
  なつみ宛ての印（`attention`）の付いた更新でも同じである。外の係の返事（[ADR 0069](0069-agent-replies-as-files-in-sources.md)）も、走っているターンには届かない。
- ターンの中で待つ手段は `sleep` しかない。`sleep` は知らせが来ても起きず、`run_shell` の応答の上限より長く眠れない。
- 待つためにターンを終えると、作業の文脈を失う。終わったターンは畳まれ、思考と作業の途中（`run_shell` の結果など）は落ち、届いたもの・外に送ったもの・`read` で読んだもの・1 行の振り返りだけが残る（[ADR 0047](0047-folding-ended-turns-with-a-memo.md)、`src/server/turn-fold.ts` の `KEPT_TOOLS`）。

**ターンを長くすると、文脈が育ち続ける。**

- compaction は、ターンの間にだけ、`compactionThreshold` を越えていたら走る（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md) の Decision「上限での compaction」、`ThinkingLoop.maintain`）。
  ターンの途中では走らず、畳み込みも終わったターンにしか効かないので、長いターンでは文脈が上限を越えて育ち得る。
- 1 ターンの上限は、モデルの呼び出しの回数 `loop.eventModelCalls`（既定 8）と時間 `loop.eventTimeoutMinutes`（既定 10 分）で、インスタンスごとの設定で変えられる（ADR 0008、[ADR 0058](0058-settings-and-chat-in-the-browser.md)）。
  ペネロペは `eventModelCalls` を 20、`compactionThreshold` を 128000 にしている（環境のリポジトリの `apps/natsumi/penelope/config.json`）。

手元の事実と、すでにある仕組みは次のとおりである。

- runner は、コマンドごとに `Setpgid` で別のプロセスグループを作って `bash -c` で動かす。待つのは 1 度に 1 つで、答えを返したら次の要求を受け付ける（`runner/runner.go` の `Server.Run` と `Server.handle`）。
  runner が答えに使う接続は、答えの 1 行を書くと閉じる。
- runner が残す出力は、標準出力と標準エラー出力のそれぞれ先頭 64 KiB（`-max-output`）で、モデルに返すのは標準出力 8000 文字・標準エラー出力 2000 文字の先頭である（`src/server/workspace-shell.ts` の `SHELL_OUTPUT_CHARS`）。
  エラーや集計の結果は出力の末尾に出ることが多いが、長い出力では末尾が落ちる。
- サーバーと作業環境は、同じ Pod の別のコンテナである（環境のリポジトリの `apps/natsumi/base/statefulset.yaml` の `server` と `workspace`）。
  リリースや Pod の再起動では両方が作り直され、動いていたコマンドも一緒に落ちる。サーバーだけが止まって作業環境が残るのは、サーバーのコンテナだけが再起動したときに限られる。
- 外から届くものは、可能な限り `/sources` の下のファイルにし、`sources_updated` で知らせる方針がある（ADR 0069）。
  印はすぐ、夜でも知らせる。印の無い変化は、最初の変化で引いたランダムな待ちの後に知らせ、awake hours の外では起こさない（[ADR 0053](0053-waiting-at-random-for-source-updates.md)）。
- 更新元が自分で作ったディレクトリを「なつみにとって新しくない」として黙って取り込む口がある（ADR 0050 の「追記（2026-10-12）: 動いている間に新しく現れたディレクトリも、ふつうの更新として出す」、`src/server/sources.ts` の `Sources.takeIn`）。外のエージェントへの依頼のディレクトリがこれを使う。
- 夜の記憶の整理係（curator、[ADR 0068](0068-a-curator-that-remembers-like-a-person.md)）も、同じ runner に `run_shell` を送る。整理係の session は出来事を受け取らない。
- 外の係の返事を待ち続ける上限は、既定 24 時間である（[ADR 0036](0036-a-manual-to-read-and-a-limit-on-waiting.md) の Decision「返事を待ち続ける上限」）。

## Decision

この ADR は、なつみの session（natsumi のどのインスタンスでも同じ）の `run_shell`・ターンの中の差し込み・ターンの中で待つツールを決める。
夜の整理係と、設定で宣言したツールは、後の「夜の整理係と、宣言したツールには付けない」の節のとおり範囲の外である。

### `run_shell` に、省略できる待ち時間 `wait_seconds` を足す

- なつみの `run_shell` に、省略できる引数 `wait_seconds`（秒）を足す。
  - その秒数のうちにコマンドが終われば、今と同じく終了コードと出力を返す。
  - 終わらなければ、そこまでの出力を返してコマンドを**裏に回す**。止めない。終わったら、`sources_updated` で知らせる（以下の節）。
- 範囲は 0 から runner の応答の上限（既定 60 秒）までで、省略したときは上限まで待つ。省略したときの動きは、知らせが届くことを除いて今と同じである。
- `0` は、待たずにすぐ裏に回す。別のツールを足さずに「裏で動かす」をこれで表す。
- 範囲の外の値は断らずに、範囲に丸めて動かし、丸めたことを結果の文に書く。コマンドを無駄にしないためである。
- 上限は runner の `-response-limit` に合わせる。`wait_seconds` のための別の設定は作らない。サーバーの `loop.shellWaitSeconds` の決まり（runner の上限より長くする）は変えない。
- runner が 1 度に 1 つのコマンドを待つことは変えない。runner が次の要求を受け付けるのは、`wait_seconds` が過ぎて最初の答えを返した後である。

### 終わったことは、runner が同じ接続に 2 行目を書いて伝える

- 裏に回ったコマンドについて、サーバーは runner との接続をつないだまま待つ。runner は、コマンドが終わったら、同じ接続に結果の 2 行目を書く。
- runner には、裏に回ったコマンドの一覧や、終わった結果を後から取りに来られる状態を持たせない。結果を知るのは、つないだままのサーバーだけである。
- サーバーだけが落ちて接続が切れたら、その後の結果は失われる。サーバーだけが落ちるのはサーバーのコンテナだけが再起動したときに限られ、リリースや Pod の再起動ではコマンドも落ちるので、これを受け入れる。
- 2 行目のための時間の上限は、次の節の最長の待ちとする。

### 待つ数と、待つ長さの上限

- 終わりを待つ裏のコマンドの数の上限を、設定 `loop.backgroundJobs`（既定 **5**）にする。
  - 裏に回る時点で上限の数を待っていれば、そのコマンドは今と同じ扱いにする。止めない・その後の出力は読み捨てる・終わっても知らせない。そうなったことを結果の文に書く。
  - 既定を 5 にした理由: 1 つのターンで追うには足り、作業環境の pids の上限（ADR 0019 の Decision「資源の上限」、256）に対して小さい。
    数で抑えるのは、終わらないコマンドが待ちの枠を埋め続けるのを止めるためで、資源の保護は pids とメモリの上限が受け持つ。
  - 設定にした理由: ペネロペのように VM を何台も立ててテストを流すインスタンスでは、5 個では足りない。
  - 値はインスタンスの config で決める。動いている間に画面から変える設定（ADR 0058）には加えない。
- 1 つのコマンドを待つのは、裏に回ってから最長 **24 時間**とする。過ぎたら待つのをやめ、「もう待たない」ことを知らせる。プロセスは止めない。
  - 24 時間にした理由: 外の係の返事を待つ上限（ADR 0036）と揃え、夜の整理と作業場の棚卸し（ADR 0019）を 1 度は挟む長さにする。
    数の上限だけだと、終わらないコマンドが上限までたまったところで枠が空かなくなる。
  - 24 時間は設定にしない。環境ごとに変える理由が無い。
- 裏に回ったときの結果の文と、24 時間の知らせには、そのコマンドのプロセスグループの番号と、グループごと止める `kill -- -<番号>` を書く。片付けの手がかりにする。

### 知らせは `sources_updated` で、置き場所は `/sources/jobs/<時刻>-<印>/`

- 更新元 `jobs` を足す。深さは 1（`jobs/<時刻>-<印>`）で、裏に回ったコマンド 1 つが 1 ディレクトリである。
  ディレクトリの名前の形は、外のエージェントへの依頼（ADR 0069）や A2A の依頼（[ADR 0089](0089-hearing-from-agents-over-a2a.md)）と同じ、時刻と短いランダムな印にする。
- ディレクトリは裏に回ったときに作り、コマンド、裏に回った時刻、プロセスグループの番号を書いて、黙って取り込む（ADR 0050 の「追記（2026-10-12）」の例外に、3 つ目の使い道として加える）。
  なつみが自分で始めたことなので、始まったこと自体はなつみにとって新しくない。裏に回ったときの結果の文に、このディレクトリの場所を書く。
- 終わったら、同じディレクトリに終わり方（終了コード、またはシグナルの名前）、標準出力、標準エラー出力を置く。
  - 差分の履歴には、終わり方を書いた `README.md` だけを入れ、出力のファイルは外す。出力の全体はファイルで読む。
- 知らせ方は、終わり方で分ける。
  - **終了コードで終わった**: なつみ宛ての印を付け、すぐ知らせる。種類は `shell_finished` で、場所はそのディレクトリの `README.md` とする。
    印に載せるのは終了コードまでで、出力は載せない。自分で始めて結果を待っているものなので、ふつうの更新の待ちに回さない。
  - **シグナルで終わった**（`kill`、メモリの上限による OOM など）: 印を付けず、ふつうの更新として知らせる。`README.md` にシグナルの名前を書く。
    なつみ自身が止めたものに印を付けてすぐ起こすことはしないが、OOM のような予想外の終わり方は、ふつうの更新として必ず目に入る。
  - **24 時間を過ぎた**: 印を付けず、ふつうの更新として「もう待たない」ことと、プロセスグループの番号・`kill -- -<番号>` を `README.md` に書く。
- サーバーが起動したとき、終わり方の書かれていない `jobs` のディレクトリには、サーバーの再起動で待てなくなったことを書く（ふつうの更新）。
  Pod ごと作り直されたのなら、コマンドも落ちている。
- ディレクトリは消さない。外のエージェントの返事（ADR 0069 の Decision「返事は消さない」）と同じく残す。1 つの大きさは、次の節の出力の上限で抑えられる。
- 出来事の種類、system prompt は変えない。印の種類の意味は、更新元のマニュアル（`jobs` の 1 枚）に書く（ADR 0050）。

### 出力は先頭と末尾を残す

- runner が残す出力は、標準出力と標準エラー出力のそれぞれについて、先頭と末尾を残して間を捨てる形にする。合計は今の `-max-output` に収め、捨てたバイト数を答えに入れる。
- これは裏のコマンドだけでなく、ふつうの `run_shell` の結果にも同じく効かせる。runner の出力の持ち方を 1 つにする。
  サーバーがモデルに返す上限（標準出力 8000 文字・標準エラー出力 2000 文字）も、先頭と末尾を残す形で切る。
- 省いたことと省いた量は、結果の文と `README.md` に書く。
- 全部の出力が要るときは、今どおり `/work` のファイルへリダイレクトする。ツールの説明にそう書く。
  `/sources` は git の履歴を持つので、出力を上限なく置く場所にしない。

### 印の付いた更新は、走っているターンに差し込む

- 出来事のターンが走っている間になつみ宛ての印が付いたら、その印の `sources_updated` を、本人のメッセージと同じく次のモデルの呼び出しの境目で差し込む。
  `shell_finished` に限らず、印の付いた更新すべて（外の係の返事、Slack のメンションと DM、印の付く webhook など）である。
  - 理由: 長いターンでは、裏のコマンドだけでなく外の係の返事も待つ。印は「なつみ宛て」の知らせなので、本人のメッセージと同じ扱いにする。
  - 差し込む `sources_updated` に載せるのは、印とその印のあるディレクトリである。印の無い変化は差し込まず、今どおりターンが終わった後の `sources_updated` に回す。
  - 本人のメッセージで差し込まない場面では、印も差し込まない。夜の振り返りのターン、止める途中（[ADR 0083](0083-waiting-for-the-turn-in-progress-at-a-stop.md)）、画像を添える必要がある印（steering は文字だけを運ぶため）は、今どおり次のターンで知らせる。
  - 差し込んだ `sources_updated` は、差し込まれた本人のメッセージと同じく、境目で文脈に入った時点で「見た」とする（[ADR 0024](0024-no-event-ids-for-the-model.md)）。届かなかった差し込みは、待ち行列に戻す。
- 差し込みはすべてのインスタンスで有効にし、設定にしない。短いターンではほとんど何も変わらない。ターンの長さは既存の設定（`eventModelCalls`・`eventTimeoutMinutes`）で決める。

### ターンの中で知らせを待つツール `wait_for_events` を足す

- なつみの session に、ツール `wait_for_events` を足す。引数は最長の秒数 `max_seconds` である。
  - 差し込める知らせ（本人のメッセージ、または印の付いた `sources_updated`）が来るか、秒数が過ぎたら戻る。届いたものは、戻った後の境目で差し込まれる。
  - 名前は、思考ループへの入力をすべて「出来事」（events）として渡す形（ADR 0008）に合わせた。
- 待つ時間は、ターンの時間の上限に数える。
  - `max_seconds` はターンの残り時間に丸める。残りが無ければ待たずに、「ターンを終えて」と返す。
  - ターンを長くするかどうかは、インスタンスごとの `eventTimeoutMinutes`（と `eventModelCalls`）で決める。たとえばペネロペは長くし、なつみは今のままにする。値は環境の設定で決める。
- 待つ相手が 1 つも無いときは、すぐ戻り、「待つ相手がいないので待ちませんでした」と返す。待つ相手は、知らせを待っている裏のコマンドと、返事を待っている外の係への依頼である。
  むやみに待ってターンを延ばさないためである。
- 夜の振り返りのターンでは、差し込むものが無いので待たずに戻る。
- すべてのインスタンスに入れ、設定にしない。
- モデルが直接呼ぶツールとし、Codemode のスクリプト（[ADR 0066](0066-codemode-to-keep-raw-output-out-of-the-context.md)）からは呼ばせない。待っている間に届いた知らせは、モデルの呼び出しの境目でしか差し込めないためである。

### 長いターンで文脈が育ちすぎたら、区切りを促し、保険で止める

- 出来事のターンの中で、モデルの呼び出しの境目ごとに文脈の大きさを測る。経路の `compactionThreshold`（ADR 0009）を越えていたら、次のことをする。
  - 次のツールの結果に、「区切りのいいところでターンを終え、続きは振り返りに書く」よう添える。
  - `wait_for_events` は待たずにすぐ戻り、同じことを伝える。
- 保険として、文脈が `compactionThreshold` の **1.5 倍**を越えたら、ターンを時間切れと同じく止める（返事を送っていない出来事は失敗として記録し、送ったものは残す）。
  - 1.5 倍にした理由: 促しを受けてから区切りを付けてターンを終えるまでの数回の呼び出しの分を見込みつつ、促しに従わないターンが文脈を際限なく育てるのを止める。経路の文脈の長さは経路ごとに違うので、閾値に対する倍率で決める。倍率は設定にしない。
- ターンが終われば、今どおりターンの間に compaction が走る。ターンの途中では compaction しない（ADR 0009 のまま）。
  ターンの途中の compaction は、作業の途中の結果を要約に置き換え、作業を崩しやすいためである。

### 裏に回ったときの結果の文

- 裏に回ったときの結果の文は、次のことを伝える。
  - コマンドは止めずに裏で動いていて、終わったら `sources_updated` で知らせること。置き場所のディレクトリ、プロセスグループの番号と `kill -- -<番号>`。
  - `ps` や `sleep` で様子を見に行かなくてよいこと。
  - 次の 3 つの道があること。ほかにすることがあれば続ける。結果を見てこのターンで続けたいなら `wait_for_events` で待つ。急がないならターンを終える（終わったら知らせが届く）。
- どれを選ぶかはモデルに任せ、ターンの上限で抑える。「ターンを終える」とだけ言い切らない。本人への返事の途中でも、言い切るとターンを切りがちだからである。
- 待っている裏のコマンドについては、結果の末尾の「まだ動いているコマンドが N 個」の行（ADR 0019）でも、`ps` で確かめるよう促さない。
  促すのは、知らせを待っていないコマンド（上限を超えた分と、知らせが無くなったもの）だけにする。
- ツールの説明の「長い処理はそのまま残せる…」の段落は、この形に合わせて書き直す。説明の書き方の規則（設定の値から文面を組み立てない、環境で変わる数字は書かない）は ADR 0019 の Decision「ツールの説明と prefix cache」のままとする。

### 夜の整理係と、宣言したツールには付けない

- 夜の記憶の整理係（ADR 0068）の `run_shell` には、`wait_seconds` も裏に回す動きも付けない。`wait_for_events` も渡さない。整理係は出来事を受け取らないので、知らせの届け先が無い。
  上限を過ぎたコマンドは、今と同じ扱い（止めない・読み捨てる・知らせない）のままである。
- 出力の先頭と末尾を残す形は runner の持ち方なので、整理係の `run_shell` にも効く。
- 設定で宣言したツール（[ADR 0075](0075-tools-declared-in-the-config.md)）の動き（時間切れで止める、結果は出力だけ）は変えない。
- なつみの `run_shell` を Codemode のスクリプトから呼ぶとき（ADR 0066）も、`wait_seconds` は同じ引数と同じ動きである。

### 本 ADR で決定しないこと

- runner との要求・答えの欄の名前、2 行目の形、`README.md` と出力のファイルの名前と書き方、印の欄の名前（委譲先: この ADR の実装の PR と、更新元 `jobs` のマニュアル）。
- `loop.backgroundJobs` の枠が埋まっているかをいつ判断するか（要求を送る時点か、裏に回る時点か）と、その数え方（委譲先: この ADR の実装の PR。どちらでも、知らせを約束できないコマンドにはそう書く）。
- ツールの説明の文面、結果の文の文面、保険で止めたターンの失敗の記録の名前（委譲先: この ADR の実装の PR。説明は ADR 0019 の規則に従う）。
- ペネロペなどインスタンスごとの `eventModelCalls`・`eventTimeoutMinutes`・`loop.backgroundJobs` の値（委譲先: 環境のリポジトリのインスタンスの config）。
- 古い `jobs` のディレクトリを消すこと（委譲先: ADR 0069 の「返事は消さない」と合わせ、量が問題になったときの ADR）。
- 本番に出す前に、ローカルのモデルで、裏に回った後に `ps` や `sleep` で様子を見に行かないか、`wait_for_events` を使い分けるかを試すこと（委譲先: この ADR の実装の PR の確認）。

### 置き換える既存の決定

- ADR 0019
  - 置き換え: Decision「1 コマンドの寿命と、残ったプロセス」の、応答の上限を過ぎたコマンドの出力を読み捨て続け、返さない点。
    なつみの `run_shell` では、待つ数の上限までのコマンドの出力を先頭と末尾で残し、終わったら `/sources/jobs/` に置いて知らせる。読み捨てて知らせないのは、上限を超えた分と整理係のコマンドだけになる。
  - 置き換え: 同じ節の、応答の上限まで待つ点。なつみが `wait_seconds` で上限より短く選べる。上限は「答えを返す線」のまま残す。
  - 置き換え: Decision「コマンドと出力の上限」の、runner が残す出力とモデルに返す出力を先頭から取る点。先頭と末尾を残す形にする。上限の大きさは変えない。
  - 置き換え: Decision「ツールの説明と prefix cache」の説明に書く項目のうち「長い処理は残せること。応答が返った後もプロセスは動き続けるので、`ps` と `kill` で自分で始末すること」。
  - 残す: runner が 1 度に 1 つのコマンドを待つこと、コマンドを止めないこと、`loop.shellWaitSeconds` の決まり、ツールの説明の規則。
- ADR 0008
  - 追加: Decision「思考ループ」の「ターンの途中に届いた本人のメッセージは、次のモデル呼び出しの境目で差し込む」に、なつみ宛ての印の付いた `sources_updated` を加える。
  - 追加: ツールに `wait_for_events` を加える。
  - 残す: 外から思考を中断しないこと、1 ターンのモデルの呼び出しと時間の上限（待つ時間は時間の上限に数える）。
- ADR 0009
  - 追加: Decision「上限での compaction」に、ターンの途中で文脈の大きさを測り、`compactionThreshold` を越えたら区切りを促し、1.5 倍を越えたらターンを止めることを加える。
  - 残す: compaction はターンの間にだけ行い、ターンの途中では行わないこと。
- ADR 0050
  - 追加: 更新元 `jobs`（深さ 1、出力のファイルを差分から外す）と、印の種類 `shell_finished`。
  - 追加: 「追記（2026-10-12）」の黙って取り込む例外の使い道に、裏に回ったコマンドのディレクトリを作った直後を加える。
  - 追加: Decision「イベントは `sources_updated` の 1 種類」の、待っている `sources_updated` は走っているターンの後に始まる点の例外として、出来事のターンが走っている間に付いた印は、そのターンに差し込む。印の無い変化は変えない。
- ADR 0069
  - 適用: 「外から届くものは、可能な限り `sources_updated` に寄せる」を、なつみ自身が裏に回したコマンドの終わりに適用する。新しい出来事の種類は作らない。

## Consequences

- なつみは、長くなりそうなコマンドを短い待ちや `0` で回し、待たずに本人と話したり、ほかの作業を進めたりできる。
- 1 つのターンの中で複数の仕事を裏に投げ、`wait_for_events` で終わりを待ち、作業の文脈を保ったまま結果を見て続けられる。外の係の返事も、同じターンの中で受け取れる。
- 裏に回したコマンドが終わると、終了コードと出力の先頭と末尾が `/sources/jobs/` に残り、知らせが届く。`ps` を打ちに行く必要がなくなる。
- 長い出力でも末尾が残るので、ふつうの `run_shell` でもエラーや最後の集計を読み落としにくくなる。その代わり、出力の中ほどは、先頭だけを残していた今より短くなる。
- 長いターンの間、印の無いふつうの更新（Slack の流れ、合図など）は後回しになる。ターンが長いインスタンスほど、ふつうの更新に気づくのが遅れる。
- 印の付いた更新が走っているターンに入るので、短いターンでも、作業の途中に係の返事やメンションが割り込むことがある。分けて扱いたい知らせも同じターンで扱うことになり、1 ターンのモデルの呼び出しの上限を分け合う。
- `wait_for_events` が戻るたびにモデルの呼び出しが 1 回増える。ターンを長くするインスタンスでは、`eventTimeoutMinutes` と合わせて `eventModelCalls` も上げる必要がある。
- 長いターンでは文脈が `compactionThreshold` を越え得る。区切りの促しに従わなければ、1.5 倍でターンが止まり、返事を送っていない出来事は失敗になる。その手前までの文脈の長さと prefill の時間は受け入れる。
- 終了コードで終わった裏のコマンドは、夜でもなつみを起こす。夜に終わる長い処理を回せば、夜にターンが走る。
- シグナルで終わったものと 24 時間の知らせは、ふつうの更新の待ちの後になる。awake hours の外なら朝まで知らされない。
- サーバーだけが落ちると、裏のコマンドの結果は失われる。起動したときに「待てなくなった」とは書くが、コマンドが動き続けていれば、その結果は残らない。
- `loop.backgroundJobs` を超えて裏に回したコマンドと、整理係のコマンドは、今と同じく終わっても知らされない。結果の文でそう伝える。
- 24 時間を過ぎても、プロセスは止めない。終わらないコマンドの始末は、今と同じくなつみと夜の棚卸しに残る。
- runner はつないだままの接続ごとに、裏のコマンドの出力（最大で `-max-output` の 2 倍）を持ち続ける。`loop.backgroundJobs` を大きくするほど、作業環境のメモリを使う。
- 裏に回った後に、モデルが `ps` や `sleep` で様子を見に行くと、ターンが延びて待たない利点が消える。結果の文で抑えるが、モデルによっては効かない。
- `jobs` のディレクトリを消さないので、`/sources/jobs` は少しずつ増える。

## Alternatives Considered

- **裏で動かす別のツール `bg_run` を足す**: なつみは、コマンドを回す前に、それが長いかどうかを読んでツールを選ぶことになる。読み違えると、短いコマンドを裏に回して知らせを待つか、長いコマンドで止まる。
  `run_shell` の待ち時間にすれば、短いものは今どおり結果が返り、長いものだけが裏に回る。ツールの数も増えず、振る舞いは 1 つで済む。`wait_seconds: 0` で `bg_run` と同じことができる。
- **`run_shell` の上限を過ぎたら自動で裏に回すだけにする（待ち時間の引数を足さない）**: 終わりは知らされるようになるが、待つのは毎回上限の 60 秒で、なつみが待たずに済ませる手段が無い。
  考えられない時間を減らすという困りごとの片方が残る。
- **runner に裏のコマンドの状態を持たせ、サーバーが後から取りに行く**: サーバーだけが落ちても結果を取れるが、runner に一覧と保存の寿命を持たせることになる。
  サーバーのコンテナだけが再起動する場合にしか効かず、リリースや Pod の再起動ではコマンドも落ちるので、得るものが少ない。
- **終わりを専用の出来事で知らせる**: 出来事の種類と system prompt が増える。ADR 0069 の方針どおり、`/sources` と `sources_updated` で足りる。
- **待つ数に上限を付けず、24 時間だけで抑える**: 短い間に大量に裏に回すと、つないだままの接続と runner が持つ出力が際限なく増える。
- **走っているターンに差し込むのを `shell_finished` だけにする**: 長いターンでは外の係の返事も待つ。係の返事だけがターンの後に回ると、`wait_for_events` で係を待てない。
- **印の無い更新も含めて、すべての `sources_updated` を差し込む**: Slack の流れのような急がない変化が、作業の途中に何度も割り込む。ADR 0053 が印の無い変化を待たせる理由と同じく、印の有無で分ける。
- **ターンの中で待つのに `run_shell` の `sleep` を使う**: 知らせが来ても起きられず、`run_shell` の応答の上限より長く眠れない。
- **ターンの中で待つ手段を持たない**: 結果を待つにはターンを終えるしかなく、畳み込みで作業の文脈を失う。
- **`wait_for_events` の待ちをターンの時間に数えない**: ターンの時間の上限が効かなくなり、待ち続けるターンを止められない。ターンを長くしたいインスタンスは、`eventTimeoutMinutes` を上げれば足りる。
- **文脈が育っても何もしない**: 長いターンでは文脈が経路の長さを越え、モデルの呼び出しが失敗するか、prefill が際限なく遅くなる。
- **ターンの途中で compaction する**: 作業の途中の結果が要約に置き換わり、作業を崩しやすい。ADR 0009 がターンの途中の compaction を避けた理由と同じである。
