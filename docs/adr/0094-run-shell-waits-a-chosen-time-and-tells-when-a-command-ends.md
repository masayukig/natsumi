# 0094. run_shell は選んだ秒数だけ待ち、待ちを過ぎたコマンドは終わったら sources_updated で知らせる

- Date: 2026-11-05
- Status: Accepted

## Context

なつみは作業環境のコマンドを `run_shell` で動かす（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
長い処理（集計、変換、画像の生成など）を回すと、次の 2 つが起きている。

**待っている間、なつみは考えられない。**

- Pi は、ツールの結果が返るまで次のモデルの呼び出しに進まない。本人のメッセージも、走っているターンには次のモデルの呼び出しの境目で差し込まれる（`src/server/thinking-loop.ts` の `ThinkingLoop` の説明）。
  `run_shell` を待っている間は、本人が話し掛けても返事ができない。
- 待つのは、作業環境の実行役（runner）の応答の上限までである。上限は runner の `-response-limit`（既定 60 秒、`runner/main.go` の `serve`）で、
  サーバーは `loop.shellWaitSeconds`（既定 75 秒、`src/server/workspace-shell.ts` の `DEFAULT_SHELL_WAIT_SECONDS`）まで runner の答えを待つ。
  なつみは、コマンドが数秒で終わるか何分も掛かるかを先に読めないので、長い処理を回すたびに最大 60 秒止まる。

**上限を過ぎたコマンドは、終わっても知らされない。**

- 上限を過ぎたコマンドは止めずに動かし続ける。ADR 0019 の Decision「1 コマンドの寿命と、残ったプロセス」で、上限を「コマンドを止める線」から「答えを返す線」に変えた。
- その後の出力は、パイプを詰まらせないために読み続けるが、読み捨てる（`runner/runner.go` の `capped` と `drain`）。終了コードもどこにも残らない。
- 結果の文は「終わったかどうかは ps で確かめ、要らなくなったら kill してください」と伝える（`src/server/workspace-shell.ts` の `describe`）。
  終わりを知るには、なつみが後で `ps` を打ちに行くしかない。そのためにターンを延ばすか、忘れるかになる。
- 出力を残したいときは `/work` のファイルへリダイレクトするよう、ツールの説明で求めている（`src/server/prompts.ts` の `RUN_SHELL_DESCRIPTION`）。リダイレクトしても、終わったことは知らされない。

手元の事実と、すでにある仕組みは次のとおりである。

- runner は、コマンドごとに `Setpgid` で別のプロセスグループを作って `bash -c` で動かす。待つのは 1 度に 1 つで、答えを返したら次の要求を受け付ける（`runner/runner.go` の `Server.Run` と `Server.handle`）。
  runner が答えに使う接続は、答えの 1 行を書くと閉じる。
- runner が残す出力は、標準出力と標準エラー出力のそれぞれ先頭 64 KiB（`-max-output`）で、モデルに返すのは標準出力 8000 文字・標準エラー出力 2000 文字の先頭である（`src/server/workspace-shell.ts` の `SHELL_OUTPUT_CHARS`）。
  エラーや集計の結果は出力の末尾に出ることが多いが、長い出力では末尾が落ちる。
- サーバーと作業環境は、同じ Pod の別のコンテナである（環境のリポジトリの `apps/natsumi/base/statefulset.yaml` の `server` と `workspace`）。
  リリースや Pod の再起動では両方が作り直され、動いていたコマンドも一緒に落ちる。サーバーだけが止まって作業環境が残るのは、サーバーのコンテナだけが再起動したときに限られる。
- 外から届くものは、可能な限り `/sources` の下のファイルにし、`sources_updated` で知らせる方針がある（[ADR 0069](0069-agent-replies-as-files-in-sources.md)）。
  `sources_updated` は、変わったディレクトリ、なつみ宛ての印（`attention`）、差分の見方を載せる 1 種類の出来事である（[ADR 0050](0050-telling-of-source-updates-with-one-event.md)）。
  印はすぐ、夜でも知らせる。印の無い変化は、最初の変化で引いたランダムな待ちの後に知らせ、awake hours の外では起こさない（[ADR 0053](0053-waiting-at-random-for-source-updates.md)）。
- 更新元が自分で作ったディレクトリを「なつみにとって新しくない」として黙って取り込む口がある（ADR 0050 の「追記（2026-10-12）: 動いている間に新しく現れたディレクトリも、ふつうの更新として出す」、`src/server/sources.ts` の `Sources.takeIn`）。外のエージェントへの依頼のディレクトリがこれを使う。
- 夜の記憶の整理係（curator、[ADR 0068](0068-a-curator-that-remembers-like-a-person.md)）も、同じ runner に `run_shell` を送る。整理係の session は出来事を受け取らない。
- 外の係の返事を待ち続ける上限は、既定 24 時間である（[ADR 0036](0036-a-manual-to-read-and-a-limit-on-waiting.md) の Decision「返事を待ち続ける上限」）。

本人は、裏で動かす手段をなつみに持たせたいと考えた。

## Decision

### `run_shell` に、省略できる待ち時間 `wait_seconds` を足す

- なつみの `run_shell` に、省略できる引数 `wait_seconds`（秒）を足す。
  - その秒数のうちにコマンドが終われば、今と同じく終了コードと出力を返す。
  - 終わらなければ、そこまでの出力を返してコマンドを**裏に回す**。止めない。終わったら、`sources_updated` で知らせる（以下の節）。
- 範囲は 0 から runner の応答の上限（既定 60 秒）までで、省略したときは上限まで待つ。省略したときの動きは、知らせが届くことを除いて今と同じである。
- `0` は、待たずにすぐ裏に回す。別のツールを足さずに「裏で動かす」をこれで表す。
- 範囲の外の値は断らずに、範囲に丸めて動かし、丸めたことを結果の文に書く。コマンドを無駄にしないためである。
- 上限は runner の `-response-limit` に合わせる。`wait_seconds` のための別の設定は作らない。サーバーの `loop.shellWaitSeconds` の決まり（runner の上限より長くする）は変えない。
- runner が 1 度に 1 つのコマンドを待つことは変えない。runner が次の要求を受け付けるのは、`wait_seconds` が過ぎて最初の答えを返した後である。

### 終わったことは、runner が同じ接続に 2 行目を書いて伝える

- 裏に回ったコマンドについて、サーバーは runner との接続をつないだまま待つ。runner は、コマンドが終わったら、同じ接続に結果の 2 行目を書く。
- runner には、裏に回ったコマンドの一覧や、終わった結果を後から取りに来られる状態を持たせない。結果を知るのは、つないだままのサーバーだけである。
- サーバーだけが落ちて接続が切れたら、その後の結果は失われる。サーバーだけが落ちるのはサーバーのコンテナだけが再起動したときに限られ、リリースや Pod の再起動ではコマンドも落ちるので、これを受け入れる。
- 2 行目のための時間の上限は、次の「待つ数と、待つ長さの上限」の最長の待ちとする。

### 待つ数と、待つ長さの上限

- 終わりを待つ裏のコマンドは、同時に **5 個**までとする。
  - 裏に回る時点で 5 個を待っていれば、そのコマンドは今と同じ扱いにする。止めない・その後の出力は読み捨てる・終わっても知らせない。そうなったことを結果の文に書く。
  - 5 個にした理由: なつみが同時に追える数として足り、作業環境の pids の上限（ADR 0019 の Decision「資源の上限」、256）に対して小さい。
    数で抑えるのは、終わらないコマンドが待ちの枠を埋め続けるのを止めるためで、資源の保護は pids とメモリの上限が受け持つ。
- 1 つのコマンドを待つのは、裏に回ってから最長 **24 時間**とする。過ぎたら待つのをやめ、「もう待たない」ことを知らせる。プロセスは止めない。
  - 24 時間にした理由: 外の係の返事を待つ上限（ADR 0036）と揃え、夜の整理と作業場の棚卸し（ADR 0019）を 1 度は挟む長さにする。
    数の上限だけだと、終わらないコマンドが 5 個たまったところで枠が空かなくなる。
- どちらの値も設定にしない。環境ごとに変える理由が無い。要るようになったら設定にする。
- 裏に回ったときの結果の文と、24 時間の知らせには、そのコマンドのプロセスグループの番号と、グループごと止める `kill -- -<番号>` を書く。片付けの手がかりにする。

### 知らせは `sources_updated` で、置き場所は `/sources/jobs/<時刻>-<印>/`

- 更新元 `jobs` を足す。深さは 1（`jobs/<時刻>-<印>`）で、裏に回ったコマンド 1 つが 1 ディレクトリである。
  ディレクトリの名前の形は、外のエージェントへの依頼（ADR 0069）や A2A の依頼（[ADR 0089](0089-hearing-from-agents-over-a2a.md)）と同じ、時刻と短いランダムな印にする。
- ディレクトリは裏に回ったときに作り、コマンド、裏に回った時刻、プロセスグループの番号を書いて、黙って取り込む（ADR 0050 の「追記（2026-10-12）」の例外に、3 つ目の使い道として加える）。
  なつみが自分で始めたことなので、始まったこと自体はなつみにとって新しくない。裏に回ったときの結果の文に、このディレクトリの場所を書く。
- 終わったら、同じディレクトリに終わり方（終了コード、またはシグナルの名前）、標準出力、標準エラー出力を置く。
  - 差分の履歴には、終わり方を書いた `README.md` だけを入れ、出力のファイルは外す。出力の全体はファイルで読む。
- 知らせ方は、終わり方で分ける。
  - **終了コードで終わった**: なつみ宛ての印を付け、すぐ知らせる。種類は `shell_finished` で、場所はそのディレクトリの `README.md` とする。
    印に載せるのは終了コードまでで、出力は載せない。自分で始めて結果を待っているものなので、ふつうの更新の待ちに回さない。
  - **シグナルで終わった**（`kill`、メモリの上限による OOM など）: 印を付けず、ふつうの更新として知らせる。`README.md` にシグナルの名前を書く。
    なつみ自身が止めたものに印を付けてすぐ起こすことはしないが、OOM のような予想外の終わり方は、ふつうの更新として必ず目に入る。
  - **24 時間を過ぎた**: 印を付けず、ふつうの更新として「もう待たない」ことと、プロセスグループの番号・`kill -- -<番号>` を `README.md` に書く。
- サーバーが起動したとき、終わり方の書かれていない `jobs` のディレクトリには、サーバーの再起動で待てなくなったことを書く（ふつうの更新）。
  Pod ごと作り直されたのなら、コマンドも落ちている。
- ディレクトリは消さない。外のエージェントの返事（ADR 0069 の Decision「返事は消さない」）と同じく残す。1 つの大きさは、次の節の出力の上限で抑えられる。
- 出来事の種類、system prompt は変えない。印の種類の意味は、更新元のマニュアル（`jobs` の 1 枚）に書く（ADR 0050）。

### 出力は先頭と末尾を残す

- runner が残す出力は、標準出力と標準エラー出力のそれぞれについて、先頭と末尾を残して間を捨てる形にする。合計は今の `-max-output` に収め、捨てたバイト数を答えに入れる。
- これは裏のコマンドだけでなく、ふつうの `run_shell` の結果にも同じく効かせる。runner の出力の持ち方を 1 つにする。
  サーバーがモデルに返す上限（標準出力 8000 文字・標準エラー出力 2000 文字）も、先頭と末尾を残す形で切る。
- 省いたことと省いた量は、結果の文と `README.md` に書く。
- 全部の出力が要るときは、今どおり `/work` のファイルへリダイレクトする。ツールの説明にそう書く。
  `/sources` は git の履歴を持つので、出力を上限なく置く場所にしない。

### 裏に回ったときの結果の文

- 裏に回ったときの結果の文は、次のことを伝える。
  - コマンドは止めずに裏で動いていて、終わったら `sources_updated` で知らせること。置き場所のディレクトリ、プロセスグループの番号と `kill -- -<番号>`。
  - 待たなくてよいこと。`ps` や `sleep` で様子を見に行かなくてよいこと。
  - ほかにすることがあれば続け、なければターンを終えること。
- 「ターンを終える」とだけ言い切らない。本人への返事の途中でも、言い切るとターンを切りがちだからである。
- 待っている裏のコマンドについては、結果の末尾の「まだ動いているコマンドが N 個」の行（ADR 0019）でも、`ps` で確かめるよう促さない。
  促すのは、知らせを待っていないコマンド（5 個を超えた分と、知らせが無くなったもの）だけにする。
- ツールの説明の「長い処理はそのまま残せる…」の段落は、この形に合わせて書き直す。説明の書き方の規則（設定の値から文面を組み立てない、環境で変わる数字は書かない）は ADR 0019 の Decision「ツールの説明と prefix cache」のままとする。

### 夜の整理係と、宣言したツールには付けない

- 夜の記憶の整理係（ADR 0068）の `run_shell` には、`wait_seconds` も裏に回す動きも付けない。整理係は出来事を受け取らないので、知らせの届け先が無い。
  上限を過ぎたコマンドは、今と同じ扱い（止めない・読み捨てる・知らせない）のままである。
- 出力の先頭と末尾を残す形（前の節）は runner の持ち方なので、整理係の `run_shell` にも効く。
- 設定で宣言したツール（[ADR 0075](0075-tools-declared-in-the-config.md)）の動き（時間切れで止める、結果は出力だけ）は変えない。
- なつみの `run_shell` を Codemode のスクリプトから呼ぶとき（[ADR 0066](0066-codemode-to-keep-raw-output-out-of-the-context.md)）も、同じ引数と同じ動きである。

### 本 ADR で決定しないこと

- runner との要求・答えの欄の名前、2 行目の形、`README.md` と出力のファイルの名前と書き方、印の欄の名前（委譲先: この ADR の実装の PR と、更新元 `jobs` のマニュアル）。
- 5 個の枠が埋まっているかをいつ判断するか（要求を送る時点か、裏に回る時点か）と、その数え方（委譲先: この ADR の実装の PR。どちらでも、知らせを約束できないコマンドにはそう書く）。
- ツールの説明の文面（委譲先: この ADR の実装の PR。ADR 0019 の規則に従う）。
- 古い `jobs` のディレクトリを消すこと（委譲先: ADR 0069 の「返事は消さない」と合わせ、量が問題になったときの ADR）。
- 本番に出す前に、ローカルのモデルで、裏に回った後に `ps` や `sleep` で様子を見に行かないかを試すこと（委譲先: この ADR の実装の PR の確認）。

### 置き換える既存の決定

- ADR 0019
  - 置き換え: Decision「1 コマンドの寿命と、残ったプロセス」の、応答の上限を過ぎたコマンドの出力を読み捨て続け、返さない点。
    なつみの `run_shell` では、待つ数の上限までのコマンドの出力を先頭と末尾で残し、終わったら `/sources/jobs/` に置いて知らせる。読み捨てて知らせないのは、上限を超えた分と整理係のコマンドだけになる。
  - 置き換え: 同じ節の、応答の上限まで待つ点。なつみが `wait_seconds` で上限より短く選べる。上限は「答えを返す線」のまま残す。
  - 置き換え: Decision「コマンドと出力の上限」の、runner が残す出力とモデルに返す出力を先頭から取る点。先頭と末尾を残す形にする。上限の大きさは変えない。
  - 置き換え: Decision「ツールの説明と prefix cache」の説明に書く項目のうち「長い処理は残せること。応答が返った後もプロセスは動き続けるので、`ps` と `kill` で自分で始末すること」。
  - 残す: runner が 1 度に 1 つのコマンドを待つこと、コマンドを止めないこと、`loop.shellWaitSeconds` の決まり、ツールの説明の規則。
- ADR 0050
  - 追加: 更新元 `jobs`（深さ 1、出力のファイルを差分から外す）と、印の種類 `shell_finished`。
  - 追加: 「追記（2026-10-12）」の黙って取り込む例外の使い道に、裏に回ったコマンドのディレクトリを作った直後を加える。
- ADR 0069
  - 適用: 「外から届くものは、可能な限り `sources_updated` に寄せる」を、なつみ自身が裏に回したコマンドの終わりに適用する。新しい出来事の種類は作らない。

## Consequences

- なつみは、長くなりそうなコマンドを短い待ちや `0` で回し、待たずに本人と話したり、ほかの作業を進めたりできる。
- 裏に回したコマンドが終わると、終了コードと出力の先頭と末尾が `/sources/jobs/` に残り、知らせが届く。`ps` を打ちに行く必要がなくなる。
- 長い出力でも末尾が残るので、ふつうの `run_shell` でもエラーや最後の集計を読み落としにくくなる。その代わり、出力の中ほどは、先頭だけを残していた今より短くなる。
- 終了コードで終わった裏のコマンドは、夜でもなつみを起こす。夜に終わる長い処理を回せば、夜にターンが走る。
- シグナルで終わったものと 24 時間の知らせは、ふつうの更新の待ちの後になる。awake hours の外なら朝まで知らされない。
- サーバーだけが落ちると、裏のコマンドの結果は失われる。起動したときに「待てなくなった」とは書くが、コマンドが動き続けていれば、その結果は残らない。
- 5 個を超えて裏に回したコマンドと、整理係のコマンドは、今と同じく終わっても知らされない。結果の文でそう伝える。
- 24 時間を過ぎても、プロセスは止めない。終わらないコマンドの始末は、今と同じくなつみと夜の棚卸しに残る。
- runner はつないだままの接続ごとに、裏のコマンドの出力（最大で `-max-output` の 2 倍）を持ち続ける。5 個までなので、作業環境のメモリの上限に対して小さい。
- 裏に回った後に、モデルが `ps` や `sleep` で様子を見に行くと、ターンが延びて待たない利点が消える。結果の文で抑えるが、モデルによっては効かない。
- `jobs` のディレクトリを消さないので、`/sources/jobs` は少しずつ増える。

## Alternatives Considered

- **裏で動かす別のツール `bg_run` を足す**: なつみは、コマンドを回す前に、それが長いかどうかを読んでツールを選ぶことになる。読み違えると、短いコマンドを裏に回して知らせを待つか、長いコマンドで止まる。
  `run_shell` の待ち時間にすれば、短いものは今どおり結果が返り、長いものだけが裏に回る。ツールの数も増えず、振る舞いは 1 つで済む。`wait_seconds: 0` で `bg_run` と同じことができる。
- **`run_shell` の上限を過ぎたら自動で裏に回すだけにする（待ち時間の引数を足さない）**: 終わりは知らされるようになるが、待つのは毎回上限の 60 秒で、なつみが待たずに済ませる手段が無い。
  考えられない時間を減らすという困りごとの片方が残る。
- **runner に裏のコマンドの状態を持たせ、サーバーが後から取りに行く**: サーバーだけが落ちても結果を取れるが、runner に一覧と保存の寿命を持たせることになる。
  サーバーのコンテナだけが再起動する場合にしか効かず、リリースや Pod の再起動ではコマンドも落ちるので、得るものが少ない。
- **終わりを専用の出来事で知らせる**: 出来事の種類と system prompt が増える。ADR 0069 の方針どおり、`/sources` と `sources_updated` で足りる。
- **待つ数に上限を付けず、24 時間だけで抑える**: 短い間に大量に裏に回すと、つないだままの接続と runner が持つ出力が際限なく増える。
