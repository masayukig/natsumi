# 0064. 自分で予約した確認を、本人がダッシュボードで見て 1 件ずつ取り消す

- Date: 2026-09-30
- Status: Accepted

## Context

[ADR 0063](0063-repeating-self-checks-without-limits.md) で、natsumi が自分で予約する確認（self-check）の上限をすべてなくし、cron 式で繰り返せるようにした。
サーバーは予約の暴走を止めない。止めるのは本人であり、その手段としてダッシュボードで予約を見て消せるようにする、と決めていた（grill-me の Q2・Q5）。

手元の事情は次のとおりである。

- ダッシュボード（[ADR 0049](0049-a-read-only-dashboard-in-the-browser.md)）は読み取り専用で、サーバーが HTML を組む。状態を変える操作は、ログアウトの POST（Origin を照合する）だけである。
  「失敗と待ち」の節に、待っている予約の一覧（予定・理由・予約した時刻）がすでにある。
- [ADR 0058](0058-settings-and-chat-in-the-browser.md) は、ブラウザから状態を変える口を開けた。設定と承認は `/`・`/settings` の画面から WebSocket のコマンドで変え、ダッシュボードの中は読み取り専用のまま保つ、とした。
  守りは、cookie `natsumi_session`（`HttpOnly`・`SameSite=Strict`）、Origin が `publicOrigin` と一致することの照合、画面の側での押し間違いの確認である。
- 予約を途中で終わらせる処理は、natsumi のツール `cancel_self_check` が使う `SelfChecks.cancel` の 1 つだけである。予約を消さず、状態を「取り消し」にする。
- 予約の件数に上限はないので、暴走すれば待っている予約は何百件にもなりうる。

## Decision

### 置き場所はダッシュボードの新しいページ「予約」

- ダッシュボードに「予約」のページ（`/dashboard/checks`）を足し、ナビゲーションの「失敗と待ち」の次に置く。
- 待っている予約（`state = 'pending'`）だけを、次の時刻の近い順に 50 件ずつ並べる。取り消したものと、届いた一回きりのものは出さない。
- 1 件ごとに次を出す。
  - 種類: 繰り返しなら cron 式、そうでなければ「一回きり」
  - 次の時刻: 本人のタイムゾーン（`loop.timeZone`）で出す。繰り返しは、次に届く回の時刻である。
  - 理由
  - check_id
  - 予約した時刻
- 並べ方は `list_self_checks` と同じにする。本人となつみが同じ順で予約を見られる。
- このページは自動更新しない。押そうとしている行が、更新で動かないようにするためである。
- 「失敗と待ち」の節の一覧は残す。繰り返しの列を足し、ほかの一覧と同じく近いものから 20 件に絞り、「予約」のページへのリンクを置く。

退けた案:

- **`/settings` の画面に置き、WebSocket のコマンド（`self_check.list`・`self_check.cancel` など）で読み書きする**: ADR 0058 の作り方にはそろう。後で Mac や iPhone から同じコマンドを使えるという利点もある。
  ただし、クライアントの契約、偽のサーバー、ブラウザのアプリ、Playwright のテストまで手を入れることになる。
  一方、予約の一覧はダッシュボードにすでにあり、欲しいのは暴走を止めるための削除だけである。
  アプリからも取り消したくなったら、そのときにコマンドを足せばよい。取り消しの処理は同じ `SelfChecks.cancel` を通せる。
- **「失敗と待ち」の節の一覧に削除のボタンを置く**: この節は 10 秒ごとに作り直されるので、押す直前に行が入れ替わりうる。また 20 件で切っているので、暴走したときに全部を見られない。

### 取り消しは、確認のページを通した POST にする

- 一覧の各行の「削除…」は、その予約のページ（`GET /dashboard/checks/<check_id>`）へのリンクである。このページは予約の中身を出し、「この予約を削除しますか」と尋ねる。
  - 繰り返しの予約では、この先の回もすべて届かなくなると書き添える。
  - 開いただけでは何も変わらない。
  - 待っている予約でなければ 404 を返す。
- そのページのフォームが `POST /dashboard/checks/<check_id>/cancel` を送る。「やめる」は一覧に戻るリンクである。
- 確認をページ 1 枚にしたのは、ダッシュボードの CSP（inline の script を許さない）のまま JS を足さずに済み、サーバー側のテストで確かめられるからである。
- 取り消せるのは 1 件ずつである。まとめて消す操作は置かない。
  暴走した予約は同じ繰り返し 1 件であることが多く、1 件を止めれば済む。何百件の一回きりが入った場合は手間がかかるが、それが起きてから考える。

### 書き込みの守りは、ADR 0058 とログアウトにそろえる

- 認証: `natsumi_session` の cookie で、`allowedUserId` の生きているセッションだけを受け付ける。
  セッションが無いか切れていれば 403 で断り、ログインは始めない。POST の中身を GitHub のログインの先まで持ち越さないためである。
- CSRF: Origin ヘッダーが `publicOrigin` と一致することを照合し、`SameSite=Strict` と合わせて防ぐ。Origin が無いか一致しない POST は 403 で断る。これは ADR 0049 のログアウトと、ADR 0058 の WebSocket の照合と同じ規則である。
- 方法: 取り消しの口は POST だけを受ける。GET には 405 を返す。ダッシュボードのほかのパスへの POST も、これまでどおり 405 である。
- 確認: 押し間違いの確認は画面の側で持つ（ADR 0058 と同じ）。上の確認のページがそれに当たる。
- 結果:
  - 取り消せたら、303 で一覧（`/dashboard/checks?cancelled=<check_id>`）に戻り、「予約 … を削除しました」と出す。
  - すでに待っていない予約（取り消し済み、届いた一回きり）なら、409 と `SelfChecks.cancel` の文を返す。二重に取り消しても何も起きない。

ADR 0058 との違いは、口が WebSocket のコマンドではなくフォームの POST であることだけである。前例はダッシュボードのログアウトにある。

### 取り消しは、natsumi の `cancel_self_check` と同じ処理を通す

- ダッシュボードは、思考ループが持つ `SelfChecks` の `cancel` を、狭い口（`DashboardLoop.cancelSelfCheck`）から呼ぶ。SQL を別に書くことはしない。
- 予約の行は消さず、状態を「取り消し」にして更新時刻を記録する。natsumi が取り消したときと同じ記録になる。
- 取り消しは SQLite の 1 回の更新なので、ターンの最中に行っても、思考ループを待たずに済む。
  スケジューラーは次の見回りで、その予約を拾わなくなる。すでにイベントに載って届いた回は取り消せない。

### natsumi には知らせない

- 本人が取り消したことを、natsumi へのイベントにはしない。
- natsumi が次に `list_self_checks` を呼べば、その予約は一覧から消えている。同じ check_id を `cancel_self_check` すると「待っている予約ではありません」と返る。
- 暴走を止めるのが目的なので、止めたことを伝えてすぐ予約し直されるより、黙って止まる方がよい。これを既定とする。

## ADR との関係

- ADR 0049
  - 改める: 「ダッシュボードは読み取り専用」の例外に、ログアウトに加えて、予約の取り消しの POST を加える。守りはログアウトと同じ（Origin の照合と `SameSite=Strict`）で、生きているセッションを必須とする。
  - 追加: 画面に並べるものに「予約」のページを加える。
  - 保つ: 画面はサーバーで HTML を組み、JS は自動更新の小さなファイルだけにする。CSP は変えない。
- ADR 0058
  - 改める: 「ダッシュボードの中は読み取り専用のまま」を、予約の取り消しを除いて、と読み替える。
  - 保つ: 設定と承認は `/`・`/settings` から WebSocket で変える。cookie、Origin の照合、画面の側での確認は同じ規則を使う。
- ADR 0063
  - 追加: 「止めるのは本人（ダッシュボードで消す）」の、ダッシュボードの側の作り。
  - 保つ: 取り消しは `cancel_self_check` と同じ処理である。予約の規則（cron、上限なし、時間帯の外の回）は変えない。

## Consequences

- 本人は、natsumi が入れた予約をすべて見て、暴走した予約を 1 件ずつ止められる。繰り返しの予約は cron 式で見分けられる。
- ダッシュボードに、状態を変える口が 1 つ増える。
  守りは、GitHub ログインと許可ユーザー 1 人の照合、`HttpOnly`・`SameSite=Strict` の cookie、Origin の照合、確認のページである。
  [権限と秘密の一覧](../permissions.md)に口を足した。
- ダッシュボードでできる変更は、ログアウトと予約の取り消しの 2 つになる。これ以上増やすときは、ADR 0058 の WebSocket のコマンドに寄せるか、改めて決める。
- natsumi は、本人が取り消したことを一覧を見るまで知らない。
  「毎日 16 時に確かめるね」と本人に約束した予約が消えていても、自分からは気づかない。本人が取り消すのは暴走したときなので、これを受け入れる。
  気づかないことが困る使い方が出てきたら、取り消しをイベントで知らせることを改めて決める。
- 一回きりの予約が何百件も入ったときは、1 件ずつ消すしかない。
