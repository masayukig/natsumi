# 0080. 外のエージェントに頼むとき、作業環境のファイルを中身ごと渡す

- Date: 2026-10-14
- Status: Accepted

## Context

なつみは `ask_agent` で外のエージェントに頼める（[ADR 0035](0035-asking-outside-agents-and-hearing-back.md)）。
引数は `agent`・`message`・`continue` の 3 つで、相手に渡せるのは文面だけである。
相手が返すファイルは受け取れる（[ADR 0048](0048-bringing-in-images-an-agent-hands-back.md)・[ADR 0069](0069-agent-replies-as-files-in-sources.md)）が、こちらから渡す道は無かった。

本人がチャットに添えた PDF（[ADR 0071](0071-attaching-files-to-a-chat-message.md)。`/sources/uploads/` の下）を係に読ませたい、
なつみが `/work` に作ったファイルを係に渡したい、という用途が出てきた。今は中身を文面に貼るしかなく、PDF や画像は渡せない。

手元の事情は次のとおりである。

- 外のエージェントがなつみのサーバーからファイルを取りに来る口は無い。サーバーが配るファイルは、本人の端末とダッシュボードに向けたものである。
  外のエージェントへの呼び出しは、いつもなつみのサーバーから出ていく（[ADR 0025](0025-talking-to-outside-agents-over-a2a.md)）。
- A2A 1.0 の Part は、ファイルを URL（`url`）か中身そのもの（`raw`。JSON では base64）で運べる。どちらも `filename` と `mediaType` を持つ。
- 作業環境のファイルを、パスを確かめてからサーバーが読む部品はすでにある。`view`（[ADR 0039](0039-slack-as-files-and-a-scored-dove.md)）は `/sources` と `/work` の下だけを読み、
  リンクや `..` で外に出るものは外として断る。画像の受け取り（[ADR 0044](0044-drawing-with-sdctl-and-posting-images.md)）も同じ形である。
- ツールの定義は prefix cache に載る。変えると、変えた直後に一度だけ cache が外れる（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
- 受け手の `yuanying/fraction-agents` の汎用ホストは、0.7 までは文面の無いメッセージを断り、ファイルの Part を黙って捨てる。
  加えて、本文の JSON を SDK の既定（100 KB）までしか受け付けないので、大きなファイルを付けた依頼は HTTP 413 で断られる。
  natsumi からは、それは「つながらない」と見分けがつかない。
  ファイルを受け取る側の変更は、ホストの側で別に行う。受け取れるホストは Agent Card の `defaultInputModes` に `["text/plain", "*/*"]` を出す。
- ホストは、聞き返し（`INPUT_REQUIRED`）への答えに付いたファイルを置かない。答えとして読むのは文面だけである。
- SendMessage の応答の Task は、既定で history を含む。history には送ったメッセージが、ファイルの中身ごと入る。

## Decision

### `ask_agent` に省ける引数 `files` を足す

- 値は作業環境のパスの配列である。モデルが見ているとおりのパス（`/work/…`・`/sources/…`）を書く。
- 引数の並びの最後に、省ける引数として足す。前の 3 つの定義はそのままである。
- ツールの説明には、`files` が省けること、置き場所、大きさと数に上限があること、受け取れない相手もいること、詳しくは `/manual/ask-agent.md` にあることだけを書く。
  `ask_agent` の説明には今まで数字が無く、テストもそれを確かめている。そのままにして、上限の数字は手引きと、当たったときの結果の文で伝える。
- ポッポさん（[ADR 0074](0074-asking-poppo-in-json-and-hearing-back-in-sources.md)）には `files` を渡せない。渡すと頼まずに断り、画像は JSON の `images` に書くよう返す。

### 中身を送る。URL は送らない

- サーバーがファイルを読み、文面の Part の後ろに、ファイルごとに Part を 1 つ並べる。Part は中身そのもの（`raw`）と、
  `filename`（パスの最後の部分）と `mediaType` を持つ。A2A 1.0 の JSON では `{ "raw": "<base64>", "filename": "…", "mediaType": "…" }` と書かれる。
- URL にしない理由は、相手がなつみのサーバーからファイルを取れないからである。取れるようにするには、外のエージェント向けにファイルを配る口と、
  その認証を新しく作ることになる。中身を送れば、受け渡しは 1 回の呼び出しで済み、送った時点の中身が渡る。
- 文面は省けない。今までどおり `message` が 1 つ目の Part になる。

### 読めるのは `/work` と `/sources` の下だけ

- `view` と同じ規則で読む。`/work/` か `/sources/` から始まるパスだけを、data directory の `work/`・`sources/` に写して読み、
  実際のパス（リンクをたどった先）がその場所の中にあることを確かめる。外を指すリンク・`..`・場所そのものは、外として断る。どこを指していたかは書かない。
- `/memory` は読まない。記憶のファイルを渡したいときは、なつみが `/work` に写してから渡す。外へ出る記憶を、なつみが一度手で選ぶことになる。
- `mediaType` は中身で見分ける。PDF・ZIP・gzip・SQLite は先頭のバイト、画像は PNG・JPEG・GIF・WebP の先頭のバイト（ダッシュボードと同じ部品。[ADR 0054](0054-her-files-on-the-dashboard.md)）で見る。
  UTF-8 として読める文字は `text/plain` で、拡張子が `.md`・`.csv`・`.json`・`.html` のものはそれに合わせる。どれでもなければ `application/octet-stream` とする。

### 上限は相手との契約の値

- 1 個 20 MiB まで、1 回に 8 個まで、合わせて 50 MiB までとする。fraction-agents のホストが受け付ける上限と同じで、設定には出さない。
  ホストは合計を超えた依頼を REJECTED にし、JSON の本文が約 68 MiB を超えると HTTP 413 で断る。合計 50 MiB は base64 にして約 67 MiB で、本文の上限に収まる。
  こちらで先に断れば、送ってから断られるより早く、なつみに直し方を返せる。
- 大きさは開いたときの大きさで断り、読んだ後にもう一度数える（読む間に大きくなることがあるため）。合計も、それまでに読んだ分に足して同じように数える。

### 1 つでも渡せなければ、何も頼まない

- 置き場所の外・無い・ファイルでない・大きすぎる・数が多すぎる・合わせて大きすぎる、のどれかが 1 つでもあれば、依頼のディレクトリも作らず、相手にも送らずに、ツールの結果で直し方を返す。
  ファイルの一部だけが届いた依頼にしないためである（ADR 0045 の画像と同じ考え方）。
- ファイルは、依頼のディレクトリを作る前、文面の検査の後に読む。
- 聞き返しへの答え（`continue` が真で、相手が `INPUT_REQUIRED` のとき）には `files` を付けられない。付けると頼まずに断り、
  答えは `files` なしで送り、ファイルは `continue` を偽にして新しく頼むよう返す。ホストが置かないファイルを、送ったことにしないためである。

### 渡したことは `request.md` に書く

- 依頼の `request.md`（ADR 0069）に「送ったファイル」の行を足し、なつみが書いたパスを並べる。ファイルの無い依頼には行を置かない。
- `agent_tasks` には足さない。依頼の記録は `request.md` にあり、表の形を変える migration は要らない。
- 中身の写しは残さない。`/work` のファイルは後で変わりうるので、何を送ったかの記録はパスまでである。

### 受け手が読めること

- ファイルを付けた依頼は、相手の Agent Card の `defaultInputModes` に `text/plain` 以外（`*/*` か具体的な型）があるときだけ送る。
  無い相手、カードを取れない相手には送らずに断り、`files` を外して頼むよう返す。
  - 古いホストに送ると、小さなファイルは黙って捨てられ、大きなファイルは 413 で断られて「つながらない」に見える。どちらも、なつみには理由が分からない。
  - カードは、返事の拡張（ADR 0069）を見るために読んだものを使う。読めなかった相手は、頼むときに読み直す。
  - 確かめるのは送る直前で、依頼のディレクトリは作った後に消す。何も送らないことは、ほかの送れなかった依頼と同じである。
- 送るときは `historyLength: 0` を付け、応答に history を返させない。history は送ったメッセージそのもので、ファイルの中身ごと戻ってくる。
  natsumi は応答と GetTask の history を読んでいない（状態の文面と artifact だけを読む）。

### ADR との関係

- ADR 0035
  - 追加: `ask_agent` の省ける引数 `files`。
- ADR 0069
  - 追加: `request.md` の「送ったファイル」の行。

## Consequences

- なつみは、本人がチャットに添えた PDF や、自分で作ったファイルを、係にそのまま渡せる。モデルに URL や token を扱わせずに済む。
- ツールの定義が変わるので、反映した直後の最初のモデル呼び出しで prefix cache が一度外れる。その後はまた載る。
- 1 回の依頼で最大 50 MiB（base64 で約 67 MiB）を、サーバーがメモリに読んで送る。呼び出しの時間の上限（30 秒）は変えていない。
  大きなファイルを遅い相手に送ると、上限に当たって「つながらない」と返ることがある。
- 外へ出るのは、なつみが `files` に並べたファイルだけである。`/sources` には Slack やチャットで届いたものも入るので、
  なつみがそれを並べれば、その中身は相手の URL に送られる。送り先は設定の `a2a.agents` の URL に限られる。
- 古いホストの相手には、ファイル付きの依頼は送られない。なつみは断りの文を読んで、`files` を外して頼み直す。
  受け取れるホストでも、カードの `defaultInputModes` に `text/plain` しか出していなければ、同じく断る。
