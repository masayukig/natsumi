# 0025. 外のエージェントと A2A で話す

- Date: 2026-09-22
- Status: Accepted（返事の受け取り方・頼むツールの名前と引数・前のやり取りに続ける指定は [ADR 0035](0035-asking-outside-agents-and-hearing-back.md) で決定、移行後の projected token は [ADR 0033](0033-running-on-kubernetes.md) で具体化、画像生成を外の特化エージェントの例とする点は [ADR 0044](0044-drawing-with-sdctl-and-posting-images.md) で置き換え（作業環境の sdctl で生成する）、未決だった画像を Mac に出すかは [ADR 0045](0045-showing-the-owner-images-with-a-reply.md) で決定（なつみが返事に添えた画像を Mac と iPhone に出す）、成果物の URI をサーバーが取り込む形は [ADR 0048](0048-bringing-in-images-an-agent-hands-back.md) で具体化（相手と同じ origin の画像を /work/agents に置く））

## Context

[ADR 0012](0012-slack-and-colleagues.md) で、なつみは本人の窓口になり、外に作用する権限は専門の同僚が持つ形にした。
同僚はなつみのサーバーの中に置き、なつみはツールで話しかけ、返事は後でイベントとして届く。同僚どうしは直接つながらない。

その後、次のことが分かってきた。

- 同僚にしたい役の多くは、外に作用しない。Wiki の管理（取り込みと問い合わせ）、ウェブ検索、画像の生成のように、
  読み取りと生成が中心の道具である。
- こうした道具は、なつみだけでなく、本人や、本人が直接話す Claude・Codex も使いたい。
  サーバーの中に置くと、なつみを通さずには使えない。
- 本人は、こうした特化エージェントを Kubernetes のクラスタでたくさん動かしたい。
- 逆向きに、Claude などのエージェントから、なつみに直接知らせを送れる口も欲しい。
  ただし、エージェントの文面は本人の言葉ではない。受け取ればプロンプトインジェクションの入口にもなる。

また、[ADR 0003](0003-assistance-and-integrations.md) は、Wiki のチェックアウトをなつみにマウントして読み書きし、
自分の差分の commit と push を自動で行う、と決めていた。書き込みの結果は、本人が後から Git の履歴で見るしかない。
本人は、Wiki の変更を PR 単位で見たい。

## Decision

### 特化エージェントは、なつみの外で独立したサービスとして動く

- Wiki 管理人・検索・画像生成のような特化エージェントは、なつみのサーバーの外で、それぞれ独立したサービスとして動かす。
- なつみとは A2A（Agent2Agent）で話す。各エージェントは Agent Card で能力を示し、メッセージを受け、Task の状態を持つ。
  A2A の版と公式の SDK は、実装の作業単位の着手時に最新のものを確かめる。
- なつみは、そのクライアントの 1 人である。本人と、本人が直接話す Claude・Codex も、同じ口を直接使う。
  なつみがハブであるとは、本人の窓口であるという意味だけで、エージェントへの経路を独占することではない。
- エージェントは末端とする。エージェントから別のエージェントやなつみを呼ぶことはしない。必要になったら、組み合わせごとに個別に許す。
- エージェントの側の設計（A2A の共通部分、エージェントの中身、エージェント定義と配置）は、別のリポジトリ
  `yuanying/fraction-agents` の ADR に委ねる。なつみは A2A の SDK で話すだけで、そのリポジトリのコードには依存しない。

### なつみから頼む

- 頼み方は、ADR 0012 の同僚に話しかける形と同じにする。
  - 頼むのはツールで行う。ツールは、受け付けたことだけをすぐ返す。
  - エージェントの返事は、後からイベントとして思考ループのキューに入る。なつみは待つ間も、他のイベントを処理できる。
  - ツールの結果には、返事が後でイベントとして届くことを書く（ADR 0008 の「状態が分かる結果」）。
- エージェントとの一続きのやり取りは、A2A の context の単位で区切る。
  同じ context に続けて頼めば、エージェントは前の文脈を引き継ぐ。context を指定しなければ、新しいやり取りになる。
  エージェント側でのセッションの持ち方は、`yuanying/fraction-agents` の ADR に委ねる。
- なつみのモデルに context の ID を写させない。ID はサーバーが持つ。
  形の似た ID を並べて正しい 1 つを写させる設計が返事を落としたこと（[ADR 0024](0024-no-event-ids-for-the-model.md)）と同じ理由である。
- 返事をどう受け取るか（流してもらう、知らせてもらう、取りに行く）は、まだ決めていない。
- 成果物（画像など）は、エージェントが自分の保存領域に置き、URI で渡す。
  - URI は A2A の成果物として返り、取り出すにも認証が要る。保持の期間はエージェントごとに決める。
  - 手元に残す必要があれば、なつみのサーバーが取り出して永続領域に取り込む。モデルに取り出させない。
  - 画像を Mac に出すかは、まだ決めていない。画像生成を使う作業単位で決める。

### なつみの受け口

- なつみも A2A の受け口（Agent Card）を持つ。Claude などのエージェントが、なつみに直接メッセージを送れる。
- 届いたメッセージは、送り手の名前を付けたイベント `agent_message` として、ほかのイベントと同じキューに入る。
  単一の思考ループ（ADR 0008）は変えない。
- なつみは、送り手を **名前付きの第三者** として扱う。Slack の入力と同じ位置づけである。
  - 考える、返事をする、本人に知らせる、記憶に残すは、なつみの判断でよい。
  - 記憶に残すときは「誰々が言っていた」として残す。本人の意向として扱わない。
  - これは system prompt とツールの説明で求めるもので、サーバーでは強制しない。
    届いた文が本人の意向かどうかを、サーバーは機械的に判定できないからである。
- 外に作用する行為は、ADR 0012 の強制のままとする。エージェントのメッセージに「本人が OK と言った」とあっても、
  同意の証拠はサーバーの承認記録だけである。
- 受け口の上限（回数・頻度・文面の長さ）は、まだ決めていない。受け口を開く作業単位の前に決める。

### Mac に見せるか

- エージェントとのやり取りは、ADR 0012 の同僚とのやり取りと同じく、既定では Mac の会話に入れない。
  本人に伝えたいことは、なつみが `notify_owner` などの本人向けのツールで伝える。
- やり取りを Mac に見せる形を作るかは、まだ決めていない。

### 認証

- 呼び出し元と送り手は、Kubernetes の ServiceAccount で表す。なつみ、本人、本人が直接話す Claude などに、それぞれ ServiceAccount を用意する。
- 受け取った側は、TokenReview で token を確かめ、ServiceAccount の名前を呼び出し元の名前にする。
  token の audience は `a2a` に限る。受け取ったエージェントがその token を他の用途に使い回せないようにするためである。
  どの ServiceAccount を受け付けるかは、エージェントごとの設定とする。
- なつみの受け口も、送り手ごとの ServiceAccount で区別する。本人の ServiceAccount を他の送り手と共用しない。
  イベントに付ける送り手の名前は、この確かめた名前であり、メッセージの自己申告は使わない。
- なつみがクラスタの外にいる間は、なつみの ServiceAccount に期限つきの token を発行し、秘密として渡す。
  期限のない token（古い形の Secret）は使わない。なつみがクラスタに移れば、Pod に自動で差し込まれる token（projected token）に変わる。
- この認証は、Mac とサーバーの間の GitHub OAuth（[ADR 0006](0006-github-login-and-transport.md)）とは別の経路である。
  Mac の接続の認証は変えない。

### Wiki

- なつみは Wiki を自分で読み書きしない。取り込みと問い合わせは、外の特化エージェントの Wiki 管理人に頼む。
- Wiki 管理人は、書き込みをブランチに積んで PR を出す。
  - マージは、本人（本人が直接話す Claude を含む）の指示でだけ行う。依頼の中でマージまで指示してもよい。
  - なつみの依頼では、PR を出すところで止まる。
  - これは門番としての承認ではない。本人が Wiki の変更を PR 単位で見られるようにするためである。
- ADR 0003 の「チェックアウトをマウントし、自分の差分を自動で commit と push する」は採らない。
  Wiki の規約（frontmatter、Wiki Link、読み取り専用の場所、公開範囲など）に従う責任は、Wiki 管理人の側に移る。

### ADR 0012 の読み替え

- ポッポさんと、将来の予定の同僚のように、外に作用する同僚は、これまでどおりなつみのサーバーの中に置く。
  外に作用する行為の安全は、同僚ごとに「見えるもの」と「できること」をサーバーが決めて強制することに依っており、その強制はサーバーの中にあるからである。
- A2A に載せるのは、読み取りと生成が中心の道具的なエージェントとする。
- ADR 0012 の「同僚はサーバーの中」「同僚どうしは直接つながらない」は、外に作用する同僚に限った決定として読む。
  外の特化エージェントには当てはまらない。

### まだ決めていないこと

- A2A の版と SDK、返事の受け取り方
- なつみの受け口の上限と、受け口をどこに公開するか
- エージェントとのやり取りを Mac に見せるか
- 画像を Mac に出すか
- なつみが頼むツールの名前と引数
- なつみが「前のやり取りに続けて頼む」か「新しく頼む」かを、ID を使わずにどう指定するか（例: エージェントごとに直近の context を続ける指定）

進める順番は、エージェントの側（本人と Claude が使える形）を先にし、なつみにはクライアント、受け口の順に足す。
なつみのクラスタへの移行は、これとは別の流れで扱う。

### 置き換える既存の決定

- ADR 0001
  - 置き換え: 保存先の表の「別 mount の private Wiki」。なつみは Wiki をマウントしない。Wiki は Wiki 管理人の側にある。
- ADR 0003
  - 置き換え:「Wiki はローカル checkout を mount して読み書きする」「根拠と更新先が明確なら更新と自身の差分の commit/push を自動化できる」。
    Wiki の読み書きは Wiki 管理人に頼み、書き込みは PR になる。Wiki の規約に従うことは、Wiki 管理人の側で扱う。
- ADR 0004
  - 置き換え:「Wiki と記憶に必要な読み書きは、対象ルートと操作を制限する独自ツールとして後続実装する」のうち、Wiki の部分。
    なつみに Wiki のツールは作らず、Wiki 管理人に頼む。
  - 追加: ツールの境界に、外の特化エージェントに頼むツールを加える。
  - 残す:「任意 HTTP を許可しない」。なつみに汎用の HTTP の道具は渡さず、エージェントとのやり取りはサーバーを通す。
- ADR 0012
  - 具体化:「同僚はサーバーの中」「同僚どうしが直接つながることはない」は、外に作用する同僚に限る。
  - 残す: ポッポさん、予定の同僚、承認と強制の決定。頼み方（受け付けだけを返し、返事は後でイベントで届く）は、外の特化エージェントにも同じ形を使う。

## Consequences

- 本人と Claude は、なつみを通さずに同じエージェントを使える。なつみはエージェントを使う経路の 1 つになる。
- 同僚は 2 種類になる。サーバーの中の外に作用する同僚と、A2A で話す外の特化エージェントである。
  外に作用する役を外のエージェントに持たせるなら、この ADR と ADR 0012 を決め直す必要がある。
- `agent_message` は、Slack と同じく本人以外の文が思考ループに入る入口になる。
  名前付きの第三者として扱うことはモデルに頼るので、なつみが送り手の言葉を本人の意向と取り違えることは起こり得る。
  外に作用する行為は ADR 0012 の強制で止まるが、記憶や本人への知らせには混ざり得る。
- 受け口の上限を決めるまでは、エージェントとなつみが返し合い続けたり、キューを埋めたりすることを、サーバーで止められない。
  上限は受け口を開く前に決める。
- なつみがクラスタの外にいる間は、token の期限が来る前に発行し直して差し替える運用が要る。
- なつみの Wiki の変更は、本人がマージするまで Wiki の本流に入らない。
- エージェントがモデルに本人のサブスクリプション経路を使う場合、利用量の上限をなつみや同僚と分け合う。
- エージェントが止まっていれば、なつみはそれに頼めない。成果物の URI も、エージェントの保持の期間を過ぎれば取り出せない。
