# 0021. 入力欄と履歴を 1 つのウインドウにする

- Date: 2026-09-21
- Status: Accepted（§5 の「開いても既読にしない」は [ADR 0022](0022-only-her-last-line-in-the-balloon.md) で置き換え。§2 の層・Space・全画面の扱いは [ADR 0078](0078-the-conversation-window-and-the-settings-as-ordinary-windows.md) で置き換え）

## Context

[ADR 0010](0010-mac-app-structure.md) は、話しかける入力欄と、会話を読み返す履歴を、別のものとして決めた。

- **入力欄**は、キャラクターのクリックで下に開く枠のない紙色のパネルで、一列の一番下に入る。Esc・もう一度の
  クリック・ほかのアプリのクリックで閉じ、右下のつまみで幅と高さを変える。時計のボタンで履歴を開く。
- **履歴**は、タイトルバーのあるウインドウで、一列の横の空いている側に開く。送信欄はない。

[ADR 0016](0016-opening-a-card-and-moving-the-character.md) は、この 2 つを舞台に入れずに自分のウインドウのままとし、
入力欄は舞台の子ウインドウとして配置の計算で追わせ、履歴は移動が終わってから置き直すことにした。
入力欄が開いている間はキャラクターがどかないこと、ほかのアプリのクリックを見張ることも、同じ ADR にある。

使ってみると、**話しかけることと読み返すことが 2 つのウインドウに分かれている**のが不便だった。返事を読んでから
続きを書くには、履歴を開いたまま入力欄も開くことになり、キャラクターの下と横に 2 枚が出る。入力欄から履歴へは
時計のボタンで行けるが、履歴から入力欄へは戻れない。

利用者から、**入力欄を廃止して履歴と統合する**指示が出た。キャラクターをクリックすると入力のウインドウが出る
ことは変えず、そのウインドウの上部のボタンで履歴が上下に開く、という形である（手描きのスケッチ: 畳んだ状態は
タイトルバーと「話しかける」の欄だけ、開くと履歴の行が入力欄の上に並び、右上のボタンがひらく⇔とじるになる、
開くときはアニメーションで伸びる）。

## Decision

### 1. 1 つのウインドウにする

入力欄のパネルと履歴のウインドウを廃し、**「会話のウインドウ」を 1 つ**にする。中身は下から、入力欄、履歴の行、
接続の状態の行である。履歴の部分は**畳める**。

- **畳んだ状態**: タイトルバー、接続の状態の行、入力欄。今の入力欄に当たる。
- **開いた状態**: タイトルバー、接続の状態の行、履歴の行（スクロール）、入力欄。今の履歴に入力欄が付いた形である。

ひらく⇔とじるは、**ウインドウの右上（タイトルバーのすぐ下）のボタン**と、**Cmd+L** で切り替える。「とじる」は
履歴を畳むだけで、ウインドウは消えない。

### 2. タイトルバーのある通常のウインドウにする

今の履歴と同じ、**タイトルバーと閉じるボタンのあるサイズ変更のできるウインドウ**（`.titled`・`.closable`・
`.resizable`。最小化と拡大のボタンは置かない）にする。層・Space・全画面の扱い、アプリを前面にしない
`.nonactivatingPanel`、key になれること、最初のクリックで効くことは、今の履歴のパネルと同じである。

タイトルバーのあるウインドウは AppKit が画面の中に押し戻し、子ウインドウにすると親まで動いてしまう
（ADR 0010）。そのため、**このウインドウは舞台の子ウインドウにせず、一列にも入れず、キャラクターを追わない。**
利用者は「キャラクターとの位置の追従は不要」と決めた。

- **出る場所**: 前回消したときの枠を覚えておき、次はそこに出す。覚えていない初回だけ、キャラクターの真下に出す
  （今の入力欄が出る場所）。ウインドウのある画面が無くなっていれば、AppKit が押し戻した場所でよい。
- **大きさ**: 畳んだ状態と開いた状態で**高さを別々に**覚える。幅は 2 つの状態で共通で、どちらの状態で変えても
  同じ幅になる（幅まで切り替わると開閉のアニメーションが不自然になる）。どちらの状態でも利用者は自由に
  サイズを変えられる。畳んだ状態で高さを増やせば、最初から何行分もある入力欄になる。
  ADR 0010 の**右下のつまみは廃止**し、ウインドウの縁でサイズを変える。今まで保存していた入力欄の幅と高さは、
  初回だけ幅と畳んだ高さとして読み替える。
- **開いた状態の記憶**: 開いた状態か畳んだ状態かも覚える。開いたまま消せば、次にキャラクターをクリックしたときも
  開いた状態で出る。
- **文字の大きさ**は、キャラクターの倍率に連動しない。今の履歴と同じ固定の大きさである（ウインドウがキャラクターの
  そばに無いので、そろえる意味がない）。

### 3. 開くとき、上下に伸びる

畳んだ状態から開くとき、ウインドウは**上下に均等に**伸びる。畳んだウインドウの縦の中心を保ち、上辺は上へ、
下辺は下へ、開いた高さになるまで動く。**片側に余裕が無ければ、足りない分だけ余裕のある側に余計に伸びる。**
両側とも足りなければ、画面の見える範囲いっぱいにする。

畳むときは、**開く前に畳んで置いてあった場所に戻す。** 片側にはみ出して伸びた分を中心を保って縮めると、
開閉のたびに畳んだ位置がずれていくためである。ただし、**開いたあとにウインドウを動かした・大きさを変えたときは、
その場で上下に均等に縮める**（本人が置き直した場所のほうが、開く前の場所より新しい）。そのために、開いた
ウインドウは「開く前の位置」と「開いた直後の枠」を覚えておき、畳むときの枠が開いた直後の枠のままなら前者へ戻す。

どこに置くかの計算は `NatsumiCore` の純粋関数にし、`OverlayLayout` と同じように UI なしでテストする
（画面の上端・下端・両端に寄せた場合、開いた高さが画面より大きい場合）。

**ウインドウの枠そのものを AppKit のアニメーションで動かす**（`NSWindow` の `animator()`、今のカードの開閉と同じ
0.25 秒・ease-in-ease-out）。これは ADR 0016 の「ウインドウの枠は動かさない。動くものは舞台の中の View」に反する。
ADR 0016 が枠のアニメーションを退けた理由は、枠と中身の同期、角で切られること、隣のカードが跳ぶこと、走りに
列がついてこないことだった。会話のウインドウはそのどれにも当たらない。1 枚きりで隣に動くものがなく、
中身は履歴のスクロール領域が伸び縮みするだけで、切られて困る絵柄も無い。したがって、**この 1 つのウインドウに
限って、枠のアニメーションを例外として認める。** 舞台の中身と他のウインドウは ADR 0016 のままである。

### 4. 開く・消す・戻す

- **キャラクターのクリック**は今までどおり**トグル**である。ウインドウが無ければ覚えている状態で出して入力欄に
  焦点を移し、あれば消す。
- **消すのは、Cmd+W とタイトルバーの閉じるボタン**である。Esc では消えない（入力欄で Esc を押しても何も起きない。
  変換中の Esc は今までどおり入力メソッドのもの）。ADR 0010 の「ほかのアプリのクリックで閉じる」は廃止し、
  グローバルなマウスのクリックの監視も止める。利用者は「アプリ外クリックで閉じる挙動は不要」と決めた。
- Cmd+W と Cmd+L は、アプリが前面でなくても効くように、**ウインドウ自身が key equivalent として受ける**
  （メニューのショートカットには頼らない。`.nonactivatingPanel` なので、ウインドウが key でもアプリは前面でない）。
- メニューバーの「話しかける」は畳んだ・開いたを問わず覚えている状態で出す。**「履歴を開く」と、吹き出しの
  「続きは履歴で」は、開いた状態で出す**（覚えている状態が畳んだ状態でも開く。消えていれば出してから開く）。
  そのとき覚えている状態も開いた状態になる。
- Enter で送り、Shift+Enter で改行し、空の下書きは送らないことは変えない。送った後もウインドウは消えない。

### 5. 中身

- **接続の状態の行は常に出す。** 今の履歴の流儀である（入力欄は問題のあるときだけ出していた）。畳んだ状態では
  入力欄の上、開いた状態では履歴の上に置き、再接続やログインのボタンも今までどおりそこに出す。
- **送れなかった送信**は、畳んだ状態では入力欄の上に赤い行で出し（今の入力欄）、開いた状態では履歴の末尾の
  「受付中」の行が失敗に変わる形で出す（今の履歴）。消すボタンはどちらにもある。
- **見た目は今の履歴に合わせる。** ウインドウの背景はシステムの色で外観に従い、履歴の行は今までどおり natsumi の
  発言を漫画の吹き出し風、本人の発言をアクセント色の箱にする。入力欄は通常の文字の欄で、紙色の箱にはしない
  （ADR 0010 の「入力欄は白地でしっぽなし」「パネルの外観をライトに固定」は、入力欄が一列の中の吹き出しの
  仲間だったからで、通常のウインドウの中では要らない）。
- 未読の返事と未確認の知らせの印、開いても既読にしないこと、「考え中」の行は、今の履歴のままである。
- 履歴の行には、いつの発言・知らせかを、吹き出しの下のその行の側に小さく薄い文字で添える。今日のものは時刻だけ
  （`14:32`）、今年のものは月日と時刻（`9/21 14:32`）、それより前は年も付ける（`2025/12/31 23:59`）。
  サーバーの `createdAt` を利用者のカレンダーで読む。今日かどうかは描くときに決めるので、日付が変わっても次に
  描き直すまでは前の表示のままである。

### 6. キャラクターの振る舞い

**ウインドウが出ている間も、キャラクターは普段どおり動く。** ADR 0016 の「入力欄が開いている間はどかない」は、
入力欄がキャラクターの真下にあり、そこへ向かうポインタで逃げられては使えないからだった。ウインドウは
キャラクターから離れて置かれるので、その理由がなくなる。ポインタが一列のパネルの上にあるときにどかない規則は
残るが、その一列に入力欄は含まれなくなる。

配置の計算（`OverlayLayout`）から入力欄が消える。一列は、知らせの束・吹き出し・キャラクターだけになり、
上下の反転で「入力欄を反対の端に回す」場合分けも消える。パネルの幅の上限は、これまで入力欄の幅にそろえていた。
今後はその**数だけを設定として残す**（利用者が決める一列の幅）。値は今までの入力欄の幅を引き継ぐ。

### 7. 木の中での形

[ADR 0015](0015-mac-ui-passive-view-tree.md) の木では、`input`（その子の `input.field`・`input.historyButton`・
`input.grip`）と `history` の 2 つがあった。これを **1 つの `conversation` の Component** にし、子は文字の欄と、
ひらく⇔とじるのボタンとする。状態は `isInputOpen`・`isHistoryOpen` の 2 つから、ウインドウが出ているか・
履歴が開いているかの 2 つに変わる（意味が変わるので名前も変える）。描画パラメータは `InputProps` と
`HistoryProps` を 1 つにまとめ、Root がウインドウの枠を置く。Mediator と導出は、枠のアニメーションを知らない。
ウインドウが出ていることに依る効果（焦点を移す、key にする）は、ADR 0015 のとおり描き終えてから実行する。

## Consequences

- 話すことと読み返すことが 1 枚に収まる。返事を読みながら続きを書ける。
- ウインドウはキャラクターを追わない。キャラクターを別の場所へ運んでも、ウインドウは置いた場所に残る。
  キャラクターの真下に出るのは初回だけで、以後は本人が置いた場所である。
- ほかのアプリをクリックしてもウインドウは残る。消すには Cmd+W か閉じるボタンが要る。ウインドウが key の間は
  前面のアプリのウインドウは key でないので、そちらへ戻るには一度クリックが要る（ADR 0010 と同じ）。
- 枠のアニメーションを 1 つだけ認める。ADR 0016 が挙げた問題のうち、中身との同期は起きうる（履歴のスクロール
  領域が枠より遅れて伸びる）。この 1 枚に閉じているので、目に付けば時間を縮めるか、開くときだけ中身を先に
  確定させるかで直す。舞台の中身や他のウインドウには広げない。
- 一列から入力欄が消えるので、`OverlayLayout` の反転の場合分けと、それに当たるテストが減る。一列の幅の上限は
  設定の数だけになる。
- 保存する値が変わる。入力欄の幅と高さ（`inputBoxSize`）は、幅と畳んだ高さとして初回だけ読み替える。
  ウインドウの枠・開いた高さ・開いているかどうかは、新しく保存する。
- グローバルなマウスのクリックの監視が要らなくなる。`.mouseMoved` の常時の監視は ADR 0016 のとおり残る。
- ADR 0010 の入力欄・履歴の節、ADR 0016 の「入力欄は舞台の子ウインドウ」「入力欄が開いている間はどかない」は、
  この ADR で置き換える。吹き出しと知らせの束、舞台、走り、どく判断そのものは変えない。
- 変更の範囲は Mac アプリだけである。サーバーとの契約（`conversation.send`・既読・確認）は変わらない。
