# 0050. 読みものの更新を 1 種類のイベントで知らせ、差分は git で見せる

- Date: 2026-09-27
- Status: Accepted（「いつ起こすか」の間隔の決め方（直近 1 時間の書き込みの速さによる間隔と、「前回の確認 + 間隔」の期限）は [ADR 0053](0053-waiting-at-random-for-source-updates.md) で置き換え（最初の変化で引く指数分布の待ち）、Slack の `attention` の種類に natsumi のスレッドへの返事の `thread-reply` を同 ADR で追加）

## Context

[ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で、natsumi が読むものは `/sources/<更新元>/` のファイルとし、
新しく来たものは合図（`ping`・`self_check`、[ADR 0014](0014-self-checks-and-pings.md)）の `updates` の欄に件数で載せることにした。
Slack のメンションと DM だけは、専用のイベント `slack_mention` として、本文・直前の流れ・画像を載せて届けていた。
[ADR 0043](0043-reactions-in-the-channel-files.md) では、natsumi 自身の投稿へのリアクションを `updates` の `reactions_on_mine` で数えた。

使ってみて、次のことが分かった。

- 更新は、静かな時間の合図に相乗りしないと届かない。賑やかな日ほど合図は出にくく、チャンネルの流れに遅れる。
- 件数だけでは、どこが変わったのかが分からない。natsumi は毎回ファイルを開き直して、前に読んだところを探す。
- `slack_mention` は Slack に特化した中身（直前の流れ、参照の文字列）をサーバーが組み立てる。更新元を足すたびに、同じ形の専用イベントが要る。

本人は、更新を合図の欄ではなく「読みものが更新された」というイベントで知らせ、メンションもその形に揃え、
メンションであることだけを特別に知らせると決めた。
細部は本人との問答で決めた。主な分かれ目は次のとおりである。

- いつ起こすか。すぐ（書き込みのたびに）、固定の間隔、人間のように「賑やかなら頻繁に、静かなら間を空けて」。本人は最後を選んだ。
- 間隔をだれが決めるか。natsumi が決めると、そのためにモデルを呼ぶ回数が増える。サーバーが書き込みの速さから決めることにした。
- 差分をどう持つか。写しを 2 世代持つ案は、変わっていないディレクトリの中身を二重に持つ。本人の案で git にした。
- 差分をイベントに載せるか。載せると大きさが読めない。載せずに、見方だけを渡すことにした。
- ファイルの形。Markdown のままでは、メンションの場所を指す手段が無い。1 行 1 発言の JSON Lines にし、`jq -s` のパスで指すことにした。

## Decision

### イベントは `sources_updated` の 1 種類

- 読みものの更新は、イベント `sources_updated` で知らせる。更新元の数や種類でイベントの種類は増えない。
- イベントに載せるのは、変わったディレクトリとそのファイル、なつみ宛ての印（`attention`）の一覧、差分の見方である。
  - 差分の本文は載せない。natsumi が必要なときに作業環境のコマンドで見る。
  - Slack の ts などの ID は載せない（[ADR 0024](0024-no-event-ids-for-the-model.md)）。
- 処理を待っている `sources_updated` は、キューに 1 件しか置かない。待っている間に来た更新は、その 1 件がターンの始めに中身を作るときに一緒に入る。
- ターンの始めに、変わったものも印も無いと分かったら、ターンを始めずにイベントを閉じる。
- ターンの上限（モデルの呼び出しの回数、時間）は、ほかのイベントと同じである。

### コアは Slack を知らない

- サーバーのコアは、`/sources` の下を 1 つの git の作業ツリーとして扱う。管理用のディレクトリは `/sources` の外、data directory の中に置く。更新元は git を知らず、ファイルを書くだけである。
- 更新元は、名前・活発さを測るディレクトリの深さ・差分から外すファイルを登録する。Slack は深さ 2（`slack/<ワークスペース>/<チャンネル>`）で、目次の `INDEX.md` と取り込んだ画像の `files/` を外す。
  外したファイルは履歴に入れない。画像は発言の行にパスが書かれるので、差分からは行の変化として分かる。
- 変わったかどうかは、サーバーが定期的に作業ツリーを見て判断する。更新元に「書いた」と言わせない。

### いつ起こすか

- ディレクトリごとに、前回それを見せた時点を git の ref（`refs/seen/<ディレクトリ>`）で持つ。
- commit は、イベントの中身を作るときにだけ作る。書き込みのたびには作らない。全体を 1 つ commit し、見せるディレクトリの ref だけを進める。
- 初めて見るディレクトリは、黙って ref を今の commit に置く。過去の中身を丸ごと「更新」として見せない。
- 活発さは、ディレクトリごとの書き込みの回数で測る。次の確認までの間隔は、k を直近 1 時間の書き込みの速さで割った値とし、最短と最長で頭打ちにする。
  - 既定は k が 3、最短 3 分、最長 60 分で、どれも設定で変えられる。
  - 期限は「前回の確認 + 間隔」である。変わっていないディレクトリでは、期限が来てもイベントを出さない。
  - あるディレクトリの期限でイベントを出すとき、期限が最短の間隔より近いほかのディレクトリも一緒に載せる。
- awake hours の外は、なつみ宛ての印の無い更新では起こさない。ref を進めないので、朝の最初の確認の差分に夜の分がまとめて出る。

### なつみ宛ての印（`attention`）

- 更新元は、ファイルのどこかがなつみ宛てだとコアに伝えられる。伝えるのは、ファイル、ファイルの中の場所（`jq -s` のパス）、種類を表す文字列、任意で画像のパスである。
  - 種類の意味はコアでは解釈しない。意味は更新元ごとのマニュアルに書き、system prompt には「意味は各更新元のマニュアル」とだけ書く。
- 印を受けたら、間隔を待たずにそのディレクトリの確認を出す。awake hours の外でも出す。
- 印の画像は、コアが一律にイベントに添える。上限は 4 枚である。
- 印は届けるまで SQLite に残す。止まっている間に来た印も、次に起きたときに届く。

### 差分の見方

- 作業環境に `sources-diff` のコマンドを置く。直前のイベントで見せた分と、「昨日から」のような範囲の差分を出す。
- 作業環境には、git の管理用ディレクトリを読み取り専用で見せる。commit と ref を動かすのはサーバーだけである。
- runner はコマンドに image の環境変数を渡さない（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）ので、コマンドは自分で管理用ディレクトリの場所を知っている。

### 履歴の刈り込み

- 夜に、N 日前の中身を親の無い commit にし、それ以後の commit を付け直して、古いものを捨てる。N の既定は 7 で、設定で変えられる。
- `refs/seen` は付け直した先へ移す。N 日より前を指していた ref は、新しい出発点へ移す。
- 刈り込みに失敗しても、履歴が長いまま残るだけで、確認は続ける。

### Slack の更新元

- チャンネルの日付ファイルを、1 行 1 発言の JSON Lines（`<日付>.jsonl`）にする。
  - スレッドの返信も 1 行とし、返信先の行の番号を欄に持つ。返信は親と同じファイルに書く。
  - 行は記録した順に並べる。削除された発言は「削除済み」の行として残し、行の番号をずらさない。
  - リアクション、画像のパス、編集済み、natsumi 自身の投稿であることを欄に持つ。
  - 時刻と発言者は今までどおり、なつみのタイムゾーンの秒までの時刻と表示名で書く。ポッポさんへの返信先の参照（ADR 0039）はこの 2 つから書け、サーバーの突き合わせは変えない。
- 反映のとき、SQLite の全期間から JSON Lines を書き起こし、Markdown の日付ファイルは消す。`INDEX.md` は Markdown のまま残す。
- bot への本物のメンションと DM は、`attention`（種類は `mention` と `dm`、画像のパス）として伝える。受け取ったときの 👀 は今のままサーバーが付ける。
- サーバーはメンションの前後の流れを組み立てない。natsumi がファイルから読む。スレッドの親が記録に無いときに取ってくる処理は残す。ファイルに流れが揃っていることが、流れを送らない前提だからである。
- 設定の `slack.mentionContext` と `slack.updates` は使わなくなる。古い設定で起動が止まらないよう、書かれていれば無視し、ログで知らせる。

### 合図

- `ping` と `self_check` から `updates` の欄をなくす。`ping` は `local_time` と `unacknowledged_notices` だけの、静かな時間の合図として残す。

### 置き換える既存の決定

- ADR 0014
  - 置き換え: `ping`・`self_check` の `updates` の欄（ADR 0039 で追加したもの）。欄はなくなり、更新は `sources_updated` で届く。
- ADR 0039
  - 置き換え:「イベントの種類は増やさず、更新元を足す」。イベントの種類を 1 つ（`sources_updated`）足し、更新元はそれに載る。更新元を足してもイベントの種類は増えない点は保つ。
  - 置き換え: 合図の `updates` の欄と「前回見せてから増えた件数」。変わったディレクトリとファイル、差分の見方になる。
  - 置き換え:「メンションと DM のイベント」。`slack_mention` はなくなり、`attention` として `sources_updated` に載る。本文・直前の流れ・参照はイベントに載せない。
  - 置き換え: Slack のチャンネルのファイルを Markdown で書く点。JSON Lines になる。
- ADR 0043
  - 置き換え:「合図の `updates`」の `reactions_on_mine`。リアクションの付け外しはファイルの変化として `sources_updated` に出る。natsumi 自身の投稿かどうかは行の欄で分かる。
  - 置き換え:「ファイルの書き方」の `リアクション:` の行。行の欄になる。

## Consequences

- 更新は、合図を待たずに届く。賑やかなチャンネルほど早く、静かなチャンネルは間を空けて届く。そのぶん思考ループの動く回数は増える。
- 更新のターンでも静かな時間の時計は 0 に戻るので、賑やかな日は `ping` が出にくくなる。本番で様子を見る。
- natsumi は差分で、前回からどこが変わったかを読める。差分をイベントに載せないので、イベントは小さいままだが、読むには shell を 1 回使う。
- メンションの流れはファイルから読むので、メンションのターンで shell を使う回数が増える。
- data directory に git の管理用ディレクトリが増える。刈り込みで N 日分に抑える。バックアップの対象に含めてよく、失っても最初の commit からやり直せる。
- 作業環境に管理用ディレクトリを読み取り専用で見せるマウントが 1 つ増える。無ければ `sources-diff` はそう答えるだけで、ほかは動く。
- 更新元を足すときは、登録（名前・深さ・外すファイル）とマニュアルの 1 枚を足す。イベントの種類、system prompt、ツールの定義は変わらない。
- system prompt の出来事の説明が変わるので、反映した時点で prefix が変わる。
