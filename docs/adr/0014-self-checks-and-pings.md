# 0014. 自分で予約する確認と定期の合図

- Date: 2026-09-17
- Status: Accepted（`ping` と `self_check` のイベントに、更新元ごとの新しい件数を知らせる `updates` の欄を足す点は [ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で追加、その `updates` の欄をなくし、更新は `sources_updated` のイベントで知らせる形に [ADR 0050](0050-telling-of-source-updates-with-one-event.md) で置き換え）

## Context

ADR 0008 で、natsumi は一本の思考ループとして、届いたイベントを 1 件ずつ処理するようになった。
イベントは本人のメッセージ（`mac_message`）と夜の振り返り（`nightly_review`）だけで、natsumi が自分から動くきっかけはなかった。

- 「30 分後にもう一度聞く」「15:00 に確かめる」のような約束を、自分で覚えて実行する手段がない。
- 静かな時間に、本人への声かけや、やり残しに手を付ける機会がない。
- ADR 0013 で、本人が確かめていない知らせの件数を natsumi に渡すようにした。念押しをいつ・どの頻度で行うかは、スケジューラーの作業に残していた。
- 表情は、サーバーが付けた `thinking` だけを処理の終わりに `neutral` に戻していた。
  モデルが付けた `thinking` や `happy` などは、次に変わるまで残り続けた。

一方で、評価（ADR 0008）では、同じ出力を繰り返して止まらない失敗が出ていた。
自分から動くきっかけを与えると、予約を重ねて思考を回し続ける形の失敗も起こり得る。
回数と間隔はモデルの判断に任せず、サーバーで制限する。

予約の書き方には二つの案があった。

- 間隔（「30 分後」）: モデルが今の時刻を知らなくても書ける。予定の時刻には合わせにくい。
- 時刻（「15:00」）: 予定に合わせられる。モデルが今の時刻やタイムゾーンを取り違える危険がある。

## Decision

### 定期の合図（ping）

- 起きている時間帯にだけ、静かな時間が一定の長さ続いたら、合図のイベント `ping` を思考ループに入れる。
  「何かしたいことは？」という意味で、何もなければ natsumi は `finish_event` だけで終える。
- 静かさは、最後の出来事から数える。
  - 本人のメッセージを受け付けたとき、イベントの処理（合図や予約の処理、夜の振り返りも含む）が終わったときに、時計を 0 に戻す。
  - 会話の直後や、処理の最中には合図を出さない。合図の処理が終わると時計が戻るので、合図も間隔を空けて出る。
  - この時刻はメモリに持ち、再起動のときは起動の時刻から数える。起動直後に合図は出ない。
- 時間帯と間隔は設定で変える。時刻は `loop.timeZone` で解釈する。時間帯は日付をまたいでもよい（例: 22:00〜6:00）。
- 時間帯の外（夜）は合図を出さない。夜に行うのは、振り返りと session の切り替え（ADR 0009）だけである。
- 合図のイベントには、本人のタイムゾーンの今の時刻（`local_time`）と、本人がまだ確かめていない知らせの件数
  （`unacknowledged_notices`、1 件以上のときだけ）を添える。書き方は ADR 0013 の `mac_message` と同じである。
  声をかけるかは natsumi が決める。サーバーから名指しの念押しは出さず、Mac で目立たせることもしない。

### 自分で予約する確認（self-check）

ツールを 3 つ足す。予約を変えるツールは作らず、一覧と取り消しは読み取りと取り消しに限る。

| ツール | 役割 |
| --- | --- |
| `schedule_self_check(reason, in_minutes?, at?)` | 後で自分から確かめる予約をする。`in_minutes` と `at` のどちらか一方だけを書く |
| `list_self_checks()` | まだ届いていない予約を、check_id・時刻・理由で一覧する |
| `cancel_self_check(check_id)` | まだ届いていない予約を取り消す |

- 間隔でも時刻でも書ける。サーバーが絶対の時刻に直して保存する。
  - `in_minutes`: 今から何分後か（整数）。
  - `at`: 本人のタイムゾーンの `HH:MM`（今日のその時刻）か `YYYY-MM-DD HH:MM`。夏時間などで存在しない時刻は、形の誤りとして断る。
  - 結果の文に、直した時刻をタイムゾーン付きで書く。モデルは自分の読み違いに気づける。断るときも今の時刻を書く。
- 次の場合は予約せず、ツールの結果で理由を返す（エラーの結果にする）。思考ループは止めない。
  - 理由が空、`in_minutes` と `at` の両方か、どちらもない、`at` の形が違う
  - 過去の時刻、最短の先より近い、遠すぎる先
  - 同時に持てる件数を超える
  - 1 日（本人のタイムゾーンの日付）に予約した件数を超える。取り消した予約も数える。予約と取り消しを繰り返して上限をすり抜けないようにするためである。
- 同じ理由の予約が待っていれば、新しく作らず 1 件にまとめる。成功の結果として、まとめた先の check_id と時刻を返す。
  - 理由は NFKC にそろえ、空白をまとめてから比べる。
  - まとめた先の時刻は変えない。時刻を変えるには、取り消してから予約し直す。
    新しい時刻で上書きすると、同じ予約を先へ送り続けることで、いつまでも確認しない形の失敗を許すからである。
  - まとめた呼び出しは、件数にも 1 日の回数にも数えない。
- 起きている時間帯の外の時刻も受け付ける。結果の文で、実際に届くのは朝であると伝える。

### 予約が届くとき

- 予約の時刻が来たら、イベント `self_check` を思考ループに入れる。`checks` に、予約ごとの check_id・理由・予定の時刻（`scheduled_for`、本人のタイムゾーン）を添える。
- 時刻の来た予約は、何件あっても 1 件のイベントにまとめる。
  - サーバーの停止や夜をまたいで時刻を過ぎた予約も、起動後（夜なら朝）に 1 件で渡す。1 分以上遅れたものには、遅れた分数（`late_minutes`）を添える。
  - 連続して思考を回さず、忘れもしない。
- 予約とイベントは、同じ transaction で「届いた」と記録する。同じ予約を二度渡さない。
  イベントの処理中にサーバーが止まった場合、そのイベントは ADR 0008 のとおり失敗（`interrupted`）となり、予約も戻さない。
- 予約も合図も、ループが静かなとき（処理中のターンがなく、キューも空）にだけ入れる。
  - 本人のメッセージが待っている間は後回しにする。
  - 夜の切り替え（振り返りのターンと session の作り直し）の最中に時刻が来た予約は、切り替えが終わってから新しい session に渡す。遅れた分数が付く。
  - 合図と予約の時刻が重なったら、予約を先に渡す。その処理で時計が戻るので、合図はさらに間隔を待つ。

### 時計

- サーバーは 10 秒ごとに時計を見る。予約の時刻、合図、表情の戻しは、この粒度で判定する。
- テストは時計を差し替え、時計を見る処理を直接呼んで確かめる。実際には待たない。

### 表情

- 処理の終わりに、キューが空なら、誰が付けたかに関わらず `thinking` を `neutral` に戻す。
  これまでは、サーバーが付けた `thinking` だけを戻していた。モデルが付けた `thinking` が残り、ずっと考え込んで見えた。
- `neutral` と `thinking` 以外の表情は、最後に変わってから一定の時間（既定 3 分）で `neutral` に戻す。
  - 同じ表情を付け直しても、その時点から数え直す。
  - `thinking` は時間では戻さない。処理が長引いても、処理中は考え中のままにする。
  - 夜の切り替えの間は戻さない。`sleepy` は切り替えが終わったときに、これまでどおり戻す（ADR 0009）。
- 戻すときも、ほかの表情と同じ `avatar.expression` を全端末に送る。契約の形は変えない。

### 記録

SQLite の migration version 7 で、予約の表を足す。

- 予約ごとに、check_id、理由、比べるためにそろえた理由、絶対の時刻、状態（待っている・届いた・取り消した）、届けたイベント、作った時刻を持つ。
- 届いた予約と取り消した予約も消さない。1 日の回数を数えることと、後から経緯を追うことに使う。
- 同じ理由の待っている予約が 2 件にならないよう、一意の制約を掛ける。
- 合図と予約のイベントは、ほかのイベントと同じ `loop_events` に記録する（kind は `ping` と `self-check`）。
  どちらも本人のメッセージを持たないので、Mac の snapshot の `pendingEvents` にも、`conversation.event.completed` にも出ない。
- 最後に出来事があった時刻と、最後に表情が変わった時刻は、メモリだけに持つ。表情そのものもメモリにあり、再起動で `neutral` に戻るためである。

### 設定

`loop` 節に次を足す。すべて省略でき、省略時は既定値を使う。

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `awakeHours.start` / `awakeHours.end` | `08:00` / `23:00` | 起きている時間帯（24 時間の HH:MM）。合図と予約はこの間だけ届く。日付をまたいでもよい |
| `pingIntervalMinutes` | `30` | 合図までの静かな時間（分、5 以上）。`false` で合図を出さない |
| `selfCheck.minDelayMinutes` | `5` | 予約できる最短の先（分） |
| `selfCheck.maxDelayDays` | `7` | 予約できる最も遠い先（日） |
| `selfCheck.maxPending` | `5` | 同時に待たせられる予約の件数 |
| `selfCheck.maxPerDay` | `20` | 1 日に予約できる件数（取り消したものも数える） |
| `expressionResetMinutes` | `3` | `thinking` 以外の表情が `neutral` に戻るまでの時間（分） |

夜の切り替えの時刻（既定 4:00）は、既定の時間帯の外にある。

### 範囲外

- Gmail と Google Calendar の定期確認（ADR 0003）。まだ接続していない。後の作業で、この予約と合図の仕組みに乗せる。
- Slack の定期確認（ADR 0012 の作業）。
- 評価用の環境での事前評価。モデルの使い方は、本番に入れてから記録で見る。
- 知らせを名指しで念押しするサーバーの振る舞いと、どの知らせが未確認かを読むツール。

### 置き換える既存の決定

- ADR 0008
  - 置き換え:「表情がサーバーの出した `thinking` のままなら `neutral` に戻す」。誰が付けた `thinking` も戻し、ほかの表情は時間で戻す。
  - 置き換え: 登録するツール。`schedule_self_check`・`list_self_checks`・`cancel_self_check` を足す。
  - 具体化: 範囲外としていた「スケジューラーと自発的な確認」のうち、予約と合図の土台を、この ADR で決める。
- ADR 0009
  - 具体化:「時刻の判定の仕組みは最小限で、スケジューラーと自発的な確認の実装で統合する」。
    夜の切り替えの時刻の判定は、これまでどおりサーバーのタイマーに残す。予約と合図は、切り替えの最中には入れず、終わってから渡す。
  - 残す: 切り替え中の `sleepy` と、終わったときの戻し方。
- ADR 0013
  - 追加: 未確認の知らせの件数を、`mac_message` に加えて `ping` にも添える。
  - 具体化:「念押しをいつ・どの頻度で行うか」。サーバーは合図に件数を添えるだけで、声をかけるかは natsumi が決める。

## Consequences

- 本人が何も話さなくても、起きている時間帯には、静かな時間ごとにモデルを使う。既定では最大で 1 時間に約 2 回である。
  自前のエンドポイントなら負荷、サブスクリプションなら利用量として表れる。`pingIntervalMinutes` で調整する。
- 合図と予約の処理にも思考ありのモデル呼び出しを使うので、その最中に本人がメッセージを送ると、次の境目までの差し込み待ちが起こり得る。
- 予約の上限はサーバーが強制するので、モデルがどう使っても、1 日の予約は既定で 20 件を超えない。
  一方、上限に達すると、本人に頼まれた正当な予約も断られる。断った理由はモデルに返る。
- 同じ理由の予約は時刻を更新しないので、時刻を変えるときにモデルは取り消しと予約の 2 回の呼び出しが要る。
- 最後に出来事があった時刻をメモリに持つので、再起動の直後は合図が遅れる。
- 夜の予約は朝にまとめて届く。夜中に本人へ声をかける用途には使えない。
- 時計は 10 秒ごとに見るので、予約は最大で約 10 秒遅れて届く。
- 処理中のイベントがサーバーの停止で失敗した場合、その予約は戻らない。
