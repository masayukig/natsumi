# 0034. 出口を許可リストで絞る

- Date: 2026-09-24
- Status: Accepted（出口の proxy に、loopback で平文の HTTP を受け、行き先を固定して token を付ける画像生成の中継を足す点は [ADR 0044](0044-drawing-with-sdctl-and-posting-images.md) で追加。loopback で受けて GitHub の ssh へ送る中継を足す点は [ADR 0073](0073-skills-from-the-owner-and-her-own.md) で追加（ADR 0044 の画像生成の中継と同じ形））

## Context

[ADR 0011](0011-memory-shell-in-a-confined-container.md) と [ADR 0019](0019-a-workspace-not-a-memory-tool.md) は、
なつみの作業環境 `natsumi-workspace` にネットワークを与えなかった（`network_mode: none`）。
閉じ込めの多くを「外へ出す口が無い」ことに預けていた。

これを続けられなくなった。

- 本番を Kubernetes に移す（[ADR 0033](0033-running-on-kubernetes.md)）。サーバー・作業環境・sshd を同じ Pod に置く。
  Pod の中のコンテナはネットワークの名前空間を共有するので、「同じ Pod の中で作業環境だけネットワークが無い」形は作れない。
  NetworkPolicy の粒度も Pod であって、コンテナではない。
- なつみは、今後は外を見るようになる。閉じ込めを「ネットワークを与えない」から「出口を許可リストで絞る」に変える、と本人が決めた。
- サーバー自身にも外向きの通信がある。モデルのバックエンド、GitHub のログイン（[ADR 0006](0006-github-login-and-transport.md)）、
  APNs（[ADR 0029](0029-push-notifications-on-the-iphone.md)）、外のエージェント（[ADR 0025](0025-talking-to-outside-agents-over-a2a.md)）である。
  Kubernetes に移れば、証明書はクラスタの入口が取るので、Let's Encrypt への通信は無くなる（ADR 0033）。

宛先の絞り方には制約がある。

- NetworkPolicy の宛先は、Pod・名前空間・CIDR でしか書けない。インターネット上のサービスの名前は、安定した CIDR にならない。
  また、NetworkPolicy が効くかどうかはクラスタの CNI に依る。
- 名前解決を絞るだけでは境界にならない。IP を直接書けば素通りする。
- サーバーの外向きの通信は Node の標準の `fetch` で行っており、既定では `HTTPS_PROXY` を読まない。
  明示的な proxy を使うなら、通信するすべての箇所にコードの変更が要る。

ADR 0019 は、出口を開ける ADR が前提にすべきことを 4 つ挙げていた。
答えを返した後も動き続けるプロセス、検査されない `/work` と `/home/natsumi`、インタプリタ、git である。

## Decision

### 閉じ込めの軸を「出口の許可リスト」にする

- 閉じ込めは、ネットワークの不在ではなく、**出口の許可リスト**で掛ける。許可リストに無い外向きの通信は拒否する。既定は拒否である。
- 規則は Pod のネットワークの名前空間の中に張る。ホストにも CNI にも触らない。
  - 規則を張るのは、Pod の初期化のコンテナ（init container）だけとする。`NET_ADMIN` を持つのはこのコンテナだけである。
  - 常駐するコンテナには `NET_ADMIN` を与えない。サーバー・作業環境・proxy は、非 root で動かし、全 capability を外し、
    `no-new-privileges` を付ける。どれも規則を書き換えられない。**この方式の強さは、この capability の制限に依っている。**
  - クラスタの NetworkPolicy が効くかどうかに依らない。
- 同じ Pod の中の誰の通信かは、**プロセスの UID** で見分ける。サーバーと、作業環境・sshd は、別の UID で動かす（ADR 0033）。
  - サーバーの UID: 外向きの HTTPS（tcp 443）は、同じ Pod の proxy へ回す。名前解決は、クラスタの DNS にだけ直接出てよい。それ以外は拒否する。
  - 作業環境と、sshd でログインするユーザーの UID: 外向きはすべて拒否する（後述）。
  - proxy の UID: tcp 443 と名前解決だけを通す。宛先を名前で絞るのは proxy 自身の許可リストである。
  - 上に挙げない UID の外向きは拒否する。外から届いた接続への応答は、どの UID でも通す。本人が sshd やクラスタの入口からつなぐためである。

### サーバーの外向きは、透過型の proxy を名前で通す

- サーバーの外向きの HTTPS は、同じ Pod のサイドカーの透過型の proxy を通す。
  proxy は TLS の ClientHello の **SNI の名前**を読み、許可リストの名前だけを通す。TLS は解かない。証明書を配る必要も無い。
  - 透過型にするので、サーバーのコードは変えない。どの通信が proxy を通るかは、コードではなく規則で決まる。
  - 実装は nginx の stream モジュール（`ssl_preread`）とする。公式の image と設定だけで作れ、自分で保守するコードが増えない。
- **つなぐ先は、SNI の名前を proxy が引き直して決める。元の宛先の IP は使わない。**
  元の宛先の IP を使うと、許可された名前を SNI に書いたまま任意の IP へつなげる。SNI はクライアントが自由に書ける値なので、
  名前と行き先を一致させるには、名前から行き先を決めるしかない。
- SNI の無い接続（IP を直接指定した TLS）は拒否する。SNI が見えない接続（ECH）も通さない。
- 平文の HTTP（tcp 80）は拒否する。ほかのポートも拒否する。サーバーの宛先はすべて HTTPS で足りる。

### 許可する宛先

許可リストに入れるのは、次の種類の宛先である。

| 種類 | なぜ要るか |
| --- | --- |
| モデルのバックエンド | 思考ループがモデルを呼ぶ |
| GitHub のログイン | OAuth の code の交換と、アカウントの数値 ID の取得（ADR 0006） |
| APNs | iPhone への通知（ADR 0029） |
| 外のエージェント | A2A で頼む（ADR 0025、[ADR 0035](0035-asking-outside-agents-and-hearing-back.md)） |
| 名前解決 | クラスタの DNS。proxy を通さず、UID の規則で許す |

- 具体的な名前は、環境の設定（private のリポジトリ）に置く。この公開のリポジトリには書かない。
- 外のエージェントとも、クラスタの中の Service に直接つながず、**この proxy を通る公開の入口（Ingress）で話す**。
  - 呼び出しの token（ADR 0025、ADR 0033）が TLS の中に置かれる。クラスタの中を平文で流れない。
  - 許可リストの書き方が「名前を 1 つ足す」の 1 通りにそろう。宛先の種類ごとに別の仕組みを持たない。

### 作業環境の外向きは、今は全部拒否する

- 移行では作業環境の出口を開けない。作業環境と sshd の UID の外向きは、名前解決も含めてすべて拒否する。
  閉じ込めの強さは、ネットワークを与えなかった今と同じに保つ。
- このため、ADR 0019 が挙げた 4 つ（残ったプロセス、検査されない書き場所、インタプリタ、git）は、今は外へ出る手段にならない。
- **今後の方向**として、作業環境に `curl` などを持たせ、許可リストの中のインターネットに出られるようにすることを考えている。
  - そのときに、[ADR 0004](0004-pi-tool-and-voice-boundaries.md) の「任意 HTTP を許可しない」を決め直す。この ADR では決め直さない。
  - 作業環境の許可リストをどう決めるか、ADR 0019 の 4 つをどう扱うかも、その作業単位で決める。
  - 外のエージェントとのやり取りは、そのあともサーバーを通す。token を作業環境に見せないためである（ADR 0033）。
- proxy は、後で作業環境用の許可リストを別に持てる形にしておく。UID ごとに proxy の待ち受けを分けられるようにし、
  それぞれに許可リストを持たせる。移行の時点では、サーバー用の 1 つだけを作る。

### 確かめ方

- 規則と許可リストは、Pod の中から実際につないで確かめる。
  サーバーの UID で、許可した名前には届き、許可していない名前・IP の直接指定・平文の HTTP には届かないこと。
  作業環境の UID で、どこにも届かないこと。
- ADR 0019 の閉じ込めの実測のうち「インターフェースが loopback だけであること」は、
  「作業環境の UID から外へ出られないこと」の確認に置き換える。

### NetworkPolicy との関係

- NetworkPolicy は名前で書けないので、NetworkPolicy が効くようになっても、この名前の層は残る。
- NetworkPolicy の粗い網（CIDR）を重ねるかは、そのときに決める。

### ADR 0011・0019 の仕分け

生きるもの:

- 非 root、全 capability を外すこと、`no-new-privileges`。Pod の `securityContext` に移す。
- ルートファイルシステムを読み取り専用にすること。書ける場所は ADR 0019 の 4 つのまま。
- 資源の上限、コマンドの応答の上限、出力の切り詰め。
- 記憶以外をマウントしないこと。SQLite・秘密・Pi の状態領域・設定ファイルを作業環境に見せない。
  外へ出る道を開ける方向に進む以上、ファイルの閉じ込めの重みはむしろ増す。
- なつみにコンテナの実行基盤の操作権を渡さないこと。Kubernetes では、ServiceAccount に強い権限（RBAC）を与えないことに読み替わる。
- runner と Unix ソケットだけでつなぐこと（ソケットの置き場は ADR 0033）。
- 入れるコマンドの一覧を持たず、普通の Debian の環境にすること（ADR 0019）。

変わるもの:

- `network_mode: none` と、閉じ込めを「コンテナの形だけで掛ける」こと。形に加えて、Pod の中の規則で掛ける。
- ADR 0019 の「今回も絶つ」。作業環境の外向きは、この ADR の規則で全部拒否する形になる。

### ツールの説明

- `run_shell` のツールの説明は変えない。作業環境から外へ出られないことは、移行の後も変わらないからである。
  説明を変えないので、prefix cache にも影響しない。作業環境の出口を開けるときに、説明も直す。

### 置き換える既存の決定

- ADR 0011
  - 置き換え:「ネットワーク: `network_mode: none`。インターフェースは loopback だけになる」。
    ネットワークの名前空間は Pod で共有し、出口はこの ADR の許可リストで絞る。作業環境の UID の外向きは全部拒否する。
- ADR 0019
  - 置き換え:「ネットワーク」の節の「今回も絶つ。`network_mode: none` のままとする」と、「閉じ込めは、これまでどおりコンテナの形だけで掛ける」。
    閉じ込めは、コンテナの形と、Pod の中の規則で掛ける。
  - 置き換え: 閉じ込めの実測の「インターフェースが loopback だけであること」。
  - 残す:「境界をネットワークの不在に寄りかからせない」と、出口を開ける ADR が前提にすべき 4 つ。作業環境の出口を開ける作業単位で扱う。
- ADR 0004
  - 具体化:「ネットワークの到達先制限はデプロイ側で実施する」。この ADR の規則と許可リストで行う。
  - 残す:「任意 HTTP を許可しない」。作業環境の出口を開ける作業単位で決め直す。

## Consequences

- サーバーの外向きの通信は、許可リストに名前を足さなければ届かない。宛先を増やすたびに、環境の設定を直して反映する必要がある。
  許可リストを書き損じると、モデルのバックエンドやログインに届かず、なつみが動かない。
- 作業環境は、移行の後も外へ出られない。調べものは、作業環境の出口を開ける作業単位を待つ。
- 閉じ込めの強さは、常駐するコンテナが capability を持たないことに依る。capability を足すと、規則を書き換えられるようになる。
- proxy は TLS を解かないので、許可した名前の先で何を送っているかは見ない。名前の単位で絞るだけである。
- ECH を使う相手や、SNI を送らない相手には届かない。
- サーバーの UID は、名前解決の問い合わせを外へ出せる。サーバーはモデルが書いたコードを動かさないので、承知のうえとする。
- サーバーは、クラスタの中の他の Service にも、許可リストの公開の入口を通らない限り届かない。
- NetworkPolicy が効かないクラスタでも同じ強さで効く。一方、Pod の外からこの Pod への通信は、この規則では絞らない。
- proxy のサイドカーと初期化のコンテナが増える。proxy が止まると、サーバーは外へ出られない。
