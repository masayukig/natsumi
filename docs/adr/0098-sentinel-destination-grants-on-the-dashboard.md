# 0098. 関所が断った名前と宛先の許しを承認の画面に足し、範囲の選択肢は関所が示すままに並べる

- Date: 2026-11-13
- Status: Accepted

## Context

[ADR 0096](0096-sentinel-approvals-on-the-dashboard.md) で、関所（ペネロペの出口に置く別のプログラム。用語は [ADR 0095](0095-letting-her-act-and-noticing-quickly.md) の Context）が本人に聞くものの窓口を、ダッシュボードの承認の画面（`/dashboard/sentinel`）に置いた。
承認の画面は、関所の承認待ちと効いている許しと監査の記録を、開くたびに関所の制御の口（Unix socket）から読んで並べる。答えと取り消しは、Origin を照合するフォームの POST である。
範囲の選択肢は、関所が承認待ちごとに示したものをそのまま並べ、サーバーは範囲の値と意味を持たない。

今の関所は、振り分けに名前の無い宛先（表に無い名前）を、名前解決の時点で断る。承認待ちにはならず、本人が許す道も無い。
初めての文書のサイトやパッケージの置き場をペネロペが読むたびに、本人が環境のリポジトリの振り分けを直すことになっている。
関所の側は natsumi-sentinel の ADR-0008 で、表に無い名前を本人の許し（宛先の許し）で通すことにした。その中で、次を決めている。

- 関所は、表に無い名前を断ったら、その名前を覚える（断った名前）。断った名前のたびに承認待ちは作らない。作業環境の道具は、利用者が頼んでいない名前（テレメトリの送り先など）も引くので、承認待ちとその知らせが、本人が頼んでいない名前で埋まるためである。
- 本人は、承認の画面で断った名前の一覧を見て、そこから宛先の許しを出せる。
- 運用の係（ペネロペ）は、宛先を先に頼める。頼んだ宛先は 1 つの承認待ち（宛先の承認待ち）になり、今の承認待ちと同じに知らされる。
- 宛先の許しの範囲は、期限・単位（この名前だけ／ドメインの下すべて）・扱い（開いて見る／開かない）・読み書き（読みだけ／読み書き）を組み合わせる。範囲は本人が選び、運用の係は指定できない。既定は「この名前だけ・開いて見る・読みだけ」である。
- 「開かない」を選んだら、読みだけは選べない（中身を見ないので、読みと書きを分けられない）。
- 承認の画面には、ドメインの下すべての広さと、開かないときに読み書きとも通り中身を見ないことを、関所が組んだ文で示す。環境が渡す内側のドメインの一覧の名前（内側の名前）は、内側の名前と分かるように示す。

関所の承認の口は、宛先の許しのために欄と口を足すが、今ある欄の意味と口の形は変えない。今の承認の画面は、足した欄を知らなくても動く。
宛先の許しを持たない版の関所も、しばらく動き続ける。

## Decision

### 断った名前の一覧を承認の画面に置き、そこから宛先の許しを出す

- 承認の画面に、関所が覚えた断った名前の一覧を置く。名前、向け直し元、断った回数、最初と最後の時刻、関所が組んだ文を見せる。
- 一覧の 1 件から、宛先の許しを出すフォームを開ける。範囲の選び方は、下の宛先の承認待ちと同じである。
- 断った名前から許しを出すことは、承認待ちを経ない。関所は承認待ちを作らないので、Web Push も `/sources/sentinel/approvals` のファイルも出ない。
  ペネロペは、次に同じ名前を引いたときに通ることで分かる。
- 断った名前では、知らせない。一覧は本人が画面を開いたときに読むものである。

### 宛先の承認待ちは、今の承認待ちと同じ一覧と同じ答えの道に載せる

- 宛先の承認待ちは、今の承認待ちと同じ一覧に並べ、同じ 1 件のページで答える。Web Push と、閉じたときの `/sources/sentinel/approvals/<id>.json` も今の承認待ちと同じである（ADR 0096 の Decision「知らせ: 承認待ちが出たら Web Push」と「答えが出たら `/sources/sentinel/approvals/<id>.json` と `sources_updated`」）。
- 答えのフォームには、期限に加えて、関所が示す単位・扱い・読み書きの選択肢を並べ、選ばれたものを答えに載せて関所に渡す。
- 既定は、関所が示す既定のままにする。画面が別の既定を選ばない。

### 範囲の文と事実は、関所が組んだものをそのまま出す

- ドメインの下すべての広さの文、開かないときの文、内側の名前の印は、関所が組んだものをそのまま出す。画面で言い換えず、足さない。
- 名前・文・事実は、ADR 0096 と同じく平文として出し、HTML・Markdown・リンクとして解かない。名前は作業環境が決めた値である。

### 「開かない」と「読みだけ」の組み合わせだけは、サーバーが知る

- ADR 0096 の Decision「答えと取り消しは、Origin を照合するフォームの POST」は、サーバーが範囲の値と意味を持たないとしている。この ADR は、その例外を 1 つだけ足す。
  サーバーは、扱いのうち「開かない」には読み書きの選択が無いことを知り、画面で「開かない」と「読みだけ」を一緒に選べない形にする。そうでない組み合わせを受けても、関所に渡さずに断る。
- 理由は、関所が断る組み合わせを本人が選べる画面にしないためである。断られてから選び直す形では、本人が「読みだけで開かない」許しがありうると誤って理解しうる。
- 選択肢そのもの（どの単位・扱い・読み書きを出すか、その文、既定）は、今までどおり関所が決め、サーバーは並べるだけである。

### 宛先の許しも、今の許しの一覧で見て取り消す

- 効いている宛先の許しは、今の許しの一覧に並べ、同じ取り消しの道で 1 件ずつ取り消す。範囲は関所が組んだ文で見せる。
- 取り消しは、ADR 0096 と同じく知らせない。

### 守りと失敗したときの倒し方は ADR 0096 のまま

- 守る対象は、関所の許しを出す権限である。宛先の許しは、振り分けに無い宛先への出口を開くので、操作の許しより広く効きうる。
- 許す範囲: 断った名前からの許しも、宛先の承認待ちへの答えも、本人の生きているセッションを持つブラウザからの、Origin の一致するフォームの POST だけが関所に渡せる。状態は GET では変えない。
- **モデルには、この窓口を呼ぶツールを渡さない**（ADR 0096 の Decision「窓口はダッシュボードの中の承認の画面、サーバーは関所への薄い窓口」のまま）。ペネロペにできるのは、関所の作業環境向けの口で宛先を先に頼むことまでである。
- 失敗したとき: socket が無い・つながらない・関所が断ったときは、許さない側に倒す。関所が断った答えと許しは、その状態と関所の言葉のまま本人に伝える。サーバーは範囲を推測で補わない。

### 宛先の許しを持たない関所につないでも、今の画面のまま動く

- 関所が断った名前の口を持たないときは、承認の画面に断った名前の一覧を出さない。ほかの部分は今のまま動く。
- 承認待ちと許しに宛先の欄が無ければ、宛先の部分を出さない。今の承認待ちの答えは、今と同じ形で関所に渡す。
- 関所を config に書かないインスタンスでは、ADR 0096 の Decision「config に関所の socket を書いたときだけ有効にする」のとおり、何も出さない。

### 本 ADR で決定しないこと

- 宛先の許しの範囲の選択肢とその意味、既定、許されない名前、照合の決まり、断った名前を覚える数と日数（委譲先: natsumi-sentinel の ADR-0008 と仕様書 `docs/destination-grants.md`）。
- socket の上の欄と口の形（委譲先: natsumi-sentinel の仕様書 `docs/approvals-api.md` の「宛先の許し」）。
- 断った名前の一覧の 1 件に、内側の名前の印をどの欄で載せるか（委譲先: natsumi-sentinel の仕様書 `docs/approvals-api.md` の「宛先の許し」）。
- 画面のパスとフォームの欄、画面の並び（委譲先: この ADR の実装の PR）。
- ペネロペが宛先を先に頼むときのツールの説明（委譲先: 環境のリポジトリの運用の係の配置）。
- iPhone・Mac のアプリから答えること（委譲先: ADR 0096 と同じく、アプリの画面を見直すときの ADR）。

### 置き換える既存の決定

- ADR 0096
  - 改める: Decision「答えと取り消しは、Origin を照合するフォームの POST」の「サーバーは範囲の値と意味を持たない」に、「開かない」には読み書きの選択が無いことだけをサーバーが知る例外を足す。
  - 追加: Decision「画面に並べるもの」に、断った名前の一覧と、そこから宛先の許しを出すフォームを加える。状態を変える POST に、断った名前からの宛先の許しを加える。守りは答えと同じである。
  - 保つ: 窓口・守り・知らせ・`/sources` のファイル・モデルにツールを渡さないこと・config に書いたときだけ有効にすること。
- ADR 0049
  - 改める: ADR 0096 が足した読み取り専用の例外に、断った名前からの宛先の許しの POST を加える。

## Consequences

- 初めての宛先を、環境のリポジトリの振り分けを直さずに、本人が承認の画面から通せる。ペネロペが先に頼めば、その場で Web Push が届く。
- 断った名前では知らせないので、本人が画面を開かなければ、ペネロペが頼まずに引いた名前は通らないままになる。ペネロペが要る宛先は、先に頼むことに頼る。
- 断った名前からの許しには承認待ちが無いので、`/sources` にも記録が残らず、ペネロペは次に引いたときに通ることで分かる。ペネロペの側で待っている作業は、本人が会話で伝えるか、ペネロペが試し直すまで進まない。
- 宛先の許しは、操作の許しより広く効きうる（ドメインの下すべて、開かない）。広さの判断は、関所の文と本人の選択に頼る。画面は文を言い換えないので、文が分かりにくければ関所の側で直すことになる。
- サーバーが「開かない」と読み書きの関係を 1 つだけ知るので、関所がこの関係を変えれば、サーバーも直すことになる。
- 関所の版が古くても今の画面が動く代わりに、宛先の部分が出ない理由（関所の版か、断った名前が無いのか）は、画面からは区別しにくい。

## Alternatives Considered

- **断った名前のたびに承認待ちを作り、Web Push で知らせる**: 本人が頼んでいない名前（テレメトリの送り先など）で承認待ちと知らせが埋まる。関所の側でも採らなかった（natsumi-sentinel の ADR-0008）。
- **単位・扱い・読み書きを独立に選ばせ、ありえない組み合わせは関所の断りに任せる**: サーバーは範囲の意味を何も持たずに済むが、本人が選べるのに通らない組み合わせが画面に残る。
- **組み合わせごとの選択肢を関所が `choices` に並べ、画面はそれだけを並べる**: サーバーは範囲の意味を持たずに済むが、期限との組み合わせで選択肢が多くなりすぎる。関所の側で、期限だけを `choices` に分けた。
