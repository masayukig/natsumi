# 0018. 記憶を git で持ち、shell で読み書きし、夜に組み直す

- Date: 2026-09-18
- Status: Accepted（足すコマンドの列挙と `git` を入れないこと、1 コマンドの長さの上限の理由づけ、閉じ込めの条件のうち資源と `/tmp` と 1 コマンドの時間、ツールの説明の中身は [ADR 0019](0019-a-workspace-not-a-memory-tool.md) で置き換え、夜の再構成に作業場の棚卸しを同 ADR で追加、常時記憶の上限を書き込みのときに掛ける形と、夜の再構成を手順から候補に変えること、夜のモデル呼び出しの上限の値は [ADR 0020](0020-limits-at-write-time-and-a-nightly-menu.md) で置き換え、引き継ぎを切り替えの記録にどう残すかは同 ADR で具体化、夜に記憶を組み直すのをなつみから人格を持たない記憶の整理係へ移すこと、固定のファイルに書けるのは係だけの `INDEX.md` を加えること、係のコミットは検査に当たれば全部を捨てることは [ADR 0055](0055-a-memory-curator-at-night.md) で置き換え・追加、`personality.md` が無いときにアバターの `personality.md` を初期値として置くことは [ADR 0060](0060-a-personality-to-start-from-in-the-avatar.md) で追加、本人が自分でコミットした変更は検査の対象にしないことは [ADR 0067](0067-the-owner-commits-memory-over-ssh.md) で具体化）

## Context

[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md) で、長期記憶は data directory の `memory/` に置く平らな Markdown の置き場になった。
1 トピックが 1 ファイルで、記憶は日付付きの箇条書きの 1 行として `remember` で書き足す。
[ADR 0011](0011-memory-shell-in-a-confined-container.md) は、そこに読むための shell（`run_memory_shell`）を足した。

しばらく動かして、次のことが分かった。

- 記憶は 8 トピックになった。書けるのが 1 行の追記だけなので、どのファイルも時系列に積み上がる。
  同じことが言い方を変えて何度も並び、古くなった行も残る。なつみ自身、トピックの中を整理し直したいと記憶に書いていた。
- 記憶を作り直す手段がない。`remember` は 1 行足し、`forget` は 1 行消す。
  ファイルの統合・分割・改名、フォルダ分け、全文の書き直しはできない。
- 夜の切り替えは動いている。ただし引き継ぎは SQLite の中にしかなく、人が読むにも、変化を追うにも向かない。長さも 200 字に満たない。
- `personality.md` は雛形のままである。ADR 0009 が「読むだけで、編集するツールは作らない」と決めたので、なつみは自分では直せない。
- 記憶の全体は prompt に入れないと決めたので、本人の呼び方や口調のような毎回要ることも、毎回探し直すことになる。

つまり、なつみの「中身」は、追記できるが育たない置き場と、履歴の残らない雛形に分かれている。

外の方式を二つ見た。

- 毎回 prompt に入れる記憶を小さく固定し、満杯になったらモデル自身に整理させ、過去の会話は全文検索で引く形（Hermes Agent）。
- 記憶を多く持って検索で引き、定期の「夢」の処理で昇格・整理する形（OpenClaw）。

前者の「小さな常時記憶と、上限での整理」と、後者の「定期の組み直し」を採る。後者の全文検索は採らない。

書き込みを shell に許すかどうかも、決め直す必要があった。
ADR 0011 は、破壊半径と、汚れた内容が prompt に入ることを避けるために、記憶を読み取り専用にした。
一方で、`remember` という書き込みの道はすでにある。外部の入力が思考ループに入る以上、経路としての差は破壊半径と検査の時機だけであり、
その二つは git の履歴とコミットのときの検査で埋まる。

## Decision

### 記憶のリポジトリ

- 記憶・常時記憶・性格・夜の引き継ぎを、すべて Markdown にし、1 つの git リポジトリで持つ。なつみの中身が丸ごと履歴になる。
- 場所は設定 `loop.memoryRepository` にする。既定は data directory の `memory/` で、これまでと同じ場所である。
  オーナーが別の場所を bind mount して指してもよい。`natsumi-tools` のマウントも同じ場所に合わせる。
- 初回起動で、そこが git のリポジトリでなければ作る。ブランチ名は git の既定に任せず、サーバーが `main` を指定する。
- サーバーが行うのは commit だけである。**push も pull もしない。** リモートを設定するか、外へ出すかはオーナーが決める。
- 夜の引き継ぎは SQLite からファイルへ移す。新しい session の system prompt に入れる形は ADR 0009 のままである。
  ファイルにあるのは最新の 1 つで、過去のものは git の履歴にある。どの session がどの引き継ぎで始まったかは、
  これまでどおり SQLite の切り替えの記録に残す。再起動のときは、その記録と `handoff.md` から同じ system prompt を作り直せる。

### サーバーが固定する骨組みと、なつみの自由

サーバーが固定するのは、次の 3 つのファイル名と、それらがリポジトリの直下にあることだけである。

| ファイル | 中身 |
| --- | --- |
| `always.md` | 常時記憶。毎ターン prompt に入る |
| `personality.md` | 性格・話し方。session を作るときに prompt に入る |
| `handoff.md` | 夜の引き継ぎ。次の session の prompt に入る |

- それ以外は、なつみが決める。トピックの切り方、ファイル名、見出し、統合・分割・改名、サブフォルダの作り方は自由である。
- サーバーは中身の形を要求しない。ADR 0009 の「見出しと、日付付きの箇条書きの 1 行」も、トピック名から機械的にファイル名を作る規則も、やめる。
- 置けるのは `.md` のファイルとフォルダだけとする（検査で守る）。
- 人が手で置いたファイル、手で直したファイルも、同じように扱う。

### 常時記憶

- `always.md` の中身を system prompt に入れる。本人の呼び方、口調、いま続いていること、よく使う事実など、毎回要ることを、なつみ自身が短くまとめる。
- 上限は `loop.alwaysMemoryMaxChars`（既定 2000 文字）とする。日本語の 2000 文字は概ね 2〜3 千 tokens で、
  BASE_INSTRUCTION・性格・引き継ぎを足しても、compaction の上限（6 万 tokens）に対して十分小さい。
- 上限を超えていたら、中身を入れない。代わりに「常時記憶が上限を超えているので読み込んでいない。夜に削ること」を prompt に書く。
  途中で切り詰めない。切れた記憶は、誤って読まれるほうが害が大きい。
- 読み直すのはターンの終わりだけである。ターンの途中の書きかけを読まない。
  Pi の session は作るときに system prompt を固定するので、走っている session の instructions を差し替えられるかは実装で確かめる。
  差し替えられない場合、反映は次に session を作るとき（夜の切り替えと起動）になる。日中は常時記憶を書けない（後述）ので、実際に変わるのは夜と、オーナーが手で直したときだけである。
- 記憶の全体は、これまでどおり prompt に入れない。詳しいことは shell で探して読む。

### 記憶の読み書きを shell に一本化する

- `remember`・`recall`・`read_memory`・`forget` を廃す。記憶の読み書きは `run_memory_shell` だけで行う。
  - 道が二つあると、書ける形（1 行の追記）と書けない形（作り直し）が分かれたままになる。
  - ADR 0009 の `recall` は文字の重なりで探す近似で、`rg` のほうが強い。
  - 検査はコミットのときにまとめて行うので、書き込みのツールごとの検査は要らなくなる。
- `natsumi-tools` の記憶のマウントを読み書き可にする。その上に、`.git` を読み取り専用で重ねる。
  作業ツリーはすべて消せるが、履歴はモデルの手の届かないところに置く。消されても履歴から戻せる。
- 書き込みに要るコマンドとして `mkdir`・`mv`・`cp`・`rm`・`sed`・`awk` を足す。ファイルの中身は `sh` のリダイレクトでも書ける（`>` で書き直し、`>>` で追記）。
- `sed`・`awk` を入れてよい理由。ADR 0011 は、ファイルを書き換えられることと、`e` コマンド・`system()` で別のコマンドを動かせることの 2 つを理由に、この 2 つを入れなかった。
  - 前者は、この ADR で許す。記憶を書き換えられることが、そもそもの目的である。
  - 後者は、閉じ込めをコマンドの検査ではなくコンテナの形で掛けている（ADR 0011）ので、問題にならない。
    動かせるのは image に入っている一覧のコマンドだけであり、`sh` でできること以上は増えない。
  - `sed -i` は一時ファイルに書き切ってから rename するので、途中で止まったときの状態がリダイレクトの `>` よりよい。
    行の差し替えや削除に、ファイルの全文を書き直さずに済む。
  - Debian のパッケージでは GNU の `sed` と、`mawk` か `gawk` になる。どちらの `awk` を入れるかは実装で決めてよい。
- リダイレクトで書くときの注意。
  - `>` は先に中身を捨ててから書くので、途中で止まると空のファイルや書きかけのファイルが残り得る。
    空はターンの終わりの検査で直前のコミットの状態に戻り、書きかけがコミットされても、履歴から戻せる。
  - 1 コマンドの上限（8000 文字）より大きいファイルは、1 回では書き切れない。`>` で書き始め、`>>` の追記に分けて書く。
    1 ファイルの上限（32000 文字）まで書くには、数回に分かれる。部分的な直しは、`sed -i` で全文を書かずに済ませられる。
- `git` は `natsumi-tools` に入れない（ADR 0011 のまま）。コミットはサーバーが行う。
- 1 コマンドの長さの上限を、2000 文字から 8000 文字に上げる。ファイルを 1 回で書き直すには 2000 文字では足りない。
  runner が受け取る 1 行の JSON の上限（16 KiB）の中に収まる。
- 閉じ込めの他の条件は変えない。ネットワークなし、記憶以外のマウントなし、ルートは読み取り専用、書けるのは 16 MB の `/tmp` だけ、
  非 root、capability なし、`no-new-privileges`、CPU 1・メモリ 256 MB・プロセス 64、1 コマンド 10 秒、出力 64 KiB。
- ツールの説明を書き直す。使えるコマンド、記憶を書けること、書いたものはターンの終わりに検査してコミットされること、
  常時記憶と性格は夜だけ書けること、時間と出力に上限があることを書く。

### 書き込みの時間

- 記憶のファイルは、日中も夜も shell で読み書きできる。
- `always.md` と `personality.md` だけは、夜の再構成（`nightly_review` のターン）の間しか書けない。
  日中のターンでこの 2 つが変わっていたら、コミットのときに直前のコミットの状態へ戻し、理由を次のターンの入力で伝える。
  - この 2 つは毎ターン prompt に入る。会話の途中で書き換えさせると、同じ日のうちに自分の前提が変わる。
  - 性格の変更を夜の 1 コミットにまとめると、オーナーが差分で見守りやすい。会話の流れでうっかり書き換わることも避けられる。
- `handoff.md` は、夜の振り返りで `write_handoff_note` が書く。shell からは他のファイルと同じに扱う（日中も書けるが、書く理由はない）。
- マウントの権限では分けない。夜だけ書けるようにするために別のマウントを用意すると、閉じ込めの形が増える。検査で戻すほうが、他の検査と同じ道で済む。

### コミットと、そのときの検査

- 記憶に変更があったターンの終わりごとに、サーバーが 1 コミットする。夜の再構成も 1 コミットになる。
- 順序は、ターンが終わる → 変更されたファイルを検査 → 当たったものを戻す → 残りをコミット → 常時記憶を読み直す → 次のイベント、とする。
  ターンの途中ではコミットしない。shell のコマンドは 1 つずつ順に実行する（ADR 0011 のまま）ので、コミットは必ずコマンドとコマンドの間の状態を撮る。
- ターンがモデル呼び出しの上限や時間切れで終わったときも、同じ検査をしてコミットする。書きかけを捨てるより、履歴に残して戻せるほうがよい。
- 検査は ADR 0009 の記憶の検査を引き継ぎ、ファイル単位で行う。次のどれかに当たったファイルは、直前のコミットの状態に戻す。
  新しく追加されたファイルは、戻す先がないので消す。
  - `.md` 以外のファイル、symlink
  - 空（空白だけ）
  - 大きすぎる（1 ファイル `loop.memoryFileMaxChars`、既定 32000 文字）
  - テンプレートの制御文字列、制御文字
  - 日本語以外の文字（ハングルと、日本語で使わない簡体字の一覧。本人に届く出力の検査と同じもの）
  - 日中のターンでの `always.md`・`personality.md` の変更
- 戻したファイルと理由は、次のターンの入力に添える。なつみは理由を読んで書き直せる。
  夜の再構成で戻した場合は次のターンがないので、新しい session の system prompt に、引き継ぎと並べて書く。
- なつみが作ったファイルの削除と改名は検査しない。全部消しても通るが、履歴から戻せる。名前もトピックの切り方も
  なつみのものなので、消すのも名前を変えるのも同じくなつみが決めてよい。
- 固定の 3 つ（`always.md`・`personality.md`・`handoff.md`）だけは、削除も改名も戻す。この 3 つは中身ではなく
  **名前と、リポジトリの直下にあること自体をサーバーが固定している**もので、サーバーはそこにあるものとして prompt を組む。
  消えても誰にも知らされないまま前提が崩れるので、他のファイルと同じには扱えない。戻した理由は、他の検査と同じく次のターンの入力に添える。
- 日中のコミットメッセージは、サーバーが機械的に付ける（イベントの種類と、変わったファイル）。
- 夜のコミットメッセージは、なつみが書く。振り返りのターンで `write_change_note(note)` に、何をどう組み直したかを書かせ、サーバーがそれをコミットメッセージにする。
  本人に届く出力と同じ検査（空、長さ、テンプレートの制御文字列、日本語以外の文字）を掛け、当たれば書き直させる。
  書かれないまま終わったら、サーバーが機械的なメッセージを付ける。コミットメッセージが無いことを理由に、夜を失敗にはしない。
- author と committer はサーバーが固定する。git の hook は実行しない設定で呼ぶ。

### git を実行するのは誰か

- natsumi のコンテナに git の CLI を入れ、サーバーが子プロセスとして実行する。
  - 記憶のリポジトリは、オーナーが自分の git で pull・push し、手で直すものである。サーバーが作る履歴は、本物の git が作るものと同じでなければならない。
    CLI なら実装が git そのもので、オブジェクトの詰め直しや設定の解釈も git に従う。
  - JavaScript の実装（isomorphic-git など）は依存が 1 つ増え、オブジェクトの掃除や差異を自分で見ることになる。記憶は長く積み上がるので、そこは git に任せたい。
  - natsumi のコンテナはモデルの shell の対象ではない（ADR 0011）。git を入れても、モデルの手には渡らない。
- `natsumi-tools` には git を入れない（ADR 0011 のまま）。

### 夜の再構成

- 形は ADR 0009 のままとする。決まった時刻に、その日の session の末尾で振り返りのターンを行い、新しい session に切り替える。
  切り替えの手順、失敗の扱い、切り替え中のメッセージとアバターの扱いも変えない。
- 指示を「今日のことを書き足す」から「記憶全体を読み直して組み直す」に変える。順序は次のとおりとする。
  1. 記憶全体を読み直す。
  2. 今日のことのうち残すものを書き、重複と古くなったものを直す。
  3. トピックの統合・分割・改名と、フォルダの整理を行う。
  4. `always.md` を見直す。上限を超えていると伝えられていたら、削る。
  5. `personality.md` を見直す。変えたいところがあれば直す。
  6. `write_handoff_note` で、明日の自分への引き継ぎを書く。
  7. `write_change_note` で、今夜の変更の説明を書く。
  8. `finish_event` で終える。本人には何も送らない。
- このターンのモデル呼び出しの上限を 16 回から 40 回へ、時間を 10 分から 30 分へ上げる（`loop.reviewModelCalls`・`loop.reviewTimeoutMinutes`）。
  読み直しと書き直しに、ファイルの数だけコマンドが要るためである。上限に達しても、そこまでの変更は検査してコミットする。
- 結果はオーナーに知らせない。オーナーは git の履歴で見る。

### 性格

- `personality.md` は、なつみ自身が夜に書き換えてよい。ADR 0009 の「読むだけで、編集するツールは作らない」を置き換える。
- オーナーは差分で見て、気に入らなければ直すか、コミットを戻す。
- 性格も検査の対象である。当たれば戻る。反映は、次に session を作るときである。

### 移行

初回起動で、`loop.memoryRepository` がまだ git のリポジトリでなければ、次を行って 1 つの最初のコミットにする。

1. その場所にリポジトリを作る。
2. いまの `memory/` の Markdown を、名前も中身も変えずに取り込む。
3. data directory の `personality.md` を、リポジトリの直下へ移す。
4. `always.md` の雛形を置く。書き方の見出しだけの、ほとんど空のファイルとする。
5. SQLite にある最新の引き継ぎを `handoff.md` に写す。
6. 以上を最初のコミットにする。

- 中身の作り直し（トピックの統合や、常時記憶を埋めること）はサーバーがやらない。最初の夜に、なつみが行う。
- すでにリポジトリになっていれば、足りない 3 つのファイルを作るだけにする。

### 設定

`loop` 節に足す。すべて省略でき、省略時は既定値を使う。

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `memoryRepository` | data directory の `memory/` | 記憶のリポジトリの場所 |
| `alwaysMemoryMaxChars` | `2000` | 常時記憶がこれを超えたら prompt に入れず、警告を書く（文字数） |
| `memoryFileMaxChars` | `32000` | 1 ファイルの上限。超えたファイルは直前のコミットに戻す（文字数） |
| `reviewModelCalls` | `40` | 夜の再構成のターンのモデル呼び出しの上限 |
| `reviewTimeoutMinutes` | `30` | 夜の再構成のターンの時間の上限 |

### 範囲外

- 過去の会話の全文検索は入れない。思い出す道は記憶のファイルだけにする。session の記録は、これまでどおり思考の記録として残り、夜に切り替わる。
- Slack を通じて記憶が漏れる問題は、ADR 0011・[ADR 0012](0012-slack-and-colleagues.md) の前提のままとする（本人以外に届く出力は本人の承認で止める）。書き込みを許したことで、この前提は変わらない。
- リモートへの push、バックアップ、暗号化は、オーナーの運用に任せる。

### 置き換える既存の決定

- ADR 0009
  - 置き換え: 記憶の置き方とファイル名の作り方、記憶の 4 つのツール、書き込みのたびの検査、`personality.md` は読むだけという点、
    引き継ぎを SQLite に保存する点、夜の振り返りの指示とその上限。
  - 残す: 夜に session を切り替えること、その手順・失敗の扱い・切り替え中の振る舞い、引き継ぎを新しい session の system prompt に入れること、
    上限での compaction、記憶の全体を prompt に入れないこと（常時記憶だけは入れる）。
- ADR 0011
  - 置き換え: 記憶を読み取り専用でマウントすること、`sed`・`awk`・`rm` を入れないこと（`e` コマンドと `system()` を避けるという理由も含めて置き換える）、記憶の書き込みはサーバーのツールで行うこと、
    ツールの説明の中身と、1 コマンドの長さの上限。
  - 残す: コンテナの形と閉じ込めの条件、runner と呼び出し方、コマンドを 1 つずつ実行すること、`natsumi-tools` に git を入れないこと。
- ADR 0004
  - 置き換え:「Wiki と記憶に必要な読み書きは、対象ルートと操作を制限する独自ツールとして後続実装する」のうち、記憶の部分。
    記憶の読み書きは、ADR 0011 の閉じ込めたコンテナの shell に一本化する。Wiki は変えない。
- ADR 0008
  - 置き換え: 登録するツールの一覧。記憶の 4 つを外し、`write_change_note` を足す。

## Consequences

- なつみの中身が丸ごと git の履歴になる。オーナーは差分で見守り、気に入らなければ直すか戻せる。
  反面、履歴には本人の私的なことが全部残る。リポジトリは個人データであり、リモートを作るなら private でなければならない。
- サーバーは push しないので、ディスクが壊れれば記憶は失われる。バックアップは、これまでどおり state.sqlite と Pi の session 領域と一組で、オーナーが行う。
- 記憶を消す・壊すコマンドが通る。ターンの終わりまで壊れた状態が残るが、コミットされるのは検査を通ったものだけで、履歴から戻せる。
  `.git` を読み取り専用で重ねるので、履歴そのものは壊せない。
- 検査はファイル単位なので、大きな書き直しの中に 1 文字の混入があると、そのファイルの変更が丸ごと戻る。理由は伝わるので書き直せるが、夜だと次の夜まで戻ったままになる。
- 記憶の読み書きが `natsumi-tools` に依存する。runner が落ちている間や、その設定のない開発の環境では、記憶を読むことも書くこともできない。
  ADR 0011 までは `remember`・`recall` がサーバー側にあったので、shell が無くても記憶は使えた。
- 常時記憶の分だけ、毎ターンの入力が増える（既定で最大 2000 文字）。上限を超えると常時記憶は丸ごと入らないので、夜に削るまで、毎回探し直すことになる。
- 日中の記憶は、これまでどおり追記になりやすい。まとまりが育つかどうかは、夜の組み直しでのモデルの判断に依存する。うまくいかなくても、履歴で確かめられる。
- 夜のターンが長くなる（最大 30 分、モデル呼び出し 40 回）。その間に届いた本人のメッセージは待つ。深夜の時間帯だが、モデルの利用は増える。
- コミットが 1 日に数回から数十回増える。記憶は小さいので容量は問題にならないが、リポジトリは消さない限り伸びる。
- natsumi の image に git が入り、少し大きくなる。`natsumi-tools` には 6 つのコマンドが増え、書ける範囲が変わるので、閉じ込めの実測は作り直す。
- 記憶のファイルの形が自由になるので、人が読むときの読みやすさも、なつみの書き方次第になる。サーバーは形を直さない。
