# 0049. ブラウザで見る読み取り専用のダッシュボードを、サーバー自身が配る

- Date: 2026-09-27
- Status: Accepted（画面に並べるものに、なつみの作業環境・記憶・マニュアルのファイルを読み取り専用で見る閲覧を加えることと、そのための Markdown の整形の依存は [ADR 0054](0054-her-files-on-the-dashboard.md) で追加、ターンの種類に記憶の整理係のターンを加え、統計には混ぜないことは [ADR 0055](0055-a-memory-curator-at-night.md) で追加、「足りなくなったら作り方を決め直す」をチャットと設定の画面のために決め直し、cookie を `natsumi_session`・`Path=/` に置き換えることは [ADR 0058](0058-settings-and-chat-in-the-browser.md) で改める。ダッシュボードの中の読み取り専用は保つ）

## Context

なつみが各ターンで何をしたかは、今は外から見にくい。
ターンの中身（届いた出来事、思考、ツールの呼び出しと結果、返事、一行メモ）は Pi の session のファイル（JSONL）にだけある（[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md)）。
数値はターンごとに `turn_stats` に 1 行あるが、本文は持たない（[ADR 0047](0047-folding-ended-turns-with-a-memo.md)）。
本人は、ブラウザで `<公開オリジン>/dashboard` を開き、ターンの一覧から詳細（ツールの呼び出しとメッセージ）までを見たいと考えた。
あわせて、ターン以外にも見えると役に立つ状態を並べたい。

手元の事情は次のとおりである。

- ログインは GitHub OAuth で、許可するのは `github.allowedUserId` の 1 人だけである。セッションは `Authorization: Bearer` の token で、**cookie は使わない**と決めている（[ADR 0006](0006-github-login-and-transport.md)。寿命は [ADR 0030](0030-a-session-that-lasts-while-it-is-used.md)）。
  ログインの戻り先はアプリの URL scheme に固定されていて、ブラウザ向けの戻り先は無い。
  ブラウザの WebSocket には Authorization ヘッダーを付けられない。
- 本番は Kubernetes にあり、Ingress には認証を掛けない。認証はすべてサーバーが持つ（[ADR 0033](0033-running-on-kubernetes.md)）。
- HTTP は `node:http` の素のハンドラで、フロントエンドのビルドの仕組みは無い。
- `turn_stats` には、そのターンが JSONL のどこにあるかを示す列が無い。ターンの境目を JSONL だけから組み立てると、失敗したターンや、途中に差し込まれた本人のメッセージで境目がずれる。
  夜の振り返りのターンは、`turn_stats` に行を作らない。
- JSONL は追記だけで縮まず、夜の切り替えで新しいファイルになる（`session_rotations` で辿れる）。最後の行が書きかけのことがある。
  HTTP の処理の中で同期にファイルを全部読むと、思考ループと WebSocket を止める。
- 実行中のターン、出来事のキュー、その場の文脈の大きさは、思考ループのメモリの中にしかない。
- JSONL には、思考、ツールの結果（記憶・Slack・ファイルの中身）、本人の発言、画像まで、個人データが全文で入っている。

設計は grill-me（Q1〜Q8）で詰めた。

## Decision

### ブラウザのログインは既存の GitHub ログインで、cookie に載せる

- ブラウザでも、ログインは既存の GitHub OAuth で行う。state・PKCE・数値 ID と `allowedUserId` の照合は、アプリのログインと同じである。GitHub OAuth App に登録する callback も同じものを使う。
- ブラウザ向けのログインは、ダッシュボードの入口から始める。照合に成功したら、ブラウザ向けの固定のパス（`/dashboard`）に戻す。戻り先はコードに固定し、設定にもリクエストにも依存させない。open redirect にしないためである（ADR 0006 のアプリの戻り先と同じ考え方）。
- ログインの状態は cookie に載せる。属性は `HttpOnly`・`Secure`・`SameSite=Strict`、`Path=/dashboard` とする。
  - 中身はアプリと同じ形のセッションである。SQLite にはハッシュだけを持ち、検証のたびに `allowedUserId` との一致を確かめる。寿命と延長もアプリのセッションと同じ規則（最後に使ってから 30 日、使うたびに延びる）に従う。ブラウザだからといって短くはしない。これは本人が決めた。
  - `Path=/dashboard` なので、cookie は `/v1/ws` や `/v1/images/` などアプリの口には送られない。アプリの口は、これまでどおり bearer token だけを受け付け、cookie を見ない。
- **ダッシュボードは読み取り専用とする。** 状態を変える操作（承認、経路や畳み込みの切り替えなど）は置かない。cookie を自動で送るブラウザで起こり得る CSRF の余地を、`SameSite=Strict` と合わせて小さくするためである。
- 例外はログアウトだけである（本人の決定）。`/dashboard` の下の POST で、そのブラウザのセッションだけを失効させ、cookie を消す。ほかのセッション（アプリのものを含む）には触らない。
  - CSRF は、Origin ヘッダーが `publicOrigin` と一致することの照合と、`SameSite=Strict` で防ぐ。Origin が無いか一致しない POST は断る。
- 自動更新は WebSocket ではなく、`/dashboard` の下のポーリングか SSE で行う。cookie がそのまま届き、ADR 0006 の WebSocket の検証（Origin と bearer token）を変えずに済む。

これは ADR 0006 の「cookie は使わない」に対する、**ブラウザのダッシュボードに限った例外**である。
ADR 0006 が cookie を避けた理由（ブラウザが自動で付けるので、CSRF や別サイトからの WebSocket の余地が生まれる）には、読み取り専用（例外はログアウトの POST だけで、Origin を照合する）・`SameSite=Strict`・`Path=/dashboard` で応える。

退けた案:

- **token をページの JS で持ち、Authorization に付ける**: XSS が一度でも起きれば token を盗まれる。`HttpOnly` の cookie なら JS から読めない。
- **Ingress の側で認証を掛ける**: ADR 0033 の「Ingress には認証を掛けない」を改め、認証の部品が増える。許可ユーザーの照合もサーバーとの二重になる。

### ターンの中身は全文で見せる

- 見せるのは、思考、ツールの呼び出しの引数と結果、返事、一行メモの全文である。要約はしない。なぜそう動いたかを追うのが目的だからである。
- 長いツールの結果（目安 2KB 超）は、既定で畳み、クリックで開く。
- 画像は、ダッシュボード用の認証付きの URL（`/dashboard` の下、cookie で認証する）で出す。
- 見るのは許可ユーザー 1 人だけである。見せる相手が増えることは想定しない。

退けた案:

- **思考とツールの結果は要約だけ見せる**、**思考だけ既定で隠す**: どちらも、なぜそう動いたかを追うという目的に合わない。

### ターンと JSONL を、`turn_stats` の列で対応付ける

- これからのターンは、`turn_stats` に対応付けの列を足す。session のファイル、そのターンの最初と最後のエントリの ID、ターンの出来事の ID（途中で差し込まれた出来事を含む）である。
- 夜の振り返りも 1 ターンとして `turn_stats` に行を作る。種類で普通のターンと見分けられるようにする。
- 列を足す前のターンは、時刻と JSONL の `<events>` の区切りから推定して対応付け、画面では「推定」と印を付けて出す。
- `turn_stats` が持つのは位置だけであり、本文は持たない。ADR 0047 の「`turn_stats` は本文を持たない」「同じ記録を二重に持たない」は保たれる。

退けた案:

- **すべて JSONL の区切りから組み立てる**: 失敗したターンや差し込みで境目がずれる。
- **列を足す前のターンは出さない**: 導入より前の振る舞いが見えなくなる。

### natsumi のサーバー自身が配る

- `/dashboard` は natsumi のサーバーが配る。ログイン、セッション、許可ユーザーの照合をそのまま使う。
- ターンの一覧は SQLite だけで組む。
- ターンの詳細は、JSONL を `turn_stats` の位置から、非同期に必要な分だけ読む。同期でファイルを全部読むことはしない。思考ループと WebSocket を止めないためである。書きかけの最後の行は読み飛ばす。
- いまの状態（実行中のターン、出来事のキュー、その場の文脈の大きさなど）は、思考ループに読み取り用の狭い口を足して出す。この口から思考ループの状態は変えられない。

退けた案:

- **同じ Pod の別コンテナで配る**: ログインを二重に持つことになり、思考ループのメモリの中の状態が見えない。

### 画面はサーバーで HTML を組み、ビルドしない

- 画面は、サーバーで HTML を組んで返す。フロントエンドのビルドは持たない。
- 埋め込む値はすべてエスケープする。JSONL の中身はなつみや外から来た文字列なので、マークアップとして解釈させない。
- 畳みは `<details>` で行う。
- JS は自動更新のための小さな静的ファイルだけにする。CSP は `script-src 'self'` とし、inline の script を許さない。あわせて `frame-ancestors 'none'` とし、ほかのページの枠の中に表示させない（クリックジャッキングを防ぐ）。
- グラフもサーバーで SVG を描いて HTML に埋め込む。JS は使わない。
  - 時系列の折れ線か棒で、返事までの時間の p50・p90、モデルの呼び出しの回数、tokens、打ち切りの回数を出す。
  - 期間は 24 時間、7 日、30 日から選ぶ。
  - 点の値は SVG の `<title>` で出し、グラフの下に同じ数値の表を置く。
- この作り方で足りない、作り込みが要る機能が出てきたら、その機能の時点で作り方（JSON の API とビルドする SPA、ビルドなしの素の JS など）を改めて決める。

退けた案:

- **グラフを JSON の API と同梱の JS のグラフライブラリで描く**: 依存と JS が増え、CSP とエスケープで守る範囲が広がる。

### 画面に並べるもの

最初の版から、次のすべてを入れる。

- ターンの一覧と詳細（上の「全文で見せる」のとおり）。
- いまの状態の欄。モデルの経路（ADR 0046）、畳み込みの on/off（ADR 0047）、サーバーの生死、実行中のターン、出来事のキュー、文脈の大きさなど。
- 失敗と待ちの一覧。失敗した出来事、承認待ち、自分で予約した確認（self-check）、外のエージェントへの依頼、夜の切り替え。
- 統計のグラフ（上の「グラフ」のとおり）。
- 一行メモ、ポッポさんの投稿、端末の一覧。

### ADR との関係

- ADR 0006
  - 例外の追加: ブラウザのダッシュボードに限り、ログインの状態を cookie（`HttpOnly`・`Secure`・`SameSite=Strict`・`Path=/dashboard`）に載せる。
  - 追加: ブラウザ向けのログインの戻り先（コードに固定の `/dashboard`）と、ダッシュボードのログアウト（Origin を照合する POST）。
  - アプリの口（`/v1/ws` など）の認証は変えない。
- ADR 0033
  - 変えない: Ingress には認証を掛けない。ダッシュボードの認証もサーバーが持つ。
- ADR 0047
  - 追加: `turn_stats` の対応付けの列（session のファイル、最初と最後のエントリの ID、出来事の ID）と、夜の振り返りの行。
  - 保つ: `turn_stats` は本文を持たない。

## Consequences

- 本人は、ブラウザでターンごとの思考・ツール・返事を全文で追える。一行メモと畳み込みの効果も、元のターンと並べて確かめられる。
- 思考やツールの結果を含む個人データの全文が、ブラウザに出るようになる。守りは、GitHub ログインと許可ユーザー 1 人の照合、`HttpOnly` の cookie、全エスケープと CSP である。[権限と秘密の一覧](../permissions.md)に入口を足した。
- ブラウザの端末にセッションが 1 つ増える。アプリのセッションと同じく、`allowedUserId` を変えれば使えなくなる。
- `SameSite=Strict` の cookie は、GitHub から戻る redirect の続きの移動では送られない。ログインの直後は、サーバーが同じオリジンのページを一度返してから `/dashboard` に移るなど、実装で手当てが要る。
- 列を足す前のターンは推定なので、境目がずれることがある。画面の「推定」の印で見分ける。
- 夜の振り返りの行が `turn_stats` に入るので、`stats` の集計は種類で普通のターンと分ける必要がある。
- 詳細を開くたびに JSONL を読む。位置から必要な分だけ読むので、ファイルが大きくなっても 1 回の読みは 1 ターン分に収まる。
- ダッシュボードで状態を変えられるのは、自分のセッションのログアウトだけである。経路や畳み込みの切り替え、承認はこれまでどおりアプリとコマンドで行う。

### 進め方

1 人が次の順に PR を出す。本番への反映は、2 と 3 がそろった時点で一度行い、本人がブラウザで確かめる。

1. この ADR と、権限と秘密の一覧の更新。
2. 土台: ブラウザのログイン（`/dashboard` の戻り先と cookie）、CSP、骨組み、いまの状態の欄。
3. ターン: `turn_stats` の列と夜の振り返りの行（migration）、一覧、詳細（JSONL を位置から読む。前のターンは推定）。
4. 失敗と待ち、一行メモ、ポッポさん、端末の一覧。
5. 統計のグラフ。
