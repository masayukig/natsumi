# 0066. Pi の Codemode で、作業環境の生の出力を文脈に入れずに済ませる

- Date: 2026-10-03
- Status: Accepted（「本人に見えること、外に出ることは、モデルが直接呼ぶ」と「スクリプトから呼べるのは作業環境の 3 つだけ」は組み込みのツールに限り、config で宣言したツールの見え方は config を書く人の判断に移すことを [ADR 0075](0075-tools-declared-in-the-config.md) で一部覆す）

## Context

なつみの文脈を伸ばしているのは、作業環境のツールの出力である。
[ADR 0047](0047-folding-ended-turns-with-a-memo.md) の集計では、過去のターンの思考の次に大きい塊が `run_shell` の結果だった。
畳み込みは終わったターンにしか効かないので、1 ターンで何度も呼ぶ重いターンの途中経過は、そのターンの間は積まれる。
長い `rg` や `ls` の出力、記憶を何か所も読んで照らし合わせる、`sdctl` で描いて `view` で見る、といったターンがこれに当たる。
上限を超えれば compaction が走り、prefix cache を全部外す（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md)）。

Pi は 0.99.0 で Codemode を入れた。なつみが使っているのは 0.87.1 で、まだ無い。要点は次のとおりである。

- `codemode` という**ツールが 1 つ増える**。モデルはその入力に JavaScript を書き、スクリプトの中から他のツールを呼ぶ。
- **モデルに返るのは、スクリプトが出力したものだけ**である。大きな結果は、スクリプトの中で絞ってから返せる。並列や連鎖も 1 回の呼び出しにまとまる。
- スクリプトは QuickJS（WASM）で動く。ファイル・ネットワーク・タイマーには触れず、外に触れる手段はツールと、Pi が渡す `models`（分類器と画像生成）だけである。
  プロセスは分けていないので、スクリプトから呼んだツールは、モデルが直接呼んだときと同じ権限で動く。途中で失敗しても、それまでの呼び出しは取り消されない。
- ツールごとに見え方（exposure）を決められる。
  - `direct`（既定）: モデルから直接も、スクリプトからも呼べる
  - `model-only`: モデルから直接だけ呼べる
  - `codemode`: モデルからは見えず、スクリプトからだけ呼べる
  - ほかに `deferred` と `hidden` がある
- mode は `"on"` と `"only"` がある。`"only"` では、codemode 以外のツールがモデルから隠れる。
- スクリプトから呼べるツールの説明は、TypeScript の宣言として codemode の説明に載る。説明はツールの集合と順序で決まる。
- スクリプトの中の呼び出しも、`tool_call`・`tool_result` の hook を通る。呼び出し元を示す `parentToolCallId` が付く。
  ただし session の記録には toolCall・toolResult として残らない。codemode の結果に、中の呼び出しの一覧（名前・引数・状態・時間。結果は無し）が付くだけである。
- スクリプトの中で値を持ち越す `store()`・`load()` がある。値は session に残り、session を替えると消える。
- ターンの abort はスクリプトとその中の呼び出しに伝わる。スクリプトの時間の上限は、既定では無い。

なつみの側の事情は次のとおりである。

- Pi の拡張は、コードから渡したものだけを読み込む（ADR 0047）。ツールは許可リストで明示する（[ADR 0004](0004-pi-tool-and-voice-boundaries.md)）。
- 副作用（SQLite への記録、配信、二重送信の防止）は、どれもツールの実行の中で同期して行っている。スクリプトの中から呼ばれても、同じ保証が効く。
- 1 ターンの上限は、モデルの呼び出しの回数（既定 8 回）と時間（10 分）である（[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md)、[ADR 0024](0024-no-event-ids-for-the-model.md)）。
  スクリプトの中の呼び出しはモデルの呼び出しではないので、この上限には数えられない。
- モデルの経路は、同じ session のまま本人が手で切り替える（[ADR 0046](0046-named-model-routes-switched-by-hand.md)）。
- 本人のエンドポイントのモデルは prefill が遅く、system prompt とツールの定義は session の間は動かさない。
- 夜の整理係は、`run_shell`・`read`・`search_memory` と変更の説明を書くツールだけを持ち、ファイル操作を繰り返す（[ADR 0055](0055-a-memory-curator-at-night.md)）。

目的は **文脈の節約**である。生の出力を文脈に入れずに済ませ、compaction の頻度を下げる。
往復の回数が減るのは副次の効果とする。物差しは、1 ターンで増える文脈の tokens と compaction の回数である。

設計は grill-me（Q1〜Q9 と、質問せずに既定とした事項）で詰めた。

## Decision

### 本体と整理係で、別々に入り切りする

- Codemode は、なつみの本体の session と整理係の session のそれぞれで、設定で on/off する。既定は off である。
- 入り切りの単位は**プロセス**である。設定で決め、変えるにはサーバーを再起動する。
  [ADR 0047](0047-folding-ended-turns-with-a-memo.md) の畳み込みのような、動いているサーバーでの切り替えは持たない。
- 経路ごとには入り切りしない。経路の切り替えは同じ session のまま行うので、経路ごとに codemode を出し入れするとツールの集合が変わり、そのたびに prefix が壊れる。
  ある経路で質が出なければ、その経路を使う間は設定で off にする。

### ツールの見え方

| ツール | 見え方 |
|---|---|
| `reply_to_mac`・`notify_owner`・`set_mac_avatar_expression` | `model-only` |
| `write_handoff_note`・`write_change_note` | `model-only` |
| `ask_agent` | `model-only` |
| `schedule_self_check`・`list_self_checks`・`cancel_self_check` | `model-only` |
| `run_shell`・`read`・`search_memory` | 設定で `direct` か `codemode`（スクリプトからだけ）を選ぶ |

- 本人に見えること、外に出ることは、モデルが直接呼ぶ。スクリプトの条件分岐で、返事が出たり出なかったりするのを避ける。
  畳み込みが残す呼び出し（返事・知らせ・`ask_agent`）が toolCall として記録に残る、という前提も保たれる。
- `ask_agent` を並列に投げる利点はあるが、相手への依頼文はモデルが書くものである。頼みすぎの歯止めもスクリプトの外に置いたままにする。
- 夜のメモと予約は決まった手順で、まとめる利点が無い。
- スクリプトから呼べるのは、作業環境の 3 つだけになる。新しく外へ出る道は増えない。
- 作業環境の 3 つを `direct` にするか `codemode` にするかは、評価で決める（下の「評価と、本番に入れる順」）。
  `direct` ならモデルは単純な 1 回の呼び出しを直接でき、`codemode` なら生の出力が文脈に入る道が無くなる。どちらが文脈を減らし、質を保つかは、本物の経路で比べないと分からない。

### mode は `"on"` にする

- 「スクリプト経由だけ」は、作業環境の 3 つの見え方を `codemode` にすることで実現する。`"only"` は使わない。
- `"only"` は codemode 以外のツールをすべてモデルから隠す。`model-only` にした返事や知らせまで隠れる。

### スクリプトの中の呼び出しに、ターンごとの上限を設ける

- スクリプトの中の呼び出し（`parentToolCallId` を持つもの）を、`tool_call` の hook でターンごとに数える。上限を超えた呼び出しは断る。
- 上限は設定で変えられる。本体の案は 1 ターン 40 回である。
- ターンの時間の上限はそのままにする。abort はスクリプトとその中の呼び出しに伝わるので、スクリプトに別の締め切りは与えない。
  `sdctl` の画像生成は数分かかるので、短い締め切りは邪魔になる。
- codemode を呼んだモデルの呼び出しは、モデルの呼び出しの上限にこれまでどおり 1 回と数える。
- 振り返り中に全ツールを断る hook は、codemode とスクリプトの中の呼び出しにも効く。

### Pi の `models` と `store()` は使わない

- `models`（分類器と画像生成）は渡さない。目的の文脈の節約の範囲外である。画像は [ADR 0044](0044-drawing-with-sdctl-and-posting-images.md) のとおり作業環境の `sdctl` で作る。
- `store()`・`load()` は使わせない。値は夜の session の切り替えで消える。記憶の正本は、これまでどおり Markdown である。system prompt でも触れない。

### Pi の版上げを先に分けて出す

- Pi を 0.87.1 から 1.0.1 に上げる変更を、Codemode と分けて先に出す。版上げだけで本番に入れて様子を見てから、Codemode を入れる。
  版上げの不具合と Codemode の不具合を混ぜないためである。
- 版上げでは、既存の session の記録を新しい版で再開できること、評価の結果が変わらないことを確かめる。

### 評価と、本番に入れる順

- [ADR 0051](0051-evaluating-one-turn-on-the-real-path.md)・[ADR 0052](0052-trying-a-turn-on-a-copy-of-production.md) の評価の仕組みに、作業環境を使う固定の場面（記憶を探す、描いて見る、など）を足す。
- 本人のエンドポイントの経路（README の例の `local`）で、off・`direct`・スクリプト経由だけ の 3 つを比べる。
- 見るものは、1 ターンで増える文脈の tokens、スクリプトの失敗率、返事の質である。
- 本番では、まずなつみのインスタンスだけを on にする。様子を見てから、ミャオのインスタンスに広げる。戻すときは設定を off にして再起動する。

### 置き換える既存の決定

- ADR 0004
  - 追加: Pi の `tools` の許可リストに `codemode` を加えうる。設定で on にしたときだけで、off なら許可リストは変わらない。Codemode の拡張は、コードから渡す拡張の一つとして読み込む。
  - 残す: 許可リストを明示すること、拡張をコードから渡すものに限ること、任意の HTTP を許さないこと。スクリプトの実行環境はファイルにもネットワークにも触れず、呼べるのは許可リストのツールだけである。
- ADR 0008
  - 追加: ターンの上限に、スクリプトの中の呼び出しの回数を加える。モデルの呼び出しの回数と時間の上限は変えない。
- ADR 0047
  - 追加: 読み直しの指標に、codemode の結果に付く中の呼び出しの一覧の `run_shell`・`read` を数える。スクリプトの本文が前と同じ codemode の呼び出しも数える。
- ADR 0055
  - 追加: 整理係のツールに、設定で on にしたとき `codemode` が加わる。入り切りは本体と別の設定である。

## Consequences

- 作業環境の結果をスクリプトの中で絞れば、生の出力は文脈に入らない。1 ターンで増える文脈が減り、compaction の頻度が下がる見込みである。効果は評価と本番の統計で確かめる。
- 畳み込みでは、codemode の呼び出しと結果は `run_shell` と同じく「残さないツール」として畳まれる。返事などは `model-only` なのでスクリプトの中から呼ばれず、残すツールの前提は崩れない。
  一方、スクリプトの中で `read` で読んだものは、畳んだ後に残らない。「既に読みました」の比べる相手にもならない。
- スクリプトの中の呼び出しは session の記録に toolCall として残らない。ダッシュボードや夜の振り返りで、中で何を呼んだかは一覧（名前・引数・状態）でしか分からず、結果は見えない。
- codemode を on にすると、ツールの定義に codemode が 1 つ増え、その説明に作業環境のツールの宣言が載る。入り切りと見え方の切り替えは、どれも再起動を伴い、新しい session まで prefix cache が一度外れる。
  見え方を固定すれば説明も固定になる。prefix の検査には codemode を含めた並びを加える。
- 本人のエンドポイントの経路（OpenAI 互換の Chat Completions）では、スクリプトを JSON の文字列の引数として書くことになる見込みである。エスケープの崩れや JavaScript の質が採否を分ける。実際の届き方は実装のときに測る。
- スクリプトの中の呼び出しは、途中で失敗しても取り消されない。作業環境のファイルを書き換えた後にスクリプトが失敗すると、書き換えは残る。これは `run_shell` を続けて呼んだときと同じである。
- 整理係はファイル操作を繰り返すので、本体より効果が大きい見込みである。整理係の呼び出しの上限（既定 60 回）と、中の呼び出しの上限の釣り合いは、評価で決める。
- 実装のときに確かめること:
  - `defineTool` で作るツールに見え方を指定できるか。できなければ、拡張の側でツールを登録する形に移すか、別の手段を探す。
  - 0.87.1 で書いた session の記録を、1.0.1 で再開できるか。
  - 本人のエンドポイントで、codemode の引数がどういう形で届くか。
  - codemode に既定の締め切りを与える設定があるか。無ければターンの abort に任せる。
  - compaction が中の呼び出しの一覧をどう使うか。

## 追記（2026-10-03）: 版上げと同じリリースに入れる。既定値の 2 点と、実装で分かったこと

### 版上げと Codemode は、PR を分けたまま同じリリースに入れる

「Pi の版上げを先に分けて出す」の、版上げだけで本番に入れて様子を見てから Codemode を入れる、という順は、本人の指示で改めた。
Pi 1.0.1 への版上げと Codemode は PR を分けたまま、同じリリースに入れる。

- PR を分けたので、版上げの不具合と Codemode の不具合を混ぜない、という狙いはコードの上では保たれる。
- Codemode は既定で off である。off のときは、ツールの集合・説明・system prompt が、Codemode を入れる前と一字一句同じになる（prefix の検査で固定した）。
  このため、リリースしても本番の挙動は版上げだけのときと同じで、本番で様子を見る対象は版上げだけになる。
- 本番で on にするのは、これまでどおり評価の後で、順は「評価と、本番に入れる順」のとおりである。

### 「評価で決める」とした 2 点の、評価までの既定値

- **作業環境の 3 つの見え方の既定は `direct`** にした。
  `direct` は、off のときのモデルの使い方（作業環境のツールを直接呼ぶ）をそのまま残し、そこに `codemode` を足すだけなので、on にしたときの変化が一番小さい。
  スクリプトからだけにすると、作業環境を使うすべての呼び出しがスクリプトを書く形になり、本人のエンドポイントでのエスケープの崩れや JavaScript の質が、そのまま返事の質に響く。
  どちらが文脈を減らし質を保つかは、評価で比べてから決め直す。
- **整理係のスクリプトの中の呼び出しの上限の既定は、1 ターン 120 回**にした。係のモデルの呼び出しの上限（既定 60 回）の 2 倍である。
  係の夜は作業環境の呼び出しの連続で、モデルの 1 回の呼び出しごとに 1 回以上ある。上限がモデルの呼び出しの回数より小さいと、仕事をスクリプトに移したほうが早く打ち切られ、移す意味が無くなる。
  一方、記憶のファイルを全部なめるような繰り返しは、時間の上限（30 分）より先に、この回数で止まる。本体の 40 回（ふつうのターンのモデルの呼び出し 8 回の 5 倍）は案のままにした。

設定は `loop.codemode` と `curator.codemode` で、どちらも `enabled`・`workspaceTools`（`"direct"` か `"codemode"`）・`nestedCalls` を持つ。

### 実装で分かったこと（「実装のときに確かめること」への答え）

- `defineTool` で作るツールにも見え方（`exposure`）を指定できる。拡張の側でツールを登録する形に移す必要は無かった。
- ただし Pi は、`tools` の許可リストで名指したツールを、見え方に関わらずモデルに宣言する。スクリプトからだけにするときは、session を開いた後に、宣言するツールを作業環境の 3 つを除いた集合に絞る。
- Pi の Codemode の拡張は、`models` を既定で渡す。`models: false` を明示して渡さない。
- codemode の説明は Pi が組み、`store()`・`load()` の 1 行を含む。なつみの system prompt では触れない。Pi の文面を書き換えると、Pi の更新のたびに壊れうるので、説明からは消していない。
- codemode に既定の締め切りを与える設定は無い（スクリプトの先頭の `// @options` だけ）。決定どおり、ターンの abort に任せる。
- 作業環境が無いとき（runner が設定されていないとき）は、スクリプトから呼べるツールが無いので、on でも何も足さない。整理係は作業環境があるときだけ動くので、係では常に足される。
- Pi の compaction は、中の呼び出しの一覧の `read` のパスを、要約に添える読んだファイルの一覧に入れる。モデルが直接呼んだ `read` と同じ扱いである。
- スクリプトの worker は、なつみが Pi を束ねずに `node_modules` から読むので、テスト・`dist`・Docker image のどれでも Pi に同梱の worker から起動する。
