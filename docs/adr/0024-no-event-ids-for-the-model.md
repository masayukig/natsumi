# 0024. モデルにイベントの ID を扱わせず、ターンは止まれば閉じる

- Date: 2026-09-21
- Status: Accepted（差し込まれた本人のメッセージと同じく、差し込まれた印の付いた `sources_updated` も、境目で文脈に入った時点で「見た」とすることを [ADR 0094](0094-background-commands-and-waiting-for-news-within-a-turn.md) で追加）

## Context

[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md) は、`<events>` の各行に `event_id` を持たせ、
返事（`reply_to_mac`）と、イベントを終えるツール（`finish_event`）に、その ID を書かせる形にした。
夜の引き継ぎと変更の説明（ADR 0009・0020）も、振り返りのイベントの ID を引数に取っていた。

本番で、この形が返事を落とした。

- 静かな一日で、合図（ping）のイベントが 20 回以上続いた。どれも `{"event_id":"event-…","type":"ping",…}` という、
  よく似た形の行である。
- その後に本人のメッセージが届いた。なつみは `reply_to_mac` に、**別の合図のイベントの ID** を書いた。
  サーバーは「処理中の本人のメッセージではない」と断った。
- 断る文が正しい ID を示さなかったので、なつみは今のメッセージの ID を思い出そうとして、それまでの ID を何度も列挙し始めた。
  同じ誤りに何度も戻り、**出力の上限に達して切れた。** 返事は届かず、そのイベントは失敗した。
  本人は同じことを送り直すことになった。後のターンでも同じ混乱を蒸し返した。

見立ては次のとおりである。

- 原因は合図そのものではなく、**形の似た UUID が並ぶ中から、今の 1 件を正しく写させる設計**にある。
  合図が積み重なると、紛らわしい候補が増えるだけである。ADR 0008 の評価でも、
  「本人への相談に、別のイベントの ID を付ける」誤りが既に出ていた。
- ID が本当に要るのは、steering で複数の本人のメッセージが同じターンに入ったときだけである。
  本番の session では、ターンはすべて 1 ターン 1 イベントだった。
- `finish_event` は、イベントの状態にはほとんど効いていない。ターンが普通に終われば、呼ばなかったイベントも
  「返事なしで終えた」（`no-reply`）になる。効いていたのは「ツールの実行後にモデルを呼び直さずに終える」ことだけである。

## Decision

### 1. モデルにイベントの ID を扱わせない

- `<events>` の各行から `event_id` を外す。`type` と、`received_at`・`text`・`local_time`・`checks` などのほかの項目は残す。
- どのツールも、イベントの ID を引数に取らない。
  - `reply_to_mac(text)`
  - `notify_owner(text)`。関係するイベントの ID（`about_event_ids`）はなくす。
  - `write_handoff_note(text)`・`write_change_note(text)`。夜の振り返りのターンの中でだけ使えるという検査は残す。
    どのターンかはサーバーが知っているので、ID で指させる必要がない。
- 予約の `check_id` は残す。これは `cancel_self_check` で取り消す対象を選ぶためのもので、
  なつみ自身が `list_self_checks` で見て選ぶ。今のイベントを写させるものではない。
- ツールの説明と system prompt から、`event_id` と `finish_event` への言及を消す。文面は固定の文のままにする（ADR 0019）。

### 2. 返事は、まだ返事をしていない本人のメッセージにまとめて返す

- `reply_to_mac` の宛先は、**このターンでなつみが既に見ていて、まだ返事をしていない本人のメッセージのすべて**である。
  どのメッセージへの返事かを、モデルに指させない。
- 無ければ断る。断る文には、送れない理由と、代わりにどうするか（付け足しは `notify_owner`、なければそのまま終える）を書く。
  ID はもう示さない。
- 返事を送った後に steering で新しい本人のメッセージが入れば、もう 1 回送れる。
- steering で差し込まれたメッセージは、Pi がモデル呼び出しの境目で context に入れた時点で「見た」とする。
  それより前に送られた返事は、そのメッセージへの返事にしない。見ていないものに答えたことにはしない。
- 差し込まれた出来事は、まだ済んでいない作業（返事や、将来の Slack への投稿）に織り込めばよい。
  system prompt にその旨を足す。

#### 記録と配信

クライアント契約（`docs/client-contract.md`）と SQLite の schema は変えない。

- 返事の行は、答えたメッセージのうち **いちばん新しいもの** に結びつける（`replyTo` はそのイベント）。
  会話の上で、本人の側がいまいる位置だからである。
- それより前の、まとめて答えたメッセージには返事の行が無い。そのイベントは、返事を送ったのと同じトランザクションで
  **返事済み（`replied`）として記録する。** ターンの終わりを待たない。
  - 起動のときに閉じるのは「処理中」のイベントだけなので、ターンの途中で止まっても、再起動の後にこれらが
    失敗になったり、二度答えられたりしない。
  - 1 つのメッセージへの返事の行は、これまでどおり最大 1 つである（SQLite の一意制約）。
- `conversation.event.completed` は、これまでどおりターンの終わりにイベントごとに送る。まとめて答えたメッセージも `replied` になる。
- 返事を送った時点で、そのメッセージは `session.snapshot` の `pendingEvents` から外れる。
  返事の後もなつみがターンを続けている間に同期した端末は、そのメッセージを処理待ちとして見ない。
  接続中の端末の表示は、これまでどおり完了のイベントで変わる。
- 知らせは `about` を持たなくなる。契約では「関係するイベントがあれば」の任意の項目なので、契約は変わらない。
  列は残し、空で入れる。

### 3. `finish_event` をなくす

- ターンは、**Pi の普通の終わり方（モデルがツールを呼ばずに止まる）で閉じる。** ターンが閉じれば、そのイベントも閉じる。
- Pi の `finishTurn`（Pi 0.87.0 で `shouldStopAfterTurn` から置き換わった）は、モデル呼び出しの上限の判定だけに使う。
- **steering が待っているときにモデルが止まっても、ターンは閉じない。** Pi 0.85.1 の agent loop は、
  ツールを呼ばずに止まったモデル呼び出しの後でも、待っている steering を取り出し、あれば同じターンで次のモデル呼び出しに進む。
  この振る舞いをテストで固定した。届いたメッセージが、終わったように見えたターンに置き去りにされることはない。
- 失敗の判定（呼び出しの上限・時間切れ・モデルのエラー・停止）は変えない。出力の上限で切れた呼び出しは、
  これまでどおりモデルのエラーとして失敗にする。普通に終わって返事の無いイベントは `no-reply` になる。
- 返事の結果の文は、「ほかにやることがなければ、ツールを呼ばずに終える」ことを添える。
  ADR 0008 の評価では、結果が短いツールの後に同じ返事を繰り返す誤りがあった。止まる合図を結果の側で渡す。
- 合図（ping）は「なければ何もせずに終えます」、夜の振り返りの必須は引き継ぎを書くことだけ、とする。
  振り返りのターンを終えることは、ほかのターンと同じく止まれば済む。

### 変わらないこと

1 ターン 1 イベントの普段の形では、本人から見える振る舞いは何も変わらない。本人のメッセージに 1 回返事が届き、
イベントが返事済みで終わる。変わるのは、steering で同じターンに複数の本人のメッセージが入ったときの返し方だけである。

## 置き換える既存の決定

- **ADR 0008**
  - 置き換え:「思考ループ」の節の「`<events>` の中に 1 行 1 件の JSON を置く形で、`event_id` と `type` を必ず持つ」。
    `type` を必ず持ち、`event_id` は持たない。
  - 置き換え: ツールの表の `reply_to_mac(event_id, text)`。`reply_to_mac(text)` とし、宛先はこのターンで見ている、
    まだ返事をしていない本人のメッセージのすべてとする。1 つのメッセージへの返事の行が最大 1 つで、
    再起動をまたいでも SQLite の一意制約で守ることは変えない。
  - 置き換え: ツールの表の `notify_owner(text, about_event_ids?)` と「参照するイベントは実在するものに限る」。
    `notify_owner(text)` とする。件数の上限は変えない。
  - 置き換え: ツールの表の `finish_event(event_id)`。このツールはなくす。
  - 置き換え:「ターンを閉じるのは、処理中のイベントがすべて `finish_event` で終わり、差し込み待ちもないときである」と、
    続く `shouldStopAfterTurn` で閉じる説明。ターンはモデルがツールを呼ばずに止まったときに閉じ、
    差し込み待ちがあれば閉じない。
  - 置き換え: ツールの結果の例のうち「対応は完了し、追加の出力は不要」。
  - 残す: 単一の思考ループ、steering で差し込むこと、モデル呼び出しと時間の上限、本文の検査、Mac に見せる会話の記録と配信。
- **ADR 0009**
  - 置き換え: 夜の切り替えの手順のうち、「`write_handoff_note` で明日の自分への引き継ぎを書き、`finish_event` で終える」の
    `finish_event` で終える部分。止まれば終わる。
  - 残す: 夜に session を切り替えること、その手順・失敗の扱い、引き継ぎの扱い。
- **ADR 0014**
  - 置き換え:「定期の合図」の節の「何もなければ natsumi は `finish_event` だけで終える」。何もなければ何もせずに終える。
  - 残す: 合図と予約の形、予約の `check_id`。
- **ADR 0017**
  - 置き換え: Consequences の「返事が届いてから `finish_event` までの間」。未読の返事が隠れるのは、
    返事が届いてからターンが閉じるまでの間である。
- **ADR 0018**
  - 置き換え:「夜の再構成」の手順の 8 段目「`finish_event` で終える」。この手順は ADR 0020 で候補の一覧に置き換わっており、
    ここではその名残を消すだけである。
- **ADR 0020**
  - 置き換え: 夜の必須の 2 つのうち「ターンを終えること」。ツールを呼ぶ必須の作業ではなくなり、
    夜の指示にも必須として書かない。必須は引き継ぎを書くことだけになる。
  - 残す: 夜の指示を候補の一覧にすること、`write_change_note` を夜のターンの外で拒否すること。

## Consequences

- なつみが ID を写し間違える、あるいは ID を探して出力を使い切る、という失敗の仕方がなくなる。
- 返事の後にターンを閉じるには、ツールを呼ばないモデル呼び出しがもう 1 回要る。これまで返事と `finish_event` を
  同じ呼び出しで出せば 1 回で済んだ場面が、2 回になる。
  - モデル呼び出しの上限（通常 8 回、夜は設定値）に対して、**上限の回に呼んだツールは、そのターンを上限で切る。**
    上限ちょうどの回で返事を送ると、返事は届くが、ほかのイベントは失敗として残る。
    返事や引き継ぎは、上限より 1 回前までに済ませる必要がある。
  - 止まるための呼び出しは短い出力で済み、前の呼び出しまでは prefix cache に乗る。
- 走っている session の履歴には、`finish_event` の呼び出しと結果が残っている。新しいツールの定義で同じ session を
  開き直すと、ツールの定義が変わるため prefix cache は一度失われる（ADR 0019）。
  なつみが古い習慣で `finish_event` を呼んだ場合、Pi は「そのツールは無い」というエラーの結果を返してターンを続ける。
  `reply_to_mac` に古い形で `event_id` を付けて呼んだ場合は、余分な引数として無視され、返事は送られる。
- 同じターンに差し込まれた複数のメッセージに、別々の返事を返すことはできない。まとめて 1 回で答える。
  答え終わった後に届いたものには、もう 1 回返せる。
- まとめて答えたメッセージのうち、いちばん新しいもの以外には、返事の行が結びつかない。
  履歴の上では、その返事は後ろのメッセージへの返事に見える。どれに答えたかは、完了のイベントの状態（`replied`）で分かる。
- 知らせを特定のイベントに結びつける手段がなくなる。必要になったら、サーバーがターンの中身から結びつける形で足す。
  モデルに ID を書かせる形には戻さない。
