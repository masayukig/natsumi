# 0036. 読み取り専用のマニュアルと、返事を待ち続ける上限

- Date: 2026-09-24
- Status: Accepted（作業環境に見せる読み取り専用の場所に `/sources` を加える点と、Slack の送信役のポッポさんを頼める相手の一覧に載せる点は [ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で追加。サーバーの image にも `manual/` を置き、ダッシュボードで読むことは [ADR 0054](0054-her-files-on-the-dashboard.md) で追加。system prompt に固定の 1 文だけを足し、道具が増えても system prompt を変えない点は、目次の中身とシステム独自のコマンドを入れる形に [ADR 0056](0056-the-manual-index-and-the-workspace-commands-in-the-prompt.md) で置き換え）

## Context

[ADR 0035](0035-asking-outside-agents-and-hearing-back.md) で、なつみは汎用のツール `ask_agent` で外のエージェントに頼み、
返事はサーバーが Task を取りに行ってイベントで届ける、と決めた。そのうえで次の 2 つを決めずに残していた。

- なつみが、頼める相手の名前をどこで知るか。ツールの説明には相手の一覧を書かない。
- 返事を待ち続ける上限。相手が完了も失敗も返さないまま止まったとき、いつ諦めてなつみに知らせるか。

1 つ目には、次の制約が掛かる。

- system prompt とツールの説明は、session の生成時に 1 度だけ組み、session の間は変えない。
  設定の値から文面を組み立てない（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
  相手の一覧は設定そのものなので、どちらにも書けない。
- なつみには、`run_shell` で読める作業環境がある（ADR 0019）。作業環境は外へ出られず（[ADR 0034](0034-an-allow-list-for-the-way-out.md)）、
  外のエージェントを呼ぶ token も見えない（[ADR 0033](0033-running-on-kubernetes.md)）。
- 使い方の説明を system prompt に足していくと、道具が増えるたびに prefix が長くなる。毎回読まれるが、ほとんどの回で要らない。

## Decision

### なつみ向けのマニュアルを作業環境に置く

- なつみ向けの読み取り専用のマニュアルを、作業環境の `/manual` に置く。なつみは `run_shell` で読む。
- system prompt には、作業環境の節に固定の 1 文だけを足す。「やり方が分からないときは、まず `/manual/INDEX.md` を読む」の類である。
  作業環境につながっていない構成の節（ADR 0019 の 2 つの固定の文のもう片方）には足さない。読む手段が無いからである。
- マニュアルは 2 つの部分からなる。

| 部分 | 中身 | 置き場所 | 作る者 |
| --- | --- | --- | --- |
| 汎用の部分 | 目次（`INDEX.md`）と、`ask_agent` の使い方 | natsumi のリポジトリの `manual/`。作業環境の image に焼く | 人が書く |
| 相手の一覧 | 頼める相手の名前・説明・スキル | `/manual/agents/INDEX.md` | サーバーが起動時に書き出す |

- 汎用の部分は image の中にあり、作業環境のルートは読み取り専用なので、なつみは書き換えられない。
  使い方を直すのはコードの変更であり、image を作り直して反映する。
- 道具が増えたら、マニュアルに 1 枚足し、目次に 1 行足す。system prompt は変えない。

### 相手の一覧は、サーバーが Agent Card から書き出す

- サーバーは起動時に、設定にある相手ごとに Agent Card を取り、名前・説明・スキルを 1 つの Markdown に書き出す。
  - 一覧に載せる「頼むときの名前」は、設定の名前である。`ask_agent` でサーバーが確かめる名前と同じ設定から作るので、ずれない。
  - Agent Card は認証なしで返る公開の情報なので、token を付けずに取る。token を送る先を必要以上に増やさない。
  - 取れなかった相手は、名前と「今は取れない」を書く。名前が載っていれば、なつみは頼むことはできる。
  - 書き出すのは起動時だけである。動いている間に相手の説明が変わっても、次の起動まで一覧は変わらない。
  - 相手の URL と token は書かない。なつみが扱うのは名前だけである（ADR 0035）。
  - Agent Card の文は外から来た文なので、長さを切り詰め、制御文字を除いてから書く。
- 置き場所は data directory の `agents/` とし、作業環境からは `/manual/agents` に読み取り専用で見せる。
  - Docker の構成では、`natsumi-data` の subpath `agents` を読み取り専用でマウントする。
  - Kubernetes の構成では、サーバーのコンテナと作業環境のコンテナで共有する emptyDir に置き、作業環境には読み取り専用でマウントする。
    起動のたびに書き直すものなので、永続させる必要も、バックアップする必要も無い。マニフェストは移行の作業単位で書く。
- 設定に相手が 1 つも無ければ、一覧には「頼める相手はいない」と書く。

### ADR 0019 の閉じ込めとの整合

作業環境に見せるものに、次の 2 つを加える。どちらも読み取り専用で、なつみが書ける場所は ADR 0019 の 4 つのままである。

| 場所 | 永続 | 書ける | 中身 |
| --- | --- | --- | --- |
| `/manual` | image の一部 | 書けない | 汎用のマニュアル |
| `/manual/agents` | 起動ごとに書き直す | 書けない | 相手の一覧 |

- 秘密は増えない。見せるのは、リポジトリにある文と、設定の相手の名前と、公開の Agent Card の中身だけである。
- 作業環境の外向きは変えない（ADR 0034）。マニュアルを読むのにネットワークは要らない。
- SQLite、Pi の状態領域、secrets、設定は、これまでどおり見せない。

### 頼むツールは常に登録する

- `ask_agent` は、外のエージェントの設定が有っても無くても登録する。設定が無ければ、頼まずに「頼める相手が設定されていない」旨の結果を返す。
- ツールの一覧が設定の有無で変わらないので、prefix もそれで変わらない。ADR 0035 の「相手が増えてもツールの定義は変わらない」を、
  相手が 0 のときまで広げたものである。
- `run_shell` は runner の設定があるときだけ登録している（ADR 0019）。これは変えない。

### 返事を待ち続ける上限

- 上限は設定で変えられるようにし、既定は **24 時間** と緩めにする。
- 数え始めは、その Task に最後に送った時点である。聞き返し（`INPUT_REQUIRED`）に答えれば、そこから数え直す。
- 上限を過ぎた Task は、取りに行くのをやめ、「待っても返事が来なかった」ことを相手の名前つきのイベントでなつみに知らせる。
  - 相手に取り消し（CancelTask）は送らない。相手の側の作業はそのまま続き得るが、その結果はなつみには届かない。
- 聞き返しで止まっている Task は、なつみの答えを待っている状態なので、取りに行かず、上限も数えない。
  相手の側で答えの待ちが切れていれば、なつみが答えたときに頼めなかった結果が返る。

### イベントと、頼むときの細部

- 返事のイベントは `agent_reply` とし、相手の名前・状態・文面を載せる。状態は、完了・失敗・聞き返し・諦めの 4 つである。
  Task と context の ID は載せない（ADR 0024、ADR 0035）。
  - 返事の文面は長さを切り詰めてから載せる。切り詰めたことはイベントに書く。
  - 返事は Mac の会話に入れない（ADR 0025 の既定）。本人に伝えるかは、なつみが本人向けのツールで決める。
  - イベントは実行中のターンに差し込まず、キューの後ろに並べる。本人のメッセージのように、その場で答えを待つ人がいないからである。
- `continue` を真にしたのに、その相手との直近のやり取りが無ければ、頼まずに断る結果を返す。
  黙って新しいやり取りにすると、なつみは前の文脈が相手にあると思ったまま話を進めるからである。
- `continue` を真にしたのに、直近のやり取りの Task がまだ返事を待っていれば、頼まずに断る結果を返す。
  相手は 1 つの context で同時に 1 つの Task しか受けない。
- 頼むときに相手につながらない、または相手が断ったときは、その場のツールの結果で伝える。イベントにはしない。

### 置き換える既存の決定

- ADR 0035
  - 決定:「まだ決めていないこと」の 2 つ（相手の名前をどこで知るか、返事を待ち続ける上限）。
- ADR 0019
  - 追加: 作業環境に見せるものに `/manual` と `/manual/agents`（どちらも読み取り専用）。
  - 残す: 書ける場所の 4 つ、system prompt とツールの説明を設定から組み立てない規則。

## Consequences

- 使い方の説明を足しても、prefix は伸びない。その代わり、なつみはマニュアルを読むのに `run_shell` を 1〜2 回使う。
  1 回の対応で考えを進められる回数の上限から、その分が引かれる。
- なつみが「やり方が分からないときはマニュアル」という 1 文に従わなければ、相手の名前を知らないまま頼み、断られる。
  断る結果の文に一覧の場所を書いて補う。
- 作業環境につながっていない構成では、なつみは相手の名前を知る手段が無い。
- 相手の説明を変えても、サーバーを再起動するまで一覧に反映されない。起動時に止まっていた相手は、「今は取れない」のまま残る。
- 相手が 24 時間より長い仕事を受けると、終わる前に諦めてしまう。そういう相手を加えるときは、上限を延ばす。
- 諦めた後に相手が仕事を終えても、なつみには届かない。相手の側には結果が残る。
- 設定の無い構成でも、ツールの説明の分だけ prefix が長くなる。
