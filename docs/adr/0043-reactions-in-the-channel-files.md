# 0043. Slack のリアクションをチャンネルのファイルに書き、なつみの投稿へのものを合図で知らせる

- Date: 2026-09-26
- Status: Accepted（`updates` の `reactions_on_mine` と、ファイルの `リアクション:` の行は [ADR 0050](0050-telling-of-source-updates-with-one-event.md) で置き換え（リアクションは JSON Lines の行の欄、付け外しはファイルの変化として `sources_updated` に出る））

## Context

[ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で、natsumi は Slack のチャンネルを `/sources/slack/` のファイルとして読むことにした。
ファイルに書くのは発言（本文・添付・編集と削除）だけで、発言に付いたリアクションは書いていなかった。
そのため natsumi は、自分の投稿がどう受け取られたか（👍 が付いた、🎉 が付いた）も、ほかの人の発言にだれが賛成しているかも知れなかった。

natsumi もポッポさんへの依頼でリアクションを付けられる（ADR 0039・[ADR 0042](0042-any-emoji-that-exists.md)）。
付ける側だけがあり、付けられたことを知る側が無かった。

本人は、リアクションもチャンネルのファイルに書き、どの発言にだれが何を付けたかを natsumi が知れるようにすると決めた。
あわせて、合図（`ping`・`self_check`）の `updates` でどこまで知らせるかを選んだ。

- A: すべての発言へのリアクションを件数で知らせる
- B: なつみ自身の投稿に付いたリアクションだけを件数で知らせる。ほかはファイルに書くだけ

本人は B を選んだ。ほかの人の発言へのリアクションは、雑談の流れの一部であり、発言と同じくファイルを読めば分かる。
自分の投稿への反応は、返事を待つ相手からの合図になりうるので、知らせる価値がある。

## Decision

### 受け取るもの

- Socket Mode で `reaction_added` と `reaction_removed` のイベントを受け取る。
- 対象は、記録しているチャンネルの、記録にある発言へのリアクションだけとする。
  - 記録に無い発言（埋める期間より古い発言、まだ見ていないチャンネル）へのリアクションは捨てる。そのために発言を取りには行かない。
  - ファイルなど、発言でないものへのリアクションも捨てる。
- だれが付けたかは、発言者と同じ解決のしかたで表示名にする。名前が取れなければ `someone` とする。natsumi 自身が付けたものも書く。
- 同じイベントが何度届いても、記録は 1 つである。

### 記録

- リアクションは SQLite の表に、発言・絵文字の名前・付けた人ごとに 1 行で持つ。個人データとしてバックアップの対象である（migration 15）。
- 付けた人の Slack の ID はサーバーの側に持ち、外すイベントとの突き合わせにだけ使う。natsumi が読むものには書かない（[ADR 0024](0024-no-event-ids-for-the-model.md)）。
- 付け外しのたびに、その発言の日のファイルを SQLite から書き直す。発言の編集と削除と同じである。
- 発言の中のリアクションの並びは Slack に合わせる。だれかが付けている間は、そのリアクションは最初に付いた位置のままである。

### 埋め直し

- 起動時とつなぎ直したときの埋め直しで、`conversations.history`・`conversations.replies` が返す発言の `reactions` を取り込み、記録をそれに合わせる。
  - 取り直した発言については、止まっている間に外されたものは消え、付いたものは足される。
  - 最後に記録した発言より前の発言に、止まっている間に付いた・外されたリアクションは拾わない。埋め直しがその発言を取り直さないからである。
- Slack が数だけを返し、付けた人の一部を返さない場合がある。返された人は名前で書き、残りは「ほか N 人」とする。
  - 名前の分からない人がリアクションを外したイベントが来たら、その N を 1 減らす。
  - 名前の分からない人の分は、合図の件数に数えない。だれか分からないので、新しいかどうかも分からないからである。

### ファイルの書き方

- 発言の本文・添付・「（編集済み）」の後に、1 行で書く。スレッドの返信なら、返信と同じだけ字下げする。
  - 例: `リアクション: :+1: 山田・佐藤、:tada: 田中・ほか 3 人`
  - 絵文字は Slack の名前をコロンで囲んで書く。natsumi がポッポさんへの依頼にそのまま写せる。
- 削除された発言のリアクションは書かない。

### 合図の `updates`

- Slack の更新元の欄に `reactions_on_mine` を足す。チャンネルごとに、前回見せてから、ほかの人が natsumi 自身の投稿に付けたリアクションの数である。
  - natsumi 自身が付けたもの、ほかの人の発言へのもの、見せる前に外されたもの、削除された投稿へのものは数えない。
  - 見せたら数え直す。発言の `new` と同じである。
- `files` には、`new` の分と並べて、リアクションの付いた投稿のあるファイルを載せる。投稿が前の日のものなら、そのファイルになる。
- 数えるものが無い種類は、欄ごと付けない。発言も無ければ、Slack の欄ごと付けない（ADR 0039 のまま）。
- 更新元の枠は、`new` に限らず、更新元ごとに数える種類を足せる形にする。
- system prompt の `ping` の説明（`self_check` の `updates` もこれに従う）に、`reactions_on_mine` の意味を 1 文足す（本人の決定）。
  文は固定であり、session の間は変わらない。足した時点で prefix が変わるので、走っている session は夜の切り替えまでキャッシュを失う。
  ファイルの行の読み方などの細部は Slack のマニュアル（`manual/slack.md`）に書く。

### メンションの出来事

- `slack_mention` の前後の流れ（`context`）には、リアクションを載せない。
  出来事が大きくなるわりに、返事を決める材料としての重みは小さい。必要なら `file` のファイルで見られる。

### Slack App

- bot の scope に `reactions:read` を、購読するイベントに `reaction_added`・`reaction_removed` を足す。

### 置き換える既存の決定

- ADR 0039「Slack のチャンネルのファイル」
  - 追加: 発言に付いたリアクションを、発言の下に書く。付け外しでその日のファイルを書き直す。
- ADR 0039「更新元の枠」
  - 追加: 更新元は `new` のほかに数える種類を持てる。Slack は `reactions_on_mine` を持つ。

## Consequences

- natsumi は、自分の投稿への反応を合図で知り、ほかの人の発言への反応をファイルで読める。
- 自分の投稿への反応だけを数えるので、合図が雑談のリアクションで膨らまない。そのぶん、ほかの人の発言へのリアクションは、ファイルを読まない限り気づかない。
- リアクションの付け外しのたびに、その日のファイルを 1 度書き直す。リアクションの多いチャンネルでは書き込みが増える。
- 止まっている間の古い発言へのリアクションは拾わないので、ファイルが Slack とずれることがある。次にその発言が取り直されるまでずれたままになる。
- 名前の分からない「ほか N 人」は数えないので、よく使われるリアクションが埋め直しで入ったときの件数は、実際より少なく出る。
- Slack App に `reactions:read` とイベントを足して入れ直すまでは、リアクションのイベントは届かない。ファイルには、埋め直しで取り込めた分だけが書かれる。
