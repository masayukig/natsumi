# 0056. マニュアルの目次と作業環境のコマンドを system prompt に置く

- Date: 2026-09-28
- Status: Accepted

## Context

[ADR 0036](0036-a-manual-to-read-and-a-limit-on-waiting.md) で、なつみ向けの使い方の説明は作業環境の `/manual` に置き、
system prompt には「やり方が分からないときは、まず `/manual/INDEX.md` を読む」という固定の 1 文だけを足すと決めた。
道具が増えてもマニュアルに 1 枚、目次に 1 行を足すだけで、system prompt は変えない。prefix を伸ばさないためである。

その後、道具は画像を作る `sdctl`（[ADR 0044](0044-drawing-with-sdctl-and-posting-images.md)）、読みものの差分を見る `sources-diff`（[ADR 0050](0050-telling-of-source-updates-with-one-event.md)）、
画像を見る `view`（[ADR 0039](0039-slack-as-files-and-a-scored-dove.md)）と増えた。
評価の場面（`self-look`・`show-image`・`draw-other`）で、次の 2 つが残った。

- 気分の絵を頼まれたとき、`/manual/images.md` を開かずに Python で PNG を作る回がある。
  目次を読む 1 手を飛ばすと、`sdctl` があることを知らないまま手を動かす。
- 本人に絵を見せる場面で、`cd … && view <パス>` のように `view` をほかのコマンドとつなぎ、画像が見えない。
  `view` はサーバーが run_shell のコマンドを見て自分で答えるもので、コマンド全体が `view <パス>` のときだけ効く。
  マニュアルにそう書いても、読む前に書くので直らなかった。

どちらも「マニュアルを読む前に手が動く」ことが原因である。目次は毎日のように開くものであり、
システム独自のコマンドは、名前を知らなければ使えず、書き方を間違えると黙って効かない。
本人から「システム独自のコマンドは system prompt に書いてもよい。マニュアルの目次も毎日必ず開くものだから、system prompt に入れてもよい」と提案があった。

制約は次のとおりである。

- system prompt とツールの説明は、session の生成時に 1 度だけ組み、session の間は変えない（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
- 文面を設定の値や image の中身から組み立てない（ADR 0019）。デプロイのたびに prefix が勝手に動くからである。
- バックエンドは prefill が遅い。prefix cache に乗る形は保ちたいが、コードの更新のような日常でない出来事のために設計を複雑にはしない。

## Decision

### 目次は `manual/INDEX.md` の中身を、そのまま作業環境の節に差し込む

- サーバーは起動時に、コードに同梱の `manual/INDEX.md` を読む。
  場所はダッシュボードが `/manual` として読むのと同じ、コードの位置から決まる `manual/` である（[ADR 0054](0054-her-files-on-the-dashboard.md)）。
  サーバーの image と作業環境の image は同じビルドから作るので、なつみが `/manual/INDEX.md` として読むものと中身は同じである。
- 読んだ中身は、system prompt の作業環境の節（ADR 0019 の 2 つの固定の文のうち、作業環境につながっている方）の中に、
  目次として差し込む。ファイルの先頭の見出しは除き、サーバーが付ける見出しに置き換える。
- **中身の持ち主は `manual/INDEX.md` の 1 か所だけ**とする。同じ目次をコードに二重に書かない。
  - `INDEX.md` は、なつみが read で開くファイルでもあり、system prompt の一部でもある。
    どちらで読んでも自然な文にする。「read で読んでください」のような、ファイルとして開いたときにしか合わない前置きは置かない。
    読み方（read を使う、read で読んだものは残る）は、作業環境の節の既存の文が言っている。
- これまでの「やり方が分からないときは、まず `/manual/INDEX.md` を読む」の 1 文は、
  「やり方が分からないときは、下の目次から合うページを read で読む」の類に変える。
- 頼める相手の一覧 `/manual/agents/INDEX.md` の中身は入れない。サーバーが起動のたびに Agent Card から書き直すもので、
  相手の説明が変われば prefix が動くからである。目次の中の「頼める相手の一覧は `/manual/agents/INDEX.md`」という案内の 1 行はそのまま残る。

### `INDEX.md` を読めないときは、これまでの 1 文に戻す

- 読めなかったときは、起動を止めずに、ADR 0036 の固定の 1 文（「まず `/manual/INDEX.md` を読む」）を使い、そのことをログに書く。
- 起動を止めない理由: 目次は手引きであって、無くてもなつみは作業環境の `/manual` を読める。
  サーバーは、ログインが無いときや session を失ったときでも起動して理由を見せる作りであり、手引きの有無で止めるのは釣り合わない。
  image から起動する限り `manual/` は必ずあるので、戻るのはチェックアウトの外から動かしたような例外のときだけである。

### システム独自のコマンドを、各 1 行で書く

作業環境の節に、作業環境にしかないコマンドを 3 行で書く。各行は、名前・何をするか・効かない書き方と、詳しい使い方のあるページである。

| コマンド | 何をするか | 効かない書き方として書くこと | 詳しいページ |
| --- | --- | --- | --- |
| `sdctl` | 画像を作る。設定は既定のままで、プロンプトの YAML のファイルを渡す | 画像を Python などで自分で描かない。作る前にページを読む | `/manual/images.md` |
| `sources-diff` | `/sources` の読みものの、前回からの差分を見る | 読みものの履歴は `/sources.git` にあり、`/sources` で git を直接使っても差分は出ない | `/manual/slack.md` |
| `view` | `/work`・`/sources` の下の画像を見る | run_shell のコマンドを `view <絶対パス>` の 1 つだけにする。`cd` や `&&`・`;` とつなぐと、ただのコマンドとして動いて失敗する | `/manual/slack.md`・`/manual/images.md` |

- `view` は、サーバーが run_shell のコマンドの全体を見て、`view` と 1 つのパスだけのときに自分で答える（ADR 0039）。
  作業環境に `view` という実行ファイルは無い。この仕組みのまま、効く書き方を 1 行で言う。
- 3 行は固定の文としてコードに書く。コマンドの一覧を image から生成しない（ADR 0019）。
  コマンドが増えたときは、コードを直してこの行を足す。

### 作業環境につながっていない構成には入れない

- 作業環境につながっていない構成の節には、目次もコマンドも入れない。読む手段も動かす手段も無いからである（ADR 0036 と同じ理由）。

### ADR 0019 の「image の中身から文面を組み立てない」との関係

- `manual/INDEX.md` はリポジトリのファイルであり、コードの一部として人が書く。
  変わるのはコードを直して image を作り直すときだけで、ソースに固定の文字列として書いた文と同じ性質である。
- ADR 0019 が避けたのは、Debian のパッケージのようにビルドのたびに変わり得るものや、設定の値から文面を作ることだった。
  それには当たらない。設定では変えられず、置き場所も設定にしない（ADR 0054 と同じくコードの位置から決める）。

### prefix cache

- system prompt が変わるので、この変更を反映した後の最初の session は prefix cache が効かない。
- `INDEX.md` が変わるのは image を作り直すときだけである。session の間に読み直すことはなく、起動時に読んだものを使い続ける。
- 増えるのは目次とコマンドの分だけで、ページの本文は入れない。道具が増えても、system prompt に増えるのは目次の 1 行とコマンドの 1 行までである。

### 評価の場面

- 評価（[ADR 0051](0051-evaluating-one-turn-on-the-real-path.md)）は、その回の `manual/` の写しの `INDEX.md` を読み、サーバーと同じ道筋で system prompt に差し込む。
  場面がマニュアルを差し替えれば、system prompt の目次もそれに従う。

### 置き換える既存の決定

- ADR 0036
  - 置き換え: 「system prompt には、作業環境の節に固定の 1 文だけを足す」「道具が増えても system prompt は変えない」。
    目次の中身とシステム独自のコマンドは system prompt に入る。
  - 残す: マニュアルを作業環境の `/manual` に読み取り専用で置くこと、汎用の部分と相手の一覧の 2 つに分けること、
    相手の一覧をサーバーが起動時に書き出すこと、作業環境につながっていない構成には足さないこと。
    固定の 1 文は、`INDEX.md` が読めないときの戻り先として残る。
- ADR 0019
  - 残す: system prompt を session の生成時に 1 度だけ組むこと、設定の値や image のビルドで変わるものから文面を組み立てないこと。

## Consequences

- なつみは、目次を開く 1 手を使わずに、どのページを読めばよいかと、作業環境独自のコマンドの名前を知る。
  1 回の対応で考えを進められる回数の上限から、目次を読む分が引かれなくなる。
- 目次とコマンドの分だけ、毎回読まれる prefix が長くなる。道具が増えるたびに、その分も伸びる。
- `manual/INDEX.md` を直すと system prompt が変わる。目次の文は、ファイルとしても system prompt としても読まれることを意識して書く。
- 反映した後の最初の session と、`INDEX.md` を変えた image に入れ替えた後の最初の session は、prefix cache が効かない。
- `INDEX.md` が読めずに戻ったときは、ログにしか現れない。なつみの振る舞いは ADR 0036 のときに戻る。
