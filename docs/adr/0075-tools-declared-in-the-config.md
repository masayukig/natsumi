# 0075. インスタンスに特有のツールを config で宣言する

- Date: 2026-10-08
- Status: Accepted（2026-10-08: 実行先から HTTP 型を外し、コマンド型だけにした。秘密の要る API を道具にするときの方向は「後で決めること」に残した）

## Context

本人は、インスタンス（なつみ・ミャオ・Aki）ごとに違う道具を持たせたい。ある人にだけ要る API や、ある人の仕事にだけ使うスクリプトを、ツールとして渡したい。

今の natsumi のツールは、コードで固定されている。

- モデルに渡すツールは、サーバーのコードが組み、Pi の `tools` の許可リストで明示する（[ADR 0004](0004-pi-tool-and-voice-boundaries.md)）。
  Pi の拡張は、コードから渡したものだけを読み込む（[ADR 0047](0047-folding-ended-turns-with-a-memo.md)）。
- インスタンスごとに変えられるのは、Codemode の入り切りと中の呼び出しの上限（[ADR 0066](0066-codemode-to-keep-raw-output-out-of-the-context.md)）、
  skills（[ADR 0073](0073-skills-from-the-owner-and-her-own.md)）、作業環境に入れたコマンド（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）だけである。

Codemode はこの問いの答えにならない。

- Codemode は、既存のツールの呼び方（exposure）を変えるだけで、ツールの集合は増やさない。
- スクリプトの QuickJS のサンドボックスが閉じ込めるのはスクリプト自身である。スクリプトが呼んだツールはサーバーのプロセスで、モデルが直接呼んだときと同じ権限で動く。
  スクリプトから新しい道具を作ることはできない。

ほかに考えた拡張ポイントと、退けた理由は次のとおりである。

- **サーバーのプロセスに plugin のコードを import する**: 秘密を持つプロセスで、任意のコードが動く。
  ADR 0047 の「Pi の拡張はコードから渡したものだけ」も崩れる。
- **作業環境の CLI と skill だけで済ませる**: モデルから見るとツールではなく、引数の型も無い。なつみは `run_shell` でコマンド文字列を組み立てることになる。
  ただし、これは今でもできるので、選択肢としては残る。
- **`ask_agent` で外のエージェントに頼む**（[ADR 0035](0035-asking-outside-agents-and-hearing-back.md)）: 一往復が重い。道具ではなく依頼になる。

作業環境には `python3`（標準ライブラリのみ）があり、ルートは読み取り専用である（ADR 0019）。
作業環境の外向きは、名前解決も含めてすべて拒否している（[ADR 0034](0034-an-allow-list-for-the-way-out.md)）。

設計は grill-me（Q1〜Q11 と、質問せずに既定とした事項）で詰めた。
最初の版では、実行先にコマンド型と HTTP 型の両方を持つと決めていた。
同じ日に、今は HTTP を呼ぶ道具が要らないことから、HTTP 型を外してコマンド型だけにした。

## Decision

### 宣言は config の最上位の `tools` に書き、起動時に読む

- インスタンスに特有のツールは、サーバーの config の最上位の `tools`（配列）で宣言する。コードは足さない。
- 読み込むのは起動時だけである。宣言を変えるにはサーバーを再起動する。
- 1 つのツールの項目は次のとおりである。正確な名前と既定値は実装の PR で決める。
  - `name`: ツールの名前
  - `description`: モデルに見せる説明。固定の文字列で、prefix に載る
  - `parameters`: 引数の JSON Schema。使える型は object・string・number・boolean・enum・array に絞り、起動時に検査する
  - `exposure`: Codemode での見え方（下の「Codemode での見え方」）
  - `timeoutSeconds`: 時間切れ
  - `maxOutputChars`: モデルに返す本文の上限。既定は `run_shell` に合わせて 8000 文字
- system prompt は変えない。ツールの使い方は `description` だけで伝える。

### 実行先はコマンド型だけ

- 宣言したツールは、作業環境の runner がコマンドを起動し、その出力をモデルに返す（コマンド型）。
- サーバーが宣言した URL へ要求を送る形（HTTP 型）は持たない。

退けた案:

- **HTTP 型も最初の版で持つ**（grill では一度これに決めた。サーバーが宣言した URL へ引数の JSON を送り、秘密はサーバーだけが持つ形）:
  今は HTTP を呼ぶ道具が要らない。要るようになったら、下の「後で決めること」の方向で別に決める。
- **HTTP 型だけ**: 作業環境の中で済む小さな道具まで、HTTP のサービスに仕立てることになる。

### コマンド型の本体は、ConfigMap を作業環境の `/tools` に読み取り専用で mount する

- コマンドの本体（スクリプトなど）は、環境の設定（private のリポジトリ）の ConfigMap に置き、インスタンスごとに作業環境の `/tools` へ読み取り専用で mount する。
- argv は宣言に固定で書く。コマンドの置き場所は、なつみが書き換えられない場所（`/tools`）に限る。
  `/memory` に置くと、なつみが自分のツールを書き換えられてしまう。
- stdout がモデルに返る本文である。exit code が 0 以外なら失敗として返す。

退けた案:

- **Git リポジトリを clone する**（skills と同じ、ADR 0073）: 道具の本体は小さく、インスタンスごとの宣言と一緒に環境の設定で持つほうが、宣言と本体が食い違いにくい。
- **image に焼く**: インスタンスごとに違う道具を持たせるたびに、natsumi のリリースと image の作り直しが要る。

### コマンド型の引数は stdin で渡し、bash を通さずに起動する

- runner の要求に argv と stdin を足す。runner は宣言の argv を、bash を通さずにそのまま起動する。
- モデルが書いた引数（JSON）は stdin に渡す。コマンド文字列には埋め込まない。

退けた案:

- **今の runner のまま、引数を base64 にしてコマンド文字列に埋める**: 1 コマンドの長さの上限（8000 文字、ADR 0019）に縛られる。

### コマンド型は、時間切れで runner がプロセスを止め、失敗として返す

- `timeoutSeconds` を過ぎたら、runner がプロセスを止め、失敗として返す。
- 長い仕事は、これまでどおり `run_shell` で回す。

退けた案:

- **`run_shell` と同じにする**（60 秒で「まだ動いている」を返し、プロセスは動かし続ける）: 道具の呼び出しは、結果が返るか失敗するかのどちらかであるほうが扱いやすい。
  動き続ける道具の結果を、後から受け取る道も無い。

### Codemode での見え方は、ツールごとに config で選ぶ

- 宣言したツールの `exposure` は、ツールごとに config で自由に選べる（`model-only`・`direct`・`codemode`）。
- 書かないときの既定は `model-only` である。

退けた案:

- **readOnly の宣言と組み合わせて制限する**（grill では推奨していた。読むだけと宣言したツールだけをスクリプトから呼べるようにする）: 道具を宣言する人が一番よく知っている。サーバーが別の宣言で縛る理由が薄い。
- **すべて `model-only`**: 生の出力を絞りたい道具まで、モデルが直接呼ぶしかなくなる。

### 整理係には渡さない

- 宣言したツールは、なつみの本体の session にだけ渡す。夜の整理係（[ADR 0055](0055-a-memory-curator-at-night.md)）には渡さない。

退けた案:

- **ツールごとに、渡す session を選ぶ**: 整理係の仕事は記憶のファイルの組み直しで、インスタンスに特有の道具を使う場面が無い。

### ツール名は自由。組み込みのツールと重なれば起動時に拒む

- ツール名は自由に付けられる。
- 組み込みのツールや `codemode` と同じ名前なら、起動時に拒む。

退けた案:

- **接頭辞（`x_` など）を強制する**: 名前の衝突は起動時の検査で防げる。接頭辞はモデルに見える名前を不自然にするだけである。

### 画像は扱わない。最初の版では文字だけ

- 最初の版では、宣言したツールの結果は文字だけである。
- 画像が要るときは、コマンド型の道具が `/work` に書き、なつみが `view`（[ADR 0039](0039-slack-as-files-and-a-scored-dove.md)）で見る。

退けた案:

- **応答に画像の欄を足す**: 結果の形が固定でなくなる。最初の版では、`/work` と `view` で足りる。

### tools を変えて再起動しても、同じ session のまま続ける

- 宣言を変えて再起動しても、session は切り替えない。
- ツールの定義が変わるので、prefix cache は一度外れる。
- 古い履歴に、消えたツールの呼び出しが残るのは許す。
- 入れる時刻は運用で選ぶ。

退けた案:

- **新しい session に切り替える**: ツールを変えるたびに、その日の文脈を失う。再起動のような日常でない出来事のために、session の扱いを変えない。

### 組み込みのツールと同じ道を通す

- ターンの上限、振り返り中にツールを断る hook、`repeatedCalls`、ターンの記録、畳み込みは、宣言したツールも組み込みのツールと同じ道を通す。
- dashboard では、宣言したツールだと分かるようにする。

### 試験

- 試験は、偽の runner で行う。
- tools を宣言したときの prefix の fixture を足す。

### 実装で決めること

この ADR では決めず、実装の PR で決める。

- config の各項目の正確な名前と既定値（`timeoutSeconds` の既定と上限）。
- runner の新しい要求の形（argv・stdin・timeout）と、古い要求との互換。
- dashboard での見せ方。

次は環境の設定（private のリポジトリ）の側で、別の作業単位で決める。

- `/tools` の mount の形。

### 実装で決めたこと（2026-10-10）

上の「実装で決めること」を、実装の PR で次のように決めた。`/tools` の mount の形は、環境の設定（private のリポジトリ）の側で決める。

- **config の項目**: 1 つのツールは `name`・`description`・`parameters`・`exposure`・`command`・`timeoutSeconds`・`maxOutputChars` の 7 つで、ほかの鍵は拒む。
  - argv の名前は `command`（プログラムと固定の引数の配列）にした。プログラムは `/tools/` で始まる絶対パスで、`.`・`..` を含まず、正規化した形と同じであることを起動時に確かめる。
  - `name` は英字で始まり、英数字・`_`・`-` で 64 文字まで（モデルの provider が関数名として受け取る形）。組み込みのツール、`codemode` に加えて、
    Pi の組み込みのツール（`bash`・`edit`・`write`・`grep`・`find`・`ls`・`powershell`）の名前も拒む。許可リストに入れると Pi の組み込みが有効になりうるためである。
  - `parameters` は省略でき、省略すると引数なしの object。キーワードは `type`・`description`・`enum`・`properties`・`required`・`items`・`additionalProperties`（真偽値）だけ。
    `enum` は `string` か `number` に付けるものに限り、`integer` は持たない。入れ子は 6 段まで。
  - `timeoutSeconds` は既定 30、1〜60 の整数。上限は runner の応答の上限（60 秒）にそろえた。runner は 1 つずつしか動かさないので、道具が runner を `run_shell` のコマンドより長く占めないようにするためである。
  - `maxOutputChars` は既定 8000、1〜20000。上限は runner が 1 つの出力に持つ 64 KiB を、日本語の文字数にしたおおよその値である。
  - `tools` を宣言したのに `loop.workspaceSocket` が無い config は、起動時に拒む。空の配列は書かないのと同じに扱う。
  - config の秘密の検査（`...File`・`...Env` や `token` などの鍵の名前）は、`tools` の中では鍵の名前に掛けない。`parameters` の鍵はモデルの引数の名前で、
    `outputFile` のような名前を秘密の参照と取り違えないためである。値の形（`sk-` などで始まる文字列）の検査は掛ける。
- **runner の要求**: 1 行の JSON に `argv`（配列）・`stdin`（文字列）・`timeoutSeconds` を足した形にした。`command` と `argv` の両方を持つ要求、`argv` が空・
  プログラムが絶対パスでない・NUL を含む要求、`command` に `stdin` を付けた要求は断る。
  - runner はプログラムを bash を通さずに自分のプロセスのグループで起動し、作業ディレクトリと環境変数（`PATH`・`PWD`・`HOME`・`LANG`・`TZ`）は `run_shell` と同じにする。
  - `timeoutSeconds` は runner の応答の上限で頭打ちにする。過ぎたらグループごと SIGKILL で止め、答えに `timedOut` を付ける。
    プログラムが自分で終わった後も、グループに残ったものを止める。道具の呼び出しは答えを返した時点で終わる、という扱いである。
  - 要求の 1 行の上限（64 KiB）は変えない。引数の JSON がそれを超える呼び出しは、サーバーが送る前に断る。
- **古い要求との互換**: `command` の要求は形も動きも変えない。古いサーバーと新しい作業環境の組み合わせでは、`run_shell` などはそのまま動く。
  新しいサーバーと古い作業環境の組み合わせでは、古い runner は `argv` を読まずに「command is empty」で断る。サーバーはこれを、
  作業環境の image がサーバーより古い、という文にして失敗で返す。版の食い違いを起動時に調べる仕組みは持たない（サーバーと作業環境の image は同じ版でそろえる）。
- **結果**: 終了コード 0 なら標準出力がそのまま本文で、空なら「（出力は空でした）」、切ったら切ったことを一行添える。標準エラー出力は返さない。
  失敗（0 以外の終了コード、時間切れ、シグナル）は、理由の一文に、標準出力（`maxOutputChars` まで）と標準エラー出力（2000 文字まで）の先頭を添える。
  `run_shell` と違い、記憶の変更の一行は足さない。結果は道具の出力だけ、という形を崩さないためである。
- **ツールの並びと見え方**: 宣言したツールは、組み込みのツールのすべての後ろ（Codemode が on なら `codemode` の前）に、宣言した順で並べる。
  宣言が無ければ、ツールの集合・説明・system prompt は今と一字一句同じである。
  Codemode が off のときは、`exposure` に関わらず、組み込みのツールと同じくモデルが直接呼ぶツールにする。`codemode` の見え方のツールは off では呼べる道が無くなるので、off は「見え方を使わない」として扱う。
  on のときは宣言どおりの `exposure` を付け、`codemode` のものはモデルへの宣言から外す。
- **組み込みのツールと同じ道**: ターンの上限、振り返り中に断る hook、ターンの記録、畳み込みは、Pi のツールとして渡すことで同じ道を通る。
  畳み込みでは「残さないツール」として畳まれる。`repeatedCalls` には、同じツールを同じ引数（JSON にした形が同じもの）でもう一度呼んだものを数える。スクリプトの中の呼び出しも同じである。
- **dashboard**: 宣言したツールの結果には、Pi の結果の `details` に印（`declared: true`）を残す。失敗も投げずに error の結果として返すので、印は失敗にも残る。
  ターンの詳細は、この印を見て、呼び出しの名前の横に「config で宣言したツール」と出す。今の config ではなく記録の側で見分けるので、宣言を変えた後でも、過去のターンの印は変わらない。
- **起動のログ**: 宣言したツールの名前を、起動時に 1 行だけログに出す。

### 後で決めること

秘密の要る API を道具にしたくなったときに、別の ADR で決める。今の方向は次のとおりで、細部は決めていない。

- 認証は、出口の proxy の中継が付ける。秘密は出口の proxy のコンテナだけが持ち、作業環境にもサーバーにも渡さない。
  前例は画像生成の中継である（[ADR 0044](0044-drawing-with-sdctl-and-posting-images.md)。作業環境の loopback で受け、行き先を固定して token を付ける）。
- つなぎ方は、中継が TLS を終端する形を目指す。作業環境からは上流の URL のまま呼べるようにする。

## Consequences

- 本人は、natsumi のコードを変えずに、インスタンスごとの道具を足せる。反映は、config と ConfigMap を変えてサーバーを再起動した後である。
- 宣言したツールの数だけ、ツールの定義が長くなる。`description` と `parameters` はそのまま prefix に載る。
  宣言を変えた後の最初の呼び出しでは prefix cache が外れる。同じ session のまま続けるので、古い履歴には消えたツールの呼び出しが残る。
- runner の要求の形が変わるので、サーバーと作業環境の image は同じ版でそろえる。片方だけ上げると、コマンド型のツールが動かない。
- 今の `parseConfig` は知らない鍵を拒む。`tools` を書いた config は、対応した版より前のサーバーには入れられない。skills（ADR 0073）と同じ注意である。
- `exposure` を自由にしたので、外へ副作用が出る道具も `direct` や `codemode` にでき、スクリプトから呼べる。
  そうしたときは、スクリプトの条件分岐で外への作用が出たり出なかったりしうる。どの道具をスクリプトから呼ばせるかは、config を書く人の判断である。
- コマンド型の道具は、作業環境の中で、作業環境の権限で動く。作業環境の出口は ADR 0034 のままで、道具を足しても広がらない。
- サーバーは、宣言したツールのために外へ要求を出さない。サーバーの外向きの許可リスト（ADR 0034）は、宣言したツールでは増えない。
- 秘密の要る API は、まだ道具にできない。作業環境に秘密を置かない限り、コマンド型の道具からも呼べない。道具にするには「後で決めること」の ADR が要る。
- 環境の設定の側に、別の作業単位が要る。
  - インスタンスごとの ConfigMap を作業環境の `/tools` へ読み取り専用で mount する。

### 置き換える既存の決定

- ADR 0004
  - 追加: ツールの許可リストに、config で宣言したツールが入る。許可リストを明示することは変わらず、宣言はその明示の一つの形である。
  - 残す: 拡張をコードから渡すものに限ること。宣言したツールは、サーバーのコードが config から組むツールであり、外のコードを読み込まない。
    「任意 HTTP を許可しない」も残す。サーバーは宣言したツールのために HTTP の要求を出さない。
- ADR 0019
  - 追加: runner の要求に argv と stdin を足し、bash を通さずに起動する形を加える。この形では、`timeoutSeconds` を過ぎたらプロセスを止めて失敗として返す。
  - 残す: `run_shell` は `bash -c` で実行し、60 秒で「まだ動いている」を返してプロセスを残すこと。1 コマンドの長さの上限 8000 文字。
- ADR 0066
  - 一部覆す:「本人に見えること、外に出ることは、モデルが直接呼ぶ」と「スクリプトから呼べるのは作業環境の 3 つだけ。新しく外へ出る道は増えない」は、組み込みのツールに限る。
    宣言したツールの見え方は、config を書く人の判断に移る。既定は `model-only` である。
  - 残す: 組み込みのツールの見え方の表。
- ADR 0034
  - 残す: サーバーと作業環境の外向きの規則。宣言したツールでは出口は広がらない。
- ADR 0047
  - 残す: Pi の拡張はコードから渡したものだけを読み込むこと。
- ADR 0055
  - 残す: 整理係のツール。宣言したツールは整理係に渡さない。
