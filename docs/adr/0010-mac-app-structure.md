## Context

サーバーは GitHub ログイン（ADR 0006）、単一の思考ループと Mac との会話（ADR 0008）、夜の切り替え（ADR 0009）を提供している。
Mac の側には、まだ何もない。合意しているのは、Swift/SwiftUI と AppKit で作り、デスクトップにキャラクターが常駐して、
クリックで会話欄を開くことだけである。

最初の Mac アプリを作るにあたり、次を決める必要がある。

- Xcode プロジェクトの形、対応する macOS、署名。Apple Developer のチームがなくても、手元で build とテストができること
- [client-contract.md](../client-contract.md) の同期（端末の登録、stream と seq、差分の再送と snapshot）、送信の requestId、再接続を、
  実際のサーバーやネットワークなしにテストで確かめる方法
- セッションのトークンを Keychain 以外に書かないことを、どう保証するか
- キャラクターの絵。合意した時点ではアートが未決定だったが、その後、Codex のペットの形式で作ったナツミのアセットを使うことになった

## Decision

### プロジェクト

- `mac/Natsumi.xcodeproj` に、次の 3 つのターゲットと、共有の scheme `Natsumi` を置く。
  - `Natsumi`: アプリ。AppKit と SwiftUI の UI、WebSocket の接続、`ASWebAuthenticationSession` など、OS に依存する部分だけを持つ。
  - `NatsumiCore`: framework。envelope の読み書き、同期と再接続の判断、会話の表示の状態、ログインの PKCE と callback の検証、
    保存の境界、アバターの読み込みを持つ。AppKit と UI に依存しない。
  - `NatsumiCoreTests`: `NatsumiCore` のテスト（Swift Testing）。ホストのアプリを起動せず、ネットワークにも接続しない。
- プロジェクトは生成ツールを使わず、Xcode のフォルダーの同期（synchronized folders）で手で保つ。
  ソースを足してもプロジェクトのファイルは変わらない。生成ツールを入れる手間と、その版の管理を増やさないためである。
- 対応するのは macOS 15 以降、Swift 6 の言語モードとする。
- 署名は ad-hoc（`-`）とし、チームも証明書も指定しない。App Sandbox と Hardened Runtime は使わない。
  公証と配布は、この ADR の範囲外として後で決める。
- build と test のコマンドは README に書く。build 結果は `mac/build/` に置き、Git で追跡しない。

### 接続と同期

- 接続は、I/O を持たない状態機械（`SessionMachine`）で表す。入力は「接続した」「受信した」「切れた（close code か HTTP の状態）」「送信」
  「再接続のタイマー」で、出力は「接続する」「送る」「端末 ID を保存する」「ログインを求める」「再接続を予約する」などの指示である。
  アプリがその指示を実行する。これで同期と再接続の規則を、サーバーなしでテストできる。
- イベントは、最後の snapshot か resume で決まった stream の、次の seq のときだけ適用する。
  - すでに受け取った seq は無視する。
  - seq の欠け、epoch や stream の変化では、`resume` なしの `session.sync` を送り、snapshot を待つ。同期は一度に 1 つだけ送る。
  - 未知の `type` は適用しないが、その seq は受け取ったものとして進める。未知の表情の値も無視する。
  - 同期の前の応答（接続ごとの一時的な stream の `command.rejected` など）は適用するが、位置にはしない。
- 最後に受け取った位置はメモリにだけ置き、再接続の `resume` に使う。端末 ID は設定（UserDefaults）に保存する。
  アプリを再起動したら、サーバーの snapshot から始める（client-contract のとおり、独自の会話 DB は持たない）。
- 送信には UUID の requestId を付け、`command.accepted` が届くまで送信欄の外（outbox）に「受付中」として残す。
  同期の前や切断中の送信は、同期が済んだら同じ requestId で送る（サーバーが同じ結果を返す）。拒否されたものはエラーとして表示し、再送しない。
- 再接続は 1 秒から倍にして、30 秒で頭打ちにする。同期できたら 1 秒に戻す。
  - close code 1008 と、upgrade の 401 は、セッションの終わりとしてトークンを消し、ログインを求める。再接続しない。
  - 4001（同じ端末の新しい接続への置き換え）では再接続しない。1002・1007（プロトコルの誤り）では止まる。
  - それ以外（4002 を含む）は再接続する。
- `service.unavailable` が同期の応答なら、会話を使えない状態として表示し、利用者の操作で接続し直す。

### ログインと保存

- `ASWebAuthenticationSession` を callback の scheme `natsumi` で使う（ADR 0006）。scheme はセッションが受け取るので、
  アプリの Info.plist には URL scheme を登録しない。登録すると、ログインの外から来た `natsumi://` でもアプリが開くようになるためである。
- PKCE の verifier とアプリの state は、それぞれ 256 ビットの乱数を base64url にした 43 文字とする。
  callback では、state の一致を最初に確かめ、一致しなければ `code` も `error` も使わない。
- トークンは login keychain の generic password にだけ保存する。保存の境界は `SecretStore` の口で分け、
  テストで、ログインした後の設定（UserDefaults）に書かれたキーが接続先の origin と端末 ID だけで、トークンを含まないことを確かめる。
- 接続先の URL は設定画面で入れる。https の origin だけを受け付け、http は loopback のホストに限る。
  接続先を変えたら、前のサーバーのトークンと端末 ID を捨てる。
- 期限を過ぎたトークンは、使う前に消してログインを求める。ログアウトは `POST /auth/logout` を試みてから、トークンを消す。

### UI

- アプリはメニューバーに常駐し、Dock には出さない（`LSUIElement`）。メニューには状態、話しかける、履歴を開く、ログイン、設定、ログアウト、終了を置く。
  メニューバーのアイコンは見つけにくいので、キャラクターの右クリック（control クリック）でも同じメニューを出す。
- 設定は SwiftUI の `Settings` の scene ではなく、キャラクターと同じ層のパネルに出す。アプリを前面にしないパネルやメニューからは `Settings` の scene を開けず、全画面のアプリの上にも出ないためである。
- キャラクターは、枠のない、フォーカスを奪わないパネルで、ほかのウインドウの上に浮かび、すべての Space に出る。
  ドラッグで動かし、位置を覚える。接続していないときは、小さな印を付ける。

#### 会話の表示はキャラクターと同じ層に出す（2026-09-15 改訂）

最初の版では、会話欄を通常のウインドウにしていた。通常のウインドウは全画面表示のアプリの上に出ず、そこではキャラクターだけが見えて会話ができなかった。
また、会話欄を開くとアプリが前面になり、使っていたアプリからフォーカスを奪った。そこで、会話にかかわる表示をすべてキャラクターと同じ層のパネルにする。

- 同じ層とは、`NSPanel` の `.nonactivatingPanel`、level `floating`、`canJoinAllSpaces` と `fullScreenAuxiliary` で、
  全画面表示のアプリの上とすべての Space に出て、アプリを前面にしないことである。
- 吹き出し・知らせの束・入力欄は、キャラクターのパネルの子ウインドウにする。キャラクターをドラッグすると一緒に動き、動いた後に配置を計算し直す。
  履歴は子ウインドウにしない。タイトルバーのあるウインドウは AppKit が画面の中に押し戻し、子ウインドウだと親のキャラクターまで一緒に動いてしまうためである。
- パネルの枠は配置の計算だけで決める。`NSHostingView` の `sizingOptions` を空にし、SwiftUI の理想の大きさでウインドウの大きさを変えさせない（変えさせると、上端を保ったまま高さが変わり、パネルが配置からずれた）。
- **吹き出し**はキャラクターの上（一列を反転したときは下）に出し、しっぽでキャラクターを指す。中身は、natsumi の未読の返事、それが無ければ受付の前の送信があるときの「受付中」か、考え中の「考え中」である（下の「未読の返事と知らせ」）。
  - 「考え中」は処理待ちのイベント（queued か processing）があるときだけとし、表情が thinking かどうかでは決めない。
    サーバーは処理の終わりに、自分が付けた thinking の表情だけを戻し、モデルがツールで付けた表情は残す。表情で決めると、返事の後も考え中が続く（履歴の「考え中」も同じ）。
  - 長い発言は 120 文字・5 行で切り、「続きは履歴で」で履歴を開けるようにする。吹き出しの中でスクロールさせないのは、フォーカスを持たないパネルの中の小さなスクロールが扱いにくく、吹き出しの大きさも読み取りにくくなるためである。
  - × で閉じた「受付中」「考え中」は、中身が変わるまで出さない。
- **入力欄**は、キャラクターのクリックで下に開く。Enter で送り、Esc・もう一度のクリック・ほかのアプリのクリック（グローバルなマウスのモニター）で閉じる。
  - 接続していない・ログインが必要などの状態と、送れなかった送信のエラーは、入力欄の上に出す。ボタンの動作は以前の会話欄と同じである。
  - 文字の欄は AppKit の `NSTextView` にし、変換中（marked text がある間）の Enter と Esc は入力メソッドに任せる。Shift+Enter は改行にする。
  - 文字の欄は行に合わせて伸び、160 ポイントか利用者が決めた高さの大きい方を超えると中でスクロールする。
  - 右下のつまみで、幅（200〜640）と文字の欄の高さ（40〜400、伸びる前の高さ）を変えられる。キャラクターの倍率とは別に UserDefaults に保存する。
- **履歴**は、入力欄の時計のボタン、またはメニューで、キャラクターの横に開く。中身は以前の会話欄の履歴と同じで、送信欄はない。閉じるボタンか Esc で閉じる。
  - 履歴のボタンは入力欄にだけ置く。吹き出しは漫画のセリフとして × だけにし、長い発言の「続きは履歴で」で足りるためである。
  - 履歴のパネルは不透明な背景にする（半透明のユーティリティウインドウは、下のウインドウが透けて読みにくかった）。
- **大きさ**は、設定で 50% から 200% まで 25% 刻みで選び、UserDefaults に保存する。100% は spritesheet の 1 マス（2x のピクセル）を半分の大きさで描く。
  変えたらキャラクターの足もと（下端の中心）を動かさずに大きさを変える。吹き出しと入力欄の文字は、読める範囲（85%〜140%）で一緒に大きさを変える。
- パネルの配置は、下の「縦の一列」に従う。

#### 縦の一列と漫画の吹き出し（2026-09-15 改訂）

最初は、吹き出しを上、入力欄を下、知らせの束と履歴を横と、パネルごとに別の規則で置いていた。パネルがキャラクターの四方に散らばり、互いに覆うこともあった。
また、キャラクターを角に置いてからパネルを出すと、キャラクターが画面の中へ引き戻され、瞬間移動したように見えた。そこで、配置を一列にそろえ、キャラクターを動かさないことにする。

- **縦の一列**: 上から、知らせの束、返事の吹き出し、キャラクター、入力欄の順に置く。
  - どのパネルも横の中心をキャラクターの中心にそろえ、横に広げない。
  - パネルの幅の上限は、入力欄の幅（利用者が決める幅）にそろえる。
  - キャラクターとパネル、パネルとパネルの間隔は一定で、キャラクターの倍率に合わせる（100% で 8 ポイント）。
  - 返事が無いときは、知らせの束をキャラクターのすぐ上に置く。
- **キャラクターは動かさない**: パネルを出す・隠す・大きさが変わる・未読が増減する、のどれでも、キャラクターの枠は変えない。
  - キャラクターが動くのは、利用者のドラッグと、倍率の変更（足もとを保つ）と、画面の構成の変更（画面の中に戻す）だけである。
  - 画面の外に少しかかる位置に置いても、そのままにする。
- **入らないときは、パネルの側を変える**:
  - 上に足りなければ、一列を上下に反転する。キャラクターの下に吹き出しと知らせ、上に入力欄を置き、しっぽは上を指す。
  - 吹き出しと知らせの束は、常にキャラクターの隣に置き、しっぽとキャラクターの間に何も挟まない。入力欄が自分の側に入らなければ、一列の反対の端（知らせの束の外側）に回す。
  - 横にはみ出すパネルだけを内側にずらし、しっぽはキャラクターの中心を指し続ける。
  - それでも高さが足りなければ、後ろに重ねる枚数を 0 にし、次に前の返事と知らせの行数を 2 行、1 行と減らす（`StackBudget`）。
- **履歴**は一列に入れない。一列（キャラクターとパネル）の横の、空いている側に、一列と重ならないように開く。
- **漫画の吹き出し風の見た目**:
  - 返事は白地に黒の太めの輪郭（倍率に合わせる）、丸い角、キャラクターを指すしっぽ。重なりは、後ろの吹き出しの輪郭がキャラクターから離れる向きに少しずつずれて見える形にする。
  - 知らせは同じ輪郭の黄色地にベルの印、入力欄は同じ輪郭の白地でしっぽなし、キャラクターの印は黒の輪郭の黄色い丸。
  - 文字はヒラギノ丸ゴを優先し、無ければシステムの丸い書体にする。
  - 半透明にしない。吹き出し・知らせ・入力欄は、ダークの外観でも白地（知らせは黄色地）に黒い文字のままにする（パネルの外観をライトに固定する）。
  - 履歴は、natsumi の発言を同じ輪郭と書体の吹き出しにし、ウインドウ自体は外観に従う。
- 配置の計算（`OverlayLayout`）は `NatsumiCore` に置き、画面の四隅と中央、倍率、パネルの有無で、パネルが画面に入り、キャラクターと互いに重ならないことをテストする。
- 吹き出しの中身、開閉、大きさ、配置の計算は `NatsumiCore` に置き、UI なしでテストする。

#### 未読の返事と知らせ（2026-09-15 追記）

最初の版の吹き出しは natsumi の最後の発言だけを出していた。知らせのすぐ後に返事が届くと、知らせは目に入らないまま返事に置き換わった。
そこで、本人が確かめていないものを残して見せる。何を確かめたかはサーバーが持つ（[ADR 0013](0013-read-state-on-the-server.md)）。

- **状態はサーバーのもの**を使う。snapshot の `readThroughMessageId`・`unreadReplyCount`・`unacknowledgedNotificationIds` で置き換え、
  `conversation.read`・`notification.acked`・`conversation.message` のイベントで更新する。既読や確認を Mac に保存しない（UserDefaults にも置かない）。
  ほかの Mac で確かめたものは、その Mac のイベントでこちらからも消える。
- **返事の束（白い吹き出し）**: カーソルより後の返事を古い順に並べ、一番古いものを前に出す。後ろの返事は縁として 2 枚まで重ね、それより多い分は「あと N 件」の件数だけにする。
  - カーソルが一覧（直近 500 件）に無ければ、一覧の返事はすべて未読で、件数は `unreadReplyCount` を使う。一覧より古い未読は件数にだけ入る。
  - 前の吹き出しの本文のクリックで、その返事までの `conversation.read` を送り、次の未読を前に出す。最後を確かめたら吹き出しを閉じる。
  - 右上の × は、未読の最後の返事までの `conversation.read` を送り、束を丸ごと閉じる。本文のクリックと役割を分け、1 件ずつと全部の 2 つの操作にする（tooltip は「すべて既読にして閉じる」）。
  - キャラクターの右クリックのメニューにも、× と同じ結果の「返事をすべて既読にする」「知らせをすべて確認する」を置く。未読・未確認があるときだけ有効にする。
  - 「あと N 件」は、返事と知らせのどちらも本文の下の行の左端に、同じ書き方・大きさ・色で出す。
  - 未読の返事は、確かめる操作でしか閉じない。「続きは履歴で」で履歴を開いても、確かめたことにはしない。本人がメッセージを送っても、カーソルは進めない（契約のとおり）。
  - 未読の返事があるときは「考え中」「受付中」を出さず、未読を出したまま小さな回る印で処理中を示す。
- **知らせの束（黄色、返事とは別枠）**: 未確認の知らせを `unacknowledgedNotificationIds` の順に、黄色いカードの束にして出す。
  - 前のカードの本文のクリックで `notification.ack` を送り、次を前に出す。返事と同じ位置・見た目の × は、束の中の未確認の知らせをすべて ack して閉じる（tooltip は「すべて確認して閉じる」）。束を広げて好きな 1 件を閉じる形は、今は作らない（契約上は順不同で確かめられる）。
  - 一覧より古い知らせは本文が無いので、「前の知らせが N 件」の 1 枚にまとめ、クリックでまとめて確かめる。履歴にも無いので、履歴には誘導しない。
  - 位置は縦の一列の、返事の吹き出しのさらに外側である（返事が無ければキャラクターのすぐ隣。上の「縦の一列と漫画の吹き出し」）。
  - 返事と分けたのは、知らせは返事と違って順に読み進めるものではなく、1 件ずつ順不同で確かめるもので、既読の記録もカーソルとは別だからである。
- **キャラクターの印**: 未確認の知らせがあるとき、キャラクターの右上に黄色い件数の印を付ける。大きさはキャラクターの倍率に合わせる（100% で直径 22 ポイント、14 ポイントより小さくしない）。
  印のクリックで知らせの束を隠したり出したりする。隠しても確認にはならない。隠している間に新しい知らせが届くと、束をまた出す。
- **確かめる操作は楽観的に反映する**。サーバーの応答を待たずに見た目を進め、手元の変更として持つ。
  - `command.accepted` で手元の変更を外し、応答の位置（ほかの端末が先に進めていればその位置）を使う。
  - `command.rejected` や `service.unavailable` では手元の変更を捨て、サーバーの状態に戻す。その後の snapshot やイベントが正になる。
  - 切断中や同期の前に確かめたものは、同期の後に同じ requestId で送る。カーソルは戻らず、確認は冪等なので、送り直しても害がない。
- **履歴**では、知らせを黄色の背景と縁で返事と区別し、未読の返事と未確認の知らせに「未読」「未確認」の印を付ける。
- 新着の枠の強調（snapshot で戻った発言は強調しない）は、吹き出しに出るものがすべて未読になったので取り除いた。

#### キーボードのフォーカス

- 枠のないパネルは既定で key window になれないので、入力欄と履歴のパネルだけ `canBecomeKey` を true にする。キャラクターと吹き出しは key にならない。
- `.nonactivatingPanel` なので、入力欄が key になってもアプリは前面にならず、それまで使っていたアプリが前面のままである。
  入力欄を開くときに key にして、文字の欄を first responder にする。
- 入力欄と吹き出しのボタンは、アプリが前面でなくても最初のクリックで効くようにする（`acceptsFirstMouse`）。

### アバター

- 形式は Codex のペット（`pet.json` と spritesheet の atlas）とし、任意の `avatar.json` で atlas・動作・再生の速さ・表情と動作の対応表を足す。
  `avatar.json` がなければ、Codex のペットの既定の配置と、既定の対応表を使う。
- 対応表にない表情は neutral の動作で表示する。範囲外の行、atlas より小さい画像、対応表が指す存在しない動作、ディレクトリの外を指す spritesheet は、読み込みの誤りとする。
- 読み込む順は、利用者のディレクトリ（既定 `~/Library/Application Support/natsumi/avatar/`、設定で変更可）、同梱のアセット、仮の絵（表情ごとの絵文字）である。
  表情を足すときに、手元で試してからリポジトリに入れられるようにするためである。
- 同梱のアセットは `mac/Avatars/natsumi/` に置き、アプリの resources にフォルダーのまま入れる。
  サーバーの 8 つの表情のうち、当面は sleepy に専用の動作がなく、idle で表示する。
- ライセンスは、コードを MIT、`mac/Avatars/` のアセットを CC BY 4.0 とする。

## Consequences

- ad-hoc 署名はビルドのたびに変わるので、ビルドし直したアプリが Keychain の項目を読むときに、確認のダイアログが出ることがある。
  チームの署名にすれば解消するが、配布を決めるときに合わせて扱う。
- App Sandbox を使っていない。配布の形を決めるときに、ネットワーク・Keychain・利用者のアバターのディレクトリの権限と合わせて見直す。
- Keychain を使うテストは、ログイン中のユーザーの GUI のセッションで実行する必要がある。SSH のセッションでは失敗する。
- UI（キャラクター・吹き出し・入力欄・履歴のパネル、ログインのシート）と、`URLSessionWebSocketTask` を使う接続の部分には自動テストがない。実際のサーバーでの手動の確認に頼る。
- 入力欄が key になっている間は、前面のアプリのウインドウは key ではなくなる。入力欄を閉じても、そのウインドウに入力するには一度クリックが要ることがある。
- ほかのアプリのクリックで入力欄を閉じるために、入力欄を開いている間だけグローバルなマウスのモニターを使う。マウスのイベントの監視には、アクセシビリティの許可は要らない。
- `URLSessionWebSocketTask` は、定義済みでない close code（4001・4002）を区別して渡さないので、これらはネットワークの切断として扱い、再接続する。
  4001 を受けても再接続するが、置き換えたのは同じ端末の新しい接続なので、1 つのアプリの中では接続が往復し続けることはない。
- `service.unavailable` の後、サーバーの会話が使えるようになったことを知らせるイベントは契約にない。利用者が「接続し直す」を押す必要がある。
- サーバーからのメッセージの大きさの上限は契約にない。snapshot は最大 500 件のメッセージを含み得るので、受信の上限を 16 MiB にした。
- 知らせの束は、前のカードから順にしか確かめられない。好きな 1 件を閉じたくなったら、束を広げる形を足す。
- 一覧（直近 500 件）より古い未読の返事は、件数には入るが本文を出せない。一覧の返事がすべて既読で、未読がそれより古いものだけのときは、吹き出しに出ない。
- 承認・macOS の通知センター・Slack・音声、最終的な表情のアート（sleepy など）、配布は、この ADR の範囲外である。
