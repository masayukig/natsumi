# 0066. Slack に貼られた PDF を取り込み、なつみが作業環境の poppler で読む

- Date: 2026-10-03
- Status: Accepted

## Context

[ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で、Slack はなつみが読むファイルとして受け取ることにした。
添付は、画像（PNG・JPEG・GIF・WebP）で `slack.maxImageBytes` 以下のものだけをサーバーが取ってきて、チャンネルの `files/` に置く。
行の `images` にそのパスを書き、あなた宛ての発言なら出来事と一緒に画像として届ける。ほかの添付は `attachments` に名前だけを書く。

Slack では、資料や見積もりや案内を PDF で貼ることが多い。なつみは「PDF が付いている」ことしか分からず、中身を聞かれても答えられなかった。

手元には次のものがあった。

- 画像を取ってくる部品（宣言された種類と大きさで選び、bot token を付けて上限まで取り、中身の頭で種類を確かめてから書く）。
- 作業環境（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）は普通の Debian で、ネットワークが無く、`/sources` を読み取り専用で見る。`view` で `/sources` と `/work` の画像を見られる。
- 作業環境には PDF を読む道具が無かった。

## Decision

### PDF も画像と同じ道で取り込む

- 宣言された種類が `application/pdf` の添付を、画像と同じく取ってきて、同じ `files/` に同じ名前の付け方（拡張子 `.pdf`）で置く。
- 種類は Slack の宣言（貼った人の言い分）だけでは決めない。取ってきた中身が `%PDF-` で始まらなければ置かず、`attachments` に名前だけを書く。
- 上限は 20 MiB で、設定にはしない。`slack.maxImageBytes` に書ける最大と同じで、取ってくる間はメモリに持つので、画像と同じ桁に収める。
  Slack に貼られる資料や案内はふつう収まり、本 1 冊のスキャンのような大きなものは収まらない、という目安である（実物の大きさは測っていない）。
  宣言された大きさで先に断り、取る途中でも上限で止める。
  変えたい場面が出てから設定にする。

### 行には `pdfs` で書き、モデルには画像として渡さない

- 行には、取り込んだ PDF のパスを `pdfs` に書く。`images` は画像だけのまま変えない。取り込まなかったものは、これまでどおり `attachments` に名前を書く。
- データベースには、これまでと同じ `{ name, path }` で残す。画像か PDF かはパスの拡張子で分ける。以前の行はそのまま読める。
- あなた宛ての発言でも、PDF は出来事の画像に載せない。モデルが受け取れるのは画像だけで、PDF は何ページあるか分からない。読むかどうか、どこを読むかはなつみが決める。

### 作業環境に poppler-utils を入れ、マニュアルに読み方を書く

- 作業環境のイメージに `poppler-utils` と `poppler-data` を入れる（`poppler-data` は日本語などの文字の対応表で、無いと日本語の PDF は文字が取れず、ページも白く描かれる）。文字は `pdftotext <パス> -` で読み、図や表やスキャンは `pdftoppm -png -r 100 -f N -l N <パス> /work/pdf/<名前>` でページを画像にしてから `view` で見る。
- `/sources` は読み取り専用なので、ページの画像は `/work` に作る。手順は `/manual/slack.md` の「PDF を読む」に書く。

退けた案:

- **サーバーが PDF を文字やページの画像に変えて置く**: なつみは読むだけで済むが、サーバーのイメージに道具が増え、信用できない入力をネットワークのあるサーバーで解析することになる。
  作業環境ならネットワークが無く、閉じ込めの中で解析される。読むページもなつみが選べる。
- **PDF の上限を設定にする**: `slack.maxImageBytes` と並べて足せるが、変えたい場面がまだ無い。
- **ほかの添付（Office の文書など）も取り込む**: 読む道具がさらに要る。PDF で足りるかを見てから考える。

## Consequences

- なつみは、Slack に貼られた PDF の中身を読んで答えられる。読むのは本人が頼んだときやメンションで要るときで、文字を先に読み、要るページだけを画像で見る。
- `sources/slack` の `files/` に PDF も溜まる。画像と同じく消さないので、古いものは手で片づける。
- 作業環境のイメージが `poppler-utils` とその依存の分だけ大きくなる。
- 中身の頭だけを確かめるので、壊れた PDF や細工した PDF も置かれうる。読むのは作業環境の poppler で、ネットワークの無いコンテナの中に閉じる。
- 宣言が `application/pdf` でない PDF（`application/octet-stream` で届いたものなど）は、これまでどおり名前だけになる。多ければ、拡張子や中身で拾うかを改めて決める。
