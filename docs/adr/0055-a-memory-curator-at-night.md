# 0055. 記憶の組み直しは、人格を持たない整理係が夜に行う

- Date: 2026-09-27
- Status: Accepted

## Context

[ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) で記憶を git のリポジトリにし、夜の振り返りで「記憶全体を読み直して組み直す」ことにした。
[ADR 0020](0020-limits-at-write-time-and-a-nightly-menu.md) は、その夜の作業を手順から候補に変え、必須を引き継ぎだけにした。

しばらく動かすと、記憶は構造化されずに積み上がっていった。本人が記憶を見て「どんどん追記されていって全然構造化されていない」と指摘した。
実際に見ると、次のことが分かった。

- トピックのファイルが、日付の見出しで積み上がる「ログ」の形になっている。出来事があるたびに、日付付きの節が足されていく。
- コミットのほとんどは日中のターンのもので、夜の振り返りの変更は小さい。トピックの統合・分割・書き直しは、ほとんど起きていない。
- 原因は 4 つある。
  - 日中の書き方の指示が「要点を 1 件ずつ、短く書く」だけで、既存の節を直すのか、どこに書くのかを言っていない。
  - 夜の組み直しは候補の 1 つで、実際には選ばれていない。引き継ぎと、その日の書き足しで夜が終わる。
  - 記憶の全体を 1 ターンで読み直して書き直すのは重い。記憶は数万 tokens になり、毎日増える。バックエンドと呼び出しの上限では難しい。
  - トピックの「今の状態」と「経緯」が分かれていない。経緯は `diary/` と git にあるのに、トピックにも日付で書かれる。

本人の提案は、**なつみの人格を持たず、まっさらなコンテキストで記憶を組み直すことだけをする係**を立てることだった。
なつみの夜の session は、その日の会話と思考で埋まっている。そこに記憶全体の組み直しを載せるより、空の文脈で記憶だけを見るほうが、読める量も判断の質もよい。

設計は grill-me（Q1〜Q13）で詰めた。

## Decision

### 係は、なつみのサーバーの中の別の Pi の session として動く

- 記憶の整理係（以下、係）は、natsumi のサーバーの中で、なつみとは別の Pi の session として動かす。
  作業環境の runner、コミットの検査、git を、なつみと同じものをそのまま使う。閉じ込めの形は変えない。
- 係には人格が無い。system prompt は係のための固定の文で、なつみの性格・常時記憶・引き継ぎを入れない。
  毎晩、新しい session を作り、1 ターンで終える。session の記録は Pi の session の置き場の下の `curator/` に残す。
- 係が使えるツールは、`run_shell`・`read`・`search_memory`（後述）と、係の変更の説明を書くツールだけである。
  本人への返事や知らせ、外のエージェントへの依頼、予約は持たない。

退けた案:

- **外のエージェント（A2A）の係にする**: 記憶への書き込みがサーバーの外に出る。検査とコミットを別に持つか、PR のマージが要る。
- **同じ Pod の別コンテナにする**: ログイン、検査、コミットが二重になる。

### いつ動くか: 夜の振り返りの直後、session を切り替える前

- 毎晩、なつみの夜の振り返り（引き継ぎを書くターン）が終わり、そのコミットが済んだ後、新しい session を作る前に動かす。
- **係が動いている間、なつみは寝ている。** 思考ループは止まり、その間に届いた出来事は溜めておき、切り替えの後に新しい session が扱う。
  アバターとアプリへの見せ方は、これまでの切り替えの間と同じである。
- 振り返りが引き継ぎを書けずに切り替えが失敗した夜は、係も動かさない。
- 作業環境の runner が設定されていないときは動かさない。設定 `curator.enabled` を false にすると、係は動かない。
- 係の時間と呼び出しの上限は、振り返りとは別の設定にする（`curator.timeoutMinutes`・`curator.modelCalls`）。

退けた案:

- **切り替えの後に動かす**: 係の変更の説明が、なつみの次のターンの入力に割り込む形になる。
- **記憶の量が一定を超えたら動かす**: 動かない日に変更が溜まり、動いた日の仕事が大きくなる。

### どのモデルで動かすか: 係用の経路を設定で選ぶ

- 係の経路は設定 `curator.route` で、[ADR 0046](0046-named-model-routes-switched-by-hand.md) の名前付きの経路から選ぶ。
  指定が無ければ、そのときなつみが使っている経路で動かす。
- 選んだ経路が使えないときは、ほかの経路に替えない（[ADR 0004](0004-pi-tool-and-voice-boundaries.md)）。その夜の係は失敗とする。
- まず本人のエンドポイントで試し、足りなければ設定で替える。

退けた案:

- **なつみと同じ経路に固定する**: 係にだけ別のモデルを使うことができない。
- **常にサブスクリプションの経路にする**: 記憶の全文が毎晩外に出る。

### 一晩に渡すもの: 全体の見取り図と、その夜に中身まで触ってよいファイル

- 係の仕事の中心は**ファイルの構成**である。統合、分割、改名、ディレクトリへのまとめ、索引（`INDEX.md`）を作ることを主にする。
  構成を決めるには全体が見えていなければならないが、全部の中身を毎晩読み直すことはできない。そこで、見取り図と、その夜に中身まで触ってよいファイルを分けて渡す。
- 最初の入力に、サーバーが次を組んで入れる。
  - 記憶の全ファイルの一覧。ファイルごとに、大きさと見出し（`#` と `##`）を添える。見出しが多いファイルは先頭から一定数で切り、残りの件数を書く。
    固定のファイルと `diary/` は、触らないものとして印を付ける。`diary/` は件数と最初・最後の名前だけにする。
  - **その日に変わったファイル**。最後に係が成功してから今までのコミットで変わったものを、git から読む。
    係が失敗した夜の分は、次に成功する夜まで持ち越される。初めての夜は直近 1 日とする。
  - **順番が回ってきたファイル**。最後に係の手が入ってから日が経ったものから、その日に変わったものを除いて、設定 `curator.rotateFiles`（既定 2）件。
    一度も手が入っていないものを先にする。
- 中身の書き直しは、この 2 つに挙げたファイルに限る。それ以外のファイルは、統合・分割・移動のために読むのはよいが、書き直しはしない。
- 書き直すときの形は、日中と同じ「今どうなっているか」である（後述）。日付の節の積み重ねは、今の状態にまとめる。経緯は `diary/` と git に残っている。
- どのファイルにいつ係の手が入ったかは、SQLite に記録する（schema 22）。係が成功した夜に、渡したファイルと、係のコミットで足されたり変わったりしたファイルを、その時刻で記録する。
  git の履歴からは読めない。係が見て、直す必要が無いと判断したファイルは、コミットに現れないからである。

退けた案:

- **毎晩全部を組み直す**: 記憶が増えると上限で打ち切られる。打ち切られると全部を捨てる（後述）ので、何も進まない夜が続く。
- **範囲を係に任せる**: 毎晩どこまで読むかの判断に呼び出しを使い、同じところばかり直す夜が起きる。

### 消してよいもの

- 古くなったものと、重複は消してよい。
- **消したものは一つずつ、何をなぜ消したかを、係の変更の説明に書く。** 本人が後から確かめるためである。
- 本人の言葉、本人との約束、「覚えておいて」と言われたことは、済んだと明らかでない限り消さない。
- 経緯は `diary/` と git に残るので、トピックから消しても辿れる。

### 係が触ってはいけないもの

- 固定の 3 つ（`always.md`・`personality.md`・`handoff.md`）は、中身も名前も変えない。なつみ自身のものである。
- `diary/` は変えない。日ごとの履歴として残し、組み直しの材料として読むのはよい。
- ファイルの場所が変わっても、`always.md` や `handoff.md` の中の古いパスは係が直さない。なつみは `INDEX.md` か `search_memory` で探し直す。

### `INDEX.md`: 記憶の入口

- `/memory/INDEX.md` を固定のファイルに加える。名前とリポジトリの直下にあることを、サーバーが固定する。
  無ければ最初の起動で雛形を置く。消すことも改名することもできない（他の固定のファイルと同じく戻す）。
- **書くのは係だけである。** なつみのターン（日中も夜の振り返りも）で変わっていたら、コミットの検査で直前のコミットの状態へ戻し、理由を次のターンの入力で伝える。
  [ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) の、夜だけ書ける `always.md`・`personality.md` を戻すのと同じ道である。
- 中身は、ファイルごとのパスと 1 行の説明を主にする。ディレクトリごとの README は、係が必要と判断すれば作ってよい。サーバーは中身の形を要求しない。
- 係が入口を作ることで、なつみは記憶を探すときに、まず 1 つのファイルを読めばよくなる。

退けた案:

- **係が自由に作る**: 入口の場所が夜ごとに変わり得る。なつみに「まずここを読む」と言えない。
- **作らない**: 構成を組み替えるほど、なつみは毎回探し直すことになる。

### 係のコミットと、検査に当たったとき: 全部か無しか

- 係の変更は、その夜に 1 コミットにする。コミットメッセージは、係が書いた変更の説明である。
  書かれないまま終わったら、サーバーが機械的なメッセージを付ける（[ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) の夜と同じ）。
- 係のコミットにも、なつみのものと同じ検査（`.md` 以外、空、大きすぎる、制御文字列、日本語以外の文字）を掛ける。
  加えて、固定の 3 つの変更、`diary/` の変更、`INDEX.md` の削除を、係には許さない。
- **どれか 1 つでも当たったら、その夜の係の変更をすべて捨てる。** 作業ツリーを直前のコミットに戻し、係が足したファイルも消す。
  - なつみの検査はファイルごとに戻すが、係の変更は構成の組み替えである。統合したファイルだけが検査で戻ると、統合元は消えたまま、統合先は無い、という形になる。
    移動の途中や統合の途中には意味が無いので、部分だけを残さない。
  - 触ってはいけないファイルを変えていた場合も、その分だけを戻すことはしない。係の組み替えがそのファイルの中身を前提にしていたかは、サーバーには分からない。
- 上限（呼び出し・時間）で打ち切られたとき、モデルの呼び出しが失敗したときも、同じく全部を捨てる。
  [ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) は、なつみのターンが打ち切られたときに「書きかけを捨てるより、履歴に残して戻せるほうがよい」としたが、
  係の書きかけは構成の途中であり、残すと翌日のなつみが半端な構成で探すことになる。
- **係が失敗しても、夜の切り替えは止めない。** なつみの引き継ぎは係の前にコミット済みであり、新しい session はそれで始まる。
  その夜の組み直しは起きず、変わったファイルは次の夜に持ち越される。
- 係を始める前に、作業ツリーがコミットと同じであることを確かめる。夜の振り返りのコミットが失敗して変更が残っていたら、係は動かさない。
  全部を捨てるときに、係のものでない変更まで捨てないためである。
- 係が動いている間にサーバーが止まったときに備えて、動き始めたことを SQLite に記録する。次の起動で記録が残っていたら、コミットされていない変更を捨てる。
  係はコミットの前には何も確定しないので、捨てるのは係の書きかけだけである。

### なつみには何も渡さない

- 係の結果も変更の説明も、翌朝のなつみには渡さない。
- session は毎晩ゼロから始まるので、なつみは昨日の記憶の形を覚えていない。形が変わったことを知らせる必要がない。
  探すときは `INDEX.md` か `search_memory` から入る。
- 変更の説明は、係のコミットメッセージにだけ残す。本人が git やダッシュボードで確かめるためのものである。

退けた案:

- **移動・改名の対応表だけ渡す**: `handoff.md` の古いパスを読み替えるためだが、探し直せば足りる。system prompt が夜ごとに大きくなる。
- **説明の全文を渡す**: 同上で、さらに大きい。

### 日中の書き方: トピックは「今どうなっているか」を書く

- system prompt の「記憶と作業場」に、書き方を足す。
  - トピックのファイルは「今どうなっているか」を書く場所である。事実が変わったら、節を足さずに、その箇所を直す。
  - その日に起きたこと、経緯は `diary/<日付>.md` に書く。
  - 記憶を探すときは、まず `/memory/INDEX.md` を読む。言葉で探すなら `search_memory` を使う。
- 強制はしない（検査で戻さない）。書き方の指示だけにする。
- 係の仕事が毎晩の大掃除にならないように、日中から形を揃えておく。

退けた案:

- **変えない**: 係が毎晩、日付の節をまとめ直すことになる。
- **日中はトピックに書かせない**: 「覚えておいて」と言われたことがトピックに入るのが翌朝になる。

### なつみの夜の振り返りから、組み直しを外す

- [ADR 0020](0020-limits-at-write-time-and-a-nightly-menu.md) の候補の一覧から、「記憶全体を読み直し、重複しているところ、古くなったところを直す」と「トピックをまとめる、分ける、名前を変える、フォルダを整理する」を外す。
- なつみの夜は、書き漏れの書き足し、`always.md` と `personality.md` の見直し、作業場の片づけ、引き継ぎに絞る。
  組み直しは係の仕事だと、指示の中で明示する。
- 同じ晩に、なつみと係が同じファイルを直し合うことを避ける。

### 記憶を言葉で探すツール: `search_memory`

- 記憶を探す専用のツール `search_memory` を、なつみと係に足す。
  - 引数は検索語と、`/memory` の中のパスでの絞り込み（省略できる）である。
  - サーバーが、作業環境の runner で `rg` を決まったオプションで `/memory` に掛ける。
    検索語は文字どおりに探し（正規表現にしない）、大文字と小文字を区別せず、前後 2 行を添える。`.git` は探さない。
    1 ファイルあたりの件数、1 行の長さ、結果全体の長さに上限を置く。
  - 結果は「ファイル:行番号」と前後の行である。続きは `read` で読む。
  - 検索語もパスも、`rg` のオプションとして解釈されない形で渡す。パスは `/memory` の外を指せない。
- 記憶の外を探すのは、これまでどおり `run_shell` で行う。
- `run_shell` の `rg` でも同じことはできるが、オプションの組み立てで失敗しやすい。記憶を探す道は、毎日何度も通るので、決まった形にしておく。
- なつみのツールの一覧の末尾に足す。前にある定義は prefix の上で動かない。

退けた案:

- **`run_shell` のまま、prompt だけ整える**: オプションの組み立ての失敗が残る。

### ダッシュボード

- 係のターンは、ターンの一覧に種類を分けて出す（`turn_stats` の種類に `curator` を足す。schema 22）。夜の振り返りと同じく、session の記録の中の場所も残す。
- 係が失敗したり打ち切られたりしたターンは、「失敗と待ち」の打ち切られたターンに出る。
- `natsumi stats` とダッシュボードの統計は、これまでどおり普通のターンだけを数え、係のターンを混ぜない。

### 設定

`curator` 節を足す。すべて省略でき、省略時は既定値を使う。

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `enabled` | `true` | false なら係を動かさない |
| `route` | なし | 係の経路（`pi.routes` の名前）。無ければ、そのときなつみが使っている経路 |
| `modelCalls` | `60` | 係のターンのモデル呼び出しの上限 |
| `timeoutMinutes` | `30` | 係のターンの時間の上限 |
| `rotateFiles` | `2` | 一晩に順番で回すファイルの数 |

- 呼び出しの上限は、振り返りの既定（40）より大きく取る。係は構成を組み替えるので、移動と書き直しと索引のために、ファイルの数だけコマンドが要る。
  一方で、上限に当たると全部を捨てるので、大きすぎる組み替えを一晩で試みないよう、係の指示の中で区切らせる。

### 今溜まっている記憶

- 導入の前に、手で整理はしない。初回だけ全部を組み直すこともしない。
- 係の通常の回し方（その日に変わった分と、順番に回す分）に任せ、数晩で一巡させる。
  最初の数晩の出来は、本人がダッシュボードのファイルの閲覧と git で確かめる。

## 置き換える既存の決定

- **ADR 0018**
  - 置き換え:「夜の再構成」で、なつみ自身が記憶全体を読み直して組み直すこと。組み直しは係が行う。
  - 追加: サーバーが固定するファイルに `INDEX.md` を加える。書けるのは係だけである。
  - 追加: 係のコミットは、検査に 1 つでも当たったら全部を捨てる。なつみのコミットのファイルごとの戻し方は変えない。
  - 残す: 記憶のリポジトリ、固定の 3 つ、shell での読み書き、ターンの終わりのコミットと検査、`always.md`・`personality.md` を夜だけ書けること。
- **ADR 0020**
  - 置き換え: 夜の候補のうち、重複と古いところを直すことと、トピックの統合・分割・改名・フォルダの整理。
  - 残す: 手順ではなく候補として渡すこと、必須は引き継ぎだけであること、やらなかったことを引き継ぎに書くこと。
- **ADR 0019**
  - 追加: 記憶を言葉で探すのは `search_memory` を使う。記憶の外は `run_shell` のままである。
- **ADR 0049**
  - 追加: ターンの種類に、係のターンを加える。統計には混ぜない。

## Consequences

- 記憶の構成は、毎晩少しずつ組み直される。数晩で一巡し、その後はその日に変わった分と順番の分だけを見る。
- 記憶の組み直しが、なつみの夜の判断から外れる。なつみの夜は短くなり、引き継ぎを書く前に上限に張り付くことが減る。
- 夜にモデルを使う時間が増える（最大で `curator.timeoutMinutes`）。その間、なつみは寝ていて、届いたメッセージは切り替えの後に扱われる。
- 係は人格を持たないので、記憶の文体がなつみのものから少しずつずれることがある。本人の言葉を残す決まりで、中身の意味は守る。
- 係が上限に当たると、その夜の組み直しはすべて無くなる。変わったファイルは次の夜に持ち越されるが、同じ理由で毎晩失敗すると、組み直しは進まない。
  失敗はダッシュボードの「失敗と待ち」に出るので、本人が気づいて上限や経路を変える。
- 記憶のファイルの場所が夜に変わる。`always.md` や `handoff.md` に書かれた古いパスは、なつみが探し直すまで古いままである。
- `INDEX.md` はなつみが書けない。なつみが入口を直したいと思っても、次の夜の係を待つことになる。
- 係の書いた変更の説明は、なつみにも本人にも届かない。本人は git の履歴かダッシュボードの係のターンで見る。
- 係の session の記録が増える。Pi の session の置き場の `curator/` に、毎晩 1 ファイルずつ残る。
- `search_memory` を足したことで、なつみのツールの定義が 1 つ増え、この版を入れた後の最初の session だけ prefix cache が効かない。
