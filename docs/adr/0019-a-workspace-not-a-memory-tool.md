# 0019. 記憶の道具をやめ、なつみの作業環境にする

- Date: 2026-09-19
- Status: Accepted（「ネットワーク」の節の `network_mode: none` と閉じ込めの実測のネットワークの項目は [ADR 0034](0034-an-allow-list-for-the-way-out.md) で置き換え、永続する書き場所を 0700 で作る点は [ADR 0033](0033-running-on-kubernetes.md) で置き換え、作業環境に読み取り専用のマニュアル `/manual` を見せる点は [ADR 0036](0036-a-manual-to-read-and-a-limit-on-waiting.md) で追加、読み取り専用の `/sources` と shell の `view` のコマンドを見せる点は [ADR 0039](0039-slack-as-files-and-a-scored-dove.md) で追加）

## Context

[ADR 0011](0011-memory-shell-in-a-confined-container.md) は、モデルの shell を `natsumi-tools` という別のコンテナに閉じ込め、
**「制限はコマンドの検査ではなく、コンテナの形で掛ける」** と決めた。
その一方で、image に入れるコマンドを 11 個の一覧に絞り、絞る理由としてこう書いていた。

- `awk` は `system()` で、GNU の `sed` は `e` コマンドで、別のコマンドを動かせる。
- busybox は使わない。標準の image にはネットワークの applet（`nc`・`wget` など）が入っている。

この 2 つは、どちらも **image に無い物を動かされる** 前提の話である。
`network_mode: none`・読み取り専用のルート・capability 全落ち・`no-new-privileges`・記憶以外のマウント無しという形の前では、前提ごと消える。
[ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) は `sed`・`awk` を入れるときにこの理屈を書いたが、
適用したのはその 2 つのコマンドに対してだけで、一覧という仕組みそのものには戻さなかった。

一覧を絞って実際に減るものを数え直すと、ほとんど無かった。

- コンテナの中にあるのは記憶だけで、その記憶はモデルが元から全部読める。
- 外へ出す口が無い。
- 記憶を壊すコマンド（`rm`）は、ADR 0018 が既に入れると決めている。`.git` は読み取り専用なので履歴から戻せる。
- runner を殺すのは `sh` だけでできる。

残る差は 2 つだけだった。

- **インタプリタ**（Python など）。任意の syscall を呼べるので、カーネルの攻撃面が `sh` と決まったバイナリより広い。seccomp の既定プロファイルは効いている。
- **git**。安全のためではなく、コミットはサーバーが行うという役割分担のためである。

ここから、`natsumi-tools` を「記憶の道具」として設計していたこと自体を見直した。
なつみに渡したいのは記憶を検索する道具ではなく、**記憶の整理も、調べものも、下書きも、集計もそこで行う作業机**である。
ただし「どこに書いたものが残り、どこに書いたものが見守られるか」は、言葉で言える形に設計する必要がある。

## Decision

### 目的を「記憶の道具」から「作業環境」に変える

`natsumi-tools` を **`natsumi-workspace`** にする。中で動くのは記憶の検索だけではなく、なつみの作業そのものである。

- **入れるコマンドの一覧という仕組みをやめる。** `docker/tools-commands.txt` は役目を終える。
  閉じ込めは、これまでどおりコンテナの形だけで掛ける。
- image は、空の image（scratch）に実行ファイルを写す作りをやめ、**debian-slim を土台にした普通の環境**にする。
  `docker/tools-rootfs.sh` も役目を終える。

### 書ける場所

作業環境の中で書ける場所を、次の 4 つに決める。ルートファイルシステムは読み取り専用のままとする。

| 場所 | 永続 | 検査 | コミット | 実行 | なぜそうするか |
| --- | --- | --- | --- | --- | --- |
| `/memory` | する | する | する | する | 残すもの。git の履歴になり、オーナーが差分で見守れる（ADR 0018） |
| `/memory/.git` | する | — | — | — | 読み取り専用で重ねる。履歴はなつみの手の届かないところに置く（ADR 0018） |
| `/work` | する | しない | しない | する | 手を動かす場所。中間ファイル、下書き、集計の途中、スクリプト |
| `/home/natsumi` | する | しない | しない | する | shell の履歴、`.gitconfig`、自分で書いた道具。人間の作業環境に一番近い形にする |
| `/tmp` | しない | — | — | する | 一時。コンテナの再起動で消える。`noexec`・`nosuid`・`nodev` は付けるが、境界にはならない（後述） |

- 永続する 3 つは、これまでどおり **`natsumi-data` volume の subpath** をマウントする。
  `/memory` は ADR 0018 の記憶のリポジトリ、`/work` と `/home/natsumi` はその下に新しく作る 2 つのディレクトリである。
  サーバーが起動時に、記憶のリポジトリと同じように、無ければ 0700 で作る。
- **検査とコミットの対象は `/memory` だけである。** `/work` と `/home/natsumi` は、**サーバーが見ない領域**になる。
  ターンの終わりの検査（ADR 0018）も、コミットも、この 2 つには掛からない。オーナーも git の差分では見られない。
  境界を「残すものは記憶、手を動かすのは `/work`」と言葉で言えるようにするための対価であり、
  副作用は Consequences に書く。
- `/work` と `/home/natsumi` には `noexec` を付けない。「自分で入れた道具を置ける」と決めた以上、実行できなければ意味がない。
- **`/tmp` の `noexec` は、境界としては数えない。** `noexec` は `./script` と実行ファイルの mmap を止めるが、
  `python3 /tmp/x.py` や `bash /tmp/x.sh` は止めない。インタプリタを入れた以上、`/tmp` に置いたものは実行できる。
  外す理由も無いので付けたままにするが、「`/tmp` では実行できない」という境界があると読まれては困る。
  `apt` を消さない理由と同じで、インタプリタで回せるものは、形の制限では止まらない。
- **既定の作業ディレクトリは `/work`** とする（ADR 0011 は `memory/` だった）。
  中間ファイルが既定で記憶に落ちないほうが、記憶のコミットが「なつみが残すと決めたもの」だけになる。
  記憶を触るときは `/memory` を明示する。
- 代償として、記憶のつもりで `/work` に書いても、コミットされず、気づく手がかりが無い。
  これを補うため、**サーバーは shell のコマンドのたびに記憶のリポジトリの `git status` を取り、
  変化があればツールの結果の末尾に「記憶の変更: …」の 1 行を添える。** 変化が無ければ何も添えない。
  記憶は小さいので、毎回取っても安い。

### image に入れるもの

一覧で縛るのをやめる代わりに、**水準**を決める。

- 土台は debian-slim。
- 標準の道具（`coreutils`・`findutils`・`diffutils`・`grep`・`sed`・`gawk`・`tar`・`gzip`・`bash`）。
- 検索に `ripgrep`。
- JSON を読み書きする `jq`。
- **`python3`**（標準ライブラリのみ。ネットワークが無いので、追加のパッケージは事実上入れられない）。
- **`git`**。`/memory` では `.git` が読み取り専用なので、読む操作（`log`・`diff`・`show`）だけができる。
  「いつこう書いたか」をなつみ自身が追えることは、記憶として価値が高い。`/work` では自由に使える。
- **`procps`**（`ps`・`kill`）。残ったプロセスをなつみが自分で始末するために要る（後述）。
- `tzdata`。日付をなつみのタイムゾーンで出すために要る。
- `/etc/passwd` に `natsumi` の行を置く。既定の UID で動かしたときに名前が付く。override で UID を変えたときは名前は付かないが、`HOME` を渡しているので動く。

この列挙は Dockerfile の現在の中身であって、増減は実装の判断でよい。この ADR が決めるのは **「普通の Debian の環境 + Python」という水準**である。

- パッケージマネージャ（`apt`・`dpkg`）は、image に残っていても消さない。
  ルートが読み取り専用なので、インストール先が無い。消してもインタプリタで同じことができるので、消すことは閉じ込めの強さを変えない。
- シェルは `bash` にする。runner は `bash -c` で実行する。`pipefail` やヒアドキュメントで躓かない。

### 1 コマンドの寿命と、残ったプロセス

**長い処理を残せるようにする。** ADR 0011 の「runner が毎回プロセスグループごと止める」設計を覆す。

- runner は、応答の上限（**60 秒**）まで待つ。
  - コマンドがそれまでに終われば、これまでどおり終了コードと出力を返す。
  - 終わらなければ、**そこまでの出力と「まだ動いている」という印を返し、プロセスを殺さない。**
  - 返した後も、runner は残ったプロセスの出力を **読み捨て続ける**。読むのをやめるとパイプが詰まってプロセスが固まる。
    読み捨てた分は返さない。出力を残したいときは、なつみが `/work` のファイルへリダイレクトする。
- **応答の上限は残す。** 返らないと思考ループが待ち続ける。上限は「コマンドを止める線」ではなく「答えを返す線」になった。
- runner は、**1 度に 1 つのコマンドしか待たない**（ADR 0011 のまま）。
  ただし応答を返した後は次のコマンドを受け付ける。まだ動いている前のコマンドは、そのまま動き続ける。
- サーバー側の待ちは `loop.shellWaitSeconds`（既定 **75 秒**）とする。runner の上限（60 秒）より長くする。
  差の 15 秒は、応答の組み立てと書き出しの分である。設定で runner の上限を変えるなら、こちらも合わせて長くする。
- **残ったプロセスはなつみに任せる。** サーバーは止めない。
  - runner は、毎回の応答に **自分が起動したコマンドのうちまだ動いているものの数** を入れる。
    サーバーは、1 以上のときだけツールの結果の末尾に 1 行添える。なつみが忘れていることに気づける。
  - pids の上限に達して fork できなくなったときは、その旨と「`ps` で見て `kill` すること」を結果に書き添える。
  - **夜に「作業場の棚卸し」を専用のタスクとして渡す。** ADR 0018 の夜の再構成の手順に、
    残っているプロセスを見て要らないものを止め、`/work` の要らないファイルを片づける段を足す。
    夜の指示の実装は、記憶の側の作業単位で行う。
- コンテナが再起動すると、残ったプロセスも `/tmp` も消える。永続する 3 つのディレクトリは残る。
- `init: true` は残す。runner が待たなくなった孫プロセスを、init が回収する。

### 資源の上限

作業机として使うので上げる。ADR 0011 の数字を次で置き換える。

| 項目 | ADR 0011 | ここで決める値 | 理由 |
| --- | --- | --- | --- |
| CPU | 1 | **2** | 集計やスクリプトを回すのに 1 では待ちが長い。一方、残ったプロセスが回り続けても、同じホストでモデルの呼び出しと natsumi 本体が動ける余地を残す |
| メモリ | 256 MB | **1 GB**（swap なし） | Python で数万行を読んで集計する程度なら十分な大きさ。`/tmp` の tmpfs もこの枠から取られる |
| pids | 64 | **256** | 残ったプロセスが溜まることを前提にする。数十個の残りと普通のパイプラインが同時に通り、fork の暴走は止まる大きさ |
| `/tmp` | 16 MB | **128 MB** | メモリの枠から取るので、1 GB に対して食い過ぎない大きさにする |
| 1 コマンドの時間 | 10 秒（止める） | **止めない**（応答は 60 秒） | 上記 |

### コマンドと出力の上限

- **1 コマンドの長さの上限は 8000 文字のまま据え置く。** ADR 0018 の決定は変えない。変えるのは、その理由づけである。
  - ADR 0018 は「runner が受け取る 1 行の JSON の上限（16 KiB）の中に収まる」と書いたが、これは日本語では成り立たない。
    UTF-8 の日本語は 1 文字 3 バイトなので、8000 文字は最大 24 KiB になり、16 KiB を超える。
    **上限は今も 16 KiB のままである。** つまり、8000 文字という決定は、runner 側では通らないまま置かれていた。
  - **runner の `MaxRequestBytes` を 16 KiB から 64 KiB へ上げる。** 8000 文字は UTF-8 で最大 24 KiB、
    JSON のエスケープが最悪に効く場合（すべてが `\uXXXX` に展開される制御文字）でも 48 KiB で、64 KiB に収まる。
    ADR 0018 の 8000 文字が実際に通るようになるのは、この変更が入ってからである。
  - 8000 文字で足りない長いスクリプトは、`/work` にファイルとして分けて書き、`bash /work/<名前>.sh` で回す。
    `/work` には 1 ファイルの大きさの検査が無い（検査は `/memory` だけ）。
- **runner が残す出力は、標準出力・標準エラー出力とも 64 KiB のまま**とする。
  モデルに返るのは 8000 文字（標準エラー出力は 2000 文字）なので、これ以上残しても捨てるだけである。
- **モデルに返す上限も据え置く。** 1 回のツールの結果が 8000 文字でも、compaction の上限（6 万 tokens、ADR 0009）の数分の一を占める。
  これ以上増やすと 1 回の出力で session が圧迫される。

### ツールの説明と prefix cache

なつみのバックエンドは prefill が遅い。プロンプト類は prefix cache に載る形で設計する制約がある。

- system prompt とツール定義は、session を作るときに 1 度だけ組まれ、session の間は変わらない。
  時刻のような毎ターン変わるものも入っていない。**この性質を壊さない。**
- **走っている session の instructions は差し替えない。** 差し替えられるかどうかに関わらず、やらない。
  途中で差し替えると prefix が全部無効になり、session の残りをすべて prefill し直すことになる。
  反映したいものがあれば、次に session を作るとき（夜の切り替えと起動）に入る。
  これは prefix cache の制約から出る一般則であり、この ADR の範囲を超えて掛かる。
  常時記憶（`always.md`）をいつ読み直すかへの適用は、記憶の側（ADR 0018）で扱う。
- **`run_shell` のツールの説明は、固定の文にする。** 規則は **「設定の値や image の中身から文面を組み立てない」**
  である。これが制約の本体であって、「数字を書かない」ことではない。
  - ADR 0011 のツールの説明は、使えるコマンドの一覧を image の一覧から生成していた。
    一覧をやめる決定と、この制約はちょうど噛み合う。「使えるコマンドはこれだけ」と数える代わりに、
    「ネットワークの無い、普通の Debian の作業環境である」と書けば、説明は固定できる。
  - ソースに固定の文字列として書いた数字は、コードを直して入れ替えるまで変わらない。
    そのときは説明も直したいときなので、キャッシュの問題は起きない。
- 上限を説明に書くかどうかは、**環境で変わるかどうか**で分ける。
  - **環境で変わらないものは、数字ごと書く。** 少なくとも **1 コマンドの長さ（8000 文字）**。
    これは ADR の決定であって、デプロイごとに変わる値ではない。
    しかもこの上限は、**サーバーが runner に送る前に拒否する。** 知らずに長いコマンドを書けば 1 ターンが丸ごと無駄になり、
    prefill が遅いバックエンドではそれが一番高くつく。事前に避けられる失敗は、事前に伝える。
  - **環境で変わり得るもの**（`shellWaitSeconds`、`workspaceSizeWarnBytes`、CPU・メモリ・pids・`/tmp` の大きさ）は、
    「上限がある」とだけ書き、数字は書かない。実際の数字は、当たったときの**結果の文**で伝える。
    結果は入力側なので、prefix には影響しない。
- 説明に書くのは、次のとおりとする。
  - ネットワークの無い Debian の作業環境で、コマンドは `bash -c` で動くこと。
  - 書ける場所と、それぞれが残るか・検査されてコミットされるか。作業ディレクトリが `/work` であること。
  - `/memory` の `.git` は読み取り専用で、コミットはサーバーが行うこと。
  - 長い処理は残せること。応答が返った後もプロセスは動き続けるので、`ps` と `kill` で自分で始末すること。
  - 1 コマンドの長さの上限は 8000 文字で、超えると実行されずに返ること。
  - 時間と出力にも上限があること（数字は書かない）。
- **毎ターン変わるものは、すべて入力側（ターンの末尾）か、ツールの結果に置く。** system prompt には入れない。
  - 永続する書き場所の大きさの知らせ（この ADR）。
  - 検査で戻したファイルと理由（ADR 0018 のまま）。
  - まだ動いているコマンドの数と、記憶が変わったかどうかの 1 行（この ADR。どちらもツールの結果に付く）。

### 環境変数

ADR 0011 は「コマンドには `PATH` と作業ディレクトリの `PWD` だけを渡す」と決めたが、作業環境としては足りない。次の 5 つを渡す。

| 変数 | なぜ要るか |
| --- | --- |
| `PATH` | これまでどおり |
| `PWD` | これまでどおり |
| `HOME` | `/home/natsumi`。これが無いと bash も git も python も既定の置き場を持てない |
| `LANG` | `C.UTF-8`。これが無いと日本語のファイル名と出力が壊れる |
| `TZ` | 設定の `loop.timeZone`。これが無いと `date` が UTC を返し、記憶に書く日付とずれる |

コンテナ自体に渡す環境変数は、引き続き空にする。秘密が漏れる道を増やさない。

git の author の設定は渡さない。`HOME` が永続するので、なつみが自分で `git config --global` を書けば残る。

### 永続する書き場所の大きさ

Docker の volume には既定で容量の枠が無く、ホストのディスクを埋める経路が残る。
一方、枠で強制して作業中に突然書けなくなるのは、作業机として困る。

- **サーバーが測って知らせる。強制はしない。**
- 測るのは `/memory`・`/work`・`/home/natsumi` の合計。ターンの終わりに測るが、**最短でも 10 分に 1 回**とし、
  連続するターンで毎回走査しない。
- 目安は `loop.workspaceSizeWarnBytes`（既定 **1 GiB**）とする。
  記憶も作業の中身もテキストが主で、通常は数 MB に収まる。1 GiB は「明らかに何かを溜め込んでいる」と言える大きさであり、
  そこまで溜まっても、すぐにホストが困る大きさではない。
- 超えていたら、次のターンの入力に 1 行添える。3 つのディレクトリの内訳も書く。どこに溜まったかが分からなければ片づけられない。
- 片づけるのはなつみである。夜の棚卸しで拾う。

### 名前を workspace に揃える

中身が作業環境になるので、「記憶の道具」の名前は読む人を誤らせる。

| これまで | これから |
| --- | --- |
| サービス・image `natsumi-tools` | `natsumi-workspace` |
| ツール `run_memory_shell(command)` | `run_shell(command)` |
| 設定 `loop.memoryShellSocket` | `loop.workspaceSocket` |
| volume `natsumi-tools-socket`、マウント先 `/run/natsumi-tools` | `natsumi-workspace-socket`、`/run/natsumi-workspace` |
| 環境変数 `NATSUMI_TOOLS_UID` | `NATSUMI_WORKSPACE_UID` |
| runner のバイナリ `/usr/libexec/natsumi-tools-runner` | `/usr/libexec/natsumi-workspace-runner` |
| `scripts/check-memory-shell-sandbox.sh` | `scripts/check-workspace-sandbox.sh` |
| `src/server/memory-shell.ts` の `MemoryShell` | `src/server/workspace-shell.ts` の `WorkspaceShell` |
| Dockerfile のステージ `tools` | `workspace` |

- **データを持つ volume は `natsumi-data` のままとする。** 本番のデータの引き継ぎには影響しない。
- 設定の旧名 `loop.memoryShellSocket` は受け付けない。起動時に、新しい名前を告げるエラーで止める。黙って無視するより気づける。
- `docker/tools-commands.txt` と `docker/tools-rootfs.sh` は消す。

### ネットワーク

- **今回も絶つ。** `network_mode: none` のままとする。egress を開けて宛先を ACL で絞るのは、別の ADR で決める。
- そのうえで、**境界をネットワークの不在に寄りかからせない。**
  ADR 0011 の閉じ込めは「外へ出す口が無い」ことに多くを預けていた。この ADR は、その預け先を 3 つ減らしている。
  egress を開けるときは、次が効いてくる。開ける側の ADR は、これを前提にして書く。
  - **残ったプロセス。** 答えを返した後も動き続けるので、外への接続を保持できる主体ができる。ターンの区切りが境界にならない。
  - **検査されない `/work` と `/home/natsumi`。** 永続し、実行できて、サーバーもオーナーも差分では見ない。
    プロンプトインジェクションで仕込まれたものが、次のターン以降も残る。
  - **インタプリタ。** Python の標準ライブラリだけで任意のプロトコルを喋れる。宛先の ACL は、名前や HTTP の形では絞れない。
  - 加えて **git**。remote を設定して push できる。記憶の全体が 1 回の操作で外へ出る。

### 閉じ込めの実測

`scripts/check-workspace-sandbox.sh` として作り直す。**「一覧どおりで、他に実行ファイルが無い」という検査をやめ、形の検査に寄せる。**
一覧が無くなった以上、中身を数える検査は意味を失い、Debian のパッケージが 1 つ増えるたびに落ちるだけになる。

確かめるのは次である。

- ネットワーク: インターフェースが loopback だけであること。
- マウント: `/memory` が書けること、`/memory/.git` が書けないこと、`/work` と `/home/natsumi` が書けること、
  それ以外に volume が付いていないこと、ルートが書けないこと。
  `/tmp` が `noexec` で mount されていることも見るが、これは設定どおりかの確認であって、実行を止める境界の検査ではない。
- 権限: 非 root で動くこと、実効 capability が空であること、`no-new-privileges` が立っていること。
- 資源: pids・メモリ・CPU の上限がホスト側に効いていること。
- 秘密: `/run/secrets`・SQLite・Pi の状態領域・設定ファイル・TLS の鍵が、どれも見えないこと。
- 環境変数: 上の 5 つだけであること。
- 応答の上限: 終わらないコマンドが 60 秒で「まだ動いている」として返り、**そのプロセスが生き残っていること**。
  ADR 0011 の「答えの後まで動くプロセスは無い」の裏返しであり、新しい保証を実測する。
- 出力の上限で切れること。runner がその後も答えること。

### 設定

`loop` 節の変更。

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `workspaceSocket` | 無し | runner のソケットのパス。旧 `memoryShellSocket`。これがあるときだけ `run_shell` を登録する |
| `shellWaitSeconds` | `75` | サーバーが runner の応答を待つ秒数。runner の応答の上限（60 秒）より長くする |
| `workspaceSizeWarnBytes` | `1073741824` | 永続する書き場所の合計がこれを超えたら、次のターンの入力で知らせる（1 GiB） |

### 範囲外

- **egress とその ACL。** 別の ADR で決める。
- **夜の指示の実装。** 「作業場の棚卸し」を夜の再構成の手順に足すことはここで決めるが、書くのは記憶の側の作業単位である。
- **ターンの終わりの検査の中身。** この ADR が決めるのは検査の *対象範囲*（`/memory` だけ）である。
  何を戻すかは ADR 0018 のままとする。固定の 3 つ（`always.md`・`personality.md`・`handoff.md`）の削除と改名を戻すことも含めて、変えない。

### 置き換える既存の決定

- **ADR 0011**
  - 置き換え: 「入れるもの」の節の全部。コマンドの 11 個の一覧、`docker/tools-commands.txt`、
    scratch に実行ファイルを写す image の作り方、インタプリタ・`git`・busybox を入れないこと、そしてそれらの理由づけ。
  - 置き換え: 「ファイル」の節のうち「書き込めるのは 16 MB の `/tmp`（noexec）だけとする」。
    書ける場所は上の 4 つになる（記憶を書けるようにしたのは ADR 0018）。
  - 置き換え: 「環境変数」の節。`PATH` と `PWD` の 2 つから、上の 5 つにする。
  - 置き換え: 「資源の上限」の節。CPU 1・メモリ 256 MB・pids 64・1 コマンド 10 秒・出力 64 KiB のうち、出力以外。
  - 置き換え: 呼び出しの手順 3 の「時間の上限か、シェルの終了で、グループに残ったプロセスを止める。
    **バックグラウンドに残したプロセスが、答えの後まで動くことはない。**」
  - 置き換え: 手順 2 の作業ディレクトリ（`memory/` から `/work` へ）。
  - 置き換え: 「runner に届かない、応答がない（20 秒）」の 20 秒。`loop.shellWaitSeconds`（既定 75 秒）にする。
  - 置き換え: 「Pi のツール」の節のうち、ツールの名前、設定の名前、ツールの説明に書く中身。
  - 置き換え: `scripts/check-memory-shell-sandbox.sh` の名前と、その中身のうち一覧に基づく検査。
  - 残す: コンテナの形で閉じ込めること自体、`network_mode: none`、読み取り専用のルート、非 root・capability 全落ち・
    `no-new-privileges`、natsumi に Docker のソケットを渡さないこと、UID を natsumi と合わせること、
    Go の静的バイナリの runner と Unix ソケットだけでつなぐこと、ソケットの置き場を読み取り専用にすること、
    runner を `PATH` の外に置くこと、`init: true`、ヘルスチェック、natsumi の起動を待つこと。
- **ADR 0018**
  - 置き換え: 「記憶の読み書きを shell に一本化する」節のうち、足すコマンドを 6 つ（`mkdir`・`mv`・`cp`・`rm`・`sed`・`awk`）と
    列挙した部分、`sed`・`awk` を入れてよい理由を「動かせるのは image に入っている一覧のコマンドだけ」と説明した部分、
    そして **「`git` は `natsumi-tools` に入れない（ADR 0011 のまま）」**。git は入れる。
  - 置き換え: 1 コマンドの長さの上限 8000 文字の **理由づけ**（「16 KiB の中に収まる」）。決定の 8000 文字は残し、
    runner の `MaxRequestBytes` を 16 KiB から 64 KiB へ上げる。
  - 置き換え: 「閉じ込めの他の条件は変えない」の列挙のうち、`/tmp` 16 MB、CPU 1・メモリ 256 MB・プロセス 64、1 コマンド 10 秒。
  - 置き換え: ツールの説明に書く中身（使えるコマンドの列挙をやめ、書ける場所とその性質を書く）。
  - 追加: 夜の再構成の手順に「作業場の棚卸し」を足す。
  - 残す: 記憶のリポジトリと `loop.memoryRepository`、サーバーが固定する 3 つのファイル、常時記憶、
    ターンの終わりのコミットとそのときの検査、`always.md`・`personality.md` を夜だけ書けること、
    夜の再構成、性格の扱い、移行、git の CLI をサーバーが実行すること。
- **ADR 0008**
  - 置き換え: 登録するツールの一覧のうち、記憶の shell のツールの名前。`run_memory_shell` を `run_shell` にする。
    登録するツールの数と役割は変えない。

## Consequences

- **ADR 0011 の「バックグラウンドに残したプロセスが、答えの後まで動くことはない」という保証を手放す。**
  引き換えに得るのは、集計やスクリプトのような、1 回の応答に収まらない作業である。
  失うのは、「1 コマンド = 1 イベント」という単純さと、runner の応答がそのコマンドの全部だという保証である。
  CPU と pids を占め続けるプロセスが溜まり得る。止めるのはなつみの責任になり、忘れられたものは夜まで残る。
- **インタプリタを入れるので、カーネルの攻撃面が `sh` と決まったバイナリより広がる。** seccomp の既定プロファイルは効いている。
  承知のうえの選択である。一覧を絞っても実際に減るものはほとんど無く、残る差がこれだった以上、
  「一覧を維持する手間」と「作業机として使えること」を秤に掛けて後者を取った。
- **`/work` と `/home/natsumi` は、サーバーの検査を通らない。** プロンプトインジェクションで仕込まれたものが残る場所になり得る。
  しかも実行できて、永続する。git の履歴にも残らないので、オーナーが差分で見守る対象にもならない。
  中を見るには、オーナーが自分でコンテナに入る。
- image が数十 MB から数百 MB になる。中身は Debian のパッケージのバージョンに従い、ビルドのたびに変わり得る。
  一覧の検査をやめたので、**image に何が入っているかを追う仕組みは Dockerfile だけ**になる。
- 大きさは知らせるだけで止めないので、**ホストのディスクを埋める経路は残る。** 知らせを無視し続ければ、いつかは埋まる。
- shell のコマンドのたびに記憶のリポジトリの `git status` を取るので、ツールの呼び出しがその分だけ遅くなる。
- 環境で変わり得る上限（待ち時間、大きさの目安、資源）の数字はツールの説明に書かないので、なつみはそこに当たって初めて具体的な数字を知る。説明を固定の文に保つための対価であり、代わりに、当たったときの結果の文で数字と逃げ道を伝える。事前に避けられる 1 コマンド 8000 文字だけは、説明に数字ごと書く。
- 名前が変わるので、既存のデプロイは設定・compose の override・環境変数の書き換えが要る。
  データを持つ volume は `natsumi-data` のままなので、記憶と状態は引き継げる。
- **開発の環境（Docker なしで動かすとき）では、記憶を読むことも書くこともできない。** ADR 0018 の申し送りから続く問題で、
  この ADR でも解いていない。記憶のツールが shell だけになった後なので、影響の大きさは変わらない。
  確認の手段は、動かすときの指示に含める。
- runner を殺せることは変わらない（`ps` と `kill` が入ったので、より簡単になった）。
  殺すとコンテナが再起動し、残っていたプロセスと `/tmp` も一緒に消える。思考ループは止まらず、その間だけ記憶を読み書きできない。
