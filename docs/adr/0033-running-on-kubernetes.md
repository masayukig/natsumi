# 0033. 本番を Kubernetes に置く

- Date: 2026-09-24
- Status: Accepted（ssh の口で記憶の `.git` を書けるようにし、本人が自分でコミットしてよいこと、そのときに鍵の漏洩が SQLite と秘密に届かないための条件は [ADR 0067](0067-the-owner-commits-memory-over-ssh.md) で置き換え・条件づけ）

## Context

これまでの本番は、1 台のホストの Docker で動いていた。

- サーバーは TLS を自分で終端し、証明書は自前の ACME で取っていた（[ADR 0006](0006-github-login-and-transport.md)、[ADR 0007](0007-acme-and-fixed-ipv6.md)）。
  固定の IPv6 アドレスは、ネットワークの名前空間だけを持つ小さなコンテナで作っていた。
- 作業環境 `natsumi-workspace` は別のコンテナで、ネットワークを持たず、サーバーとは tmpfs の volume に置いた Unix ソケットでつながっていた
  （[ADR 0011](0011-memory-shell-in-a-confined-container.md)、[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
- 両方のコンテナは同じ UID で動いていた。記憶のファイルは所有者だけが読める権限だったためである。
- データは Docker の volume にあり、他のアプリと同じ形の backup が無かった。

本人は、本番を既にある Kubernetes のクラスタに移すと決めた。あわせて、次のことを求めている。

- ボリュームは、クラスタの他のアプリと同じように backup を取れて、restore できるようにする。
  クラスタでは、ボリュームを使うアプリの backup を定期ジョブ（CronJob）で取っている。
- 本人が、なつみの作業環境と記憶の領域を ssh で直接見られるようにする。
- 外のエージェントを呼ぶ token は、移行後は Pod に差し込まれる token に変える（[ADR 0025](0025-talking-to-outside-agents-over-a2a.md)）。

クラスタには、TLS を終端して証明書を取る入口（Ingress）が既にある。
閉じ込めと出口の扱いは [ADR 0034](0034-an-allow-list-for-the-way-out.md) で決める。

## Decision

### 公開と TLS

- 公開は、クラスタの既存の Ingress に任せる。TLS も Ingress で終端し、証明書も Ingress が取る。
- 自前の ACME（ADR 0007）はコードに残す。本番では設定 `listen.tls` で使わない。
  Docker で動かす構成では、今までどおり使える。
- 固定の IPv6 のための名前空間のコンテナは、本番では使わない。アドレスは Ingress の側にある。
- サーバーの外向きの通信から、Let's Encrypt が外れる。

### サーバーの待ち受け

- サーバーは、Pod の中で平文（`tls: false`）で待ち受ける。Ingress のコントローラは Pod の IP につなぐので、loopback では届かない。
- ADR 0006 の「平文の待ち受けは loopback だけ」を決め直す。**明示の設定を足したときだけ、loopback 以外のアドレスでの平文を許す。**
  - Ingress の後ろに置くことが前提である。平文なのは、Ingress から Pod までの区間だけになる。
  - 明示の設定が無ければ、今までどおり loopback 以外での平文は設定エラーとして起動を止める。
    平文の待ち受けを誤って外に晒さないという ADR 0006 の趣旨は、「うっかり」を止めることとして残す。
  - 同じ Pod のサイドカーで Pod の IP から loopback へ流す形も考えた。コードは変えずに済むが、平文の区間と晒され方は同じで、
    loopback の制限が形だけになる。条文を守る形にするより、明示の設定で意図を残す方を選ぶ。
  - 設定項目の名前は実装で決める。設定の検査の変更は、移行の作業単位で行う。
- `publicOrigin` は今までどおり https のホスト名である。クライアントから見た URL は変わらない。

### 認証

- 認証は、今までどおりなつみの GitHub OAuth（ADR 0006）で行う。
- Ingress の側では認証を掛けない。認証なしで通すのは意図したことであり、そのことを環境の設定に書き残す。
  ログイン・API・WebSocket の認証は、どれもサーバーが持っているからである。二重に掛けると、Mac と iPhone のクライアントの認証の流れが変わる。
- ホスト名は変えない。Mac と iPhone のクライアント、GitHub の OAuth App、セッションの延長（[ADR 0030](0030-a-session-that-lasts-while-it-is-used.md)）、
  APNs の端末の登録（[ADR 0029](0029-push-notifications-on-the-iphone.md)）は、どれも触らない。
- 切り替えは DNS のレコードの書き換えで行う。Ingress がこのホスト名で証明書を取れることは、移行の前に確かめる。

### 名前空間と身元

- 名前空間と ServiceAccount は、なつみ専用のものを作る。ServiceAccount には RBAC の権限を与えない。
  なつみにクラスタの操作権を渡さない（ADR 0011 の「Docker のソケットを渡さない」の読み替え、ADR 0034）。
- 外のエージェントを呼ぶ token は、Pod に差し込まれる token（projected token、audience `a2a`）にする。
  ADR 0025 の「移行後は projected token」を具体化する。期限のある token の発行し直しと差し替えの運用は要らなくなる。
  - token は、サーバーのコンテナにだけマウントする。作業環境と sshd には見せない。
  - 外のエージェントの側で、受け付ける呼び出し元にこの ServiceAccount を加える。

### Pod の構成

- サーバー・作業環境・sshd を、同じ Pod に置く。ADR 0034 の proxy と、規則を張る初期化のコンテナも同じ Pod に入る。
- sshd は、外から直接つなげる口（LoadBalancer の Service）で公開する。Ingress は通さない。
  - 門は ssh の鍵だけとする。`authorized_keys` は Secret で渡す。
  - 本人は、作業環境と記憶の領域を読み書きできる。本人が記憶や作業のファイルを直接直せるようにするためである。
  - 記憶の `.git` は読み取り専用にする。直した分は、サーバーが次の区切りでコミットする（[ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) のまま）。
  - なつみが触っている最中に本人が書くと、競合し得る。承知のうえとする。

### UID とファイルの持ち主

- サーバーと、作業環境・sshd を別の UID で動かす。sshd でログインするユーザーの UID は、作業環境とそろえる。
  - ADR 0034 の規則は UID で通信を見分けるので、同じ UID では分けられない。
- サーバーと作業環境は、共有のグループでファイルを読み書きする。
  - グループに書き込みを許す。作業環境が書いた記憶を、サーバーがコミットできるようにするためである。
  - umask を 007 にし、ディレクトリには setgid を付ける。新しいファイルとディレクトリが共有のグループになり、グループが書ける。
    グループ以外には読むことも許さない。共有のグループの外に読ませる理由が無いためである。
  - サーバーの git は、持ち主の違う記憶のリポジトリを扱うので、`safe.directory` を設定する。
  - 移行のときに、既存のファイルの持ち主を付け替える。

### ボリューム

- 永続するデータは、1 つの PersistentVolumeClaim に置く。その中を subPath で見せ分ける。
  - サーバーには、data directory と Pi の状態領域を見せる。
  - 作業環境と sshd には、作業環境の書き場所（ADR 0019 の `/memory`・`/work`・`/home/natsumi`）だけを見せる。
    SQLite・秘密・Pi の状態領域は見せない（ADR 0011・0019 のまま）。
- 作業環境とのソケットは、メモリ上の一時領域（`emptyDir` の Memory）に置く。ADR 0011 の tmpfs の volume と同じ形である。

### backup

- backup は、クラスタの他のアプリと同じ形の定期ジョブ（CronJob）で、1 日 1 回取る。
  - ボリュームは 1 つのノードにしかつながらないので、ジョブはなつみと同じノードで動かす。
    ノードに空きが無い日は動かないことがある。承知のうえとする。
- SQLite は、動いているまま整合したコピー（`sqlite3` の `.backup`）を取ってから写す。サーバーを止めない。
  ファイルをそのまま写すと、書き込みの途中を写し得るためである。
- 世代は、鏡を 1 つと、SQLite のコピーだけを日付入りで数日分（例: 14 日）持つ。古いものは消す。
  - 記憶は git の履歴が世代の代わりになる。
  - Pi の session は鏡だけとする。
- restore の手順は、最初の backup のジョブの後に実際に確かめる。

### image

- image は、版の tag（`v0.x.y`）を push したときに、GitHub Actions がビルドして公開のレジストリに置く。
  `natsumi` と `natsumi-workspace` の 2 つで、amd64 だけとする。
- 動かす版は、環境の設定（private のリポジトリ）で固定する。版の更新は、その設定を書き換えて行う。
- natsumi のリポジトリに、初めて版の tag を付ける。

### 反映

- 環境の設定（マニフェスト、設定ファイル、暗号化した Secret）は private のリポジトリに置き、手で適用する。
- この公開のリポジトリには、実際の値を置かない。

### 切り替え

- 切り替えは直接行う。本番のデータで、旧環境と新しい環境を二重に動かさない。
  同じ記憶と SQLite に 2 つのなつみが書くと、壊れるか、2 つの記録に分かれるためである。
- 手順は次のとおりとする。
  1. 旧環境を止める。
  2. データをボリュームに写し、ファイルの持ち主を付け替える。
  3. Kubernetes で起動する。
  4. DNS を書き換える前に、Pod の中で確かめる。出口の許可と拒否（ADR 0034）、起動のログ、Ingress への接続（名前を指定した接続）である。
  5. DNS を書き換える。Ingress が証明書を取るまでの間、TLS のエラーになる。
- 旧環境のコンテナと volume は、数日消さずに残す。戻すときは、DNS を戻して旧環境を起動する。
  新しい環境で増えたデータは写し戻す。
- 翌日に、backup の 1 回目のジョブと restore の手順を確かめる。

### 置き換える既存の決定

- ADR 0005
  - 置き換え:「サーバーは umask 077 で動く」。umask 007 で動く。サーバーだけが使うもの（SQLite・Pi の状態領域・証明書）は、
    今までどおり 0700 のディレクトリに置く。
  - 置き換え: `memory/` を 0700 で作ること。共有のグループが書ける権限と setgid で作る。
- ADR 0006
  - 置き換え:「平文（`tls: false`）は、待ち受けアドレスが loopback のときだけ受け付ける」。
    明示の設定を足したときだけ、loopback 以外での平文も許す。Ingress の後ろに置くための例外である。
  - 残す: 明示の設定が無いときの、loopback 以外での平文の拒否。GitHub OAuth、セッション、WebSocket の検証。
- ADR 0007
  - 置き換え: 本番の構成。本番では ACME と固定の IPv6 のコンテナを使わない。コードと Docker の構成は残す。
- ADR 0011
  - 置き換え:「UID は natsumi と同じにする。記憶のファイルは所有者だけが読める（0600）ためである」。
    UID を分け、共有のグループで読み書きする。
  - 置き換え:「両方のコンテナがマウントする小さな tmpfs の volume」。同じ Pod の `emptyDir` の Memory にする。
- ADR 0019
  - 置き換え: 永続する書き場所を「無ければ 0700 で作る」こと。共有のグループが書ける権限と setgid で作る。
- ADR 0025
  - 具体化:「なつみがクラスタに移れば、Pod に自動で差し込まれる token（projected token）に変わる」。
    token はサーバーのコンテナにだけマウントする。

## Consequences

- Ingress から Pod までは平文になる。クラスタの中でこの区間に届くものは、セッションの token とやり取りの中身を読める。
- 証明書の取得と更新は Ingress に任せる。自前の ACME は本番では動かないので、壊れても本番では気づかない。
- 本番の構成は、この公開のリポジトリの外（private の環境の設定）にある。compose の構成と、本番の構成が別になる。
- sshd の口が 1 つ増える。鍵を失うか漏らすと、作業環境と記憶を読み書きされる。SQLite と秘密には届かない。
- 本人が ssh で直したファイルと、なつみの書き込みが競合し得る。
- backup は、ノードの空きが無い日に取れないことがある。
- UID を分けたので、ファイルの権限は共有のグループに依る。umask か setgid が外れると、サーバーが記憶をコミットできなくなる。
- 版を上げるには、tag を付けてビルドを待ち、環境の設定を書き換えて適用する。
- 切り替えの間、なつみは止まる。DNS を書き換えてから証明書が取れるまで、クライアントはつながらない。
