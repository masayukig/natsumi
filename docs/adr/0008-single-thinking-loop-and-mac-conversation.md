# 0008. 単一の思考ループと Mac との会話

- Date: 2026-09-15
- Status: Accepted（登録するツールと、compaction が無効のままという点は [ADR 0009](0009-long-term-memory-and-nightly-session-switch.md) で置き換え、範囲外としていた Slack 連携と投稿の承認は [ADR 0012](0012-slack-and-colleagues.md) で決定、Mac に見せる会話の既読と知らせの確認は [ADR 0013](0013-read-state-on-the-server.md) で追加、表情の戻し方と、範囲外としていたスケジューラーと自発的な確認の土台は [ADR 0014](0014-self-checks-and-pings.md) で置き換え・決定、思考を Mac に出さないことは [ADR 0017](0017-streaming-the-line-she-is-thinking.md) で一部改訂、登録するツールの一覧は [ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) で再び置き換え、その `run_memory_shell` は [ADR 0019](0019-a-workspace-not-a-memory-tool.md) で `run_shell` に改名、`reply_to_mac`・`notify_owner` にセリフの気持ち `expression` の引数を [ADR 0026](0026-a-feeling-on-each-line.md) で追加、`reply_to_mac` に画像の引数 `images` を [ADR 0045](0045-showing-the-owner-images-with-a-reply.md) で追加、ターンの上限に Codemode のスクリプトの中の呼び出しの回数を加えることは [ADR 0066](0066-codemode-to-keep-raw-output-out-of-the-context.md) で追加）

## Context

ADR 0001・0002 は、Pi の 1 turn の応答をそのまま Mac の会話として全端末に配信し、Pi の session を会話の正本にする前提で書かれていた。
その後、natsumi の動き方を次のように決め直した。

- natsumi の思考は、一本の Pi session がシングルスレッドで回すループとする。
  Mac からの会話も、後で加える Slack・合図・スケジュールも、ループが順に処理する入力（イベント）である。
- 外への出力は、Mac への返事や表情も含めて、すべてツールで行う。モデルが書いた本文は内心であり、誰にも届かない。

この形では、Pi の session に Mac に見せない内容（思考、内心、ツールの呼び出し、Mac 以外のイベント）が混ざる。
また、session は伸び続けるので、将来は要約や切り替えで古い部分が変わる。Pi の session をそのまま Mac の履歴にはできない。

実装の前に、ローカルで動く Qwen 系のモデルで、架空の場面を使ってループを評価した。
形式（ツールの引数、表情の候補、ツールだけでの出力）はほぼ守られた。失敗は判断と止まり方にあった。

- 同じ返事を繰り返して止まらない。結果が短いツール（「delivered」だけ）の後に目立った。
- 内心や「何もしませんでした」を、返事のツールで本人に出す。
- 本人への相談に、別のイベントの ID を付ける。
- 返事にチャットテンプレートの制御文字列（`</think>`・`<tool_call>` など）や、中国語・韓国語の文字が混ざる。
- 思考ありの設定は、思考なしより明らかに誤りが少なかった。代わりに、本人への返事は中央値で約 19 秒かかった。

## Decision

### 思考ループ

- サーバーは Pi の session を 1 本だけ持ち、思考ループとして使う。
- 入力はすべてイベントとして渡す。`<events>` の中に 1 行 1 件の JSON を置く形で、`event_id` と `type` を必ず持つ。
  今回扱う種類は本人のメッセージ（`mac_message`）だけで、種類は後から足せる。
- 1 回の処理（ターン）は、キューの先頭の 1 件から始める。
- ターンの途中に届いた本人のメッセージは、進行中の思考を止めずに、次のモデル呼び出しの境目で差し込む。
  Pi SDK の steering を使い、境目で待っている差し込みはまとめて渡す。
  Pi 0.85.1 で、実際の agent loop と合成の model stream を使って次を確かめた。
  - ツールの実行中に差し込んだメッセージは、次のモデル呼び出しの前に context に入る。
  - 既定の steering は 1 回の境目で 1 件ずつなので、まとめて渡す設定にする。
  - ターンの終わりまでに届かなかった差し込みは、キューの先頭に戻す。
- 外から思考を中断する command は設けない。`conversation.interrupt` は受け付けない。
- 常に思考ありで動かす。設定 `pi.thinking` の既定は `on` で、`off` にもできる。
  `on` は Pi の思考レベル medium に当たる。OpenAI 互換のエンドポイントでは、Qwen 形式のチャットテンプレートの引数で思考を切り替える。
- 1 ターンのモデル呼び出しは既定で 8 回、時間は 10 分までとする。
  超えたらターンを止め、返事を送っていないイベントを失敗（`model-call-limit` / `timeout`）として記録する。
  それまでに送った返事や知らせは、そのまま残す。

### ツール

Pi に登録するツールは次の 4 つだけとする。Pi 既定の read/bash/edit/write は引き続き無効にする（ADR 0004）。

| ツール | 役割とサーバーの検査 |
| --- | --- |
| `reply_to_mac(event_id, text)` | 本人のメッセージへの返事。対象はこのターンで処理中の本人のメッセージに限る。1 イベント 1 回で、再起動をまたいでも SQLite の一意制約で守る |
| `notify_owner(text, about_event_ids?)` | 返事とは別の、本人への相談・知らせ。参照するイベントは実在するものに限る。1 ターン 3 件、直近 1 時間で 12 件まで |
| `finish_event(event_id)` | 処理中のイベントを終える。何もしないと決めたときも呼ぶ |
| `set_mac_avatar_expression(expression)` | 表情。候補は `neutral`・`happy`・`laughing`・`surprised`・`thinking`・`worried`・`sad`・`sleepy` の enum |

- ターンを閉じるのは、処理中のイベントがすべて `finish_event` で終わり、差し込み待ちもないときである。
  Pi の `shouldStopAfterTurn` で、ツールの実行後にモデルを呼び直さずに終える。
  ツールの結果の終了フラグだけに頼らない。実測では、同じ呼び出しに別のツールの結果があると閉じず、
  逆に、他のイベントが残っていても閉じた。
- ツールの結果は、状態が分かる文にする。例:「返事は確定し、このメッセージにはもう送れない」「対応は完了し、追加の出力は不要」。
  拒否した呼び出しはエラーの結果にし、送らなかったことと、その理由を書く。
- 本人に届く本文は、送る前にサーバーで検査する。次のどれかに当たれば送らない。
  - 空
  - 4000 文字を超える
  - テンプレートの制御文字列を含む
  - 日本語以外の文字を含む（ハングルと、日本語で使わない簡体字の一覧）

  拒否しても、1 イベント 1 回の枠は消費しない。警告に留めずに弾くのは、送った返事は取り消せない一方、モデルは理由を読んで書き直せるからである。
  評価でも、モデルは混入に自分で気づいて訂正を送り直していた。

### Mac に見せる会話

- 本人のメッセージと、`reply_to_mac`・`notify_owner` が送ったものだけを SQLite に保存する。
  これが Mac の履歴と `session.snapshot` の正本である。イベントの進み具合も SQLite に記録する。
- Pi の session は、思考の記録として別に持つ。全イベント、思考、内心の本文、ツールの呼び出しを含み、Mac には出さない。
- ADR 0001 の「SQLite に会話本文を置かない」は、「同じ記録を二重に持たない」という趣旨として決め直す。
  Mac に見せる会話と思考の記録は、中身も寿命も違う別の記録であり、二重の保存には当たらない。
- 本人のメッセージは、requestId・端末・本文を記録してから `command.accepted` を返す。
  同じ requestId の再送には同じ結果を返し、本文か端末が違えば拒否する。処理中でも busy にせず受け付ける。
- 受け付けた直後に、モデルを待たずにサーバーが全端末へ表情 `thinking` を送る。
  イベントの処理が終わったとき、表情がサーバーの出した `thinking` のままなら `neutral` に戻す。
- 返事と知らせは、ツールで確定したときに全文を一度だけ全端末へ配信する。ツールの引数の stream は流さない。
- イベントの結果（返事した、返事なしで終えた、失敗した）も全端末へ配信する。
- 端末の登録、端末ごとの stream と seq、有限バッファでの再送と snapshot での再同期、二重接続の置き換えは、ADR 0002 の方針どおりに実装する。
- 再起動のときは、キューにあったイベントを再び処理する。処理中だったイベントは Pi に二度渡さない。返事が記録されていれば返事済み、なければ失敗（`interrupted`）とする。

### 置き換える既存の決定

- ADR 0001
  - 置き換え:「会話の正本は Pi の session JSONL とし、SQLite へ会話本文や assistant 応答を複製しない」と、
    「アプリの会話 ID と Pi session の対応だけを SQLite に保存する」。
  - 残す: 厳格な復元（ファイルの消失・破損・ID の不一致で新しい session を作らない）。
  - 残す: compaction の無効化。夜の session の切り替えと、上限での compaction は、記憶を扱う ADR 0009 で決める。
- ADR 0002
  - 置き換え:「会話表示に必要な Pi イベントだけを変換して全端末へ配信する」「処理中の別メッセージは busy として返す」。
  - 置き換え:「会話本文の永続イベントログは作らない」「Pi から snapshot を読み直す」。
  - 残す: 認証、端末ごとの stream と seq、承認、通知の決定。
- ADR 0004
  - 置き換え: 登録するツールの中身。思考ループのツールは、この ADR の 4 つとする。
  - 残す: allowlist で明示し、既定のツールと自動探索を無効にする方針。

## Consequences

- 本人との会話の本文が SQLite に残る。state.sqlite のバックアップに会話本文が含まれるので、個人データとして扱う。
- 思考の記録は伸び続け、compaction も無効のままである。長く動かしたときの context の管理は、ADR 0009 まで未解決である。
- 思考ありなので、本人への返事は数十秒かかることがある。その間は表情で「考え中」を示す。
- 差し込んだメッセージは同じターンで扱うので、1 ターンのモデル呼び出しの上限を、差し込まれたイベントと分け合う。
- ツールを呼ばずに本文だけ書くと、そのイベントは返事なしで終わり、本人には何も表示されない。サーバーからの催促はまだない。
- 文字の検査は近似である。日本語と共通の漢字は区別できず、本人が頼んだ韓国語や中国語の文も Mac には送れない。
- Slack 連携、投稿の承認、スケジューラーと自発的な確認、記憶と personality の編集、気分は、この ADR の範囲外である。
