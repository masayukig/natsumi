# 0009. 長期記憶と、夜の session の切り替え

- Date: 2026-09-15
- Status: Accepted（記憶を shell で探すツールと、shell を許さないという点は [ADR 0011](0011-memory-shell-in-a-confined-container.md) で追加・置き換え、夜の切り替えと予約・合図の関係は [ADR 0014](0014-self-checks-and-pings.md) で具体化、記憶の置き方・記憶のツール・性格の扱い・引き継ぎの持ち方は [ADR 0018](0018-memory-in-git-and-the-nightly-rebuild.md) で大部分を置き換え、引き継ぎを SQLite に保存する点と、再起動のときに SQLite の記録から同じ system prompt を作り直せるという点は [ADR 0020](0020-limits-at-write-time-and-a-nightly-menu.md) で置き換え。2026-09-26: 互換エンドポイントの context の窓を設定にし、上限との組み合わせを起動時に検査することを「追記」の節に加えた。compaction の上限を経路ごとに持つこと、その検査を経路ごとに行うこと、経路を切り替えた直後に新しい経路の上限を超えていればターンの前に compaction することは [ADR 0046](0046-named-model-routes-switched-by-hand.md) で追加。終わったターンの途中経過をモデルに送る直前に畳み、ターンごとの一行メモを残すこと、畳み込みが on のとき夜の振り返りも畳んだ文脈で行うことは [ADR 0047](0047-folding-ended-turns-with-a-memo.md) で追加。compaction の仕組みは変わらない）

## Context

ADR 0008 で、natsumi の思考は一本の Pi session を使うループになった。session には全イベント、思考、ツールの呼び出しがたまり続ける。
ADR 0001 は compaction を無効にしたままで、長く動かしたときの context の管理は未解決だった。
長期記憶は data directory の `memory/` に Markdown で置くと決めていた（ADR 0001・0003）が、書き方と読み方は決めていなかった。

実装の前に、次のことが分かっていた。

- ローカルの Qwen 系モデルでの評価では、思考ありで約 6.5 万 tokens まで、返事の配送や記憶の保持は崩れなかった。
  一方、6 万 tokens を超えると 1 回の呼び出しが約 2 倍に遅くなった。
- 評価では、悪い振る舞いの型が同じ session の中で固定される例が複数あった。
- 本人に「覚えておいて」と言われたことは、context に残っている間は答えられる。context から消えた後に思い出す手段はなかった。

Pi SDK 0.85.1 の compaction を、合成の model stream と実際の session で調べた。

- 自動の compaction は、ターンの終わりに加えて、ターンの途中のモデル呼び出しの前にも判定する。ターンの途中で要約が入り得る。
- 手動の compaction は、実行中の処理を先に中断する。
- 要約は同じモデルと stream で作る。要約のプロンプトはコーディング作業向けの英語の定型で、追加の指示を末尾に足せる。
- 要約すると、session ファイルに要約の entry が追記される。古い entry はファイルに残る。
  context は「要約」と「直近の一定量（keepRecentTokens）」になり、session を開き直しても同じ形に戻る。
- 要約の直後は、次のモデル応答まで context の大きさが不明になる。短すぎる session は要約できずにエラーになる。

## Decision

### 長期記憶の置き方

- 長期記憶は data directory の `memory/` に置く。1 つのトピックを 1 つの Markdown ファイルにする。
  - ファイルの先頭はトピック名の見出しで、記憶は 1 件ずつ、日付（本人のタイムゾーン）付きの箇条書きの 1 行にする。
  - 同じトピックに同じ文面の記憶があれば、書き足さない。
  - 人が読んで直せる形にする。人が手で置いたファイルも、同じように探す対象になる。
- ファイル名はトピック名から作る。文字・数字・`_`・`-` 以外は `-` に置き換え、長さを切り詰める。
  区切り文字も `.` も残らないので、`memory/` の外や隠しファイルを指せない。
- 長期記憶は会話の写しではない。明示された記憶と、本人について今後も役立つことを、要点だけ書く（ADR 0003）。

### 記憶のツール

Pi に次の 4 つを足す。

| ツール | 役割 |
| --- | --- |
| `remember(topic, note)` | 記憶を 1 件書く |
| `recall(query)` | トピックをまたいで記憶の行を探し、点の高い順に返す。トピックの一覧も返す |
| `read_memory(topic)` | 1 つのトピックを全部読む |
| `forget(topic, text)` | トピックから、text を含む行を消す。記憶を直すときは、消してから書き直す |

- ファイルの読み書きはサーバーが行い、対象は `memory/` の直下に限る。モデルにパスは指定させない。
  - symlink はたどらない。`memory/` 自体が symlink なら、すべて拒否する。書き換えは一時ファイルからの rename で行う。
  - 任意のファイルの読み書きと shell は、引き続き許さない（ADR 0004）。
- Pi は 1 回のモデル呼び出しに含まれる複数のツールを並行して実行する。
  同じトピックへの書き込みと削除が混ざらないよう、記憶の操作は 1 つずつ順に実行する。
- `recall` の探し方
  - 問い合わせと記憶の行を NFKC にそろえ、小文字にし、約物と記号を空白に替える。
  - 空白で区切った語が行にそのまま含まれるものを最も高くする。
  - 次に、問い合わせの漢字とカタカナのうち、行に含まれる割合を点にする。半分以上（2 文字以上）含む行を当たりとする。
    モデルは「自転車の鍵の番号は？」のような空白のない自然文でも探す。語の部分一致だけでは、助詞や「？」が付くだけで 0 件になった。
    ひらがなは助詞や語尾に多く、当たりの判定を甘くするので数えない。
  - 言い換え（「バイク」と「自転車」など）は見つけられない。
- 記憶の行（見出しと空行以外）が 1 つもないトピックは、トピックとして扱わない。
  - `forget` で最後の行を消したら、ファイルを消す。
  - 見出しだけのファイルがあっても、一覧にも検索にも出さない。
  - 実際の確認で、モデルが簡体字のトピック名で書いた記憶を `forget` で消し、正しい名前で書き直したところ、見出しだけのファイルが残って一覧に出た。
- 書き込む前に、次を検査し、当たれば書かずに理由を返す。モデルは理由を読んで書き直せる。
  - 空、長すぎる（1 件 1000 文字、トピック 60 文字）
  - テンプレートの制御文字列、制御文字
  - 日本語以外の文字（ハングルと、日本語で使わない簡体字の一覧。本人に届く出力の検査と同じもの）。トピック名と記憶の本文の両方に掛ける。
- 日本語以外の文字の検査を記憶に掛ける理由
  - 当初は、記憶は本人に直接届く出力ではなく、人名などに他の文字が入り得ると考えて掛けなかった。
  - しかし実際の確認で、モデルがトピック名を簡体字で書いた。記憶のファイルは本人が読んで直すもので、検索の結果は思考の context に戻り、混入がそこから広がる。
  - 検査は近似で、ハングルと一部の簡体字にしか当たらない。人名などはカタカナで書き直させる。
- 記憶の全体を system prompt に入れない。system prompt には、記憶が外にあり、必要なときに探すという使い方だけを書く。
- `personality.md` は読むだけで、編集するツールは作らない。

### 夜の session の切り替え

- 本人のタイムゾーンの決まった時刻（既定 4:00）に、その日の session を振り返り、新しい session に切り替える。
  - 時刻の判定はサーバーのタイマーで行う。スケジューラーを作るときに、そちらへ移す。
  - 移した後は、切り替えの時刻をスケジューラーの tick（10 秒ごと）で見るので、切り替えの開始は時刻から最大 10 秒遅れる。
  - サーバーが止まっていて時刻を過ぎた場合は、起動時に、今の session がその時刻より前に始まっていれば切り替える。
  - 中身のない session は切り替えない。
  - 運用の確認のために、サーバーから手動で起こせるようにする。
- 切り替えは、思考ループの 1 つのイベント（`nightly_review`）として扱う。ループの外の保守処理にはしない。
  振り返りにはモデルと今の session が要り、他のイベントと同時に session を触らせないためである。
- 手順は次のとおりとする。
  1. 切り替えの記録を SQLite に作る（振り返り中）。
  2. 今の session で振り返りのターンを行う。モデルは `remember` で覚えておくべきことを残し、
     `write_handoff_note` で明日の自分への引き継ぎを書き、`finish_event` で終える。
     このターンのモデル呼び出しは 16 回まで。本人への返事と知らせは拒否する。
  3. 引き継ぎは書かれた時点で SQLite に保存する。引き継ぎは system prompt に入るので、本人に届く出力と同じ検査
     （空、長さ、テンプレートの制御文字列、日本語以外の文字）を掛け、当たれば保存せずに書き直させる。
  4. 引き継ぎを入れた新しい session を作る。
  5. `conversations` の参照を新しい session に替える更新と、切り替えの完了の記録を、1 つの transaction で行う。
  6. 古い session を閉じる。古い session ファイルは消さない。
- 引き継ぎは、新しい session の system prompt に入れる（最初の入力にはしない）。
  - 余分なモデル呼び出しが要らない。
  - 日中の compaction で要約されて変わることがない。
  - 再起動のときは、SQLite の記録から同じ system prompt を作り直せる。
- 切り替え中に届いた本人のメッセージは、これまでどおり記録して受け付け、キューで待たせる。振り返りのターンには差し込まない。
  切り替えの後に、新しい session で処理する。Mac に見せる会話（SQLite）は切り替えで変わらない。
- 切り替え中、サーバーはアバターを `sleepy` にする。その間に届いたメッセージでは `thinking` にしない。
  終わったとき、待っているメッセージがあれば `thinking`、なければ `neutral` に戻す。
- 失敗と停止では、黙って新しい会話にしない。
  - 引き継ぎが書かれずに振り返りが終わった、または止まった場合は、切り替えを失敗とし、今の session を使い続ける。次の夜にまた試す。
  - 引き継ぎが書かれた後に止まった場合は、次の起動で、その引き継ぎから切り替えを終える。
  - 新しい session を作れなかった場合は、失敗とし、今の session を使い続ける。
  - session ファイルの消失・破損を新しい session で置き換えない厳格な復元（ADR 0001）は変えない。

### 上限での compaction

- Pi の自動の compaction は無効のままにする。ターンの途中で要約が入ることと、実行中の処理の中断を避けるためである。
- 代わりに、サーバーがターンの終わりごとに context の大きさ（Pi の推定）を見る。上限（既定 6 万 tokens）を超えていれば、
  次のイベントを始める前に、Pi の手動の compaction で要約する。
  - 直近の 2 万 tokens（既定）は要約せずに残す。
  - 要約には、本人との約束、対応中のこと、本人の返事を待っていること、本人の様子、覚えておいてと言われたことを残すよう、日本語の指示を足す。
  - 要約の間に届いたメッセージは、キューで待つ。
  - 要約に失敗したら session はそのままで、context がさらに 1 割伸びるまで再試行しない。
- compaction の前に、記憶に移すための別のターンは設けない。
  - 日中の記憶は、モデルがその場で `remember` で書く。
  - 要約の指示で、覚えておいてと言われたことを残させる。夜の振り返りは、その要約を含む context で行う。
  - 別のターンを挟むと、上限に達するたびに本人への返事が 1 ターン分遅れる。
- 上限の既定の 6 万 tokens は、評価で振る舞いが崩れず、1 回の呼び出しが遅くなり始めた大きさである。

### 設定

設定に `loop` 節を足す。すべて省略でき、省略時は既定値を使う。

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| `timeZone` | `UTC` | 本人のタイムゾーン（IANA 名）。記憶の日付と夜の切り替えに使う |
| `nightlyRotationAt` | `04:00` | 夜の切り替えの時刻（24 時間の HH:MM）。`false` で自動の切り替えをしない |
| `compactionThreshold` | `60000` | これを超えたらターンの間に compaction する（tokens） |
| `compactionKeepRecent` | `20000` | compaction で要約せずに残す直近の量（tokens）。上限より小さくする |

### 置き換える既存の決定

- ADR 0001
  - 置き換え:「初期検証では compaction を無効にする」。Pi の自動の compaction は無効のまま、サーバーがターンの間に compaction する。
  - 具体化:「全端末に共通の永続 Pi session を一つ割り当てる」。会話に対応する session は常に 1 つだが、夜ごとに新しい session に替わる。
    SQLite の対応を切り替えで更新し、古い session ファイルは残す。
  - 具体化: data directory の `memory/` の中身と書き方は、この ADR のとおりとする。
- ADR 0003
  - 具体化:「長期記憶の Markdown は明示された記憶と重要情報の整理に使う」。ファイルの形とツールは、この ADR のとおりとする。
- ADR 0004
  - 具体化:「Wiki と記憶に必要な読み書きは、対象ルートと操作を制限する独自ツールとして後続実装する」。記憶はこの ADR の 4 つのツールで実装した。
- ADR 0008
  - 置き換え: 登録するツールを 4 つとした部分。記憶の 4 つと `write_handoff_note` を足した 9 つとする。
  - 解消:「思考の記録は伸び続け、compaction も無効のままである」という未解決の点。

## Consequences

- session ファイルは、1 日に 1 つずつ増え続ける。消さないので、ディスクの使用量は増える。バックアップの対象も増える。
- 記憶のファイル（`memory/`）は個人データであり、state.sqlite と session と一緒にバックアップする。
- `recall` は文字の重なりで探すので、同義語や言い換えは見つけられない。短い問い合わせでは、漢字を共有するだけの記憶も当たりに入り得る（点の順で後ろに並ぶ）。
- 日本語以外の文字の検査により、本人が頼んだ韓国語や中国語の表記は、記憶にも引き継ぎにもそのまま書けない。
- 引き継ぎと記憶の質は、振り返りのターンでのモデルの判断に依存する。引き継ぎを書かずに終えると、その夜は切り替わらない。
- 夜の切り替えは、その時刻にモデルを使う。本人のメッセージは、その間の数十秒から数分待たされることがある。
- compaction の要約の見出しは Pi の英語の定型のままで、日本語で書くのは指示による。
- 記憶の検索結果は、そのまま思考の context に入る。Slack 連携を加えるときは、本人の私的な記憶が Slack への投稿に漏れないかを別に検討する。
- 時刻の判定の仕組みは最小限で、スケジューラーと自発的な確認（Q9）の実装で統合する。

## 追記（2026-09-26）: 互換エンドポイントの context の窓と上限の組み合わせ

上限を既定より大きくすると、Pi に伝える context の窓（互換エンドポイントでは 128000 tokens の固定だった）を
ターンの途中で超える。compaction はターンの間にしか走らず、Pi の自動の compaction は無効なので、ターンの途中で
窓に近づいても要約は入らない。Pi は窓の残りに合わせて 1 回の返事の上限を縮めるので、返事や思考が途中で切れる。
エンドポイント自身の大きさを超えれば、要求そのものが拒まれる。

- 互換エンドポイントの窓を `pi.compatible.contextWindow`（既定 128000 tokens）で設定できるようにする。
  サブスクリプションのモデルの窓は、Pi のモデル定義のままとする。
- 互換エンドポイントでは、上限に 1 ターンの伸び（32768 tokens）、1 回の返事の上限（16384 tokens）、
  Pi が窓の手前に空ける量（4096 tokens）を足した量が窓を超える設定を、起動時に拒む。警告にとどめると、
  ふつうの日にターンが途中で失敗する設定のまま動き始めてしまう。
- 1 ターンの伸びは、ふつうのターンのモデル呼び出しと shell の出力から見積もった目安であり、上界ではない。
- 上限の既定の 6 万 tokens は変えない。既定の窓 128000 tokens と組み合わせても検査を通る。
