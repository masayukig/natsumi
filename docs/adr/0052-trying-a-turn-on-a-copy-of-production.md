# 0052. 本番の状態の写しから始め、相手役を立てて、修正したコードでターンを試す

- Date: 2026-09-27
- Status: Accepted（写しの記憶と session から整理係の一晩（全工程）を回せるようにすることは [ADR 0068](0068-a-curator-that-remembers-like-a-person.md) で追加）

## Context

[ADR 0051](0051-evaluating-one-turn-on-the-real-path.md) で、本物のターンの経路で 1 ターンを回して評価する仕組みを作った。
本番の文脈で試すには、本人が本番の Pi の session と記憶を手で取り出し、私的な場面に置く必要があった。
写せるのは session と記憶だけで、SQLite（会話、承認、頼んだことの記録）や `/sources` は入らない。

本人が望むのは、次のような試し方である。

- Kubernetes で動いている本番の状態（記憶、SQLite、`/sources`、session など）を、手軽に手元へ写す。
- 修正したコードで、その状態から 1 ターンだけ回す。
- 外のエージェント（A2A）やポッポさんは本物につながず、こちら側で待ち構える相手役（LLM）が返事をする。

手元の事情は次のとおりである。

- 本番のボリュームは、毎日 1 回の backup のジョブ（CronJob）が NFS に写している。SQLite はサーバーを止めずに整合したコピーを取り、日付入りで 14 日分を置く。
  それ以外のボリュームは、最新の 1 つだけを鏡として置く。手動で同じジョブを起こす手順もある。
- 鏡にはボリュームの全体が入る。Pi のログイン（`auth.json`）や、ボリュームに置かれたかもしれない秘密もそこにある。
- SQLite には、端末の push の token とログインの session の記録がある。
- `ask_agent` は、その場では受け付けたことだけを返す。返事は `agent_reply`（外のエージェント）と、ポッポさんの返事の出来事で、次のターンに届く（[ADR 0035](0035-asking-outside-agents-and-hearing-back.md)、[ADR 0040](0040-the-dove-sends-what-the-judge-passes.md)）。
- 評価の仕組みは、思考ループの依存の注入で外への作用を偽物にしている（ADR 0051）。workspace は bubblewrap の中の本物の runner である（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。
- 本番のデータは、本人の会話・記憶・Slack の中身そのものである。リポジトリは public である。

設計は grill-me（Q1〜Q7）で詰めた。

## Decision

### 写しは backup の仕組みから取り、本番の Pod では新しいコマンドを動かさない

- 既定では、その場で backup のジョブ（`kubectl create job --from=cronjob/…`）を起こし、終わるのを待って、その成果物を持ってくる。
- 毎日の backup の SQLite を日付で選ぶこともできる。ファイル（記憶、session など）は、鏡に 1 つしかないので常に最新である。
- NFS からの取り出しは、本番の restore の試しと同じ形にする。なつみの PVC をマウントしない使い捨ての Pod を立て、backup の NFS を読み取り専用で読む。
  NFS の場所と image は、backup の CronJob の定義から読む。リポジトリにも手元の設定にも書かない。
- なつみの Pod の中では何も動かさない。取り出しの後、使い捨ての Pod と起こしたジョブは消す。
- 取得のコマンドは評価の仕組みの一部として持つ。kubectl を呼ぶだけで、context は kubectl の選択に従う。

退けた案:

- **動いている Pod から `kubectl cp` で写す**: 動いている SQLite を写すと壊れ得る。本番の Pod で新しいコマンドを動かすことにもなる。
- **毎日の backup だけを使う**: 直前の状態で試したいときに、最大で 1 日古くなる。

### 持ってくるものは許可リストで決める

- 持ってくるのは、なつみの状態だけである。記憶（git の履歴を含む）、`/sources`（とその履歴）、`/work`、返事に添えた画像、Pi の session、SQLite の整合したコピーである。
  人格と常時記憶は記憶の中にある。
- 許可リストに無いものは、NFS の上で選ばず、手元にも届かない。Pi のログイン、設定、ボリュームに置かれた秘密、`/home/natsumi`、証明書の類は入らない。
  足し忘れは評価のずれで済むが、除き忘れは秘密の漏れになる。除外のリストにはしない。
- SQLite の写しからは、手元に置く前に、端末の push の token とログインの session の表を空にし、空いた領域も消す。
- 写しは本人の devbox の私的なディレクトリ（既定は `~/.local/share/natsumi-eval/snapshots/<日時>/`、0700）に置く。新しい 3 つだけを残し、取るたびに古いものを消す。
  リポジトリの中には置けない。

### 場面は「始めの状態 = 写し」を選べ、写しは作業用のコピーにしてから使う

- 場面の YAML で、始めの状態に写し（最新、または名前で指定）を選べる。写しが無ければ、その場面は飛ばして集計に残す。
  リポジトリに写しを使う場面の例を置いても、写しの無い環境ではそのまま飛ぶ。
- 回ごとに、写しを作業用のディレクトリにコピーしてから使う。写しそのものは変えない。
  評価するブランチの migration は、そのコピーの SQLite に走る。
- コピーの上に、場面のファイル・書き換え・前置きを重ねられる。session は、写しの SQLite が今の会話として指しているものを開く。夜の切り替えの前の session は持ち込まない。
- 写しに残っていた未処理の出来事は、評価の前に閉じる。評価するターンに、本番の途中の出来事が混ざらないようにするためである。
- 渡す出来事は、これまでどおり場面に手で書く。本番の過去の出来事を巻き戻して再生することはしない。

### ターン数は場面ごとに選び、既定は 1 ターンにする

- 既定は 1 ターンである。相手役は依頼を受け付けるだけで、返事はしない。
- 場面に書けば、相手役の返事を本物と同じ返事の出来事（外のエージェントは `agent_reply`、ポッポさんはその返事）として積み、それを処理するターンまで続ける。
  返事はサーバーの本物の道筋（外のエージェントなら返事の取りに行きと出来事の作り方）を通す。上限のターン数は場面で決め、既定は 4 である。
- 集計の数値（呼び出し回数、トークン、時間）は、続けたターンの合計である。

### 相手役は、役の説明と場面の指示で LLM が演じるか、場面に書いた返事をそのまま返す

- 相手役は、外のエージェント（Wiki 管理人、調べもの係など）とポッポさんである。
- LLM が演じるときは、役の説明（外のエージェントは Agent Card の説明、ポッポさんは「判定と承認を経て投稿する係」）と、場面の指示（例: 「デプロイは毎週木曜と答える」）を渡す。
  既定のモデルは ChatGPT Plus の経路（`openai-codex` の `gpt-6-sol`）で、評価するモデルと同じ「Pi の経路」の書き方で変えられる。
- 場面に返事の文をそのまま書けば、LLM を呼ばずにその文を返す。相手役のぶれを除いて比べたいときのためである。
- 相手役に本物の Wiki を読ませることはしない。
- 相手役への依頼と返事、どちらで返したか（LLM か、書いた文か）は結果に記録する。

### 外に作用させない保証を三重にする

1. **評価用の設定をゼロから作り、秘密を持たせない。** 本番の設定は写さない。外のエージェント、ポッポさん、Slack、APNs への作用は、依存の注入ですべて偽物にする。
   外のエージェントの token のファイルは、存在しない場所を指す。
2. **評価のプロセス全体をネットワークから隔離する。** 写しを使う回は、評価のプロセスを bubblewrap の新しいネットワークの名前空間（loopback だけ）の中で動かす。
   外へ出る道は、外側で動く中継（HTTP の CONNECT）だけで、中継は評価するモデル・相手役・判定役のエンドポイントのホストとポートだけを通す。
   それ以外の宛先は、名前の解決もされずに断られる。プロセスのファイルシステムは読み取り専用で、書けるのは結果と一時の置き場だけにする。
   workspace の runner は、入れ子の bubblewrap にせず、外側のプロセスが起動して Unix socket で渡す。
   bubblewrap で名前空間を作れない環境では、写しを使う回は動かさない。
3. **起動時に秘密らしいものを探し、見つけたら起動を拒否する。** Slack・APNs・外のエージェントの token らしいものを、環境変数、本番の秘密の置き場、使う写しの中から探す。
   写しの SQLite に push の token やログインの session の行があれば、それも拒否する。拒否の理由には、場所（変数の名前、ファイルのパス、表の名前）だけを出し、値は出さない。

### 写しを使った回の結果は、リポジトリの外の私的なディレクトリに置き、30 日で消す

- 写しを使った回の結果（session の写しを含む）は、既定で `~/.local/share/natsumi-eval/results/`（0700）に置く。リポジトリの中を指定したら拒否する。
- 30 日より古い結果は、写しを使う回を始めるときに消す。
- 集計と比較は ADR 0051 のものをそのまま使う。

## Consequences

- 本番の今の状態から、修正したコードで 1 ターン（または返事を受けるまで数ターン）を回し、ADR 0051 の場面と同じ判定・集計・比較にかけられる。
- 写しの取得は本番のクラスタに触れる（ジョブと使い捨ての Pod を作って消す）。実行は本人の承認のもとで行う。
- 許可リストに無い状態（たとえば `/home/natsumi`）は写らないので、それに頼るターンは本番と違う動きをし得る。必要になったら許可リストに足す。
- 相手役は本物の相手ではない。LLM の相手役の返事はぶれるので、比べるときは返事を書いた場面を使うほうがよい。
- 写しを使う回は、隔離のために bubblewrap の user と network の名前空間が要る。
- 秘密の探索は形で探すので、取りこぼしも誤検出もあり得る。誤検出で拒否されたら、写しのその場所を確かめて除く。
