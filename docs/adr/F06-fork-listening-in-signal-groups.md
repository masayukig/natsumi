# F06. fork: Signal のグループを聞く

- Date: 2026-10-25
- Status: Accepted（この fork だけの決定）

## Context

Slack のチャンネルでしていること（発言を読み、メンションに気づく。[ADR 0039](0039-slack-as-files-and-a-scored-dove.md)・[ADR 0050](0050-telling-of-source-updates-with-one-event.md)）を、
Signal のグループでもしたいインスタンスがある。[ADR F04](F04-fork-talking-with-the-owner-over-signal.md) の `SignalOwner` は送り主の番号だけを見て `groupInfo` を見ていなかったので、
本人がどのグループで書いたことも 1 対 1 の発言として natsumi に渡り、返事は本人の 1 対 1 に出ていた。ほかの人の発言は捨てていた。

Signal のグループに入ることは、natsumi の側では止められない:

- グループ（v2）のメンバーは誰でも natsumi のプロフィールキーを持てるので、natsumi を**招待ではなく直接**グループに足せる。足された時点で、ほかのメンバーには natsumi がメンバーとして見え、natsumi が退出するまでそのまま。
  プロフィールキーを持たない人が足すと、承認待ちの招待（natsumi は `pendingMembers`）になる。
- Signal のアプリには知らない相手からの「メッセージリクエスト」の関門があるが、signal-cli には無い。届いたものは全部受け取る。
- ブロックしたグループに足し直されるのを防げるかは確かめていない。

なので、入ったグループを全部聞くことにはできず、設定に固定の一覧を書くだけでは、足されたことに本人が気づけない。

この ADR は第 1 段の「聞く」だけを決める。グループへの投稿（ポッポさんの送り先に Signal のグループを足す）は第 2 段で別に決める。

## Decision

- `dataMessage.groupInfo` のある発言は、どのグループでも、誰の発言でも、本人の 1 対 1 としては扱わない。承認（[ADR F04](F04-fork-talking-with-the-owner-over-signal.md) のポッポさんの下書き）の照合にも回さない。
- **聞くかどうかは、グループごとに本人が 1 対 1 で決める。** 知らないグループを見つけたら、本人に 1 通だけ聞く:
  「佐藤さんが Signal のグループ『飲み会』（メンバー 3 人）にいおりを追加しました。参加しますか？ 👍 で参加、👎 で退出してブロック（引用して「参加」「見送る」でも）。24 時間答えがなければ退出してブロックします。」
  - 見つけるのは、知らないグループからの発言（足されたときのグループの更新 `groupInfo.type: UPDATE` なら、その送り主を足した人として名前を出す。分からなければ「誰か」）と、
    起動時と 1 分ごとの JSON-RPC `listGroups`（招待はストリームに何も来ないことがあるため）。ブロック済み（`isBlocked`）は聞かない。`isMember: false` は招待として聞く。
  - 答え方は F04 の承認と同じ（聞いた発言への 👍・👎・❌、引用した返信の「参加」「ok」・「見送る」「no」）。聞いた発言の時刻で照合する。
  - 👍 で承認。招待だったら `updateGroup`（招待されたメンバーが呼ぶと招待を受ける。実機では確かめていない）で受け、失敗したら本人にそう伝える。結果を 1 行送る。
  - 👎・❌、または 24 時間答えが無ければ、`quitGroup` と `block` をしてから結果を 1 行送る。どちらかが失敗しても、記録は「断った」にして、失敗したことを本人に伝える。
    24 時間の判定は、ポッポさんの承認の期限切れと同じ 1 分ごとの見回りで行う（新しいスケジューラーは作らない）。
  - 答えを待つあいだ、断ったあとは、そのグループのものは何も記録せず、natsumi に渡さず、答えない。承認より前の発言は後から記録しない。
- グループの状態（待ち・承認・断った）は、fork だけの表 `fork_signal_groups` に持つ。F02・F04 と同じく、番号付きの migration ではなく起動時に `CREATE TABLE IF NOT EXISTS` で作る。
  記録のディレクトリ名は `g-<グループ ID の SHA-256 の先頭 8 桁>`（グループ名は日本語も絵文字もあり、変えられもするので使わない）。
- 設定 `signal.groups`（`{ "<ディレクトリ名>": "<グループ ID（base64）>" }`）に書いたグループは、起動時から承認済みで、その名前のディレクトリに書く。
  名前は Slack のワークスペースと同じく小文字・数字・ハイフン（32 文字まで）、ID は signal-cli の `listGroups` の `id`。同じ ID を 2 度書くと起動時に弾く。
- 承認したグループの発言は、全員分（本人のものも）、Sources（ADR 0050）の新しい source `signal`（深さ 1）として `sources/signal/<ディレクトリ>/<日付>.jsonl` に 1 行 1 発言で書く。
  行の形は Slack の行に合わせる（`at`・`from`・`text`・`attachments`、引用は `quote: { from, text, mine? }`）。日付と時刻は natsumi のタイムゾーン、`from` は送り主のプロフィール名。
  本文のメンションの印（U+FFFC）は `@名前` に置き換える。電話番号・UUID・Signal の時刻は書かない（Slack の ID を書かない [ADR 0024](0024-no-event-ids-for-the-model.md) と同じ考え）。
  ファイルは 0640、ディレクトリは 0750（Slack の記録と同じ）。添付は取り込まず、`名前 (種類, 大きさ)` を書くだけ。本文も添付も無いもの（リアクション・グループの更新など）は書かない。
- natsumi へのメンション（`mentions[].number` が natsumi の番号）は `kind: mention`、natsumi の発言の引用（`quote.authorNumber` が natsumi の番号）は `kind: quote-reply` の attention にし、
  Slack と同じく `file` と `path`（`jq -s` のパス `.[N]`）でその行を指す。本人のメンションも同じく attention で、1 対 1 にはならない。
- 読み方は `manual/signal.md` に書き、マニュアルの目次に 1 行足す。system prompt の本文は変えない。

退けた案:

- **入ったグループを全部聞く**: 上のとおり、誰でも natsumi を別のグループに入れられる。
- **設定の一覧だけで決める**: 足されたことに本人が気づけず、natsumi は知らないグループのメンバーとして見えたまま残る。設定は「最初から承認済み」として残した。
- **グループ名をディレクトリ名にする**: 日本語・絵文字・同名があり、名前が変わると記録が分かれる。ID から作った名前は変わらない。
- **Slack と同じく SQLite に持って日ごとに書き直す**: Slack は編集・削除・リアクションでファイルを書き直すためにそうしている。第 1 段は追記だけで足り、行は動かないので `jq -s` のパスもそのまま効く。
  編集・削除・リアクションが要るようになったら、slack-archive.ts と同じ形に寄せる（コードに `ponytail:` で書いた）。
- **Markdown で書く**: Slack の記録は ADR 0050 で JSON Lines になり、attention の `path` もそれを前提にしている。同じ読み方で済むよう合わせた。

## Consequences

- natsumi は承認されたグループの発言を Slack のチャンネルと同じ手順で読み、メンションと引用に気づける。グループにはまだ書き込めないので、マニュアルにそう書いた。
- 本人は、natsumi がグループに足されるたびに 1 対 1 で聞かれる。答えなければ 1 日で抜ける。答えるまでの間、ほかのメンバーには natsumi がメンバーとして見えている（止められない）。
- 本人がグループで書いたことは、もう natsumi との 1 対 1 の会話にはならない（F04 の「本人の発言を渡す」は 1 対 1 だけになった）。
- 記録しないもの: 編集・削除・リアクション、natsumi 自身の発言（第 1 段ではグループに投稿しない）、添付の中身、承認より前の発言。
- 確かめていないこと: signal-cli の JSON の `mentions[].number`・`quote.authorNumber` に natsumi 自身の番号が入るか、`updateGroup` で招待を受けられるか、
  JSON-RPC の `quitGroup {groupId}`・`block {groupId: [..]}` の引数名、ブロックで足し直しを防げるか。natsumi のメンションが番号で来なければ、UUID で見るよう足す。
- 外されたグループも `listGroups` では `isMember: false` に見えるので、招待として聞かれることがある（`pendingMembers` を見れば分けられる。コードに `ponytail:` で書いた）。
- 発言者の名前はプロフィール名なので、同じ名前の人は区別できない。メンションの相手の名前は、その人が一度発言して名前が分かるまで `@someone` になる（サーバーのメモリにだけ持つ）。
- 記録は手で消すまで残る（Slack と同じ）。
