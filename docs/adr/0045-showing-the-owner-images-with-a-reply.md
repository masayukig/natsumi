# 0045. なつみは reply_to_mac の返事に画像を添えて、本人に見せる

- Date: 2026-09-26
- Status: Accepted（`reply_to_mac` の `images` に `/sources/agents/` の下のパスも並べられることを [ADR 0069](0069-agent-replies-as-files-in-sources.md) で追加）

## Context

[ADR 0044](0044-drawing-with-sdctl-and-posting-images.md) で、なつみは作業環境の sdctl で画像を作り、ポッポさんに頼んで Slack に投稿できるようになった。
けれども、作った画像を本人に直接見せる道は無かった。本人と話す会話（Mac と iPhone）は文字だけである。

「画像を Mac に出すか」は、[ADR 0025](0025-talking-to-outside-agents-over-a2a.md)（外のエージェントの成果物）でも ADR 0044 でも決めずに残していた。

手元には次のものがあった。

- 本人と話すツールは `reply_to_mac`（返事）と `notify_owner`（知らせ）の 2 つで、引数は本文とセリフの気持ちだけである（[ADR 0008](0008-single-thinking-loop-and-mac-conversation.md)、[ADR 0026](0026-a-feeling-on-each-line.md)）。
- ADR 0044 の実装で、サーバーには `/work` の画像を検査して写す部品と、写しを ID で記録する表と、端末がログインして画像を ID で取る道（`GET /v1/images/<imageId>`）ができていた。
  取る道が返すのは、承認に載った画像だけだった。
- Mac と iPhone は共通の部品で通信と取得を行い、画面はそれぞれが持つ（[ADR 0028](0028-the-iphone-client.md)）。Mac には吹き出しと履歴、iPhone には履歴がある（[ADR 0027](0027-her-face-beside-each-line-in-the-history.md)）。
- iPhone が裏にいる間の返事と知らせは、暗号化した本文だけを載せた APNs の通知で届く（[ADR 0029](0029-push-notifications-on-the-iphone.md)）。通知の payload は 4KB までである。
- ツールの定義は prefix cache に載る。変えると、変えた直後に一度だけ cache が外れる（[ADR 0019](0019-a-workspace-not-a-memory-tool.md)）。

## Decision

### 画像は reply_to_mac にだけ添える

- `reply_to_mac` に、省ける引数 `images` を足す。値は作業環境の `/work` の下のパスの配列である。
- `notify_owner` には足さない。知らせは本人に確かめてほしいことを伝える短い文で、画像を見せる用途は返事で足りる。
- ツールの説明は短くし、「画像を見せるときは `images` に `/work` の下のパスを並べる」とだけ書く。詳しい使い方は `/manual` の画像の手引きに書く（[ADR 0036](0036-a-manual-to-read-and-a-limit-on-waiting.md)）。

### 検査と写しは、ポッポさんへの依頼と同じ部品で、呼んだ時点で行う

- ポッポさんへの依頼の `画像` の見出し（ADR 0044）と同じ部品で検査する。`/work` の下だけ、リンクや `..` で外に出ない、PNG・JPEG・WebP（中身で見分ける）、大きさ、枚数。
- 大きさと枚数の上限は、Slack の投稿の既定と同じ（1 枚 10 MB、1 回 4 枚）とする。本人にだけ見せるものなので、設定には出さない。
- 合わなければ、本文も送らずに、ツールの結果で直し方を返す。画像の無い返事として半端に届かないようにするためである。
  本文の検査（ADR 0008 の送る前の検査）に通らないときも、画像は写さない。
- 検査に通ったら、ツールを呼んだ時点でサーバー側に写し、写しを会話の行に結び付ける。本人が見る画像は写しであり、`/work` のファイルが後で書き換わっても変わらない。
- 画像の幅と高さは、ファイルの頭から読めれば記録する。端末が画像を取る前に場所を空けておけるようにするためである。読めなくても画像は受け付ける。

### 会話の行が画像を持つ

- 返事（kind: reply）の行は、写しの ID と形式と大きさ（読めれば幅と高さ）を、なつみが並べた順に持つ。
- 画像は会話の記録と同じく SQLite に置き、会話と同じく消さない。写しは data directory の中にあり、backup に含まれる。
- 端末には、会話の行（`conversation.message`）と snapshot の `messages` に画像の一覧として載せる。画像の無い行には欄を置かない。
  古いクライアントは知らない欄を読み飛ばすので、壊れない。
- 画像そのものは、承認の画像と同じ道（`GET /v1/images/<imageId>`、ログインが要る）で取る。取る道が返す画像を、「承認に載った画像」から「承認か会話の行に載った画像」に広げる。
- 縮小した画像を返す道は作らない。写しは 1 枚 10 MB まで、1 回 4 枚までで、sdctl の既定の画像は 1 MB 前後である。
  サーバーに画像を扱う依存を足してまで縮小するより、端末が表示の大きさに縮めて手元に持つほうが簡単だからである。
  同じ ID の画像は変わらないので、端末は一度取った画像を使い回せる。

### 端末での見せ方

- Mac は、オーバーレイの吹き出しに小さな縮小画像を出し、クリックで拡大する。会話の履歴にも縮小画像を出す。
- iPhone は、会話の履歴に縮小画像を出し、タップで拡大する。
- 端末の画面は、サーバーとは別の作業で作る。形は `docs/client-contract.md` に書き、アプリはそれだけを読んで作れるようにする。
  iPhone の承認画面の画像（ADR 0044）も、同じ作業で作る。

### iPhone の通知は本文だけで、画像の数を末尾に付ける

- 通知には画像を載せない。今のまま、暗号化した本文だけを送る。payload の 4KB に画像は収まらず、通知に載せるには別の取得の仕組みが要るからである。
- 画像の付いた返事は、暗号化する本文の末尾に「（画像 N 枚）」を付ける。サーバーが付ける。
  - 端末に付けさせず、サーバーで付けるのは、今の Notification Service Extension に手を入れずに、どの版のアプリでも同じ印が出るからである。
  - 本文を 1000 文字で切るとき（ADR 0029）も、印は切らずに残す。切るのは本文のほうである。
- 会話の記録と、会話の行の本文には印を付けない。印は通知の中だけのものである。

### 置き換える既存の決定

- ADR 0025（外のエージェントと A2A で話す）
  - 決定: 未決だった「画像を Mac に出すか」。なつみが `reply_to_mac` の返事に添えた画像を、Mac と iPhone に出す。
    外のエージェントの成果物を直接 Mac に出す形は作らない。見せたいものは、なつみが `/work` に置いて返事に添える。
- ADR 0044
  - 決定: 未決として残していた「画像を Mac に出すか」。
  - 追加: 画像を取る道は、承認に載った画像に加えて、会話の行に載った画像も返す。
- ADR 0008・ADR 0026
  - 追加: `reply_to_mac` に省ける引数 `images`。`notify_owner` の引数は変えない。
- ADR 0029
  - 追加: 画像の付いた返事の通知は、暗号化する本文の末尾に画像の枚数の印を付ける。印は本文の切り詰めで切らない。

## Consequences

- なつみは、作った画像を会話の中で本人に見せられる。Slack を通さずに、本人だけに見せられる。
- ツールの定義が変わるので、反映した直後の最初のモデル呼び出しで prefix cache が一度外れる。その後はまた載る。
- 写しは会話と同じく消さないので、画像を見せるたびに data directory が増える。backup の大きさも同じだけ増える。
  増え方は運用で見て、多くなったら古い写しの扱いを考える。
- 画像の検査に通らない返事は、本文ごと届かない。なつみは直し方を読んで送り直す。本人から見ると、返事が少し遅れることがある。
- 縮小の道が無いので、端末は元の大きさの画像を取る。吹き出しや履歴に並べる数が多いと、取る量が増える。
- 通知では画像が見えない。本人は印を見て、アプリを開いて画像を見る。
- 古い版のアプリは、画像の欄を読み飛ばして本文だけを出す。通知の印は古い版でも出る。

作業は次の単位で進める。

1. natsumi のサーバー: `reply_to_mac` の `images`、写しと会話の行の画像、取る道の拡張、通知の印、`docs/client-contract.md`、偽のサーバー、`/manual` の手引き
2. アプリ: 共通の部品で画像を取る、Mac の吹き出しと履歴、iPhone の履歴、iPhone の承認画面の画像
