# 0068. 整理係は人間の記憶のように、工程を分けて古い記憶を要約し、出来事を知識にする

- Date: 2026-10-04
- Status: Accepted

## Context

[ADR 0055](0055-a-memory-curator-at-night.md) で、人格を持たない記憶の整理係（以下、係）が、毎晩なつみの夜の振り返りの後に記憶を組み直すことにした。
係が動き始めて数晩の後、本人が記憶を見て次のように指摘した。

> 記憶再構成の際、あまりファイルの構成変更がない（ディレクトリ作成やファイルの統合）のと、日付が入ってないからなのか古い情報が残ってたりする。

> ファイルの中を段落に沿って構造化し直して欲しい。だらだらと追記した中身が多い。

本番の写しで係の数晩を見ると、次のことが分かった。

- **構成が変わっていない。** 係がコミットした夜は 3 晩あり、どの夜も節の移動と重複の寄せはしているが、改名・統合・ディレクトリへのまとめは一度もしていない。
  - 係は `always.md` から指されているファイルの名前を守っていた。コミットメッセージに「always.md が指しているので触れない」と書いた夜もある。
    ADR 0055 は「古いパスは係が直さない。なつみは `INDEX.md` か `search_memory` で探し直す」と決めたが、係への指示にはパスが変わってよいことが書かれていない。
  - 係への指示は保守的に寄っている。「全部か無しか」「大きな組み替えは一晩でやりきれる分に絞る」「変えることが無ければ何も変えずに終えてよい」が並び、ディレクトリにまとめる目安も無い。
  - 記憶はまだ小さく、トピックは十本に満たない。ディレクトリにする必然性が弱いのは事実である。
- **一晩分が丸ごと消えた夜がある。** 9/30 の夜は、係の session が変更の説明を書くところまで進んだのに、コミットが無い。
  一晩 1 コミット・全部か無しか（ADR 0055）なので、どこか 1 つで失敗して全部が捨てられたとみられる。理由はまだ確かめていない。
  大きく組み替えるほど、捨てられたときに失うものが大きい。
- **古い情報が残る。** 古さを判断する手がかりが無い。
  - 事実の行に日付が無い。ADR 0055 は、トピックには「今どうなっているか」を書き、日付の節は今の状態にまとめ、経緯は `diary/` と git に残す、とした。
    その結果、ある行がいつの時点の事実なのかが分からない。
  - 係に渡す見取り図には、ファイルごとの大きさと見出ししかない。最後に変わった日も、最後に係が見た日も渡していない。
  - 何をもって古いとするかの基準が無い。指示は「済んだこと、古くなったことは消してかまいません」だけである。
- **ファイルの中が平らなままである。** 「いまの状態」の節が、追記された順に並ぶ 1 本の長い箇条書きになっている。
  名前・関心・進行中のことが順不同に並び、「約束」の節に約束でないものが入っている。見出しは `#` と `##` の 2 段だけである。
  - 係への指示は日付の節をまとめることだけで、節の中を話題ごとに分ける、合わない行を移す、を言っていない。
  - 日中のなつみの書き方の指示も「事実が変わったらその箇所を直す」だけで、新しい事柄をどの節に入れるかを言っていない。
  - 見取り図に渡すのは見出しだけなので、見出しの少ない平らなファイルは、係から見ても整って見える。
- **主語が抜ける。** 今の書き方の指示は「自分」「本人」「あの人」を禁じて呼び名で書かせているが、主語そのものを省いた文は防げていない。
  たとえば「家の用事も一言で頼んでくれる」「資料を作っている」のような文は、誰がそうしているのかが読み返したときに分からない。

これに加えて、本人は係の目指す方向を示した。

> memory-curatorをもっと高性能にして、人間の記憶をシミュレートしたい。

人間の記憶は、古いものほど細部が落ちて要約され、何度も思い出したものは残り、繰り返した出来事は知識になり、関係するもの同士が連想でつながる。
係の仕事を「ファイルの構成を整える」から、この振る舞いを真似ることへ広げる。

設計は grill-me（Q1〜Q17）で詰めた。

## Decision

### 変わりうる事実には、いつの時点かを書く

- **変わりうる事実（予定・状態・版・進行中のこと）の行に、時点の日付を書く。** 例:「なつみの Pi は 1.0.1（2026-10-03 時点）」。
- 予定は、日付そのものが時点なので添えない。名前や好みのような恒久的な事実には付けない。
- なつみ（日中・夜）と係の書き方を揃える。どちらの指示にも入れる。

退けた案:

- **全行に日付を付ける**: 読みにくく、行が長くなる。
- **節ごとに確認した日を書く**: 節の一部だけが古いことを見分けられない。
- **書かずに git blame で読む**: 係が行を動かすと日付が新しくなり、古さが消える。

### 古いかどうかは中身から判断し、消さずに要約して archive へ移す

- 古いかどうかは、時点の日付も見るが、**係が文書を読んで中身から判断する**（本人「日付もチェックするけど、文書を読んで古いかどうか判断したい」）。
- **古くなった事実は消さない。要約して、今の記憶とは別のファイルに「古い記憶」として残す**（本人「古い事実などは要約して別の古い記憶として保持したい」）。
- ADR 0055 の「古くなったものは消してよい。経緯は `diary/` と git に残る」は覆る。重複は今までどおり消してよい。
- `diary/` との違い: `diary/` はその日の出来事の記録である。archive は、トピックから外した事実の要約に限る。

退けた案:

- **日付だけで機械的に切る**: 日付の無い行と、日付は古いがまだ正しい行を扱えない。
- **基準を置かず係に任せる**: 今と同じで、古い情報が残りがちになる。
- **消す**（ADR 0055 の形）: 経緯は `diary/` と git に残るが、要約された古い記憶としては残らない。

### 古い記憶は月ごとのファイルに置く

- `archive/2026-10.md` のように、**期間（月）でファイルを分ける。** 各項目には、当時のトピック名を見出しで付ける。
- トピックの統合・分割に影響されず、追記するだけで済む。話題で引くときは `search_memory` を使う。
- 本人の問い「トピックのファイルが統合されたり分割されたらどうするの？」から決めた。

退けた案:

- **トピックごとに置き、今の構成に合わせて動かす**: 係の仕事が倍になる。一晩で動かしきれないと、トピックと archive の構成がずれる。
- **当時のトピック名で固定して置く**: 今の構成と名前が合わなくなる。

### archive/ を書けるのは係だけで、追記のみ

- `archive/` を書けるのは係だけである。係は、その夜の月のファイルに足すだけで、既にある行は直さない。過去の月のファイルは触らない。
- **サーバーの検査で強制する。**
  - なつみのターン（日中も夜の振り返りも）で `archive/` が変わっていたら、他の固定のファイルと同じく直前のコミットの状態へ戻し、理由を次のターンの入力で伝える。
  - 係が既にある行を変えたら、係の変更を捨てる。捨てる範囲は、後述の工程の単位である。
- 例外は、後述の圧縮の夜だけである。

退けた案:

- **指示だけで強制しない**: 守られなくても気づけない。
- **なつみも書ける**: 書き方が揃いにくい。

### 古いほど粗く: 月 → 四半期 → 年

- 月のファイルは、**3 か月経ったら四半期のファイル**（`archive/2026-Q3.md`）に要約してまとめる。
  四半期のファイルは、**1 年経ったら年のファイル**（`archive/2025.md`）にまとめる。
- まとめる夜だけ、係は元のファイルを消して新しいファイルを作れる。追記のみの例外である。元の細部は git に残る。
- まとめる夜の検査（消してよいのはまとめる対象のファイルだけ、など）の細部は、実装の PR で決める。

退けた案:

- **月のまま書き縮める**: ファイルが月の数だけ増え続ける。
- **大きさで圧縮する**: いつ粗くなるかが読めない。

### 思い出すと強まる: その日の会話の本文から、使われた記憶を係が推す

- サーバーが、その日の session から**マスターとのやりとりの本文**（届いた言葉と、なつみの返事）だけを抜き出し、
  なつみが記憶を `read`・`search_memory` した記録を添えて、係に渡す。思考とツールの結果は入れない。
- 係はこれを読んで、使われた記憶、話題に出た記憶を推す（本人「その日の会話内容から推測できない？」）。
  よく使われる記憶は、古い記憶として archive へ移す前の判断の手がかりになる。推した結果を係がどう使うかの指示の文は、実装の PR で決める。
- 抜き出す本文の大きさの上限は、実装の PR で決める。

退けた案:

- **一行メモと `diary/` だけを渡す**: なつみが書かなかった話題を拾えない。
- **session をそのまま渡す**: 大きく、上限に当たりやすい。
- **ファイルの参照の回数を数えるだけ**: ファイルを開かずに話題に出た記憶を拾えない。

### 出来事から知識へ: 夜に知識へ固めるのは係の仕事にする

- **なつみは日中、「覚えておいて」と言われたことと約束だけをトピックに書き、出来事は `diary/` に書く。**
- 係が `diary/` と、上の会話の本文を読み、繰り返し出ること・新しい事実を、トピックの知識や傾向として書き起こす。
- なつみの夜の振り返りから「今日のことのうち、まだ記憶に無いものを書き足す」を外す。
  なつみの夜は、引き継ぎ、`always.md`・`personality.md` の見直し、作業場の片づけに絞る。

退けた案:

- **なつみと係の両方がやる**: 同じことを二度書きやすい。
- **なつみのままにする**: 出来事から知識へ、が入らない。

### 連想のつながりは、本文のリンクと末尾の「関連」の節で張る

- 係が、本文の中に Markdown のリンクを張り、各トピックの末尾に「関連」の節を置く。読んでいる場所からそのままたどれる。
- 改名・移動のときは、後述のパスの置き換えと同じく、サーバーが全ファイルのリンクを置き換える。

退けた案:

- **`INDEX.md` に関係を書く**: 読んでいる場所からたどれない。
- **関係のファイルを別に置く**: 開かなければ使われない。

### 改名・移動のとき、古いパスはサーバーが置き換える

- **係には「ファイルの名前と場所を変えてよい」と伝える。**
- 係のコミットの後、サーバーが git の改名を読み、`always.md`・`handoff.md`・`personality.md` の中の古いパスを新しいパスに機械的に置き換える。
  リンク（前節）も同じく置き換える。
- 統合で消えたパスは、git の改名からは読めない。係が対応表で統合先を示す。対応表の渡し方は実装の PR で決める。
- 係が固定の 3 つを変えてはいけないこと（ADR 0055）は変わらない。置き換えはサーバーが行う。
- ADR 0055 の「古いパスは係が直さない。なつみは `INDEX.md` か `search_memory` で探し直す」は覆る。

退けた案:

- **伝えるだけで直さない**: `always.md` が無いパスを指す期間ができる。
- **係にパスだけを直させる**: パス以外を変えていないことを検査しにくい。

### 一晩で中身を書き直してよい範囲: 小さいうちは全部

- **トピックの合計が設定の大きさ以下なら、毎晩すべてのトピックを書き直してよい。** 超えたら、今の「その日に変わったファイル＋順番が回ってきたファイル」（ADR 0055）に戻る。
- 数えるのはトピックだけで、`archive/` と `diary/` は数えない。
- 大きさの設定は `curator.rewriteAllMaxChars`、既定は 100000 文字とする。数えるのは、`archive/`・`diary/`・固定のファイル・`INDEX.md` を除いたファイルの文字数の合計である。
  0 にすると、常に「変わったもの＋順番」になる。全部を書き直してよい夜は、渡したトピックのすべてに「最後に係の手が入った日」が付く。

退けた案:

- **制限を外す**: 記憶が増えると上限に当たり、工程ごと捨てる夜が増える。
- **今の形で、順番の本数を増やす**: 書き直せないファイルが残り、統合の妨げが残る。

### ファイルの中は話題ごとの節にする

- 節の木は係が決める。係への指示に、次を入れる。
  - 話題ごとに節を立てる。
  - 節に合わない行は、合う節か、合うファイルへ移す。
  - 長い節は `###` で分ける。
  - 各節は要点から書く。
- どのトピックにも共通なのは、末尾の「関連」の節だけである。
- 見取り図に**節ごとの行数**を添え、長く平らな節が係から見えるようにする。
- 見取り図には、ファイルごとの最後に変わった日と、最後に係の手が入った日も添える。古さを判断する手がかりにする。
- 見取り図の形（実装で決めた）:
  - ファイルごとに「大きさ・最後に変わった日・最後に整理した日（無ければ「まだ整理していない」）」を 1 行に並べ、その下に節を並べる。
  - 最後に変わった日は、そのファイルを変えた最後のコミットの日である。最後に整理した日は、SQLite の記録（ADR 0055 の schema 22）から読む。どちらもなつみの時間帯の日付で出す。
  - 節は `#`〜`###` の見出しごとに、次の見出しまでの空でない行の数を添える。見出しの前に行があれば「見出しの前」の節として数える。見出しの無い平らなファイルも、長さが見える。
  - 係への指示には、行数の多い節（目安は 20 行を超えるもの）を分けられないか考える、を入れた。

退けた案:

- **固定の型を決める**: 話題に合わない空の節ができ、中は平らになりやすい。
- **指示だけにして行数を渡さない**: 見出しの少ない平らなファイルが、係から見て整って見えるままになる。

### 文ごとに主語を書く

- **記憶に残す文は、文ごとに主語（誰が）を書く**（本人「主語を抜かさないようにしたい。」）。
- 対象は、後で読み返す文すべてである。トピック、`diary/`、`archive/`、`handoff.md`、一行メモ（[ADR 0047](0047-folding-ended-turns-with-a-memo.md)）。
- 係と、なつみ（日中・夜）の書き方の指示の両方に「主語を省かない」を足す。今の「自分」「本人」「あの人」を使わず呼び名で書く、は残す。
- 係は、書き直すファイルで主語の抜けた文を見つけたら補う。会話の本文や `diary/` から分かる範囲でよく、分からなければそのままにする。

### 一晩を工程に分け、工程ごとにターン・コミット・session を分ける

- **一晩を工程に分ける。** 例: ①出来事から知識へ → ②古い事実を archive へ移す・圧縮する → ③構成と節の組み直し・リンク・主語 → ④`INDEX.md`。
  工程の分け方と順は、実装の PR で決める。
- **工程ごとにターンとコミットを分ける。** 失敗した工程だけを捨て、前の工程のコミットは残る。工程の中は、今どおり全部か無しかである。
- **工程ごとに新しい session を作る。** 各工程は空のコンテキストで始め、その工程のための指示と入力だけを渡す（①なら会話の本文と `diary/`、③なら見取り図と節の行数）。
  前の工程の結果は、記憶のファイルとコミットから読む。
- 呼び出しと時間の上限（`curator.modelCalls`・`curator.timeoutMinutes`）は、工程ごとにまるごと使える。一晩の合計ではない。
  合計にすると、前の工程が使った分だけ後の工程が打ち切られやすくなり、工程に分けた意味が薄れる。一晩の最大の時間は、工程の数 × `timeoutMinutes` になる。
- ADR 0055 の「一晩 1 コミット、全部か無しか」「毎晩 1 つの session を作り、1 ターンで終える」は覆る。
  ADR 0055 の、係を始める前に作業ツリーがコミットと同じであることを確かめる、動き始めを SQLite に記録して次の起動で書きかけを捨てる、は工程ごとに行う。

#### 工程の分け方と順（実装で決めた）

- この版の工程は、**③構成と節の組み直し（`structure`）→ ④`INDEX.md`（`index`）** の 2 つである。①出来事から知識へと②archive は、それぞれの作業単位で前に足す。
  - 索引を最後の工程に分けたのは、索引が前の工程の結果（ファイルの移動）に合わせて書くものだからである。構成の工程が失敗しても、索引の工程は今の構成に合わせて索引を直せる。
  - 9/30 の夜は、係の最後の書き込みである `INDEX.md` に日本語以外の文字（簡体字）が 1 字残り、検査でその夜の組み直しがすべて捨てられたとみられる。工程に分けたことで、同じことが起きても捨てられるのは索引の工程だけになる。
- 工程ごとの違いは、サーバーの工程の表に持つ。1 行が 1 工程で、名前、指示、最初の入力の組み方、その工程だけの検査、トピックを書き直す工程かどうか、を持つ。工程を足すのは、表に行を足すことである。
  - 指示は、どの工程にも共通の部分（記憶の決まり・書き方・捨てられる条件）と、工程ごとの部分を、system prompt に続けて入れる。
  - 工程ごとの検査は、ADR 0055 の係の検査に重ねて掛ける。構成の工程は `INDEX.md` を変えられない。索引の工程は `INDEX.md` とディレクトリの中の `README.md` だけを変えられる。
- 1 つの工程が失敗しても、次の工程は動く。止めで打ち切られたときだけ、後の工程を始めない。
- 「その日に変わったファイル」を数える起点（ADR 0055 の、最後に係が成功したコミット）は、トピックを書き直す工程がすべて成功した夜に、その夜の最後のコミットへ進める。
  書き直す工程が失敗した夜は進めず、変わったファイルは次の夜に持ち越す。
- ダッシュボードでは、工程ごとに係のターンが 1 つ並ぶ。`turn_stats` の種類は `curator` のままで、出来事の欄（`event_kinds`）を `memory_curator:<工程の名前>` にして見分ける。schema は変えない。
  工程が機械的に付けるコミットメッセージも、同じ名前で始まる。
- 係の一晩は、記憶のリポジトリ・作業環境・モデルの経路・係の設定・SQLite の記録・時計・ログを受け取って全工程を回し、工程ごとの結果を返す関数にした。
  思考ループはそれを呼ぶだけで、なつみを寝かせること、出来事を溜めること、切り替えとの順序は思考ループに残る。写しで係の一晩を回す評価（進め方の 7）も、同じ関数を呼ぶ。

退けた案:

- **1 ターンのまま上限を上げる**: 最後の方で上限や検査に当たると一晩分が消える。9/30 の夜は、最後の書き込みが検査に当たって一晩分が消えた。
- **1 ターンの中で、係が区切りのツールを呼んでコミットする**: 区切りが係任せになり、コンテキストには一晩分がたまる。
- **同じ session で工程を続ける**: 後の工程ほどコンテキストが埋まる。

### 係のモデルを `/settings` で選ぶ

- 係の経路（`curator.route`、ADR 0055）を、[ADR 0058](0058-settings-and-chat-in-the-browser.md) の `/settings` から選べるようにする（本人「係もモデルを選択できるようにする。」）。
  ADR 0058 で「後から足す」とした記憶の整理係を、ここで足す。なつみの経路と同じく、画面から係の経路を選ぶ。
- どの経路にするかは、本人が画面で選ぶ。
- ChatGPT Plus の経路を選ぶと、記憶とその日の会話の本文が外に出る。このことを画面の説明に書く。
- 上限（`modelCalls`・`timeoutMinutes`）も画面に出すかは、実装の PR で決める。

### 本番に入れる前に、写しで係の一晩を回す

- 既存の評価（[ADR 0051](0051-evaluating-one-turn-on-the-real-path.md)・[ADR 0052](0052-trying-a-turn-on-a-copy-of-production.md)）を広げ、写しの記憶と session で、係の一晩（全工程）を回せるようにする。
- 結果の記憶を本人が見て、経路（モデル）も比べてから本番へ入れる。写しの取得は本人が行う。

実装で決めたこと（評価のコマンド `curate`・`curate-compare`、使い方は `eval/README.md`）:

- 写すのは、写しの記憶（git の履歴ごと）・SQLite・Pi の session だけである。結果の置き場の中に写してから回し、写しそのものは変えない。
- 外に作用させない仕組みは ADR 0052 の三重（評価用の設定だけ、ネットワークからの隔離、起動時の拒否）をそのまま掛ける。結果は私的な置き場に置き、30 日で消す。
- 経路は、1 ターンの評価と同じくモデルのファイルで選ぶ。設定の `curator.route` の代わりに、そのファイルの経路で係を回す。上限と順番の本数は設定の既定値で、コマンドの指定で変えられる。
- 係に伝える「今夜」は、写しを取った時刻にする。指定で変えられる。
- 写しの記憶にコミットされていない変更があれば、夜の前に別のコミットにして、夜の差に数えない。本番では夜の振り返りが係の直前にコミットしているからである。係の途中で取られた写しなら、サーバーと同じく書きかけを捨てる。
- 係は、思考ループが呼ぶのと同じ係の一晩（全工程）を、思考ループを開かずに呼ぶ。なつみの振り返りは回さない。写しに係の書きかけが残っていれば、サーバーの起動と同じく先に捨てる。
- 結果として、夜の後の記憶（履歴ごと）、夜の前からの差、コミットのメッセージ、工程ごとの成否・コミット・変更の説明・検査に当たったもの・呼び出しの回数・時間・token、係の session の記録、サーバーの記憶と係のログを残す。2 つの夜を並べる比較も出す。合否の判定は置かない。読むのは本人である。

退けた案:

- **そのまま本番で見る**: 本番の記憶で試すことになる。
- **1 ターンの評価の場面として書く**: 場面は 1 つの出来事に対する返事と、その判定の形をしている。係の一晩には出来事も判定も無く、見たいのは記憶の差である。

### ADR 0055 から残るもの

- 係は人格を持たず、なつみのサーバーの中の別の Pi の session として動く。使えるツール（`run_shell`・`read`・`search_memory`・変更の説明を書くツール）。
- 夜の振り返りの直後、session を切り替える前に動き、その間なつみは寝ている。係が失敗しても夜の切り替えは止めない。
- 固定の 3 つと `diary/` は係が変えない。`INDEX.md` は係だけが書く。
- 係のコミットに、なつみと同じ検査を掛ける。重複は消してよく、消したものは変更の説明に書く。本人の言葉・約束・「覚えておいて」は、済んだと明らかでない限りトピックから外さない。
- 係の結果は翌朝のなつみに渡さない。どのファイルにいつ係の手が入ったかを SQLite に記録する。
- 設定 `curator` 節の `enabled`・`route`・`modelCalls`・`timeoutMinutes`・`rotateFiles`。

## 置き換える既存の決定

- **ADR 0055**
  - 置き換え:「消してよいもの」のうち、古くなったものを消してよいこと。古くなった事実は要約して `archive/` へ移す。
  - 置き換え:「係が触ってはいけないもの」のうち、`always.md`・`handoff.md` の古いパスを直さないこと。サーバーが置き換える。
  - 置き換え:「一晩に渡すもの」のうち、中身の書き直しを変わったファイルと順番のファイルに限ること。トピックの合計が設定の大きさ以下なら全部を書き直してよい。
  - 置き換え:「係のコミットと、検査に当たったとき」のうち、一晩 1 コミットと、その夜の全部を捨てること。工程ごとにコミットし、捨てるのは失敗した工程だけである。
  - 置き換え:「係は、なつみのサーバーの中の別の Pi の session として動く」のうち、毎晩 1 つの session を 1 ターンで終えること。工程ごとに session とターンを分ける。
  - 置き換え:「日中の書き方」のうち、トピックに何を書くか。日中のトピックは「覚えておいて」と言われたことと約束に限り、出来事は `diary/` に書く。変わりうる事実に時点を、文ごとに主語を書く。
  - 追加: `archive/`、会話の本文を係に渡すこと、リンクと「関連」の節、話題ごとの節、見取り図の節ごとの行数と日付。
- **ADR 0020**
  - 置き換え: 夜の候補のうち「記憶全体を読み直し、今日のことのうち残すものを書く」。出来事を知識にするのは係の仕事になる。
  - 残す: 手順ではなく候補として渡すこと、必須は引き継ぎだけであること、やらなかったことを引き継ぎに書くこと。
- **ADR 0018**
  - 追加: なつみのターンで書けないものに `archive/` を加える。書けるのは係だけで、追記のみである。
  - 置き換え（ADR 0055 で追加したもの）: 係のコミットは検査に当たれば全部を捨てる、を工程ごとにする。
- **ADR 0047**
  - 追加: 一行メモも、文ごとに主語を書く。
- **ADR 0058**
  - 追加: 画面から変えられる設定に、記憶の整理係の経路を加える。
- **ADR 0051・ADR 0052**
  - 追加: 評価で回せるものに、写しの記憶と session から始める係の一晩（全工程）を加える。
- **ADR 0067**
  - 置き換え（Consequences）: 係のコミットが失敗するとその夜の変更が全部捨てられる、を工程ごとにする。捨てるときに本人がコミットしていない変更も消えることは、工程ごとに起こり得る。

## Consequences

- 記憶の構成が、パスを恐れずに変わるようになる。`always.md` などの古いパスは係の後にサーバーが直すので、無いパスを指す期間ができない。
- 古くなった事実はトピックから消え、`archive/` に要約で残る。なつみは今の記憶だけを読み、昔のことは `search_memory` で探せる。
- `archive/` は月ごとに 1 ファイルずつ増え、圧縮の夜にだけ減る。圧縮の前の細部は git にだけ残る。
- 夜にモデルを使う時間と回数が増える。工程の数だけ session とターンを作り、それぞれが上限をまるごと使える。その間、なつみは寝ていて、届いたメッセージは切り替えの後に扱われる。
- 係に、その日の会話の本文を渡す。ChatGPT Plus の経路を選ぶと、記憶に加えて会話の本文も外に出る。
- 1 つの工程が失敗しても、前の工程の結果は残る。9/30 のように一晩分が消えることは減るが、工程の途中まで進んだ記憶で翌日が始まることがある。
- なつみの日中の記憶の書き方が変わる。出来事がトピックに入るのは、その夜の係の後になる。「覚えておいて」と約束は今までどおり日中に入る。
- 係の書き方が、時点・主語・話題ごとの節・リンクの分だけ重くなる。書き直しの量も増える。
- ダッシュボードの係のターンは、一晩に工程の数だけ並ぶ。
- 係の session の記録が、毎晩工程の数だけ増える。
- 権限と秘密の一覧（`docs/permissions.md`）の、係の変更を全部捨てる記述と、係に渡すもの（会話の本文）は、実装の PR で改める。

### 進め方

1. この ADR。
2. 係の工程化と、係に渡す一覧の改良（工程ごとのターン・コミット・session、全部を書き直してよい範囲、話題ごとの節と節の行数、見取り図の日付）。
3. `archive/` と圧縮、その検査。
4. 会話の本文の抜き出し、出来事から知識へ、なつみの書き方の変更（時点、主語、日中と夜の分担）。
5. パスとリンクの置き換え。
6. `/settings` で係の経路を選ぶ。
7. 写しで係の一晩を回す仕組み。本番に入れる前の関門である。
