# 0046. モデルの経路に名前を付けて並べ、本人が手で切り替える

- Date: 2026-09-26
- Status: Accepted（経路を WebSocket の `settings.set`・`settings.reset` からも選べることと、「config に戻す」で選んだ記録を消すことを [ADR 0058](0058-settings-and-chat-in-the-browser.md) で追加）

## Context

natsumi の思考ループのモデルは、設定の `pi.model`（provider と model）で 1 つだけ選んでいた。
本人の OpenAI 互換のエンドポイントを使うなら `pi.compatible` と組にし、サブスクリプションの経路なら専用の Pi 領域の OAuth のログインを使う。
経路は設定で明示し、ほかの経路への自動の fallback はしない（[ADR 0004](0004-pi-tool-and-voice-boundaries.md)）。

本人のエンドポイントを保守で止めると、その間 natsumi は話せない。別の経路で動かすには、設定を書き換えて起動し直すしかなかった。
本人は、切り替えを簡単にしておきたいと考えた。

手元には次のものがあった。

- Pi の session は、`setModel` で途中からモデルを変えられる。変えたことは session のファイルに残る。
  ただし `setModel` は、session を作った runtime が知っている provider にしか移れない。
- 別のモデルに移ると、Pi は前のモデルの思考を平文にして渡す（暗号化された思考は捨てる）。同じモデルに戻れば、そのモデル自身の思考はそのモデルの形で戻る。
- compaction はターンの間にだけ行い、その閾値は 1 つだった（[ADR 0009](0009-long-term-memory-and-nightly-session-switch.md)）。
  閾値と窓の組み合わせは起動時に検査しているが、検査するのは互換のエンドポイントの窓だけだった。
- ポッポさんの判定は、既定で pi の互換のモデルの logprobs を使い回している（[ADR 0040](0040-the-dove-sends-what-the-judge-passes.md)）。サブスクリプションの経路は logprobs を返さない見込みである。
- 動いているサーバーに外から何かを伝える道は、データディレクトリのファイルだけである。`health` のサブコマンドも、サーバーが書く状態のファイルを読む。

## Decision

### 経路に名前を付けて設定に並べ、1 つを既定にする

- 設定の `pi.routes` に、名前付きの経路を並べる。経路ごとに model（provider と id）、互換なら `compatible` の節（接続先・キー・窓）、省ける compaction の閾値を持つ。
- `pi.defaultRoute` で既定の経路を 1 つ指す。本人が何も選んでいなければ、既定の経路を使う。
- `pi.model`（と `pi.compatible`）だけの設定は、`default` という名前の経路 1 つとして読む。`pi.routes` と一緒には書けない。
- 互換の経路は、Pi の中でそれぞれ自分の provider を持つ。`natsumi-compatible` か、`natsumi-compatible-` で始まる名前で、経路どうしで重ねない。
  1 つの provider には接続先が 1 つしかないからである。1 つ目の互換の経路の provider を今までどおり `natsumi-compatible` にしておけば、これまでの session の記録と同じモデルとして扱われる。

### 切り替えは本人が手で行い、ターンの間で効く

- 本人（と本人の Claude）が「今はこの経路」と選ぶ。サーバーは次のターンからそのモデルを使う。自動の切り替えはしない。ADR 0004 の「経路は明示し、自動の fallback はしない」はそのまま保つ。
- サーバーは、ターンを始める前に毎回、選ばれた経路を確かめる。選ばれた経路が今の経路と違えば、ターンの前に移る。だから切り替えがターンの途中に入ることはない。
- 同じ session を続ける。次のターンからモデルだけが変わり、新しいモデルはそれまでの会話を受け取る。前のモデルの思考は平文になって渡る。
  切り替えるたびに prefix cache は外れる。
- 移ったとき、session がすでに新しい経路の閾値を超えていれば、次のターンの前に新しい経路のモデルで compaction する。
- 思考の強さ（thinking）は経路によらず設定のとおりにする。Pi がモデルに合わせて選び直した値は使わない。
- 使える状態にない経路（キーが読めない、ログインが無い、Pi がモデルを知らない）には移らない。今の経路のまま、ログに一度だけ理由を書く。代わりの経路は試さない。
- 起動のときに、選ばれた経路が使える状態になければ、natsumi は話せない状態で起動する。既定の経路にも落とさない。別の経路を選んで起動し直せば戻る。

### 選んだ経路はデータディレクトリに残す

- 選んだ経路はデータディレクトリのファイルに書く。サーバーは起動のときにもそれを読むので、再起動しても選んだ経路が続く。
- 設定から消えた経路が選ばれていたら、既定の経路に戻し、ログに書き、ファイルも既定に書き直す。
- サーバーは、経路の一覧・使える状態か・今の経路・選ばれた経路を、別のファイルに書いて公開する。

### サーバーのコマンドと、アプリ向けのコマンド

- サーバーのコマンドラインに `model list`・`model status`・`model use <経路>` を足す。`health` と同じく、データディレクトリだけを相手にする。
  `model use` は選んだ経路をファイルに書くだけである。動いているサーバーは次のターンの前に読み、何もしていないときも定期の見回りで読んで移る。
  止まっているサーバーは、次の起動で読む。サーバーが公開した一覧があれば、知らない経路と使える状態にない経路は書く前に断る。
- ログインしたクライアントには、経路の一覧を読むコマンドと、経路を選ぶコマンドを足す。今の経路は同期のときにも渡し、変わったら全端末に知らせる。
  クライアントに渡すのは経路の名前・provider・model・使える状態かだけで、接続先とキーは渡さない。
- Mac と iPhone の画面は、後から足す。

### 経路ごとの閾値と、その検査

- 経路ごとに compaction の閾値を持てる。書かなければ共通の `loop.compactionThreshold` を使う。
- 起動時の検査（閾値に 1 ターンの伸びと 1 回の返事の上限と Pi の余白を足した量が、窓を超えないこと）を経路ごとに行う。
  互換の経路は設定の窓で、設定を読むときに検査する。サブスクリプションの経路は Pi のモデル定義の窓で、サーバーの起動時に検査する。
- 保存しておく直近の量（`loop.compactionKeepRecent`）は、どの経路の閾値よりも小さくなければならない。

### ポッポさんの判定は切り替えに依らない

- 判定が使い回すのは、既定の経路の互換のモデルだけである。どの経路で動いていても、判定の接続先・キー・model は変わらない。
- 既定の経路が互換でなければ、判定に明示した先が無い限り判定は無い。本文のある投稿はすべて本人の承認に回る。
- 既定の経路のエンドポイントが止まっている間は判定が無く、同じく本人の承認に回る（今の決まりのまま）。

## Alternatives

- **設定を書き換えて起動し直す（今までどおり）**: 仕組みは要らないが、保守のたびに設定の変更と適用が要る。本人は切り替えを簡単にしたかった。
- **止まったら自動でほかの経路に移る**: 本人の上限やログインを知らないうちに使うことになり、ADR 0004 の決定に反する。
- **切り替えたら新しい session にする**: 思考の記録が途切れ、夜の振り返りの前に一日の流れを失う。同じ session を続けても、別のモデルは平文で会話を受け取れる。
- **動いているサーバーに届けるためにローカルの listener を開く**: 認証の要らない口がもう 1 つ増える。データディレクトリのファイルなら、`kubectl exec` で入れる人だけが書ける。
- **経路ごとに Pi の runtime を分ける**: Pi の `setModel` は session の runtime にある provider にしか移れないので、1 つの session を続けられない。
- **ログインのファイルが無くても作って読む**: サーバーはログインのファイルを作らない（ADR 0004）。起動のときにファイルが無ければ、サブスクリプションの経路は使える状態にならず、ログインした後に起動し直せば使える。

## Consequences

- 本人は、設定を変えずに、動いているサーバーの経路を切り替えられる。切り替えは次のターンの前か、何もしていなければ見回りの間隔（15 秒）のうちに効く。
- 切り替えるたびに prefix cache が外れ、新しい経路の閾値を超えていれば compaction が 1 回入る。
- 前のモデルの思考が平文で次のモデルに渡るので、次のモデルはそれを自分が書いた文として読む。本人に見える返事はツールで出すので、本人の画面には出ない。
- 使える状態にない経路を選んだまま再起動すると、natsumi は話せない。別の経路を選んで起動し直す必要がある。
- 互換の経路を増やすときは、provider の名前を経路ごとに変える必要がある。
- サブスクリプションの経路の閾値の誤りは、設定を読むときではなく、サーバーの起動のときに分かる。
